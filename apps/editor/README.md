# 주니 문서 편집기 개발판

한글 2024 Windows를 기준으로 만드는 로컬 HWP/HWPX 편집기다. rhwp 0.8.7의 Rust/WASM 엔진과 Studio를 바탕으로 문서 탭, 탭별 도구 상자, 스타일 창, 저장 보호를 추가했다. **한글 2024 전체 기능·화면·호환성이 같은 제품으로 검증한 것은 아니다.**

## 실행과 저장

프로젝트 루트 `Start-Editor.cmd` 또는 준비된 묶음의 `JoouniEditor.exe`를 실행한다. 실행 파일 옆의 `dist` 폴더가 필요하다. Rust 런처가 `127.0.0.1:4173`에 정적 자산만 제공하고 설치된 Edge/Chrome의 독립 창을 연다. Node.js가 필요 없는 실행 경로다. AI나 외부 Studio 사이트에 연결하지 않는다. 브라우저 자체 통신까지 포함한 OS 수준 폐쇄망 검수는 별도다.

일반 Edge/Chrome에서는 File System Access API의 열기·저장 대화상자를 사용한다. 선택한 원본의 SHA-256을 기억하고, 원본이 다른 프로그램에서 바뀌었으면 저장을 거부한다. 저장 중에는 입력을 막고 문서 버전을 검사한다. 이 경로의 실제 Windows 파일 선택 UI 조작은 아직 미검증이며 저장 보호 로직을 단위 시험했다. 디스크 교체 직전의 외부 프로세스 경쟁까지 원자적으로 막는 파일 잠금은 없다.

API가 없는 브라우저 또는 `?storage=download`에서는 다운로드로 저장한다. 다운로드는 부모 창에서 시작하며 파일이 저장된 것을 사용자가 확인해야 clean 상태로 바뀐다. 이 확인 전에 문서 탭을 닫지 않는다. 다운로드 취소 시 문서와 복구 내용을 유지한다. 이 경로는 UI에서 실제 HWP/HWPX 파일을 받아 검증했다.

파일을 여러 개 편집하려면 아래쪽 `+`로 새 탭을 만든 뒤 파일을 연다. 현재 탭의 열기는 그 문서를 교체하므로 수정 내용이 있으면 저장 확인을 거친다. 여러 문서 탭의 엔진·커서·undo는 독립적이다. 새 탭에서 다른 열린 문서의 자동 복구를 다시 제안하지 않는다.

`fixtures`의 기본 문서·표 문서는 합성 검수 자료다. 실제 한글 2024에서 열어 쪽 수, 글꼴, 표 경계, 저장 후 재열기를 확인한다. 현재 PC에는 Viewer가 확인되었지만 편집 가능한 한글에서의 검수는 하지 못했다.

## 빌드

참조 소스는 `../../upstream/rhwp-source`, 고정 커밋은 `1a76570e833917d15817415a53c09ad61ab3203f`다. 빌드는 `.build/studio`에 사본을 만들며 참조 저장소의 tracked 파일을 수정하지 않는다. 소스 변경이나 패치 기준 불일치를 발견하면 중단한다.

```powershell
npm ci
npm run build
npm run typecheck
npm test
# 프로젝트 루트에서:
.\scripts\Build-Standalone.ps1
# Node 개발 서버:
.\scripts\Start-Editor.ps1
```

Windows 실행기는 프로젝트 내부 Rust 1.93.1과 VS C++ 도구를 사용한다. `scripts/Build-Standalone.ps1` 실행 전에 이미 실행 중인 같은 exe를 종료해야 한다. `dist/build-evidence.json`에 참조 커밋, 자체 코드 해시, 엔진 WASM 해시를 기록한다. 엔진은 공식 `@rhwp/core@0.8.7` 배포 WASM이며 이 빌드에서 Rust 엔진 자체를 다시 컴파일한 것은 아니다.

`src-tauri`에는 네이티브 파일 대화상자, 파일별 토큰, 임시 파일 후 교체, 외부 변경 검사와 종료 확인 코드를 준비했다. 이 PC에서는 Windows 애플리케이션 제어가 의존성 빌드 프로그램 실행을 차단했다. **Tauri 호스트와 WebView2 저장은 컴파일·실행 검증 전**이며 현재 실행기는 이를 사용하지 않는다. 보안 정책은 변경하지 않았다.

## 검증과 제한

- 빌드·TypeScript 검사 통과. 앱 테스트 8개 통과.
- UI: 입력, 실제 문단 나누기, undo, 탭 전환/취소/저장 후 닫기, 스타일 적용, 크기·굵게·가운데 정렬, 3×3 표·Tab 셀 이동, HWP/HWPX 다운로드 저장, HWPX 재열기 확인.
- 두 형식에서 기본 문단 3개와 표 셀 9개를 검사하고 양쪽 형식으로 재저장해 다시 검사했다. 같은 엔진의 재열기이므로 한글 호환성 판정이 아니다.
- 실행 중인 Rust 런처는 `node apps/launcher/verify-server.mjs`로 HTTP 검증 13개를 통과했다. Rust 테스트 실행 파일은 OS 정책으로 실행하지 못했다.
- 보안 탭, 모든 상황별 도구 상자, 전체 대화상자, 인쇄·복잡한 표·결재 양식·IME·접근성 정합성은 미완료다. 한컴 글꼴을 포함하지 않으며 대체 글꼴 때문에 지면이 달라질 수 있다.
- 자동 복구는 로컬 브라우저 저장소를 사용한다. 브라우저/프로필 변경·저장소 삭제 때의 복구 보장과 탭 세션 전체 복원은 미구현이다.
- 런처 서버는 편집 창을 닫아도 남아 다음 실행 때 재사용한다. 별도 설치 서비스나 자동 시작 등록은 하지 않는다. 오류는 실행 파일 옆 `launcher-error.txt`에 남긴다.

## 저작권과 라이선스

rhwp의 MIT 고지는 `LICENSE.rhwp.txt`, 원본 부속 고지는 `dist/THIRD_PARTY_LICENSES.rhwp.md`, 폰트 설명·고지는 `dist/fonts`, npm 런타임 고지는 `dist/licenses`에 유지한다. Rust 표준 라이브러리 고지는 실행 묶음에 복사한다. 상용 한컴/Windows 글꼴을 새로 추출해 포함하지 않았다. 최종 기관 배포의 전체 SBOM·고지는 배포 구성 확정 후 재검토한다.

화면 기준은 [한글 2024 공식 화면 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/hwpbase/screen.htm)과 [도구 상자 설명](https://help.hancom.com/hoffice130/ko-KR/Hwp/view/toolbar/toolbar.htm)이다. 원본 기능을 사용한다는 사실과 한글과 동일하게 검증됐다는 주장은 구분한다.
