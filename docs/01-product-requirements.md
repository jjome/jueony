# 제품 요구사항과 초기 범위

이 제품은 공무원이 업무 자료와 작성 중인 한글 문서를 한 화면에서 다루며, AI가 제안한 수정의 범위와 근거를 확인할 수 있게 한다. 핵심 가치는 기존 양식의 보존, 자료 출처의 추적, 승인한 변경만 적용되는 편집 흐름이다. 대화의 유창함보다 문서 손상 방지와 저장 신뢰성을 먼저 검증한다.

## 사용자와 사용 환경

- 한국 공공기관의 Windows 데스크톱 사용자. 초기 검증 대상은 Windows x64이며 실제 기관 OS·WebView2·한글 버전은 검수 환경에 기록한다.
- 편집, 자료 관리, 검색, 대화 기록은 로컬에서 동작한다. AI 생성은 허용된 기관 서버와 연결될 때 제공한다.
- 인터넷 단절과 기관 내부 AI 서버 단절은 구분한다. AI 서버가 없어도 문서 열기·편집·저장은 가능해야 한다. 첫 검증은 네트워크 요청을 만들지 않는 mock으로 수행한다.
- 설치·빌드 준비에 인터넷을 사용하는 개발 환경과 최종 사용 환경을 구분한다. 사용 시점에 패키지·폰트·WASM 다운로드가 필요해서는 안 된다.

## 대표 사용자 흐름

1. 사용자가 업무를 만들거나 기존 업무를 연다. 왼쪽에서 업무 폴더, 개별 자료, 작업 문서와 대화 목록을 확인한다.
2. 공통 자료 중 이번 업무에 쓸 범위를 선택하고, 폴더 또는 개별 파일을 등록한다. 파일 드래그나 클립보드 파일 붙여넣기는 폴더 등록 없이 허용한다.
3. HWP 또는 HWPX를 가운데 편집기에 연다. 원본 경로, 저장 형식, 미저장 상태, 글꼴 대체 여부를 식별할 수 있다.
4. 본문 문단을 선택하고 오른쪽에서 수정 요청을 입력한다. 요청에 포함될 문단과 자료 범위를 함께 보여준다.
5. AI가 수정안과 사용한 출처를 제시한다. 변경 전후 텍스트와 실제 수정 대상 문단을 확인한다.
6. 사용자가 승인하면 현재 문서 상태를 재검사한 뒤 적용한다. 충돌한 제안은 다시 생성한다.
7. 즉시 되돌리거나 저장한다. 저장 실패 시 문서는 미저장 상태와 복구 자료를 유지한다.

## 화면과 기본 조작

| 위치 | 주요 요소 | 동작 원칙 |
| --- | --- | --- |
| 왼쪽 | 업무 선택, 공통 자료, 업무 자료, 이번 요청 자료, 작업 문서, 대화 | 참고용 자료와 편집 중인 문서를 명확히 구분한다. 폴더 등록 없이 파일을 추가한다. |
| 가운데 | 문서, 선택 문단, 파일명, 미저장·저장 상태 | 문서 내용의 기준은 rhwp의 열린 문서다. 선택 범위와 AI 교체 범위를 따로 숨기지 않는다. |
| 오른쪽 | 대화, 참고 범위, 근거, 수정안, 비교, 적용·거절·되돌리기 | 자동 적용하지 않는다. 근거 열기는 파일과 위치를 함께 안내한다. |
| 상태 표시 | 분석 중·분석 완료·분석 실패, AI 연결 상태 | 파일 첨부 완료를 분석 완료로 표시하지 않는다. 제한된 발췌에는 범위를 표시한다. |

첫 검증에서는 한 번에 문서 하나와 수정안 하나만 활성화한다. 본문 일부를 선택했더라도 명령이 문단 전체를 교체한다는 점을 화면에 표시한다. 여러 문단·표 셀에 걸친 선택은 첫 단계에서 차단한다. IME 조합 중에는 문맥을 확정하지 않는다.

## 기능 요구사항

| ID | 요구사항 | 초기 제품의 수용 기준 |
| --- | --- | --- |
| F01 | HWP·HWPX 열기·편집·저장 | 형식별 호환성 시험을 통과한 범위를 명시한다. 미지원 문서에 성공을 표시하지 않는다. |
| F02 | 업무별 독립 공간 | 업무별 자료·문서·대화·작업 이력이 분리된다. 다른 업무 자료가 검색·프롬프트에 섞이지 않는다. |
| F03 | 여러 폴더와 개별 파일 | 폴더 연결과 복사한 파일을 함께 관리한다. 이름 변경·이동·삭제 상태를 표시한다. |
| F04 | 드래그·붙여넣기 자료 | HWP·HWPX 파일을 요청에 추가하고 파싱·검색하여 활용한다. 평문 붙여넣기는 별도 텍스트 자료로 기록한다. |
| F05 | 자료 범위 구분 | 공통·업무·요청 범위를 서버의 조회 조건까지 강제한다. 임시 자료를 지속 자료로 바꾸는 동작은 명시적이다. |
| F06 | 출처 검색 | 파일 버전·제목·발췌·논리 위치를 표시한다. 페이지를 확보하지 못하면 페이지 번호를 만들어내지 않는다. |
| F07 | 검토 가능한 AI 편집 | 제안 → 비교 → 사용자 승인 → 상태 재검증 → 적용 영수증 → 즉시 되돌리기가 이어진다. |
| F08 | 기관 AI 연결 | 승인된 endpoint·모델·인증을 통해서만 전송한다. 실패해도 로컬 편집은 유지된다. |
| F09 | 안전한 저장 | 원본 파일 변경 감지, 저장 실패 처리, 저장 완료 확인과 알림 순서를 보장한다. |

## 자료 범위와 보관

| 범위 | 소유와 사용 | 기본 동작 |
| --- | --- | --- |
| 공통 자료 | 같은 사용자 또는 기관 정책이 허용한 업무에서 재사용 | 해당 업무에서 사용하도록 활성화한 자료만 검색한다. 기관 전체 공유·다중 사용자 서버는 초기 범위 밖이다. |
| 업무 자료 | 특정 `workspace_id` | 업무가 유지되는 동안 로컬에 보관한다. 다른 업무에 자동 연결하지 않는다. |
| 이번 요청의 임시 자료 | 특정 `request_id` | 이번 요청에만 검색·전송한다. 다음 요청에 자동 재사용하지 않는다. |
| 편집 중인 문서 | 특정 `document_id`와 현재 문서 세대 | 저장 전 내용은 편집기에서 읽는다. 디스크의 이전 버전을 현재 내용처럼 사용하지 않는다. |

자료의 보관 기간, 로그 본문 보관, 임시 자료 만료 시점, 백업 보관은 기관 정책으로 확정한다. 요청 범위에서 제외하는 것과 파일을 실제 삭제하는 것은 별도 상태다. 원본·복사본·추출문·색인·프롬프트 스냅샷·자동복구본에 같은 보관 정책을 적용할 수 있어야 한다. 임시 자료가 삭제된 대화에는 출처가 만료되었음을 표시하고, 보이지 않게 계속 검색하지 않는다.

첫 제품은 폴더를 원위치 연결하고, 드롭한 개별 자료는 관리 공간에 복사하는 방식을 기본안으로 한다. 원본 경로와 가져온 시점의 해시를 남긴다. 같은 파일의 중복 감지 때문에 서로 다른 업무의 접근 범위를 합치지 않는다.

## 이번 단계와 첫 검증 범위

**이번 단계는 분석과 설계만 수행한다.** 아래 첫 검증의 구현은 다음 단계 작업이다.

첫 검증에 포함할 기능은 로컬 Studio·WASM·글꼴 로드, HWP·HWPX 한 문서 열기, 지원 가능한 본문 한 문단 문맥 획득, 결정적인 mock 수정 제안, 텍스트 비교, 승인·적용·거절·즉시 되돌리기, 같은 형식으로 다른 이름 저장, 실제 한글 검수 자료 준비다. 자료 검색·Python 사이드카·실제 LLM은 첫 편집 검증의 선행 조건으로 두지 않는다.

첫 검증에서 제외하는 기능은 업무 데이터베이스 통합, 표 셀 AI 편집, 다중 문단 일괄 수정, 혼합 글자 서식 문단 AI 편집, 결재선 자동화, 기관 API, 전자결재 연계, OCR, 공동 편집, 설치 프로그램 배포다. 표가 있는 문서의 표시·무수정 저장 검증은 제외하지 않는다.

## 초기 제품 범위

편집 검증을 통과한 뒤 F02~F06의 자료·대화 기능과 기관 AI 연결을 추가한다. 초기 AI 편집 범위는 검증된 단일 본문 문단을 유지한다. rhwp의 일반 편집기가 제공하는 기능과 AI 명령의 제한은 별도로 안내한다.

호환성 미확인 파일에는 편집·저장 허용 여부를 문서별로 판단할 수 있어야 한다. 열기에 성공했다는 이유로 서식 보존 저장을 보장하지 않는다. 본문 문단 편집만 지원하는 상태를 표 중심 기안문 편집 완성으로 홍보하지 않는다.

## 품질 기준과 미정 사항

- 무수정 저장에서도 내용·서식 손상이 발생하면 편집 통합보다 저장 경로 개선을 우선한다.
- 문단 적용 전 원문·서식·인접 문맥·문서 세대가 일치해야 한다. 거절된 명령은 내용을 바꾸지 않아야 한다.
- 오프라인 실행 중 허용되지 않은 외부 요청 시도는 0건이어야 한다. 단순 네트워크 차단 때문에 실패한 요청도 조사한다.
- 성능은 지정 PC와 corpus에서 측정한다. 지금 단계에서는 근거 없는 파일 크기·쪽수 SLA를 확정하지 않는다. rhwp 명령의 3초 상한은 구현 제약으로 별도 관리한다.
- 미정: 대표 문서, 기관 Windows·한글 버전, 필수 글꼴과 사용 권한, 허용 endpoint·인증, 보관 정책, 지원할 최대 문서 규모.

소스에서 확인한 제한과 실제 검증 여부는 [재검증 기록](02-source-audit.md), 통과 조건은 [호환성 검증 계획](04-compatibility-validation.md)을 기준으로 삼는다.
