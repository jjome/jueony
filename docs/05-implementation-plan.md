# 단계별 구현 계획과 첫 검증 과제

편집·저장 호환성을 먼저 입증한 뒤 업무 자료·검색과 기관 AI를 붙인다. 아래는 초기 설계 계획이다. 이후 사용자가 한글 2024 기준 편집기 구현과 중간 커밋을 요청하여 기본 편집기 개발에 착수했다. 현재 실행판과 변경된 우선순위는 [07-hangul-2024-editor.md](07-hangul-2024-editor.md)를 따른다. 기관 배포·외부 게시에는 착수하지 않았다.

## 단계별 계획

| 단계 | 구현 내용 | 진입 조건 | 완료 조건 |
| --- | --- | --- | --- |
| 0 조사와 설계 | 소스·지침·라이선스 확인, 요구사항·연결·검증 문서 | 현재 요청 | 고정 커밋과 코드 근거, 첫 검증 과제, 미확인 항목 정리 |
| 1 로컬 편집 기술 검증 | Tauri + 로컬 Studio·WASM, 문맥 adapter, mock·diff·적용·되돌림·저장 | 후속 구현 착수 지시 | 인터넷 없이 HWP·HWPX 전체 흐름 재현; 실패·충돌·저장 중 편집 처리; 검수 묶음 생성 |
| 2 실제 한글 호환성 | 독립 기준본과 corpus, 무수정·적용·되돌림 비교 | 1단계 산출물, 지정 한글과 글꼴 환경 | 형식별 합격·실패 범위 및 결함 분리; 손상 경로 해결 전 제품 확대 보류 |
| 3 업무 공간과 자료 | workspace·공통/업무/요청 scope, 폴더·개별 파일·임시 첨부 분석, 검색·출처·대화 | 편집·저장 관문 통과 | 다른 업무 자료 유출 0, HWP 임시 첨부 근거 검색, 변경·삭제·만료 반영 |
| 4 기관 AI 연결 | endpoint·인증·모델 adapter, 제한된 전송, streaming·취소·오류 | 기관 API 규격과 반출 정책 확보 | 기관 테스트 서버 계약 통과; 장애 중 로컬 편집 유지; mock과 동일한 승인 절차 |
| 5 기관 파일럿 준비 | 보관·복구·진단·SBOM·고지·오프라인 설치·업데이트 절차 | 지원 문서군·기관 정책 확정 | 기관 환경의 재현 가능한 설치·운영 검수 통과 |

단계 5의 설치·배포는 현재 요청 범위에 포함되지 않는다. 기간·인력 추정은 1~2단계의 호환성 결함과 기관 환경을 확인한 후 산정한다.

## 첫 번째 검증 과제

과제 이름은 **오프라인 본문 한 문단 편집과 저장 검증**으로 한다. 제품 전체를 만들기 전에 다음 질문에 답한다.

> 지정 Windows PC에서 인터넷 없이 HWP와 HWPX를 열어 본문 한 문단의 mock 수정안을 비교·적용·즉시 되돌리고, 두 형식의 저장물을 실제 한글 검수자에게 넘길 수 있는가?

업무 자료 검색이나 실제 모델 품질을 이 과제의 성공 조건에 섞지 않는다. 대상은 한 번에 문서 하나, 활성 제안 하나, 지원 가능한 본문 문단 하나다. 원본 저장 형식을 유지하고 별도 파일로 저장한다.

## 구현 전 준비물

- 고정 커밋의 Studio·WASM·wrapper·허용 글꼴과 실행에 필요한 자산. 개발 사본을 받은 것과 오프라인 사용 번들을 준비한 것을 구분한다.
- Tauri·Rust·Node·WASM 빌드 환경과 dependency lock. 공개 registry의 최신 버전으로 자동 갱신하지 않는다.
- C01~C04 HWP·HWPX 입력과 실제 한글 기준 출력. 우선 C01로 기술 경로를 확인하고 나머지 반례를 추가한다.
- 검수할 한글 제품·빌드 버전, 글꼴 사용·배포 조건. 미정이면 실제 한글 합격 판정을 보류한다.
- 새 제품의 로컬 작업 경로. 참조 저장소에 기관 설정이나 실문서를 넣지 않는다.

## 첫 작업 목록

| 작업 | 구체적 변경과 산출물 | 확인할 것 |
| --- | --- | --- |
| T01 자산·origin 검증 | 최소 Tauri 창과 로컬 Studio 경로, wasm·폰트 해시 목록 | 실제 parent/iframe origin, CSP, capability, cold start와 외부 요청 |
| T02 열기·무수정 저장 | 네이티브 읽기·다른 이름 저장 서비스, `loadFile`·export 연결 | HWP·HWPX 원본 보존; 한글 no-op 저장 품질을 일찍 확인 |
| T03 문맥 adapter | 같은 문서에서 원문·revision·target·필수 해시를 읽는 확장 | 공개 API와 신규 확장 구분; 여러 문단·표·IME·서식 거절 |
| T04 mock와 비교 | 고정 fixture 응답, 문단 전체 before/after, 승인·거절 버튼 | 제안만으로 engine이 변하지 않음; 적용 범위를 명시 |
| T05 명령 처리 | 기존 `applyTextCommand`, receipt 기록, 즉시 `revertTextCommand` | stale·중복·페이지 증가·후속 편집·복구 실패·timeout 반례 |
| T06 저장 완료 처리 | 저장 ticket·mutation gate, 임시 파일·flush·교체, 성공 후 `notifySaved` | 저장 중 편집, 디스크 실패, notify 실패, dirty·draft 보존 |
| T07 검수 묶음 | 원본·무수정본·적용본·되돌림본·manifest·receipt·검수표 | 어떤 파일에 어떤 변경을 했는지 검수자가 재현 가능 |
| T08 실제 한글 판정 | 지정 환경 재열기·인쇄 PDF·페이지별 검수 | 내용·서식·주변 표·이미지·쪽수·글꼴과 경고 기록 |

T02에서 무수정 저장 손상이 나오면 T04의 대화 UI를 확대하기 전에 원인을 분리한다. T03에서 필요한 원문과 검증 증거를 같은 revision에서 얻지 못하면 SHA 검사를 없애거나 텍스트 유사 매칭으로 우회하지 않는다.

## mock 계약과 예시

mock은 외부 HTTP 호출 없이, 동일 fixture와 요청에 동일 replacement를 반환한다. 대상과 검증 해시는 adapter가 만든다. 다음 예시는 사람이 이해할 수 있는 테스트 내용이며 실제 fixture의 위치는 manifest로 고정한다.

| 값 | 예시 |
| --- | --- |
| 원문 | `참석 대상자는 10월 15일까지 신청서를 제출해 주시기 바랍니다.` |
| 요청 | `의미와 날짜를 유지하면서 간결하게 다듬어 줘.` |
| mock 수정안 | `참석 대상자는 10월 15일까지 신청서를 제출하여 주십시오.` |
| 기대 | 날짜·대상 의미와 기존 서식을 유지하고 목표 문단만 교체 |

normal 응답 외에 빈 응답, 4,001 code point, 줄바꿈·제어문자, 지연·취소를 주입한다. 빈 문자열의 engine 허용 여부와 제품의 문단 삭제 정책은 별도다. 첫 UI에서는 의도하지 않은 전체 삭제를 자동 적용하지 않는다.

## 검증 순서와 완료 기준

1. existing wrapper 계약 테스트와 adapter 계약 테스트를 실행한다. 원문·서식·revision이 서로 다른 snapshot인 반례를 포함한다.
2. 실제 WASM이 들어간 Studio에서 열기·적용·즉시 되돌림을 수행한다. stub 테스트를 engine 동작 검증으로 보고하지 않는다.
3. 개발 서버가 아닌 준비한 로컬 실행 구성에서 인터넷 차단·cold start를 시험한다. 필요한 모든 자산이 포함되는지 확인한다.
4. Windows 파일 잠금·쓰기 실패·외부 파일 변경·저장 중 입력을 시험한다.
5. [호환성 검증](04-compatibility-validation.md)의 출력 묶음과 검수표를 만들고 실제 한글에서 확인한다.

기술 흐름 통과와 실제 한글 호환성 통과를 별도로 보고한다. 실제 한글 검수가 불가능한 환경에서는 `한글 검수 대기`로 남기며 목표 전체가 달성됐다고 쓰지 않는다. 특정 fixture 통과를 모든 공문·보고서의 지원으로 확대하지 않는다.

## 진행을 멈추고 설계를 재검토할 조건

| 관측 | 다음 판단 |
| --- | --- |
| 기본 문서조차 무수정 저장 후 한글 복구 경고 또는 손상 | 저장 엔진의 원인과 지원 범위를 먼저 분석 |
| 기관 대표 양식 대부분이 표·필드·혼합 서식 문단 | 본문 AI 편집만으로 제품 가치가 충분한지 평가; 표 편집 API 확장 비용을 별도 추정 |
| 합법적으로 준비 가능한 폰트로 요구 레이아웃을 재현하지 못함 | 글꼴 공급 방법·보존 목표·지원 문서군 재정의 |
| 문맥 adapter가 별도 문서 사본을 만들어야만 동작 | 소유권 구조 재검토; 복수 writer 방식으로 진행하지 않음 |
| Tauri에서 origin·CSP·WASM이 충돌 | 로컬 자산 제공 방법을 좁혀 다시 검증; 광범위한 보안 해제 금지 |
| 기관 gateway가 OpenAI 호환 요청과 다름 | 고유 adapter로 전환; 실제 endpoint 확인 전 성공 주장 금지 |

## 이번 설계 단계의 결과

참조 소스·라이선스·API를 재확인하고 제품 요구사항, 재사용 경계, 저장·편집 계약, 호환성 검수표를 작성했다. editor wrapper 테스트 32개는 새 환경에서 통과했다. 백엔드·WASM·Tauri·실제 한글·기관 API의 실행 성공은 아직 입증하지 않았다. 다음 착수 단위는 T01~T02이며 전체 제품 구현을 일괄 시작하는 계획이 아니다.
