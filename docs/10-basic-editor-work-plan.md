## 1. 이번 작업의 목표와 경계

사용자가 문서를 열고, 본문·서식·표·기본 개체를 수정하고, 여러 문서를 오가며 저장·복구·인쇄할 수 있는 기본 편집기를 만든다. 메뉴가 보이는 것과 기능이 끝까지 작동하는 것을 구분한다.

이 문서는 기본 편집기 보강 요구사항·작업 범위·완료 기준이다. 후속 사용자의 구현 지시에 따라 11번 MVP에 필요한 부분부터 보강했다. E00~E12 전체가 완료된 것은 아니다. 이 문서 작성 자체로 야간 예약 실행이나 백그라운드 자동 작업이 설정된 것은 아니다. 완료 여부는 시간을 얼마나 썼는지가 아니라 아래 산출물과 검증 결과로 판단한다.

- 기본 실행 환경은 현재 동작하는 **Rust 로컬 런처 + Edge/Chrome + 로컬 Studio/WASM**이다.
- 문서 상태의 기준은 문서 탭마다 존재하는 rhwp 엔진이다. UI에서 별도의 문서 모델이나 undo 기록을 만들지 않는다.
- 본문 입력·서식·표·기본 그림/글상자·쪽 설정·인쇄·복구·명령 실패 안내가 범위다.
- E 작업 자체는 기본 편집기를 다룬다. workspace·채팅·AI 직접 편집·실제 provider 연결은 11번 문서의 M 작업으로 추가했다. 자동 RAG, 설치 프로그램, 유료 라이선스 키는 MVP에 포함하지 않는다.
- 보안 탭의 암호화·서명·전자결재, 변경 추적·메모 협업, 고급 차트·수식 편집, HWP3·DOCX 확장은 후속 작업이다. 기존 지원 기능을 임의로 제거하지 않는다.
- 실제 한글 환경에서의 독립 재열기·인쇄 비교는 25번 계획 H00~H04의 우선 검수에 포함한다. 실행 가능한 자동 검사는 직접 수행하고 사람의 화면·출력 판정은 증거와 함께 기록한다. 실제 한글 환경이 없으면 미검증으로 남기며 내부 엔진 검사로 100% 정합성을 주장하지 않는다.
- 엔진의 페이지 배치·서식 직렬화를 근거 없이 바꾸지 않는다. 엔진 변경이 필요하면 원인·입력·영향 범위와 새 WASM 검증 계획을 분리한다.

## 2. 현재 코드에서 직접 확인한 사실

`연결됨`은 코드와 실행 경로가 있다는 뜻이다. 이번 문서 작성 중 해당 UI 동작을 새로 실행해 통과 판정을 내린 것은 아니다.

| 영역 | 현재 근거 | 이번에 할 일 |
| --- | --- | --- |
| 실행·문서 탭 | 부모 shell에 여러 iframe, 탭별 엔진과 저장/dirty API가 있다 | 초기화 실패, 빠른 전환, 키보드 포커스, 같은 파일 중복 열기, 종료 경합 검사 |
| 본문·저장 | 기존 앱 테스트 8개 통과 기록; 다운로드 확인과 저장 충돌 방어가 있다 | 실제 파일 API 경로와 취소/실패/연속 저장을 포함한 회귀 검증 |
| 한글 입력·한글 재열기 | 사용자가 두 동작의 성공을 보고했다 | 세부 IME 사례·문서/형식별 범위는 미확정; 성공을 전체 호환성으로 확대하지 않음 |
| 명령 연결 | `chrome-2024.ts`가 automation 명령을 실행한다 | 미지원·비활성·오류를 구분하고 사용자가 알아볼 수 있게 안내 |
| 명령 완료 | upstream dispatcher는 `def.execute()`를 호출한 직후 `ok:true`를 반환한다 | 비동기 작업의 실제 완료/실패와 명령 접수 성공을 혼동하지 않도록 연결점 검토 |
| 선택·서식 | 버튼의 mousedown에서 기본 동작을 막고 스타일 창을 연결했다 | 메뉴·대화상자·탭 이동 후 선택 범위와 포커스, 혼합 서식 표시 검사 |
| 표 | 만들기·셀 속성·병합/분할·행열 편집 명령이 존재한다 | 기본 표의 편집 결과·undo·저장 후 구조를 제품 화면에서 검증 |
| 그림·개체 | 그림/도형/글상자 삽입과 개체 속성, 순서·회전 명령이 존재한다 | 선택에 따른 도구 노출과 기본 개체 조작을 연결·검증 |
| 미구현 명령 | `insert:caption-top` 등 일부 캡션 위치, `insert:para-band`, `insert:comment`는 비활성 stub | 구현 범위를 표시; 빈 실행을 완료로 취급하거나 임의 활성화하지 않음 |
| 쪽·머리말 | 용지/구역/단 설정 및 머리말·꼬리말 명령이 존재한다 | 적용 범위와 편집 모드 복귀를 검증; 새로 전부 만드는 작업으로 잡지 않음 |
| 인쇄 | `file:print`, `file:print-to-pdf`, print surface 코드가 있고 `dist/print.html`도 존재한다 | 부모 shell·문서 iframe·인쇄 iframe/팝업 환경에서 활성 문서 출력 검증 |
| 자동 복구 | IndexedDB 기반 AutosaveManager, 시작 복구 UI가 있다 | 여러 문서 복구와 저장/버리기 정합성, 메모리 폴백·보관 한도 확인 |
| 복구 보관 한도 | upstream store에 `MAX_DRAFTS = 12`, DB 실패 시 메모리 폴백이 있다 | 문서 수 증가·저장소 실패 시 실제 보존 여부와 사용자 표시 확인 |
| UI 검사 스크립트 | 기존 `probe.mjs`가 부모 창의 `window.jueonyEditor`를 기다린다 | 현재 API는 자식 iframe에 있으므로 그대로 실행해 검증 증거로 쓰지 않음 |
| Tauri | 네이티브 파일 토큰·임시 파일 저장 코드가 있으나 빌드 차단 기록이 있다 | 이번 작업의 필수 선행 조건으로 만들지 않음; 런처 경로에서 계속 진행 |

이 표의 코드 검토상 위험은 아직 재현한 버그 목록이 아니다. 실행에서 실패한 결과와 정적 검토상 우려를 결과 보고에 따로 적는다.

## 3. 구현 중 유지해야 할 원칙

1. **데이터 보존**: 열기 취소·저장 실패·명령 실패·복구 실패가 원래 문서나 미저장 변경을 버리게 해서는 안 된다.
2. **활성 문서 소유권**: 작업을 시작한 문서와 끝내는 문서가 같아야 한다. 비동기 완료 시 현재 활성 탭에 무조건 결과를 적용하지 않는다.
3. **단일 명령 경로**: 메뉴·리본·단축키는 같은 dispatcher/engine 경로를 쓴다. DOM 텍스트만 바꾸거나 WASM을 우회해 저장 내용을 따로 만들지 않는다.
4. **취소는 무변경**: 대화상자를 열고 취소하면 내용·서식·dirty·undo가 바뀌지 않아야 한다. 실시간 미리보기 방식은 취소 시 원상복구를 검증한다.
5. **되돌림 가능성**: 편집 동작은 엔진의 기존 undo 단위와 맞춘다. 한 작업이 여러 단계라면 결과와 되돌림 범위를 명시한다.
6. **지원 상태의 정직한 표시**: 상황상 비활성, 이 버전에서 미지원, 실행 실패를 구분한다. 저장 손실 가능성이 확인된 형식/개체는 경고와 사본 저장 또는 저장 거절 정책으로 보호한다.
7. **로컬 자산 유지**: UI 보강 때문에 외부 CDN·글꼴·스크립트·API를 새로 요구하지 않는다. 제3자 고지와 Jueony 약관을 유지한다.
8. **기존 작업 보존**: 미추적 초안·문서·검수 자료를 삭제하거나 무관한 파일을 한꺼번에 stage하지 않는다.
9. **참조 소스 고정**: upstream 체크아웃을 직접 고치면 현재 빌드의 clean 검사에 걸린다. 필요한 연결은 자체 adapter 또는 버전 고정·정확한 매칭 검사를 가진 명시적 패치로 남긴다. 조용한 문자열 치환 실패를 허용하지 않는다.
10. **입력 보호**: 테스트 파일은 합성/허가된 사본만 사용한다. 실제 업무 원본·사용자 복구 초안·클립보드를 임의로 지우지 않는다.

## 4. 작업 순서와 의존 관계

P0는 자료 유실·잘못된 적용·검증 불능을 먼저 막는 작업이다. P1은 이번 기본 편집기의 기능 범위다. 보류가 발생하면 남은 독립 작업으로 이동하며 전체 완료로 바꾸지 않는다.

| ID | 우선순위 | 작업 | 선행 조건 | 목표 상태 |

| E00 | P0 | 명령 목록과 검사 기반 정리 | 없음 | 노출 명령별 연결·지원·검증 상태가 추적됨 |

## 5. 작업별 상세 지시

### E00. 명령 목록과 검증 기반

**근거/수정 지점**: S01, S02, S05, S09; upstream registry·automation·메뉴 모델.

- 실제로 보이는 메뉴·리본·상황 메뉴와 단축키를 명령 ID에 대응시킨다. 동일 기능의 별칭도 기록한다.
- `구현 및 연결 확인`, `연결 있으나 동작 미검증`, `상황상 비활성`, `stub/미지원`, `재현된 결함`을 분리한다.
- 출력 형식은 사람이 볼 수 있는 표 또는 JSON이다. ID, 표시 위치, 실행 조건, 대화상자, 데이터 변경 여부, 검사 ID를 포함한다.
- 현재 shell 구조에 맞는 UI 검사 진입점을 정한다. 부모 창 자체에 engine API가 있다고 가정하지 않는다.
- 앱이 준비되기 전에 검사하거나 대기 시간이 무한히 늘어나지 않게 ready/실패/제한 시간을 처리한다.
- 기존 probe는 구조 불일치가 있으므로 수정·검증 전 통과 증거로 사용하지 않는다. 이 환경의 실제 UI 조작은 적용되는 computer-use 지침과 허용된 도구를 따른다.

**완료 기준**: 노출된 명령 전부에 상태가 있고, 설명 없이 빈 실행을 하는 활성 버튼이 없다. 문서 로딩 실패를 빈 문서 성공으로 보고하지 않는다. 검사 C00~C02.

### E01. 실행 결과·오류·busy 처리

**근거/수정 지점**: S01, S03, S04; upstream dispatcher·toast·비동기 file 명령.

- 상태는 최소 `준비 중 → 사용 가능 → 작업 중 → 성공/실패/취소`로 구분한다. 문서별 상태와 앱 전체 상태를 섞지 않는다.
- `automation.execute().ok`는 비동기 완료 보증이 아니다. 저장·열기·인쇄 등은 실제 완료 신호 또는 Promise를 확인한다.
- 명령별 내부 오류 처리가 이미 있는지 확인하고 중복 경고창을 만들지 않는다. 실패 시 작업명과 다음 행동을 짧게 안내한다.
- 저장/변환 등 충돌하는 작업을 중복 시작하지 않으며 오류 후 잠금·오버레이·포커스를 복구한다.
- 모르는 명령 ID가 있어도 문서 편집 화면 전체가 멈추지 않도록 시작 시 연결 검증과 개발 진단을 분리한다.
- 비활성 사유는 “표 안에서 사용할 수 있습니다”처럼 사용자 행동으로 설명한다. 엔진 내부 타입·스택을 일반 UI에 노출하지 않는다.
- 비동기 실패를 동기 성공으로 처리하는 경로는 최소 재현으로 확인한 뒤 수정한다.

**완료 기준**: 동기 throw, 비동기 실패, 취소, 연속 클릭 모두 데이터 유실 없이 처리되고 다음 명령을 실행할 수 있다. C03~C05.

### E02. 열기·저장·닫기

**근거/수정 지점**: S02~S05; upstream file 명령과 document dirty state.

- 새 파일 열기는 기본적으로 새 탭을 사용한다. 현재의 비어 있고 수정하지 않은 탭을 재사용하는 경우도 사용자가 예측할 수 있게 일관되게 처리한다.
- 열기 대화상자 취소·손상 파일·지원하지 않는 파일·읽기 오류 때 현재 문서와 탭을 유지한다. 로딩 중인 새 탭은 실패 상태와 재시도/닫기를 제공한다.
- 파일 대화상자 열기와 파일 드롭이 같은 로드/오류 경로를 사용하게 한다. 여러 파일 드롭은 각각 탭을 만들고 한 파일의 실패가 나머지를 취소하지 않게 한다.
- 대상 형식·파일명·확장자가 일치해야 한다. HWP/HWPX 이외의 확장자 표기만 바꿔 저장하지 않는다.
- 일반 Edge/Chrome의 파일 API와 다운로드 모드를 별도로 검사한다. 다운로드 시작만으로 저장 완료·dirty 해제·초안 삭제를 하지 않는다.
- 저장 snapshot과 문서 revision을 유지하며 대화상자 대기 중 새 편집/문서 교체를 검사한다.
- 외부 변경은 사본 저장 또는 다시 열기로 복구할 수 있도록 안내한다. 기존 SHA 검사에는 마지막 확인 이후의 다른 프로세스 쓰기 경쟁까지 막는 잠금이 없다는 한계를 기록한다.
- 저장 실패/취소 후 닫기 요청은 취소되어야 한다. 여러 문서를 닫는 도중 한 문서가 취소되면 나머지 미저장 문서를 임의로 버리지 않는다.
- read-only·권한 오류는 안전한 복사본에서 재현한다. 디스크를 실제로 채우는 대신 오류 주입을 사용한다.
- 네이티브 Tauri 저장 경로는 별도 상태로 유지한다. 웹 파일 API 검증을 Tauri 성공으로 보고하지 않는다.

**완료 기준**: C06~C12 및 기존 저장 보호 검사를 통과한다. 저장 실패 전후 원본 해시가 같고 미저장 변경·복구 자료가 남는다.

### E03. 다중 탭·포커스·초기화

**근거/수정 지점**: S02, S03.

- 탭마다 안정적인 문서 식별자, ready/failed, 표시 이름, dirty, 작업 상태를 둔다. 순번이나 파일명만으로 문서를 동일시하지 않는다.
- iframe 초기화 실패 또는 API가 아직 없는 상태를 “저장할 변경 없음”으로 단정하지 않는다.
- 탭 전환 후 편집기 포커스·선택·스크롤·undo 이력이 해당 문서에 남아야 한다.
- 자식 iframe에서 발생한 키보드 이벤트가 부모에 자동 전달된다고 가정하지 않는다. 새 문서/탭 이동 명령의 책임을 정하고 기존 키맵과 충돌하지 않게 한다.
- 프로그램 상태 전달은 기존 same-origin 및 event.source 검사와 문서 식별자를 유지한다.
- 동일 파일 핸들을 판별할 수 있으면 열린 탭으로 이동한다. 다운로드 모드 등 동일성 확인이 불가능하면 파일명만으로 합치지 않고 독립 문서와 덮어쓰기 위험을 표시한다.
- 닫기 대화상자 열린 중의 연속 클릭, 비활성 탭의 늦은 완료 통지, 마지막 탭 닫기, 읽기 중 닫기 등을 검사한다.
- 탭 제거 시 observer·event listener·object URL 등 소유 자원을 해제한다. 무관한 문서의 복구 초안은 삭제하지 않는다.

**완료 기준**: A/B/C 문서 내용·서식·undo·저장이 서로 섞이지 않으며 키보드만으로 전환 후 입력이 가능하다. C13~C16.

### E10. 자동 복구와 재시작

**근거/수정 지점**: S02~S05; upstream recovery manager·store·UI.

- 파일에 저장하는 동작과 미저장 내용을 복구 저장소에 보관하는 동작을 구분한다.
- 복구 목록은 문서명·초안 시각·복구 가능 상태를 보여 준다. 선택한 초안은 새 탭에서 복원하고 원본 파일에 자동 덮어쓰지 않는다.
- 같은 이름의 다른 문서, 저장되지 않은 빈 문서, 여러 창의 초안은 별도 식별자로 관리한다.
- 현재 12개 초안 한도 및 정리 동작을 확인한다. 활성 미저장 문서를 조용히 제거해서는 안 된다. 한도·실패 시 알리고 사본 저장을 유도한다.
- IndexedDB를 열 수 없어 메모리로 폴백한 상태를 재시작 후에도 복구 가능하다고 표시하지 않는다.
- 저장 확인, 명시적 버리기, 복구 목록에서 삭제하기의 의미를 각각 정의한다. 저장 실패·다운로드 취소는 삭제 사유가 아니다.
- 오래된 비동기 저장이 버린 초안을 되살리거나 새 문서의 초안을 덮지 않도록 세대와 소유권을 확인한다.
- 강제 종료 시험은 새 테스트 프로필/테스트 창에서만 수행한다. 사용자의 기존 창·복구 저장소를 지우지 않는다.

**완료 기준**: 테스트 문서 3개의 복원, 저장/버리기 후 재노출 방지, 저장소 오류 안내를 확인한다. 정확한 영속 상태를 읽을 수 없는 환경은 보류로 기록한다. C17~C20.

### E04. 입력·선택·클립보드·찾기/바꾸기

**근거/수정 지점**: S01~S03; upstream edit·input-handler·find-dialog·clipboard.

- 한국어 조합 중 메뉴·단축키·탭 전환·저장 명령이 조합 중인 글자를 중복 확정하거나 잘라내지 않도록 한다.
- Enter/Shift+Enter, Backspace/Delete, 방향키·Home/End, 드래그 선택, 표 내부 선택을 기존 엔진 키맵과 함께 검사한다.
- 복사/잘라내기/붙여넣기는 텍스트부터 확정하고, 서식 포함 내용·그림은 실제 지원 범위를 표시한다.
- 클립보드 권한 거절 시 문서 내용이 먼저 삭제되는지 확인한다. 기본 단축키를 통한 재시도를 안내할 수 있다.
- 찾기는 이전/다음·찾을 내용 없음·처음/끝 순환을 명확히 표시한다. 찾기 입력창에서 Delete·Ctrl+A 등이 본문에 작용하지 않아야 한다.
- 한 개 바꾸기·모두 바꾸기는 검색 범위, 개수, 선택/커서 위치, undo를 검증한다. 바뀐 항목이 없는 작업은 dirty를 만들지 않는다.
- 기본 검색 범위는 지원이 검증된 본문/표로 명시한다. 머리말·각주·필드 등을 포함하지 못하면 문서 전체 검색이라고 표시하지 않는다.
- 정규식·유사어·형태소 검색은 이번에 추가하지 않는다.

**완료 기준**: 실제 한국어 입력, 선택 후 서식/탭 전환, plain text clipboard, 찾기·바꾸기와 undo가 동작한다. C21~C25. OS IME 직접 조작을 못한 경우 문자열 주입으로 대체 통과하지 않는다.

### E05. 글자·문단·스타일

**근거/수정 지점**: S01, S06; upstream format·char/para/style 대화상자.

- 기본 글자 속성은 글꼴·크기·굵게·기울임·밑줄·색상이다. 기본 문단 속성은 정렬·들여쓰기·내어쓰기·앞뒤 간격·줄 간격이다.
- 선택 범위가 있을 때와 커서만 있을 때 적용 대상을 구분한다. 여러 서식이 섞인 범위를 선택하면 단일 값으로 오인하지 않도록 혼합 상태를 표시한다.
- 도구 상자와 대화상자가 같은 값을 읽고 적용해야 한다. 스타일 적용 후 후속 직접 서식·undo도 검사한다.
- 숫자 단위와 유효 범위를 엔진 계약에서 확인한다. 잘못된 입력·빈 값·취소가 0이나 임의 기본값으로 저장되지 않게 한다.
- 글꼴 목록에 이름이 있다는 사실과 해당 글꼴이 실제 로드됐다는 사실을 구분한다. 대체 글꼴 사용 여부를 알리고 임의 외부 다운로드를 하지 않는다.
- 한컴 글꼴·아이콘·상표를 별도 허락 없이 제품 자산으로 복제하지 않는다.

**완료 기준**: 선택한 범위만 변경되고 대화상자 취소는 무변경, undo 후 원래 속성 복원, HWP/HWPX 재파싱에서 기본 속성 보존. C26~C29. 조판 일치는 별도 한글 관문.

### E06. 표·셀 편집

**근거/수정 지점**: S01; upstream table commands·table-create/cell-props/split/row-column dialogs.

- 필수 범위는 표 만들기, 셀 이동·선택, 행/열 추가·삭제, 직사각형 셀 병합·나누기, 너비/높이 조절·균등, 테두리·배경·셀 안 여백·정렬이다.
- 기본 합성 표에 각 셀마다 고유 문자열을 넣고 조작 전후 행·열·병합 정보와 문자열 순서·소속을 기록한다.
- 병합 시 여러 셀의 텍스트를 어떻게 합치는지 기존 엔진 동작을 확인하고 보존한다. 일부 셀의 텍스트를 지워 모양만 맞추지 않는다.
- 병합 셀 일부만 선택, 전체 마지막 행/열 삭제, 셀을 벗어난 명령 등 경계를 명시적으로 거부하거나 기존 계약대로 처리한다.
- 표 삭제와 셀 내용 삭제를 구분한다. Tab/Shift+Tab의 마지막 셀 동작은 현재 엔진·키맵 계약을 확인하고 문서화한다.
- 표 선택 중 일반 본문 명령과 표 명령의 enabled 상태를 맞춘다. 본문으로 돌아오면 상황 도구도 갱신한다.
- 쪽 넘김·반복 제목·중첩 표는 읽기/보존 상태와 편집 지원을 따로 적는다. 페이지 분할 엔진 수정은 독립 한글 증거 없이 완료로 처리하지 않는다.

**완료 기준**: 기본 3×3 및 병합 포함 표에서 각 편집의 내용 보존·undo·두 형식 저장 검증을 통과한다. C30~C34. 고급 표 보존이 실패하면 대상 문서군을 명시해 보류한다.

### E07. 그림·도형·글상자

**근거/수정 지점**: S01, S06; upstream insert·picture-props·object-props.

- 우선 PNG/JPEG 그림, 사각형 도형, 텍스트가 있는 글상자로 범위를 고정한다.
- 삽입 취소·잘못된 이미지·크기 한도 오류에서 기존 선택과 문서를 보존한다.
- 기본 선택·이동·크기 조절·비율 유지·삭제와 속성 대화상자 적용/취소를 검증한다.
- 글자처럼 취급하는 배치와 떠 있는 배치는 별도로 시험한다. 지원되는 앵커·배치 옵션만 노출한다.
- 글상자는 개체 선택과 내부 텍스트 편집 모드 전환·본문 복귀를 검사한다.
- 겹침 순서·회전·그룹화는 기존 경로가 있는 범위에서 검증 후 제공한다. 복잡한 그룹 변환을 새로 약속하지 않는다.
- 일부 캡션 위치/주석 stub는 기본 범위 밖으로 표시한다. 실제 `caption-toggle` 명령과 빈 위치 명령을 같은 기능으로 오인하지 않는다.

**완료 기준**: 기본 세 개체의 삽입·속성 변경·취소·undo·저장 후 내용/개체 존재를 확인한다. C35~C38. 렌더링만 보고 구조 보존을 단정하지 않는다.

### E08. 용지·쪽·머리말·꼬리말

**근거/수정 지점**: S01; upstream page·page-setup·section·column 대화상자.

- 용지 크기·방향·여백, 명시적 쪽 나눔, 머리말·꼬리말·쪽번호를 필수 범위로 둔다.
- 현재 구역과 문서 전체 중 실제 적용 범위를 명시한다. `file:page-setup`이 전달하는 구역 인자와 `page:setup` 경로의 차이를 확인한다.
- 구역이 둘인 문서에서 앞 구역을 잘못 바꾸지 않는지 시험한다. 단 설정과 구역 나눔은 구조 보존이 확인된 범위만 편집 가능하게 한다.
- 머리말·꼬리말 편집 시 현재 모드·대상을 표시하고 본문 복귀 동작을 제공한다.
- 양쪽/홀수/짝수 쪽의 설정과 상속을 구분한다. 쪽번호를 일반 문자열로 바꿔 넣어 동적 필드를 잃지 않게 한다.
- 설정 변경에 따른 정상적인 재조판과 쪽 누락·빈 쪽 증가를 구분해 기록한다.

**완료 기준**: 2개 구역이 포함된 합성 문서에서 대상 구역·필드·본문을 보존하고 취소/undo가 동작한다. C39~C42. 실제 한글의 최종 배치는 별도.

### E09. 인쇄·PDF

**근거/수정 지점**: S02, S05, S07; upstream file·print-pages·print-surface, `public/print.html`.

- `file:print`와 `file:print-to-pdf`의 기존 경로를 사용한다. PDF 저장은 현재 브라우저 인쇄 기능을 통한 경로임을 분명히 한다.
- 출력물에 Jueony 메뉴·리본·탭·선택 표시·커서가 포함되지 않게 한다.
- 인쇄 시작 시 문서 ID/revision을 고정하거나 편집을 적절히 제한해 페이지마다 다른 상태가 섞이지 않게 한다.
- 자식 iframe에서 실행한 인쇄가 활성 문서만 출력하는지 확인한다. 문서 A 출력 중 B 탭으로 바뀌어도 A의 출력이 유지되어야 한다.
- 인쇄 팝업 차단·surface 준비 실패·사용자 취소 후 문서를 유지하고 다시 인쇄할 수 있어야 한다.
- PDF 기본 파일명, 혼합 용지/방향, 전체 쪽수와 인쇄 준비 상태를 확인한다. 쪽 범위·배율은 브라우저에서 제공하는 범위와 앱 범위를 구분한다.
- 인쇄 대화상자를 열었다는 사실을 종이 출력이나 PDF 파일 생성 성공으로 보고하지 않는다.
- PDF 파일을 실제로 얻을 수 있는 환경에서 파일을 열어 모든 쪽을 확인한다. native 인쇄 UI 접근이 없으면 그 단계만 보류하고 출력용 페이지 생성·자산 검증은 수행한다.

**완료 기준**: C43~C46. 3쪽 합성 문서의 PDF가 실제 생성·열림·쪽수/내용 검사까지 통과해야 “PDF 출력 검증 완료”라고 쓴다.

### E11. 화면·키보드 접근·상태 표시

**근거/수정 지점**: S01, S02, S06; upstream menus/dialogs.

- 한글 2024의 메뉴별 기본 도구 상자와 선택 개체별 도구 노출 방식을 참고한다. Jueony의 이름과 자체 자산은 유지한다.
- 표·그림·글상자·머리말 편집 상태의 도구와 실제 명령 대상을 일치시킨다. 빈 보안 탭은 사용 가능한 기능처럼 보이지 않게 한다.
- 메뉴·리본·대화상자에 일관된 명칭·단축키 표시·툴팁을 제공한다. 상황상 비활성과 미지원 상태를 구분한다.
- 대화상자의 Tab 순서, Enter 확인, Esc 취소, 포커스 복귀, accessible name을 확인한다. 본문 입력 중에는 단축키가 대화상자나 다른 탭에 새지 않아야 한다.
- 1440×960과 1024×768에서 중요한 저장·닫기·확인 버튼에 접근 가능하게 한다. DPI 100/125/150%는 실제 가능한 환경을 기록한다.
- 상태줄의 쪽수·배율·저장 상태가 활성 문서와 맞아야 한다. 자동 복구 저장을 원본 파일 저장 완료로 표시하지 않는다.
- 초기 `MutationObserver.observe` 오류는 재현 환경과 소유 코드가 확인되면 수정한다. 원인을 모른 채 오류를 삼키거나 정상이라고 단정하지 않는다.

**완료 기준**: C47~C49. 보이는 버튼의 실제 기능, 키보드 조작과 포커스, 좁은 화면의 접근성을 직접 확인한다.

### E12. 통합 검증과 인계

- 작업별 변경과 테스트 기록을 모아 기존 사용자 보고, 이번 실행 결과, 한글 대기 항목을 구분한다.
- 필요한 검사를 통과한 source HEAD로 최종 프런트엔드와 Rust 실행 묶음을 만든다. 이전 빌드 증거를 새 코드의 결과로 재사용하지 않는다.
- 현재 앱·원본 자료·미추적 초안을 보존한다. 실행 중인 자기 런처 교체가 필요하면 경로/PID를 확인하고 저장된 테스트 세션에서 처리한다.
- README, 기능별 지원표, 체크리스트, 알려진 문제, 검수 파일 경로를 갱신한다.
- 테스트한 합성 HWP/HWPX와 출력 결과를 한글에서 재열 수 있도록 이름과 변경 내용을 적어 인계한다.
- 구현 완료이지만 한글 검수 대기인 항목을 사용자가 쉽게 찾을 수 있게 한다.

**완료 기준**: C50~C53 및 아래 최종 관문. 문서 작성이나 버튼 추가만으로 E12를 완료하지 않는다.

### 검증 층

- **정적 확인**: 명령 ID·연결·stub·조건·패키징을 확인. 실제 기능 PASS를 대신하지 않는다.
- **로직 검사**: 비동기 실패·저장 충돌·다중 탭 소유권 등 데이터 손실과 관련된 불변식을 확인.
- **WASM 재파싱**: 편집 결과의 텍스트·문단/셀 소속·기본 속성·개체 수를 확인. 동일 엔진의 검사라는 한계를 표시.
- **실제 UI**: 클릭·키보드·대화상자·저장 결과·포커스를 검사. 내부 함수 호출만으로 클릭 경로를 검증했다고 하지 않는다.
- **실제 한글**: 파일 경고·개체 편집·독립 인쇄 PDF 비교. 설치 후 수행하며 현재 통과로 처리하지 않는다.

상태는 `NOT_RUN`, `PASS`, `FAIL`, `BLOCKED`, `NOT_APPLICABLE`을 사용한다. `BLOCKED`에는 필요한 도구/자료와 계속 진행할 수 있는 작업을 적는다. 사용자 보고는 별도 `USER_REPORTED_PASS` 기록으로 유지한다.

체크리스트의 Host는 `Edge/Chrome 파일 API`, `다운로드 모드`, `Tauri`를 구분한다. 한 Host의 성공을 다른 Host에 복사하지 않는다. 입력·출력 형식도 HWP/HWPX 각각 기록한다.

### 최종 관문

1. E00~E12에 구현 결과와 미해결 항목이 존재한다. P0의 재현된 데이터 유실 결함은 없어야 한다.
2. 바뀐 동작의 정상·취소·실패 경계를 검증한다. 겉모양 변경만을 위한 구현 복제형 단위 테스트를 대량 추가하지 않는다.
3. 기존 편집기 테스트 8개와 타입 검사·빌드를 통과한다. 런처/서버/자산 제공을 바꿨다면 HTTP 검사 13개를 실행한다.
4. 기본 본문·표·개체 편집을 HWP/HWPX 각각 저장하고 다시 읽어 확인한다.
5. 브라우저 파일 API 저장과 다운로드 확인을 각 지원 환경에서 점검한다. 실행 불가 경로는 사유를 남긴다.
6. 실제 인쇄/PDF UI를 접근할 수 없으면 출력 확인 항목은 보류한다. 단순 HTML 준비를 PDF 생성 완료로 대체하지 않는다.
7. 한글 독립 재열기·IME 세부 사례·복잡한 조판은 확인한 범위만 주장한다.
8. 알려진 실패와 필수 증거 누락이 있으면 “부분 완료”로 인계한다.

## 7. 자율 실행 절차와 중단 조건

### 시작할 때

- 현재 Git 상태, 사용자 변경, 활성 서버 경로, HEAD 및 참조 커밋을 확인한다. 이 문서의 SHA와 달라졌으면 차이를 읽고 기준을 갱신한다.
- E00에서 재현 가능한 최소 점검을 하고 실패를 범주화한다. 기존에 통과한 검사를 이유 없이 여러 번 반복하지 않는다.
- 현재 작업 환경의 도구·권한·skill 지침을 확인한다. 저장된 구형 브라우저 자동화 스크립트가 현재 허용 도구나 화면 구조에 맞는다고 가정하지 않는다.
- 문서·로그·테스트 산출물은 로컬에서 보관한다. 기관 자료를 외부 서비스로 전송하지 않는다.

### 각 작업을 진행할 때

1. 코드와 현재 동작을 확인하고 기대 결과·반례를 정한다.
2. 가장 작은 연결/로직 변경을 구현한다. 기존 명령이 충족하면 새 엔진 기능을 중복 구현하지 않는다.
3. 영향 범위의 테스트와 UI를 확인한다. 저장·문서 구조 변경이면 재파싱을 추가한다.
4. 체크리스트에 실제 결과·환경·커밋·증거를 기록하고 논리적 단위로 로컬 커밋한다.
5. 해당 작업이 막히면 원인·시도·다음 조건을 남기고 독립 작업으로 진행한다. 같은 환경 오류를 조건 변경 없이 반복 실행하지 않는다.

원격 업로드는 세션의 사용자 지시 범위에 따르며, 문서가 권한을 새로 부여하지 않는다. 강제 push, 기존 이력 재작성, 공개 전환, OS 보안 해제는 수행하지 않는다.

### 환경 또는 엔진 문제를 만났을 때

- **Tauri 빌드 차단**: 보안 정책을 끄지 않는다. 현재 런처 기반 기능을 계속 보강하고 Tauri는 후속 검증으로 남긴다.
- **한글 부재**: 합성 자료·구조·UI 검증을 수행하고 독립 조판 판정만 미실행으로 둔다.
- **엔진 변경 필요**: 원본 입력과 원인 계층을 보존한다. upstream 직접 수정 전에 [작업 지침](https://github.com/edwardkim/rhwp/blob/1a76570e833917d15817415a53c09ad61ab3203f/AGENTS.md) 및 관련 빌드·검증 지침을 읽고 적용한다. 기존 npm WASM을 사용하면서 Rust 소스 수정이 앱에 반영됐다고 주장하지 않는다.
- **데이터 유실/잘못된 파일 덮어쓰기 재현**: 관련 변경을 우선 수정하거나 해당 새 기능의 제공을 보류한다. 사용자 원본을 대상으로 추가 재현하지 않는다.
- **필수 결정 부재**: 기존의 가장 보수적인 동작과 명확한 상태 표시로 구현 가능한 부분을 진행한다. 해결되지 않은 데이터 보존 문제를 묵시적으로 허용하는 결정을 만들지 않는다.

업스트림의 조판·직렬화 변경을 수행하면 Native/fresh WASM 및 독립 한글 기준 출력 등의 요구가 적용될 수 있다. 근거가 없으면 해당 변경의 정합성 완료를 선언하지 않는다. 이 제한을 기본 UI 연결 작업 전체를 멈추는 이유로 확대하지 않는다.

~~~

문서의 명령은 기본 진입점이다. 도구 제약이나 설치 상태가 다르면 변경 이유와 실제 명령을 기록한다. 검증 중 일반 사용자 창을 종료하지 않는다.

작업 산출물:
- 변경된 자체 소스와 명령/지원 상태 목록.
- 업데이트된 [검사 결과 CSV](basic-editor-checklist.csv).
- ignored `apps/editor/evidence/basic-editor/<run-id>/`의 실행 로그·스크린샷·합성 출력과 비교 결과.
- 현재 HEAD, 변경 파일, 수행한 검사, 미검증·실패·보류 항목을 담은 최종 작업 보고.
- `build/jueony-preview/JueonyEditor.exe`와 `dist`, 약관·제3자 고지, 한글 검수용 합성 저장물.
- 앱 구현에는 AI·기관 API 변경을 섞지 않는다.

## 9. 귀가 후 사용자 검수

1. Start-Jueony.cmd 실행 후 HWP/HWPX 예제를 각각 연다.
2. 두 문서 사이를 오가며 본문 입력, 서식 변경, 표 병합/나누기, 그림/글상자 조작을 해 본다.
3. 저장 취소·탭 닫기 취소·되돌리기가 예상대로 작동하는지 본다.
4. 테스트 문서의 복구 목록과 실제 PDF 출력 결과를 확인한다.
5. 설치한 한글에서 무수정/편집/되돌림 저장본을 비교한다. 자세한 방법은 [호환성 검증 계획](04-compatibility-validation.md)을 따른다.
6. 문제를 `문서/형식 → 클릭 순서 → 기대 → 실제 → 화면/저장본`으로 기록한다.

## 11. 기본 편집기만 보강할 때 사용할 지시문

> docs/10-basic-editor-work-plan.md를 읽고 E00~E12의 기본 편집기 보강을 진행해줘. 현재 코드와 사용자 변경을 먼저 확인하고, P0 데이터 보존 작업부터 구현·검증해줘. 가능한 P1 작업도 계속 진행하고 논리적 단위로 로컬 커밋을 남겨줘. 한글 설치가 필요한 검사는 보류 사유와 검수 파일을 준비하고, 나머지 독립 작업은 계속해줘. AI·workspace·기관 API는 이번에 구현하지 말고, 마지막에 실행 가능한 묶음과 체크리스트의 실제 결과·남은 문제를 정리해줘.

이 지시문은 복사해 사용할 수 있는 초안이며, 자동 예약이나 실행 완료를 뜻하지 않는다.

## 12. 추가된 workspace·채팅·AI MVP 작업

2026-10-09 제품 방향을 추가했다. 최신 작업 지시서는 [11-workspace-agent-mvp-plan.md](11-workspace-agent-mvp-plan.md)다. 이 문서의 E00~E12는 기본 편집기 보강, 새 문서의 M00~M12는 업무 화면과 AI 직접 편집 통합을 담당한다.

- 화면은 왼쪽 workspace/채팅/폴더 트리, 가운데 채팅, 오른쪽 실제 편집기로 확장한다. 왼쪽 채팅/트리 높이를 조절한다.
- 여러 폴더를 원위치 연결하고 독립 채팅·최근 작업 상태를 로컬에 복원한다. 원본 복사·이동·삭제는 하지 않는다.
- AI는 열린 문서의 미저장 최신 상태와 명시 자료를 읽고, 검증된 명령으로 같은 engine의 여러 본문 위치를 직접 변경한다.
- 매번 승인하는 UI를 필수로 두지 않는다. 결과 확인·요청 되돌리기·버전 충돌·부분 실패 처리를 갖춘다.
- 제공자 중립 LLM Port와 실제 adapter 하나를 연결한다. Context와 단일 실행 제어를 분리해 향후 RAG/loop를 추가할 위치를 마련한다.
- M00~M12의 작업/의존 관계와 V01~V28의 수용 검사는 새 문서에 정의했다. 지금은 모두 미구현/미실행이다.

MVP에서는 E00/E01의 명령·실패 처리, E02/E03의 저장·문서 격리, E10의 복구를 우선 사용한다. E04의 입력 경계와 E11의 세 영역 접근성도 해당 통합 범위에서 확인한다. E05/E06은 검증 가능한 최소 표/서식만 추가하고 E07~E09의 전체 보강은 별도 후속 작업으로 남길 수 있다.

이 추가 범위로 인해 E 작업을 모두 끝내야 AI/workspace를 시작할 수 있다는 순서는 적용하지 않는다. 구체적인 현재 실행 순서는 새 MVP 문서가 우선한다. 이번 갱신은 문서 작업이며 구현을 시작하지 않는다.
