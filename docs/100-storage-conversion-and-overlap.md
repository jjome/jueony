# 100. 형식 변환 보존과 HWP 겹침 표 tail 저장

2026-10-15. 서로 다른 저장 책임을 두 작업자가 병렬 수정하고 같은 immutable 엔진 `58f40208d1f280ed`로 통합했다. 이전 엔진과 실행본을 덮어쓰지 않았다. 보존 검사·AI 보호 조건·지면 허용치는 완화하지 않았다.

## N002: 기록된 네 변환 차이 해결

공개 5문서의 HWP/HWPX 10출력이 기존 보존 검사 **6통과/4차단에서 10통과**로 바뀌었다. 표 배치 조회가 HWPX의 불완전한 raw mirror 대신 의미 필드를 읽게 했다. 영어 줄 나눔의 세 단위, 개체 잠금 bit30 및 편집 시 raw cache, 표 셀 메모의 재귀 소유 연결을 고쳤다.

[24개 검사](evidence/format-conversion-2026-10-15/result.json), [요약·소스 지문](evidence/format-conversion-2026-10-15/summary.json), [수정 전 실제 차이](evidence/format-conversion-2026-10-15/before-differences.json)를 보존했다. 같은 24개에서 기존 엔진은 11통과/13실패, 수정 엔진은 24통과다. 메모 본문은 HWPX XML에서도 별도 확인했다. 중복·고아·빈 carrier 및 실제 flow/overlap/lock 오염은 계속 거부하며, 모호한 소유 연결은 부분 적용하지 않는다.

공개 문서 원본과 변환 바이너리는 ignored 로컬 폴더에만 두고 Git·배포에는 포함하지 않았다. 입력 SHA와 결과만 보존한다. 모든 외부 문서나 모든 특수 영역의 메모를 지원한다는 의미는 아니다. 독립 한글 재열기·지면 비교는 미실행이다.

## N001: 제한된 tail 수정, 두 반례 유지

편집 중인 native HWP5 한 쪽·한 단의 통째 표 tail과 고유 단일 줄 빈 끝 본문에 대해 실제 pagination/페이지 트리의 원점을 **일회성 저장 snapshot**에 기록한다. live 문서 상태는 바꾸지 않는다. 겹침 허용 정책을 바꾸거나 좌표를 추정·clamp하지 않는다.

두/세 표의 y 242→178.7, 긴 표 499.6→178.7, 양수 offset 255.3→192 차이와 뒤 빈 문단 배치 누락을 이 범위에서 해결했다. [18모드 및 관련 34검사](evidence/overlap-table-tail-2026-10-15/verification-summary.json), [상세 제한](evidence/overlap-table-tail-2026-10-15/notes.md)을 따른다. 반복 저장·live 불변·snapshot 복원/재적용·전체 control/text 배치·의미 보존을 확인했다. 관련 34검사는 통합 회귀와 겹칠 수 있으므로 단순히 추가 합산하지 않는다.

N001은 **PARTIAL**로 유지한다. 뒤 가시 본문의 y 242→178.7과 양수 저장 간격의 y 242→256 기존 차이는 아직 남아 있다. 의도된 원본 간격을 지우는 우회 수정은 하지 않았다. 음수/절대 배치·쪽 분할·다단·불명확한 빈 본문 원점은 기존 경로를 유지한다. 일반 HWP의 Agent 크기/여백/표 구조 보호도 유지한다.

이 저장 후보에 대한 작업자 자체 검사는 Native WASM이며, 이후 [통합 앱·브라우저 회귀](99-agent-table-structure.md)를 같은 엔진으로 실행했다. 두 신규 HWP tail 수정 반례의 직접 브라우저/한글 지면 검수는 아직 별도다. 한글 2024 비교와 Native Rust 단위 모음·유료 모델 호출은 완료 표시하지 않는다.
