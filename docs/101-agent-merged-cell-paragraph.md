# 101. 병합 셀 문단의 Agent 편집

2026-10-15. `N004`의 첫 구현은 `replace_cell_paragraph`다. 여러 문단이 들어 있는 병합 주 셀에서 지정한 한 문단을 교체한다. 셀 전체 문자열을 덮어쓰거나 다른 셀의 내용을 합치지 않는다.

## 계약과 실행

요청에는 조회된 표 ID, 병합 주 셀의 좌상단 행·열, 문단 번호, 정확한 원문과 교체문을 넣는다. 문단 번호는 0부터 시작한다. `cellParagraphSources`가 지원 가능으로 표시한 실제 원본만 사용한다. 제공자에는 문단 번호·원문·좌표와 지문을 전달하며 내부 서식 ID·자원 바이트는 노출하지 않는다.

`modules/document/domain/cell-paragraph.ts`가 계약을 검사하고 `adapters/rhwp/cell-paragraph.ts`가 열린 엔진을 읽고 실행한다. 공통 facade가 버전 검사, 요청 단위 snapshot, render 후 검사와 실패 원복을 맡는다. 원문 문단의 글자·문단·스타일 정의를 재사용하며 빈 교체문도 문단 자체를 삭제하지 않는다.

## 현재 범위와 보호

- HWPX의 한 쪽 평면 표, 병합 주 셀의 단순 문단, 문단당 최대 4,000 Unicode 문자를 지원한다.
- 요청당 이 명령 하나를 실행한다. 흡수된 셀 좌표, 원문 불일치, 오래된 버전과 같은 내용 재적용은 거절한다.
- HWP 원본, 보호·필드·책갈피·중첩·캡션·제목 반복·영역 서식·혼합 글자 서식과 복합 배치는 제외한다. 영역 서식 관측이 없을 때도 거절한다.
- 모든 본문과 다른 셀의 문단·서식, 정의와 내장 자원을 확인한다. 사용하지 않는 글꼴이 추가되는 잘못된 엔진 동작도 실패 처리한다.
- 길어진 결과가 표를 여러 쪽으로 나누면 원복한다. 실패를 성공 응답으로 표시하지 않는다.

저장 검사는 기존 portable 출력 환경에서 원본과 재열기 배치를 같은 환경으로 비교하고 화면의 Canvas metrics 선택을 `finally`에서 복구한다. 브라우저 검사는 별도로 실제 Canvas 화면과 저장 후 UI 재열기의 배치를 비교한다. 배치 허용 오차 0.2는 유지한다.

## 검증과 남은 작업

[검사 증거](evidence/cell-paragraph-2026-10-15/)에 계약, 실제 WASM, 네 합성 제공자 프로토콜, 비교 표시, 커서, undo/redo, 안전 저장·UI 재열기, 실패 원복과 후속 요청, 빈 문단 재입력, 재시작 검사를 보관한다. 최종 공통 빌드 수치는 [통합 검사](104-parallel-editor-integration.md)를 따른다.

실제 유료 모델 호출과 한글 2024 직접 비교는 미실행이다. `N004` 전체는 부분 구현이다. 병합 셀의 모든 구조·필드·개체·서식을 임의 변경할 수 있다는 의미가 아니다.
