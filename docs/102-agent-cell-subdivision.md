# 102. 지정 행·열로 셀 분할

2026-10-15. `N005`의 첫 구현은 `split_table_cell_into`다. 기존 병합을 원래 격자로 되돌리는 `split_table_cell`과 별도 명령이다.

## 동작과 경계

조회된 평면 표의 셀 하나를 지정한 행·열로 나눈다. 각 방향은 1~8이며 적어도 한 방향을 나눠야 한다. 분할 후 격자 위치는 200개 이하다. 원래 내용·문단·서식은 첫 셀에 유지하고 새 셀은 비우며 첫 문단 서식을 이어받는다. 비병합 셀 분할 시 이웃 셀은 필요한 만큼 span을 늘린다.

`modules/document/domain/table-subdivision.ts`는 원본 행·열 크기, 안 여백과 최소 크기로 기대 격자를 계산한다. `adapters/rhwp/table-subdivision.ts`는 기존 Native 명령으로 실행하고 실제 격자·본문·자원·표 외곽과 이웃 배치를 검증한다. 공통 snapshot 실행이 요청 단위 undo/redo와 실패 원복을 제공한다. 저장되지 않은 열린 문서가 기준이다.

## 지원과 미지원

- 한 쪽·한 단 HWPX에서 보호·제목 셀이 없는 평면 표, 알려진 크기와 단순 문단을 지원한다. HWP5 원본은 한 쪽·한 구역·한 단에 본문 표가 하나이고 같은 형식에서 저장 보존 검사를 통과해야 한다. 하나의 병합 주 셀이 있는 표에서는 해당 셀만 분할 대상으로 노출한다.
- 병합 주 셀의 기존 격자 너비·높이를 이웃 셀에서 확인한다. 원래 행·열 수를 지정하면 불균등 격자도 복원한다. 더 적은 수를 지정한 경우 묶음별 너비·높이와 엔진의 분할 결과가 일치해야 한다. 예를 들어 같은 폭·높이의 2×2 격자를 차지하는 셀을 가로 두 줄로 나누면, 표의 전체 격자를 유지하고 각 줄에는 두 열을 차지하는 셀 하나를 둔다.
- 요청당 이 명령 하나를 실행한다. 분할 후 표 외곽을 키우지 않으며 줄바꿈으로 외곽이 커지는 결과도 거절한다.
- HWP3·암호화 HWP, 여러 병합 셀이 있는 원본, 원래 격자선과 어긋나는 병합 셀 분할, 중첩·필드·책갈피·혼합 서식·캡션·복합 배치·여러 쪽 표와 영역 서식은 제외한다.
- 엔진의 `cellZoneCount`가 정확히 0인 경우만 허용한다. 이 관측이 없거나 잘못된 값이면 거절한다. 셀 속성이 같아 보이는 영역 서식도 제외한다.

같은 영역 보호를 기존 기본 분할·병합·표 나누기·붙이기와 행열 구조 변경에도 적용했다. 관측 getter 추가는 영역 서식 편집 자체의 구현이 아니다.

## 검증과 제한

[독립 검사](evidence/table-subdivision-2026-10-15/summary.json)는 단위 7, 실제 Native 14, Edge 13 시나리오를 통과했다. 실제 격자·독립 기대 크기·원본 전체 보존·두 방향 분할·커서·undo/redo·저장·UI 재열기·stale와 render 실패 원복을 포함한다. 네 제공자 호출은 합성 서버다. 최종 빌드의 재검사는 [통합 결과](104-parallel-editor-integration.md)를 따른다.

한글 2024 직접 비교와 실제 계정 호출은 미실행이다. 분할 후 이웃 셀에 span이 생기므로 다음 임의 분할 가능 여부는 다시 조회한다. 모든 병합·중첩 표와 내용 분배 옵션이 구현된 것은 아니며 `N005` 전체는 부분으로 유지한다.

2026-11-08에는 병합 주 셀의 불균등 원래 격자 복원, 같은 치수의 가로·세로 분할, 내용이 밀려 외곽 크기가 달라지는 사례, 오래된 셀 치수와 보호 원본을 실제 WASM으로 검사했다. Edge에서는 로컬 합성 제공자를 통해 2×2 병합 주 셀을 두 줄로 나누고 요청 되돌리기·다시 실행·HWPX 저장·편집기 재열기 후 셀과 글줄 배치를 대조했다. ### Agent가 병합 셀의 원래 문단을 나누어 배치

`split_table_cell_into`에 `distributeParagraphs: true`를 지정하면 원본의 첫 문단은 왼쪽 위 셀에, 이후 문단은 왼쪽에서 오른쪽으로, 다음 행 순서로 배치한다. 예를 들어 2×2 병합 셀의 세 문단을 분배하면 왼쪽 위·오른쪽 위·왼쪽 아래에 각각 한 문단이 들어가고 오른쪽 아래는 빈 셀이 된다. 옵션을 생략하면 원래대로 모든 문단을 첫 셀에 둔다.

단일 병합 주 셀에 단순 문단 두 개 이상이 있고, 확인된 원래 격자와 새 셀 수가 문단 수를 수용해야 한다. Rust 엔진은 원래 문단 객체를 옮기므로 문단 스타일·직접 서식·글자 모양을 함께 보존한다. 원본 문단 수가 새 셀 수보다 많으면 명령 전체를 거절한다. 다중 병합, 중첩 표, 영역 서식, 잠금, 필드와 개체는 기존 보호 범위에 속한다.

분배 기능의 단위 검사 18개, 실제 WASM 검사 22개, Edge 검사 15개가 통과했다. 두 문단을 두 행에, 세 문단과 네 문단을 각각 2×2 격자에 배치한 뒤 저장한 HWPX를 재열어 셀별 원문·글자 모양·문단 모양·스타일을 대조했다. Edge에서는 합성 제공자에 요청한 결과를 되돌리고 재실행한 뒤 UI로 재열었다. 적용 직후 인위적으로 발생시킨 오류에서는 원래 편집 이력과 파일 바이트로 복구되는 것도 확인했다. 한글 2024 직접 비교는 남아 있다.

### HWP5 원본 저장

HWP5 문서에서 지정 행·열 분할을 요청하면 원본 형식과 암호 상태를 확인하고 편집 전에 HWP로 시험 저장한다. HWP 복합 파일 서명과 엔진의 손실 보고를 확인한 뒤 별도의 문서 인스턴스로 재열어 문서 정보·저장된 날짜·셀·전체 쪽 배치를 대조한다. 분할 직후 같은 검사를 반복하고, 실패하면 요청 전 상태로 되돌린다. HWP5 지원 범위에는 평면 셀 분할, 원래 격자가 확인된 병합 셀 분할, 해당 셀의 문단 분배가 포함된다.

실제 HWP 파일로 세 경우를 저장·재열어 원래 문단의 직접 서식·글자 모양·스타일, 제목·작성자·날짜, 표 격자와 쪽 배치를 확인했다. 두 번째 표·암호·잠금·서명 불일치·저장 손실에서는 요청을 거절했고, 분할 뒤에만 발생하는 저장 손실에서는 원본 바이트와 편집 이력을 복구했다. 합성 문서로 수행한 같은 엔진의 검증이며 한글 2024 직접 검수는 남아 있다.
