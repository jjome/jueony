# 104. 두 번째 병렬 편집기 통합

2026-10-15. 사용자의 병렬 구현 요청에 따라 병합 셀 문단 편집, 지정 행·열 분할, 글상자 상태 복원을 독립 모듈에서 동시에 구현했다. 공통 계약·facade·빌드·체크리스트는 한 담당이 통합했다.

## 실행과 기능

최종 실행 묶음은 `build/jueony-parallel-editor-20261015/Start-Review.cmd`, 검수 포트는 4324다. 이전 4322와 사용자 문서·서버는 유지한다. 새 검수 포트의 업무 저장소는 이전 포트와 독립적이다.

- [병합 셀의 한 문단 편집](101-agent-merged-cell-paragraph.md): 정확한 원문·좌표로 `replace_cell_paragraph`.
- [셀의 지정 행·열 분할](102-agent-cell-subdivision.md): 원본 격자와 외곽을 보존하는 `split_table_cell_into`.
- [글상자 위치·선택 복원](103-textbox-state-and-storage.md): 지원하는 Rectangle story의 재시작·탭·미저장 편집 상태.
- 글상자 HWP 세로 정렬 저장과 표 영역 서식 관측·구조 변경 보호.

Agent 계약은 51종이다. 새 명령도 현재 원본의 지원 가능 조회를 따라야 하며 UI나 제공자 응답으로 보호 검사를 우회할 수 없다. 미지원 요청은 실패로 표시하고 변경을 원복한다.

## 검증 기록

최종 공통 소스·WASM·브라우저 자산 지문과 단위·제공자·TypeScript·경계·실제 엔진·Edge·저장 재열기 결과는 [통합 증거](evidence/parallel-editor-2026-10-15/verification-summary.json)에 기록한다. 관련 과거 검사도 새 엔진에서 다시 실행한다. 과거 증거를 최신 결과로 덮어쓰지 않는다.

검사 횟수는 기능 수나 한글 전체 완성률이 아니다. 네 제공자는 합성 프로토콜 검사이며 실제 유료 모델 호출, Native Rust 단위 검사와 한글 2024 직접 비교는 미실행이다. 공개 자료 원본과 변환 파일은 검수 묶음에 재배포하지 않는다. 자체 작성한 이번 기능의 예제와 결과만 포함한다.

## 계속 남은 작업

`N004`, `N005`, `N014`는 새로 완료한 좁은 하위 범위와 구분해 부분 상태로 유지한다. 영역 서식·중첩·이미 병합된 복합 원본, 전체 개체 조작, 모든 상태와 고급 편집은 끝나지 않았다. HWP 겹침 표 후속 본문·양수 간격 두 배치 반례도 남아 있다.

다음 병렬 후보에서 행 span을 교차하는 병합 표의 행 삽입·삭제가 셀 높이를 동기화하지 않는 Native 결함을 독립 기대값으로 찾았다. 같은 엔진 저장 재열기만 통과한다고 완료 처리하지 않는다. 다음 구현 묶음에서 이 결함과 관련 미지원 범위를 별도로 처리한다. 전체 목록이 완료될 때까지 자동 후속 작업의 범위를 유지한다.


최종 자동 검사: 단위 772, 제공자 52, 실제 WASM 330, Edge 246 시나리오 통과. TypeScript 진단 0, 경계 9개 모듈/299개 소스 통과. Windows PowerShell5의 과거 UTF-8 JSON 읽기 오류를 명시적 UTF-8 읽기로 수정하고 실행 묶음을 재생성했다. 글상자 재시작 검수에서 이전 저장 완료 문구를 읽던 race는 실제 저장 promise·해당 파일의 IndexedDB 완료 기록 확인으로 고쳤다. 저장 보호나 제품 코드의 판정은 완화하지 않았다. 최초 실패 자료는 ignored 진단 폴더에 보존했다.
