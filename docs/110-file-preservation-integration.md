## 실제 Windows에서 확인한 창·탭·복구

검수용 실행본의 `frontendDist`에 Windows 절대 경로를 넣으면 Tauri가 URL로 읽어 앱 대신 디렉터리 목록을 표시했다. `Prepare-DocumentWindowReview.ps1`을 Tauri 설정 위치 기준의 상대 디렉터리를 사용하도록 수정했다. 실제 파일과 상대 경로가 일치하는지도 확인한다. 실패 실행본과 빌드 기록은 별도로 유지했다.

상대 경로 실행본에서는 다음을 실제 Windows 입력과 OS 파일 선택창으로 확인했다. 브라우저의 합성 native IPC 검사와 구분한다.

## Agent 연결 범위

문서 요약 5필드 조회·수정과 현재 업무 탭 조회·생성·전환·수정되지 않은 탭 닫기를 연결했다. 모델의 요청은 문서 fingerprint 또는 현재 업무·탭 상태의 지문과 일치해야 한다. 실제 실행 결과는 문서 변경 영수증과 탭 명령 영수증으로 구분한다.

수정된 탭의 폐기, 임의 경로 읽기·쓰기, OS 파일 선택과 종료 권한은 이 포트로 부여하지 않는다. 문서가 변경됐거나 다른 업무의 탭을 지정하면 거절한다. 닫기 도중 새로운 복구본이 생기면 정확한 값 대조 후 삭제를 거절한다. 실행 중 공개 편집 API도 잠가 UI 차단만으로 소유권을 보장하지 않게 했다.

실제 모델 네트워크 호출과 어댑터 검사는 구분한다. 이번 Agent 브라우저 검수는 네 제공자의 응답을 로컬 fixture로 공급하고, 실제 입력창·어댑터·검증·편집 엔진·Undo/Redo·탭·복구 저장소까지 실행한다. 서비스 키나 사용자 문서를 검수 근거에 포함하지 않는다.

## 호환성 통합의 실패 처리

양수 위치 표의 원본과 실제 한글 사본 사이 좌표 차이를 없앤 뒤에도, 실제 한글 사본의 HWPX 변환에서 3.8px 차이가 발견됐다. 따라서 원본만 재저장하는 검사에 더해 **외부 앱이 저장한 사본의 양형식 재저장**도 필수로 검사한다.

번호 8~10수준의 바이너리 보존 후보도 합본에서 기본 문서 저장을 차단하는 회귀가 발생했다. 원인을 분리하는 동안 후보는 검수 완료로 표시하지 않는다. 한글에 없는 속성 비트를 추측해 만들거나 손실 검사·좌표 비교 허용치를 완화해 통과시키지 않는다.

미사용 번호 정의를 한글이 제거하는 사례도 확인했다. 따라서 번호 형식 실측은 각 정의를 실제 본문 문단에 연결한 자체 문서를 사용하고, 저장 후 탭을 닫아 디스크에서 다시 연 사본으로 판정한다. 메모리에 남아 있는 속성을 디스크 보존 성공으로 세지 않는다.

15형식 × checkable 0/1의 실제 30사례에서는 31개 정의와 30개 고유 표식이 HWP에 저장됐다. 디스크 재열기·HWPX 역변환 시 각 형식의 checkable은 입력과 무관하게 형식 코드의 홀짝값으로 정규화됐다. 15개는 보존되고 15개는 정규화 손실이다. 이를 관측 테이블의 근거로 사용하며, 기존 XML의 다른 값을 자동으로 고치거나 손실을 무시하지 않는다. [자체 문서와 원시 검증](evidence/file-completion-2026-10-18/numbering-matrix30/README.md).

상위 파일 기능 전체와 N001/N002는 별도 잔여 범위가 있다. 이 기록의 창 수명·복구 성공으로 XML 스키마 입출력, 전체 메타데이터 이력이나 복잡 문서 전체 호환성을 완료 처리하지 않는다.
