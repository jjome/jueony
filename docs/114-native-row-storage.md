## 구현

엔진99패치의 `source-247b8244ffa41455/pkg`를 새로 컴파일했다. [이전91의 metadata·자원 보존 수정](113-file-format-preservation.md)도 함께 포함한다. 새 패치는 `native-source-synthetic-rows.patch`로 끝나는 파일이며 SHA256은 `eedb6ac4c47befebfdeb727099222b83a5b7b6550d55b98546a050366b9b5f4c`다.

원본 HWP 파서 또는 버전이 명시된 HWP5-origin HWPX 파서만 원본 행 봉인을 만들 수 있다. 본문·글자 모양·행·문단 서식의 로컬 지문과 공유 글꼴·서식·구역/쪽·중첩 개체의 문서 프레임 지문이 모두 맞아야 한다. 태그만 검사하여 모든 합성 행을 허용하지 않는다. 임시 재조판 행과 순수 XML의 행은 이 권한을 얻지 않는다.

커서는 페이지 배치 입력이 아니다. 문서 속성의 알려진 세 커서 값과 원시 payload의 `14..26` 바이트만 비교에서 정규화한다. 그 밖의 필드, 원시 데이터 길이, 알 수 없는 앞/뒤 확장 바이트는 그대로 지문에 남는다. 모델을 직접 바꾸는 경로를 놓칠 수 있는 임시 revision 캐시는 추가하지 않았다.

## 자동 검사

동일한 새 빌드의 **16군194/194**, **단위970/970(skip0)**, **TypeScript·모듈 경계**, **기존 단/표24/24**, **실행 묶음7/7**을 확인했다.194에는 앞 문단 불일치의 안전한 차단 검사도 포함한다.

고정 결과는 [저장92 검증 근거](evidence/file-completion-2026-10-18/native-rows92/README.md)에 기록한다. 실제 Windows 파일 선택창이나 한글 화면의 동등성 인증과 구별한다.

- 같은 UI verifier의 변경 전 결과: 6개 파일의 실제 다른 이름 저장이 보존 오류로 차단됐다. 이에 의존한 편집 시나리오도 실행할 수 없었다. 이를13개의 독립 제품 결함으로 세지 않는다.
- 변경 후 UI: 별도 headless Edge와 OPFS에서 6개 파일의 저장·재열기·뒤쪽 본문 수정·현재 파일 재저장·한 번 Undo/Redo·반복 저장13사례가 통과했다. 실제 저장 경로가 만든 artifact/report와 디스크 바이트를 비교했으며 원본 HWP 파일은 유지됐다.
- 직접 엔진18사례: HWPX→HWP→HWPX 혼합 저장, native HWP에서 본문 수정 후 두 형식 저장, 긴 앞 문단 편집 후 손실 차단과 정확한 snapshot 복원을 확인한다. **차단 안전 검사의 통과는 그 변환이 구현됐다는 뜻이 아니다.**
- 이전 단/표의 고정 비교 및 저장 회귀도 별도로 실행했다. 과거 잘못된 HWPX 출력까지 재현하도록 요구하던 검증은 원본 배치 불변과 올바른 저장 왕복 검사로 고쳤다. 보존 검사나 허용오차는 바꾸지 않았다.

## 남은 실제 제한

1. **앞 문단의 줄바꿈·쪽 넘김을 유발하는 재조판 후 HWPX 저장:** 새로 계산한 행도 implementation 태그를 가져 XML에서 생략된다. 현재 보호가 쓰기 전에 차단한다. 원본 행을 무조건 재봉인하지 않으며, 계산된 행의 별도 수명·축·최종 프레임 계약이 필요하다. HWP 저장과 Undo/Redo는 검사했다.
2. **최초 한글 조판과 글 방향:** 원MCST15→한글16쪽, 일부 글꼴/기호 조판 차이, 명시 방향의 HWP5 저장 비트는 이번 수정 범위에서 해결되지 않았다. 동일 엔진의 저장 보존과 독립 한글 조판 일치는 다르다. 방향 손실이 있는 기존8개 변환도 차단을 유지한다.
3. **큰 문서 비용:** 각 페이지 트리에서 문서 프레임을 다시 해시한다. 전체 쪽 검사 비용이 쪽 수×문서 크기에 비례해 증가할 수 있다. 안전한 캐시 무효화 계약과 별도 대형 문서 측정이 후속 과제다.
4. **상위 기능:** HWT/XSL/일반XSD와 전체 한글 파일 메뉴·OS 대화상자 동등성은 별도 미완료 범위다. 상위0/10이나 파트 전체를 검증 없이 완료로 변경하지 않는다.

## 실행과 재현

루트 `Start-Jueony-FileReview.cmd`는 `build/jueony-file-review92/Start-Jueony.cmd`(포트4359)의 별도 검수 묶음을 사용한다. 기존 실행 앱/문서를 종료하지 않았다. 브라우저 origin이 달라지면 기존 workspace/복구 상태를 자동 이관하지 않으며, 백엔드의 Windows DPAPI 연결 키 저장소는 그대로 사용한다.

```powershell
$env:JUEONY_ENGINE_PACKAGE=(Resolve-Path 'build/rhwp-engine/source-247b8244ffa41455/pkg').Path
$env:JUEONY_TEST_DIST=(Resolve-Path 'apps/editor/evidence/dist-file-preservation92').Path
$env:JUEONY_TEST_OUTPUT=Join-Path (Get-Location) 'build/native-row-own-check'
node --experimental-strip-types apps/editor/scripts/verify-native-row-preservation.mjs
```

Node22로 실행한다. 같은 출력 디렉터리를 재사용하지 말고 별도 이름을 지정한다. 전체 합본은 `scripts/verify_file_workflows.py`가 명시한 엔진/프런트 해시와 각 verifier SHA를 검사하며 실행한다.
