위 결함의 수정과 **파트 전체 동등성 완료는 구분한다.** 원MCST/Python3 최초 조판·글꼴 차이, 명시 글 방향의 HWP5 저장 매핑, HWT/XSL/일반 XSD와 모든 OS 파일 대화상자 범위는 아래 잔여 표에 남긴다. 기존 상위 범위를 삭제하거나 완료율의 분모를 줄이지 않았다.

## 수정 방식

이전101패치 엔진은 원본에서 온 한 줄 캐시는 보존했지만, 본문 편집으로 새로 계산한 여러 줄의 수명·좌표축·표의 실제 배치 원점을 저장까지 연결하지 못했다. 원본 캐시를 재봉인하거나 손실 검사를 건너뛰지 않고, **실제 편집과 전체 재페이지네이션이 끝난 시점에만** 별도의 계산 행 계약을 만든다.

계약은 현재 텍스트·서식·행·문서 프레임·측정 파이프라인과 연결된다. 표의 원점은 해당 페이지·단의 실제 배치 관측으로 확인한다. 일반 행 교체나 입력 변경으로 소유가 해제되며, 조회·렌더링·저장은 새 소유를 만들지 않는다. 내보내기는 복제본만 변경하고 열린 문서와 undo/redo의 관측값을 공유하지 않는다.

HWPX의 **본문과 새 행은 표준 XML에 기록**한다. 부가 JSON에는 쪽·단별 행 좌표 기준, 공백 측정 선택, 검증된 빈 표 호스트의 배치 프레임만 담는다. 본문·표·폰트·전체 IR의 사본을 숨겨 복원하지 않는다. HWP에서는 실제 직렬화된 FileHeader·DocInfo·BodyText 바이트와 연결한 별도 CFB 계약을 사용하며, XML의 상대 좌표를 두 번 더하지 않는다.

HWPX→HWP 변환이 생성하는 제어 바이트는 현재 lowerer를 같은 입력으로 재실행한 결과와 정확히 같을 때만 검증용 복제본에서 역투영한다. 승인한 것은 명시된 raw 필드와 빈 `CTRL_DATA` 옵션 슬롯의 padding뿐이다. 알려지지 않은 바이트·기존 값·서식·기하 변경을 복사해서 맞추지 않는다. 실제 출력은 원래 lowerer의 결과다.

JSON 파서의 한 ULP 차이로 f64 프레임과 지문이 어긋나는 재현에는 기존 `serde_json`의 `float_roundtrip` 기능을 켰다. 버전을 바꾸거나 숫자를 반올림하지 않았다. 실제 실패 값의 비트 왕복과 한 비트 변경 거절을 검사한다.

## 마지막 리뷰에서 추가로 수정한 결함

원본 XML 바이트를 lossy UTF-8 문자열로 바꾼 뒤 지문을 만들면, 유효한 U+FFFD와 손상된 `FF`가 같은 문자열이 된다. 일반 문서 읽기의 기존 관용 동작은 유지하고 **header와 모든 section이 정확한 UTF-8인 경우만** 부가 계약을 승인한다. 이 경우 문자열 바이트가 원본 바이트와 같다. ZIP 라이브러리의 이름 인덱스가 중복을 합치는 문제도 있어 원시 central directory에서 부가 JSON·header·실제 section 각각의 유일성을 확인한다.

독립 검사에서 두 XML 항목의 잘못된 UTF-8와 중복 항목을 만든 4건은 이전 후보에서 모두 실패했다. 유효한 U+FFFD·정상 XML의 양성 대조군을 함께 두어, 모든 캐시를 거절해서 통과시키지 않는다. 실제 CRC·표준 본문·새 행·원본 바이트 지문도 별도로 확인한다.

새 검사의 지원 문서 저장 경로는 **실제로 저장돼야 통과**한다. UI13에는 오류·취소를 올바르게 처리하는 검사도 포함한다. 차단을 성공으로 세는 기존 안전 검사는 별도로 유지한다. 같은 검사기 SHA에서 이전 엔진은 저장 성공0/12·UI0/13이었다. 부가 계약22검사는 이전 후보18/22에서 최종22/22로 바뀌었다. 19군의 항목과 별도 Native/단위 검사를 합쳐 제품 검증률로 표시하지 않는다.

의미·전체 배치는 기존 공개 비교 기준을 유지한다. 측정 좌표 허용오차0.2를 늘리지 않았으며, 불균등 단의 Native 체인에는 `charX` 최대 약0.1px의 실제 수치 차이가 남아 원형 결과를 보관했다. "허용 범위 내 같음"을 "모든 숫자 정확히0 차이"로 표현하지 않는다. 긴 문단의 기존 overflow 경고도 지우지 않았다. 이는 저장 보존 검증이며 전체 조판 품질 판정은 아니다.

공식 소스에서 Native 테스트를 직접 컴파일한 시도는 기존 외부 `include_bytes!` 시험 파일 누락으로 실패했다. 소스는 고치지 않고 Rust/Cargo1,155개 파일이 바이트 단위로 같은 임시 사본에 시험 파일12개만 추가해15개 계약 검사를 실행했다. UTF-8 보강 후 동결 후보의17개 검사와 공식 WASM 실행 결과를 구분해서 기록한다. 공식 WASM에 시험 파일·환경변수 하니스는 포함하지 않았다.

## 지원 범위와 잔여 작업

| 남은 항목 | 구현 상태 | 다음 확인 |
| --- | --- | --- |
| 원MCST·Python3 최초 조판/글꼴 차이 | 기존 결함 유지 | 최초 로드의 폰트·줄/쪽 경계 대조 및 원인별 수정 |
| 명시 `textDir`의 HWP5 매핑 | 미구현 | 공식 보충 명세 또는 통제 저장 쌍으로 위치·버전 확정; 현재 손실 보고·쓰기 차단 |
| HWT·일반 Hancom XML·XSL·일반 XSD | 제한된 지원 | 기존 상위 기능 요구의 실제 구현·형식별 검수 |
| 모든 OS 파일 대화상자·한글 화면/인쇄 동등성 | 직접 검수 보류 | 사용자가 허용한 후 일괄 비교 |

새 계산 행 계약은 현재 기본 DPI·기본 측정 파이프라인의 본문 삽입/삭제와 검증된 단/빈 표 호스트를 대상으로 한다. Canvas/외부 폰트, 미완료 batch/asynchronous 조판, HWP3·암호·배포 문서, 미확인 복합 프레임에 소유를 임의로 부여하지 않는다. 최대 문단4,096·행65,536·부가 계약2MiB의 제한도 유지한다. 지원 밖의 결과가 보존 검사를 통과하지 못하면 원본 쓰기를 차단한다.

`META-INF/rhwp-computed-native-rows-v1.json`은 예약된 **파생 캐시**다. 손상·미지원 버전·측정 세대가 다른 캐시는 권한 없이 폐기하고 표준 XML을 읽는다. 이 전용 캐시를 미래 버전의 opaque 사용자 데이터처럼 보존한다고 주장하지 않는다. CFB의 미확인 원시 스트림은 기존 원문 보존 규칙을 유지한다. 이 지문은 일관성 검사이며 전자서명이 아니다.

`rtl` 시험 파일은 **단 순서** 시험이다. 미구현 문단 `textDir` 변환 성공을 뜻하지 않는다. 이전110행 후보 회귀의 기존 글 방향8건 차단도 유지했다. N001/N002와 상위10개 범위의 부분 상태는 위 잔여가 실제로 해결될 때 갱신한다.
