# 파일 저장·복구·형식 보존: 후속 합본 검수

2026-10-18. [기능 작업표](features/05-files-storage-recovery.md) · [이전 저장 결함 수정](116-reflowed-native-storage.md).

문서별 이력·저장 날짜·문서 정보·XML/HWT 읽기·표 셀 줄바꿈을 공식107패치 합본으로 구현하고 자동 검증했다. 사용자 한글 창과 파일은 조작하지 않았다. 원MCST/Python3 최초 조판 등 아래 잔여가 있어 파트 전체 완료로 표시하지 않는다.

## 남은 결함과 검증

원MCST 최초 조판의 문단 간격 소실과 Python3의 복합 프레임 원점을 조사 중이다. 글 방향의 HWP5 매핑을 추측해서 저장하지 않는다. 미지원 변환은 손실 보고와 쓰기 차단을 유지한다. 일반 HWT 편집·XSL·전체 XSD 및 실제 한글/OS 화면 검수도 별도 잔여다.

기존 상위10개 요구와24개 실행 작업의 분모를 줄이지 않았다. 기존 파일 작업표는 구현23/24·부분1, 검증22/24·부분2, 상위0/10을 유지한다. 이 수치는 한글 전체 동등성의 진행률이 아니다.

## 공식 빌드·최종 자동 검증

| 구분 | 결과 | 조건 |
| --- | --- | --- |
| 파일·복구 합본26군 | 324/324 | 같은107 엔진·프런트, 오류·외부 요청0 |
| 단위 | 1008/1008 · skip0 | 공식 엔진을 명시 지정 |

| 독립 원본 OLE 날짜 | 28/28 | 원본 바이트→표준 속성→정확 u64/UTC7자리 |

고정 근거: [SHA manifest·재검증·실제 저장24개](evidence/file-completion-2026-10-18/storage96/README.md). 공식 엔진은 `source-2feb978b45e2964e/pkg`, WASM SHA256 `5f40eebea9726b42d049f9f57694c0d686099cfef9ca4dc61d621ebc35e00fd8`, 측정 지문 `b068882aaa440590c7f55786de252795d874227503825b4dd8409a19be076b4a`다.

324에는 실제 이력16·host/iframe UI12·XML제약10·저장날짜17·WASM HWT9·모델정보5·원본 셀13이 포함된다. 선택 설치 HWT21개는 별도로 실제 추출을 확인했고 매핑16개 지원/5개 명시 거절이다. Native 선택 검사와 별도 단위를 합쳐 검증률을 부풀리지 않았다. Agent 네 제공자 시험은 합성 로컬 응답으로 요청·명령·저장 경로를 검사한 것이며 새 외부 LLM 호출은 하지 않았다.

기존 원본과 한글 재저장본은 수정 날짜가 실제로 다르다. 새 API가 이를 관측하면서 기존 단 회귀가 처음 실패했다. 완전 비교 결과를 그대로 남기고 독립 OLE 해석값의 차이와 정확히 일치하는지 검사하도록 보강했다. 이전 엔진의 API 부재도 명시 관측한다. **후보 저장→재열기에서는 이 예외 구분을 사용하지 않으며 날짜 포함 모든 의미를 엄격 비교한다.** 좌표 허용오차·저장 보호·원본 파일·비교 함수는 바꾸지 않았다.

이력 초기 검수에서 배열 모양 metadata가 크기/지문 검사를 우회하는 문제와 IndexedDB 쓰기 직후 세대가 바뀌는 문제를 재현해 수정했다. 첫 통합에서는 realm이 다른 신뢰 scope 객체가 거절돼 UI 준비가 실패한 것도 수정했다. 실패 원형과 최종16건을 함께 보관한다.

저장 날짜는 기존 실제 기록을 보존하는 기능이다. 현재 시각 자동 갱신과 편집 시간 누적을 구현했다고 표시하지 않는다. 모델 문단 통계도 한글 통계와 다른 산정 기준/제외 대상을 표시한다. HWT 버튼은 실제 WASM 기능이 있을 때만 켜지고, 본문 필드 쓰기·재저장은 제공하지 않는다.

## 실행과 재검증

- `Start-Jueony-FileReview.cmd`: 새 `build/jueony-file-review96`의 실행본을 연다. 이전 사용자 실행본은 종료하지 않았다.
- `scripts/Build-DocumentEngine.ps1 -Runtime Wsl`: 공식 패치를 적용·컴파일한다.
- `JUEONY_ENGINE_PACKAGE`에 해당 pkg를 지정하고 `JUEONY_BUILD_PROFILE=file-storage96`으로 `apps/editor/scripts/build.mjs`를 실행한다.
- `scripts/verify_file_workflows.py --help`: 동일 엔진·프런트·새 출력 폴더·Node22를 명시한다. 원본 셀 추가 검사는 baseline/source/oracle 세 경로를 모두 지정해야 하며 누락을 PASS로 세지 않는다.
- `python docs/evidence/file-completion-2026-10-18/storage96/verify.py`: 저장한206개 바이트 기록과 최종 집계를 재검증한다.

## 이어서 수정할 구체 결함

MCST p48에서 원본 간격300HU가 정규화 중 사라져 문단 앞 간격4px를 다시 차감하는 분기를 좁혔다. 별도 후보에서 소유·원본행·변경 상태 조건과 반례를 검사 중이다. Python3의 별도 복합 프레임 오류와 MCST15→16쪽 문제는 같은 결함으로 합치지 않는다. 이번 셀 수정의 공개 비교731→680에는 서식ID319개와 실제 지면361개가 함께 들어 있어, 이를680개 독립 시각 결함으로 표현하지 않는다.
