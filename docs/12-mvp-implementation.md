# Jueony 업무·채팅·본문 편집 MVP 구현 결과

2026-10-09. 사용자의 구현 지시에 따라 11번 계획의 본문 중심 MVP를 연결했다. **로컬 편집과 HTTP 호환 adapter 구현·자동 검증은 완료했으며, 실제 LLM 제공자와 한글 2024의 독립 검수는 대기 중이다.** 이 두 검증을 포함한 제품 전체 완료를 뜻하지 않는다.

## 실행과 첫 사용

프로젝트 루트의 [Start-Jueony.cmd](../Start-Jueony.cmd)를 실행한다. 현재 실행 묶음은 `build/jueony-mvp/JueonyEditor.exe`다. exe만 옮기지 말고 같은 폴더의 dist, runtime, server.mjs, providers, 고지 파일을 함께 유지한다. Edge 또는 Chrome이 필요하다. Node.js 22.22.2는 묶음에 포함하므로 사용자가 따로 설치할 필요는 없다. 기존 `build/jueony-preview` 묶음은 보존했다.

1. 왼쪽 ＋로 업무를 만들고 폴더를 여러 개 연결한다. 연결은 원본을 등록하는 동작이다.
2. 업무 안에서 새 채팅을 만든다. 채팅 이름은 두 번 눌러 변경한다. 가운데 경계를 드래그하거나 위/아래 키로 조절한다.
3. 폴더 트리의 HWP/HWPX를 누르거나 오른쪽의 열기/새 문서를 사용한다.
4. **AI 연결 설정**에 연결 이름, 실제 endpoint, 모델 ID, 키를 입력한다. 등록은 연결 정보 설정이며 실제 인증 성공을 뜻하지 않는다.
5. 필요한 파일/폴더를 체크하고 가운데에서 요청한다. 지원하는 본문 명령은 검증 후 오른쪽 문서에 바로 반영된다.
6. 결과의 변경 확인/요청 되돌리기 또는 오른쪽 편집기의 수동 편집·저장을 사용한다.

API 설정은 OpenAI 호환 **Chat Completions** 규격이다. `https://기관서버/v1` 또는 전체 `.../chat/completions` 주소와 실제 모델 ID를 등록한다. 모델 목록 조회를 가정하지 않으며 등록한 모델만 선택지에 나온다. 여러 연결/모델을 등록할 수 있다. HTTPS를 사용하며 HTTP는 루프백 테스트 서버에만 허용한다. 고유 규격 HyperCLOVA X, Azure 전용 인증, Responses API는 이번 adapter의 지원 대상이 아니다.

키는 로컬 서버의 메모리에만 있고 일반 설정·채팅·로그에 쓰지 않는다. **창을 닫아도 로컬 서버가 남아 있으면 키가 유지된다.** AI 연결 설정의 **연결 키 삭제**로 모두 제거할 수 있다. 서버를 다시 시작하면 키를 다시 입력한다. 프로필/연결 설정에는 endpoint와 모델 이름이 저장된다. 같은 프로필에서는 Jueony 업무 창 하나만 편집 가능하며 두 번째 창은 안내를 표시한다. 이는 저장소의 동시 쓰기 충돌을 막는다.

## 실제 지원 범위

| 항목 | 구현 |
| --- | --- |
| 업무 | 생성·전환·이름 변경, 각 업무의 독립 채팅/폴더/문서 탭 |
| 채팅 | 생성·전환·이름 변경, 메시지와 실행 기록 복원 |
| 폴더 | 여러 원본 폴더 연결, 하위 트리, 새로고침, 연결 해제; 원본 복사/이동/삭제 안 함 |
| 자료 | 명시적으로 체크한 HWP/HWPX, UTF-8 TXT/Markdown만 읽기; 폴더 등록만으로 분석하지 않음 |
| 최신 문서 | 같은 엔진의 전체 본문과 Unicode 추출문. 참고 파일도 같은 업무에 열려 있으면 미저장 텍스트 우선 |
| AI 명령 | 새 문서 초안, 문단 뒤 본문 삽입, 문단 내 텍스트 교체/삭제, 서로 떨어진 여러 위치 변경 |
| 편집 보호 | 전체 명령 사전 검증, 버전/원문 검사, 요청 ID 중복 차단, 취소·늦은 응답 차단, 적용 중 입력 제한 |
| 결과 | 실제 적용 개수, 전후 본문, 전달 자료 이름·문자 수·범위, 모델이 표시한 출처 구분 |
| 되돌리기 | 현재 세션에서 해당 요청이 마지막 문서 변경인 경우 요청 전체를 엔진 history 한 단계로 되돌림 |
| 파일 저장 | 기존 HWP/HWPX 저장 경로 재사용. 원본 외부 변경·저장 중 변경 검사, 다운로드 확인 |
| 복원 | 같은 브라우저 프로필/origin의 IndexedDB에서 업무·채팅·폴더 핸들·최근 문서/미저장 초안 복원 |

복구 문서는 원본 핸들을 재사용하지 않아 **다른 이름으로 저장**한다. 재시작 후 엔진 undo 이력은 복원하지 않는다. 브라우저 저장소 삭제나 프로필 변경은 복구 범위 밖이다. 미저장 복구본은 변경 후 약 1.4초 뒤 저장하므로 강제 종료 직전 입력까지 보장하지 않는다. 이전 단일 편집기 버전의 자동 복구 데이터를 새 workspace로 자동 이관하지 않는다.

### 명령과 자료 한도

- 기존 문단 편집은 단순 본문에 한한다. 혼합 글자 서식, 필드, 표/개체 제어문자가 있는 문단, 4,000자 초과 문단은 AI 편집에서 제외한다.
- 단순 문서의 구역/단 정의만 있는 첫 문단은 편집 가능하다. 다른 개체가 있는 문서의 첫 문단은 더 보수적으로 제한될 수 있다. 수동 편집 기능 전체에 같은 제한을 적용하는 것은 아니다.
- 기존 문단당 명령 1개, 요청당 최대 30개 명령. 새 문서 작성은 단독 명령이며 기존 문서를 덮어쓰지 않는다.
- 새 문단 배열은 1~100개, 생성하는 각 문단은 4,000 Unicode 문자 이하, 생성 본문 합계 60,000자 이하.
- 본문 삭제는 텍스트를 지우며 문단 구조는 유지한다. 문단 이동/병합 명령은 없다.
- 현재 문서 텍스트 최대 120,000자. 최근 메시지 최대 20개·40,000자.
- 참고 자료 최대 20개·파일당 16MB·추출 합계 120,000자. 폴더 탐색 깊이 20단계·1,000개 항목. 미지원/손상/초과 자료가 있으면 요청을 중단하고 이유를 표시한다.
- 그림 속 글자/OCR, PDF/DOCX/XLSX 추출은 미지원. HWP의 텍스트 추출은 원본 시각 배치 전체를 모델에 전달하는 기능이 아니다.
- 표 생성, 제목 서식 변경, 개체·쪽 설정·자동 저장을 AI가 수행하는 명령은 아직 없다. 수동 편집기 기존 기능을 사용할 수 있다.
- 모델이 미지원 기능을 요청받으면 변경 없는 설명을 반환하도록 계약을 둔다. 임의 명령은 앱에서 거부한다.

사용자가 AI 요청 후 문서를 바꾸거나 업무/채팅/문서를 전환하면 오래된 결과를 적용하지 않는다. 요청 이후 추가 편집을 한 상태에서 “요청 되돌리기”로 후속 편집을 지우지 않는다. 엔진 적용 실패 시 원본 바이트/본문과 비교하여 무변경·복구·부분 적용 확인 필요를 구분한다. **렌더 실패와 rollback 자체 실패를 강제로 일으키는 종합 주입 검사는 아직 남았다.**

## 구현 구조와 확장 위치

`shell → run-once → LLMPort ← 로컬 transport → provider adapter` 구조다. AI와 사용자는 같은 iframe의 rhwp 엔진을 사용한다. 서버가 작업 중인 파일을 별도로 수정하지 않는다.

| 책임 | 현재 파일 |
| --- | --- |
| 3영역 UI·문서 세션·업무 선택 | `apps/editor/src/shell.{ts,html,css}` |
| 공통 모델·업무/채팅 소유권 | `src/mvp/model.ts` |
| IndexedDB v1·트랜잭션·중단 실행 복원 | `src/mvp/store.ts` |
| 파일/폴더 명시 자료 읽기 | `src/mvp/references.ts` |
| 문맥 구성, 향후 RAG 검색 결과 추가 지점 | `src/mvp/context.ts` |
| 생성 1회·검증·실행 제어, 향후 loop 추가 지점 | `src/mvp/run-once.ts` |
| 제공자 중립 Port·HTTP 전달 | `src/mvp/llm.ts` |
| 엔진 읽기/적용/undo·명령 schema | `src/mvp/editor-bridge.ts`, `edit-schema.ts` |
| 인증된 루프백 서버·provider registry | `apps/launcher/server.mjs` |
| 요청/인증/응답/오류 변환 | `apps/launcher/providers/openai-compatible.mjs` |
| Windows 시작·번들 | `apps/launcher/main.rs`, `scripts/Build-Standalone.ps1` |

추가 adapter는 registry에 등록하고 공통 입력을 받아 `{message, sourceIds, operations}`를 반환한다. 제공자 wire format은 해당 파일 안에서만 다룬다. 현재 프런트 설정 UI는 OpenAI 호환 하나만 노출한다. 다른 인증 형태를 추가할 때 설정 항목과 지원 목록은 늘려야 하지만 Agent·업무 저장·편집기는 재작성하지 않는다.

Rust HTTP/TLS 의존성의 빌드 프로그램이 이 PC의 Windows 애플리케이션 제어에 막혔다. 보안 설정을 완화하지 않고 **Rust 실행기 + 동봉한 Node 표준 HTTP/fetch/TLS 서버 + 기존 Rust/WASM 편집 엔진**으로 구현했다. 서버용 외부 npm 패키지를 추가하지 않았다. Node 배포본의 전체 LICENSE와 원래 엔진/폰트 고지를 포함한다.

서버는 127.0.0.1에만 바인딩하며 Host, Origin/fetch metadata, 부트스트랩 헤더, 난수 토큰을 검사한다. CSP의 connect-src는 self다. 모델 호출은 등록한 endpoint로만 보내고 redirect를 따르지 않는다. 기관 관리자의 endpoint allowlist, 인증서 배포, 브라우저 자체 통신 제어와 암호화 저장 정책은 아직 제품화하지 않았다.

## 자동 검증과 근거

검증 원본은 `apps/editor/evidence/mvp`, 인계 기록은 [mvp-2026-10-09](evidence/mvp-2026-10-09/)에 둔다. 결과 숫자는 최종 로그를 기준으로 한다.

- 앱/엔진 테스트 **19 통과**: 기존 저장 보호, HWP/HWPX 재파싱, 새 초안, 여러 위치 수정, 이모지 범위, 원래 균일 서식, 명령/출처 거부, 업무·채팅 문맥, 취소/전환/충돌.
- 서버 검사 **7 통과**: 인증·Host/Origin, 두 모델 선택 전달, endpoint/redirect 제한, 오류 키 제거, HTTP 취소, 정적 경로와 CSP, 키 삭제.
- headless Edge UI 검사 **18 통과**: 3영역·두 폴더·채팅/업무 격리·실제 문서 변경·요청 undo·취소·동시 변경 차단·HWPX 트리 열기·미저장 참고 자료·키 비저장/삭제·재실행·직접 키보드 입력.
- TypeScript 검사, Vite 빌드, Rust 런처 빌드를 실행한다. 번들 최종 소스/런타임 해시는 `build/jueony-mvp/bundle-evidence.json`에 기록한다.

UI 검증의 모델 서버는 **결정적인 로컬 HTTP 테스트 fixture**다. 실제 추론 모델 호출이나 품질 검증이 아니다. 폴더 연결은 브라우저 OPFS 디렉터리 핸들로 API를 검사했으며 실제 Windows 폴더 선택 대화상자·권한 재승인을 조작한 검사가 아니다. 직접 키보드 입력은 Chromium 입력 경로 검사이며 한국어 IME 조합 검사가 아니다. 페이지에서 외부 자산 요청을 계측하지만 OS 네트워크를 실제로 차단하거나 Edge 자체 통신 전체를 감사한 것은 아니다.

실제 기관 endpoint·모델·권한·키는 제공되지 않았으므로 M07/V14의 실제 LLM 관문은 **BLOCKED**다. 실제 한글 2024 검수도 **대기**다. 이전 사용자의 재열기 성공 보고를 새 저장물의 독립 판정으로 대신하지 않는다.

## 한글 검수용 문서

[evidence/mvp-2026-10-09](evidence/mvp-2026-10-09/)의 각 단계에서 HWP와 HWPX를 연다.

- `01-created`: 올해 업무 계획 / 추진 목적을 정리합니다. / 일정을 검토합니다.
- `02-applied`: 제목을 수정된 업무 계획으로 바꾸고 마지막에 추가 검토 사항 문단을 삽입.
- `03-reverted`: 01과 같은 3개 문단으로 복원.

HWP는 UI의 저장·다운로드 확인 경로에서 얻은 파일이다. HWPX는 그 저장물을 엔진으로 읽어 변환한 동반 파일이다. 둘 모두 같은 엔진에서 텍스트/문단 경계를 재검사했다. 실제 한글에서 열림·제목과 문단 경계·글자 서식·쪽 수·재저장을 확인하고 [수용 검사 기록](mvp-acceptance-results.csv)의 V28을 갱신한다. 복잡한 문서 검수는 04번 계획을 계속 적용한다.

## 남은 우선 작업

1. 실제 기관 endpoint와 모델로 새 초안→후속 변경→undo→저장을 검증한다. HyperCLOVA X 고유 규격이면 별도 adapter를 추가한다.
2. 실제 Windows 폴더 선택/권한 복원, 한글 2024의 합성 저장물·복잡한 양식, 한국어 IME 세부 사례를 검사한다.
3. 렌더/중간 명령/rollback 실패 주입과 강제 종료·저장 공간 부족 복구를 보강한다.
4. 엔진 지원을 확인하며 AI 표/서식 명령을 하나씩 추가한다. 기존 E00~E12의 전체 편집기 보강은 별도 미완료 목록으로 유지한다.
5. 기관 배포 전에 데이터 보관/삭제·프로필 백업, endpoint 관리 정책, 전체 SBOM·라이선스 고지를 확정한다.
