[최신 합본107: 뒤쪽 편집 저장 수정·남은 구버전 호환성](121-local-edit-storage.md).

2026-10-18. [파일 작업표](features/05-files-storage-recovery.md) · [이전 합본104](119-source-table-frame-storage.md) · [고정 검수 근거](evidence/file-completion-2026-10-18/storage106/README.md).

**원본 MCST의 앞 문단을 편집한 뒤 HWPX 저장이 막히던 결함은 해결했다.** 같은 공식113 엔진과 프런트106에서 파일·복구 387개, 단위1008개가 통과했다. 다른 Python 예제의 편집 후 배치 변동은 아직 수정 중이므로 파일 파트 전체 완료로 표시하지 않는다.

| 결함 | 변경 | 실제 확인 |
| --- | --- | --- |
| 앞 본문 편집 후 원래 쪽 경계가 잘못 복원됨 | 현재 원문·글자별 서식·문단 형식·행 범위를 확인한 경우에만 원본 경계 사용 | Native와 실제 생성 HWPX의 32개 편집 경로 통과 |
| 혼합 본문·표 문단에서 첫 행을 표 행으로 오인 | 실제 8단위 제어 슬롯·행 원문·서식·측정 높이가 일치하는 단일 표 행을 선택 | 이전112에서 남았던 p44 시작 삽입 실패 해소 |
| 선언된 표 상자가 셀보다 작은데 전체가 들어간다고 판단 | 표 선언 높이가 실제 셀 행 상자를 덮는지도 확인 | Python 원형 HWPX 재열기 차이1839→0, 3회 반복 저장 통과 |
| 빈 후속 문단 간격 중복 | 실제 수용된 표 프레임과 원본 행 간격의 소유 확인 | Native 참조의 정확히92개 y값만 -8.8px; 후속 편집 결함과 구분 |

원본 행·서식을 다시 쓰거나 저장 보호 검사를 느슨하게 하지 않았다. 불명확한 위치, 범위 초과·다른 서식·모르는 제어·다른 물리 프레임은 새 권한을 얻지 않는다.

저장 거절은 저장 성공으로 세지 않았다. 원본 인스턴스의 undo/redo와, 재열기한 별도 인스턴스의 undo/redo를 각각 확인했다. 서로 다른 인스턴스의 snapshot ID를 섞지 않는다.

독립 참조 파일을 현재 엔진으로 다시 읽을 때 참조 자체의92개 좌표가 고쳐져 옛 기대 수731/680이 달라졌다. 검사를 지우지 않고 참조 엔진을 원래110으로 고정해 종전 증명을 유지했다. 현재 참조의92개 변화는 별도 전체 비교로 검증한다. 실패한 최초 합본·기대 오류·재실행 경위도 근거에 보존했다.

## 실행

`Start-Jueony-FileReview.cmd` → `build/jueony-file-review106/Start-Jueony.cmd`, 기본 `127.0.0.1:4370`. 사용자 실행 창과 원본 문서는 건드리지 않았다.
