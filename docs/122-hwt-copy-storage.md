# HWT 일반 필드 작업과 같은 형식의 사본 저장

[종합 현황](jueony-progress.md) · [파일 파트](features/05-files-storage-recovery.md) · [이전 합본](121-local-edit-storage.md)

합본110에서 **일반 필드 편집·Undo/Redo·지속 복구·사본 저장·재열기 검사를 통과했다**. 파일·저장·복구·형식 보존 파트의 B009에 속하며, 일반 HWT 전체 지원 또는 이 파트 전체 완료를 뜻하지 않는다. 한글 2024 직접 비교는 사용자 지시에 따라 보류한다. [최신 합본과 근거](123-current-stack-and-preview-storage.md).

## 실제 연결

파일 메뉴의 XML/XSD 문서 작업에서 **HWT 일반 필드 편집**을 연다. 편집기에 실제 `inspectHwtLeafDocument`와 `editHwtLeafDocument`가 있을 때만 진입을 활성화한다. 활성 HWP/HWPX와 별개의 바이트 작업 공간이며 현재 문서의 내용·선택·편집 기록을 바꾸지 않는다.

| 경계 | 책임 |
| --- | --- |
| 엔진의 HWT 일반 필드 모듈 | 실제 CFB/HWT, 스키마·필드 일대일 관계, 원문·값 CAS, 편집 결과와 저장 재열기 검사 |
| `xml-documents`의 HWT 작업 공간 | 문서 식별자·버전, 바이트 단위 undo/redo, 저장 완료 시점의 CAS |
| HWT 전용 IndexedDB adapter | 창·업무별 분리, 원문·현재값·양방향 기록의 무결성, 충돌·실패 시 기존 복구본 보존 |
| 파일 저장 adapter | 사용자 선택 대상, 파일 지문·버전 충돌, 쓰기·닫기·재읽기 후에만 저장 완료 |
| Windows Native 사본 저장 | 전용 `.hwt` 선택 명령과 창 소유 token; 기존 HWP 열기 권한과 분리 |

지원 범위는 단순 루트 `sequence`의 `xs:string`과 문단별 단일 ClickHere 일반 필드가 정확히 연결된 문서다. 복합 스키마·그룹·폼·XSL·일반 HWT 편집은 지원하지 않는다. 미지원 문서는 거절하고 기존 작업을 유지한다. Agent용 HWT 도구를 등록한 것으로 표시하지 않는다.

## 같은 형식 저장

브라우저는 실제 File System Access API를 사용한다. 선택 취소는 저장 성공이 아니다. 다운로드를 디스크 저장 완료로 간주하지 않는다.

Native 앱은 `pick_save_hwt_copy`로 사용자가 고른 `.hwt` 대상만 등록한다. 일반 `DocumentFile::open`은 계속 HWP/HWPX만 받는다. 새 사본 대상에 한해 아직 없는 파일을 빈 기준값으로 조회할 수 있고, 이미 존재했던 파일이 사라졌다면 다시 만드는 대신 거절한다. 외부 변경, 동시 생성, 교체 잠금과 실제 저장 결과 확인은 기존 저장 계층을 사용한다.

## 검증 기록

| 항목 | 현재 결과 | 한계 |
| --- | --- | --- |
| HWT·미리보기 공식 Native | 25개 통과 | 실제 공식 소스 컴파일, ignore0; 전체 엔진 라이브러리 검사가 아님 |
| 실제 Windows 저장 계층 | HWP/HWPX/HWT 포함 11개 통과 | Native 파일 선택창 직접 조작과 한글 재열기는 미실행 |
| Tauri 코드 | 실제 Windows `cargo check --offline --locked` 통과 | 실행 GUI 인증이 아님 |
| 업무·기록·저장 adapter | 전체 단위 1,025개 통과 | 최종 엔진·프런트 합본 검수는 별도 |
| HWT 작업 공간·복구 화면 | 13개 통과 | 실제 선택 WASM과 IDB/OPFS; 일반 XML 복구본 불변도 확인 |
| 전체 앱·iframe·브라우저 사본 | 7개 통과 | 실제 앱 메뉴·WASM·편집·저장·재열기, Native GUI와 구분 |
| 전체 앱 Native 사본 화면 | 10개 통과 | 실제 Native adapter와 합성 IPC; 디스크 계층은 별도 실제 Windows11개 |
| 미리보기 독립 CFB 관측 | 7개 통과 | 유효 UTF-16 정확 보존, 손상 값 HWP 원시 보존과 HWPX4개 API 거절 |
| 기존 파일 파트 회귀 | 새 합본 424개 모두 통과 | 신규37개와 한 번의461개 실행, 별도 구버전14개까지 총475개 |

제한 환경에서 처음 수행한 Windows 저장 검사는 원자적 파일 교체에 액세스 거부가 발생했다. 같은 코드와 검사기를 호스트의 자체 임시 파일에서 실행한 결과 11개가 통과했다. 최초 실패 로그를 남기며 보호 조건을 완화하지 않았다.

최초 엔진에서 중복된 표준 쪽 설정 기록이 2개에서1개로 줄어드는 결함을 발견했다. 현재는 본문 원시 레코드의 순서·수준·payload를 비교하고, 실제 필드 편집에 필요한 제한된 기록만 허용한다. 보존할 수 없는 원본은 편집 전에 거절하며 바이트와 기존 작업을 유지한다. 검증을 통과시키려고 중복 기록을 삭제하지 않았다.

두 번째 편집에서는 이모지가 포함된 파생 미리보기의 손상이 드러났다. 일반 HWP에도 공통인 UTF-16 읽기 결함을 수정했고, 원본 본문에서 생성된 것으로 증명한 미리보기만 사본에서 재생성한다. 임의 텍스트·잘못된 UTF-16 원시 데이터의 소유권을 편집 명령이 가져오지 않는다. 최초 실패 결과와 원시 관측을 고정 근거에 보존했다.

남은 범위는 일반 XSD/XSL·복합 HWT, HWT Agent 편집, 실제 Native 선택창과 한글 직접 비교다. 구버전 HWPX 배치·표준 행 저장 결함도 같은 합본에서 해결·검증했으며 [합본110](123-current-stack-and-preview-storage.md)에 별도 기록한다.
