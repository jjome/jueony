# 재조판 뒤 저장과 미리보기 보존: 합본110

[파일 작업표](features/05-files-storage-recovery.md) · [HWT 사본 작업](122-hwt-copy-storage.md) · [직전 합본](121-local-edit-storage.md).

최종 합본의 자동 검사 **475개가 통과했다**. 한 번의461개 실행과 동일 엔진의 별도14개 검사로 구성한다. 파일·저장·복구·형식 보존만 변경했다. 한글 직접 비교는 사용자 요청에 따라 수행하지 않았다. [고정 결과](evidence/file-completion-2026-10-18/storage110/README.md).

## 수정한 결함

| 결함 | 수정한 경계 | 보호 조건 |
| --- | --- | --- |
| 구버전 측정 캐시를 거절한 뒤 앞 문단과 두 표의 위치가 달라져 저장이 막힘 | 현재 원문·서식·실측 표 높이·단 폭으로 전체 배치를 증명하고, 내보내기 전용 사본에 현재 표준 행 생성 | 구버전 캐시를 허용하지 않으며 원본 모델·행·lease를 변경하지 않음 |

| HWP 미리보기의 이모지 등 보조 평면 문자 손실 | UTF-16 코드 단위 개별 변환 대신 전체 문자열 검증 | 유효한 원문은 정확히 보존; 잘못된 UTF-16은 HWP에서 원시 바이트 보존 |

| HWT 두 번째 편집의 파생 미리보기 검증 실패 | 원본 본문에서 생성됐음을 증명한 미리보기만 별도 내보내기 사본에서 재생성 | 임의의 비어 있지 않은 미리보기는 추측해서 덮어쓰지 않음 |

새 표준 행의 소유권은 현재 내보내기 사본에만 연결한다. 원문·서식·쪽/단 설정·제어 속성·전체 배치에 대한 증명이 하나라도 실패하면 기존 안전 경로를 유지한다. 공개 지면의 좌표 허용 오차는 기존 0.2를 유지하며 다른 의미 필드를 제외하지 않는다.

물리 배치 resource 지문은 기존 230개 입력을 보존하고 실제 새 계산에 쓰는 6개 입력을 추가한 **236개**다. 독립 재계산과 준비된 전체 Rust 소스 대조를 완료했다. HWT 자유 바이트 API와 미리보기 전용 메타데이터는 물리 행 계산 입력과 구분한다. 이 제외가 제품 소스 검증 제외를 뜻하지는 않으며, 전체 패치·WASM 지문으로 별도 고정한다. 크기·깊이 제한은 전체 CPU 실행 시간의 보장을 뜻하지 않는다.

## 실행과 재현

`Start-Jueony-FileReview.cmd` → `build/jueony-file-review110/Start-Jueony.cmd`, `127.0.0.1:4380`. 기존 실행본과 사용자 문서를 종료하거나 변경하지 않았다. Native HWT 사본 경계는 실제 Tauri 전체 컴파일과 별도 Windows 저장 검사까지 수행했으며, 이 로컬 서버 묶음은 Native 파일 선택창 실행본과 구분한다.

전체 검사기는 `scripts/verify_file_workflows.py`다. 기존 네 종류의 명시적 baseline/source/oracle 인자에 `--hwt-leaf`를 추가하고, `JUEONY_PREVIEW_RAW_AUDITOR`에 전용 독립 CFB 관측기 경로를 지정했다. 관측기는 `apps/editor/scripts/prepare-preview-raw-auditor117.mjs`로 자체 빌드한다. 실제 실행 인자와 결과는 고정 근거의 `checks/run-workflows.py.gz`와 `workflows/result.json`에 있다.

구버전 자체 입력은 `generate-legacy-stack-fixtures115.mjs`로 공식113 패키지와 추적된 자체 단 예제에서 재생성한다. 입력 세 개의 정확한 SHA가 같아야 `verify-legacy-stack-storage115.mjs`의14개 검사를 실행한다. 다른 세대의 입력을 같은 예제로 취급하지 않는다.
