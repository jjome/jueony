# 원본을 바꾸지 않는 날짜 포함 저장 사본

[파일·저장·복구·형식 보존](features/05-files-storage-recovery.md) · [이전 합본111](124-new-document-time-storage.md) · [검수 증거](evidence/file-completion-2026-10-18/storage112-engine/README.md)

공식119 엔진에 명시한 날짜를 저장 사본에만 넣는 API를 추가했다. 열린 문서의 내용·날짜·커서·이력은 변경하지 않는다. 앱의 저장 완료 처리와 연결하기 위한 엔진 변경이며, 파일 파트 전체 완료나 자동 편집 시간 누적 완료를 뜻하지 않는다. 검수 실행본111은 유지한다.

| 구분 | 구현과 검증 결과 |
| --- | --- |
| 사본 발급 | 정확한 원본 문서를 빌린 불투명 intent로 메타데이터 전용 사본을 만든다. 다른 문서나 본문을 끼워 넣지 못한다. |
| 원본 보호 | 임시로 live 문서를 바꾸지 않는다. 취소·잘못된 인자·직렬화 실패에서도 원본을 되돌리는 작업 자체가 필요 없다. |
| 기존 내보내기 | 일반 경로의 조건·직렬화·보호 검사를 유지한다. 앞 문단 재조판과 전체 배치의 소유 증명도 실제 사본에 연결한다. |

| 단표 | 생성 문서와 기존 고정쌍24개 통과. 새로운 한글 직접 비교는 수행하지 않았다. |

## 실제 계약

`exportStampedDocumentWithReport(format, expectedFingerprint, requestJSON)`와 암호화 버전 `exportStampedDocumentWithPasswordAndReport(format, expectedFingerprint, requestJSON, passwordBytes)`를 제공한다. 날짜 요청은 기존 schemaVersion1의 엄격한 FILETIME 계약을 사용한다.

반환 객체의 `metadataIntent()`는 원본/사본 지문, 요청 값, 변경 여부와 변경 전후 정보를 제공한다. `takeBytes()`는 한 번만 사용할 수 있고 기존 content-loss report를 유지한다. 이 증거는 디스크 저장 성공 영수증이 아니다. 저장 성공 후 live 값 적용과 Undo/복구 수명은 앱에서 별도로 검증해야 한다.

물리 배치 자원 입력은 기존236개를 모두 유지하고 사본 발급 모듈을 더한237개다. 공식 준비 소스7개와 나머지 Rust1073개를 대조했고 예상하지 않은 변경은 없었다. 옛 측정 캐시 허용, 보존 필드 제외, 좌표 오차 확대는 추가하지 않았다.

## 남은 결함과 연결 작업

- 앞 문단을 재조판한 prefix 문서의 **암호화 HWP**2건은 기존 일반 exporter와 새 경로 모두 `/RhwpComputedNativeRowsV1` 손실 경고를 낸다. 무손실 저장 성공으로 표시하지 않는다. 최초 엄격 실패와 이후 차단 검사를 보관했다. 암호화된 행 증명의 별도 소유 계약이 필요하다.
- 현재 파일 연결에 실제 쓰기·close·재읽기가 성공한 뒤에만 live 수정 시각을 승인하도록 앱 경로를 연결한다. 취소·외부 변경·늦은 문서 전환은 완료로 표시하지 않아야 한다.
- 활성 편집 시간 누적, 인쇄 성공 시각, 일반 XSD/XSL·복합 HWT, 임의 복잡 배치와 한글 전체 동등성은 잔여다. 작업표의 기존 범위를 줄이거나 완료 수를 늘리지 않았다.

증거의 `verify.py`는 결과·실패 기록·소스 증명·로그의 지문을 확인한다. 자체 생성 문서만 새 시험 입력으로 사용하며 기존 외부 원본은 새로 배포하지 않는다.
