# N001: 재조판 문서의 암호화 저장 보존

[N001 작업표](features/05-files-storage-recovery.md#n001) · [고정 검수 결과](evidence/n001-2026-10-18/encrypted120/README.md)

이번 변경은 **N001 — HWP 겹침 표의 복잡 배치·불명확 원점 저장 보존**만 다룬다. 중단된 저장 시각·최근 문서 기능은 변경하거나 실행본에 포함하지 않았다.

| N001의 구체적인 결함 | 현재 상태 | 확인한 결과 |
| --- | --- | --- |
| 재조판한 문서의 암호화 HWP 저장에서 행 배치 정보 누락 | 공식 Rust120 엔진에 수정 | 실제 WASM7개와 실제 앱3개 통과 |
| 구버전 저장본의 유효한38바이트 표 속성이42바이트 검사에서 거절됨 | 별도 후보에서 구조 검증 보강 중 | 두 자체 예제의 HWPX 공개 배치 차이282→0 관찰, 아직 정식 합본 검수 전 |
| 구버전의 해석하지 않은 배치 기록이 HWPX 변환에서 누락됨 | 수정 중 | 원본 바이트를 레이아웃 권한과 분리해 보관해야 함. 누락 검사를 제거하지 않음 |

첫 번째 수정은 Rust 파서·저장기와 해당 자원 지문만 변경한다. 현재 유효한 기록에만 기존 HWP5 스트림 암호화를 적용하고, 실제 암호 입력·본문 복호화 후에만 기록을 검증한다. 잘못된 암호, 손상·오래된 기록을 현재 배치 권한으로 받아들이지 않는다. 원본 객체와 기존 보호 검사·좌표 허용 오차는 유지한다.

WASM7개에서는 반복 암호화 HWP/HWPX 저장·재열기, 명시적 날짜를 포함하는 사본의 배치 보존, 잘못된 암호·손상 기록을 확인했다. 실제 앱3개는 두 형식의 암호 대화상자·SaveAs·후속 저장·Undo/Redo·재열기와 오류/외부 요청 부재를 검사한다. 실제 OPFS 바이트와 별도 Node 파일 재읽기를 사용했다. 한글이나 Windows 파일 선택창 직접 비교를 수행했다는 뜻이 아니다.

앱은 커밋8509733e의 고정 소스로 별도 빌드했다. 작업트리에 남아 있는 다른 기능 코드는 그대로 보존하고 제외했다. Python은 검수 실행·증거 정리에만 사용하며 이번 문서 처리 수정 코드는 Rust다.

**N001 전체는 아직 완료로 표시하지 않는다.** 위의 남은 결함을 같은 항목에서 계속 수정·검증한다. 원래 작업 범위나 완료 기준을 줄이지 않았다.
