# N001 일반 복합 배치의 저장 보존 확대

[기능 작업표](features/05-files-storage-recovery.md#n001) · [직전 저장 수정](127-n001-legacy-layout-storage.md) · [고정 검사 자료](../apps/editor/tests/fixtures/n001-general125-own/README.md)

이번 변경은 **파일·저장·복구·형식 보존의 N001만** 다룬다. 문서 처리 코드는 Rust다. Python과 JavaScript는 빌드·실행 검사·증거 정리에 사용한다. 저장 시각 수명이나 최근 문서 Agent 작업의 기존 미완성 변경은 보존하고 이 검수 앱에서는 제외했다.

개수 계산의 확대가 공개 API로 새로 만든 모든 표의 지원을 뜻하지 않는다. 기존 구조의 원시 속성을 가진 연속 표는 현재 틀 증명을 재사용할 수 있지만, 새 표·본문 교차·다단·음수/양수 오프셋은 각각 실제 조판 결과와 물리 틀을 증명해야 한다. 알려진 실패를 저장 성공으로 바꾸거나 원본 쓰기 보호를 해제하지 않았다.

## 정확히 바꾼 경계

표 뒤 간격 검사는 실제 Native 파싱 때 관찰한 입력과 현재 입력이 같은 경우에만 기존 반 간격 정책을 선택한다. 표·셀·원시 데이터·서식·문서 및 구역 정의·자원 세대와 문단 위치를 묶는다. 루트 행의 세로 위치는 이 간격 계산의 입력이 아니므로 별도 정책 지문에서는 제외하지만, 기존 전체 위치·reset·행 정보 권한 검사는 그대로 유지한다.

뒤 문단은 정체성이나 전체 좌표가 아니라 **다음 위치가 존재하며 그 첫 행에 저장 행 정보가 없는 정책 분류**만 검사한다. 첫 행 없음과 구현 행 존재는 원래 전체 간격 분기가 모두 거짓인 같은 분류다. 이 관찰은 행·원점·캐시·저장 권한을 주지 않는다. 다음 위치가 없어지거나 저장 행 정보가 생기면 적용하지 않는다.

HWPX의 임시 표준 행 계획은 전체 의존 문단·투영할 문단·문서 정의를 계속 정확히 비교한다. 기존 writer가 Native의 비어 있는 미투영 본문 행에 추가하는 표식도 그 **정확한 출력 표현**에 포함한다. 원형 또는 변환형 중 임의의 지문을 허용하는 OR 검사가 아니다. 원본 지문 보관 자체가 저장 시 원본 객체를 다시 검사하는 것은 아니며, 실제 바인딩 검사는 생성 시 계산한 정확한 목표 전체 지문과 각 투영 문단 지문을 사용한다.
