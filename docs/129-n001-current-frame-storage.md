공개 저장에서는 본문·표 교차, 새 표3·4개, 양·음수 오프셋, 설정된 균등 다단 안의 현재 전체 문단과 표, 명시 쪽 경계가 추가로 통과했다. 여러 구역의 초기 저장도 연결했지만, 구역0의 마지막 표 호스트에 후속 본문을 넣는 경로는 아직 실패한다. 이를 구역 지원 전체 완료로 확대하지 않았다.

## 구현 경계

- 실제 formatter가 선택한 불변 조판 객체와 allocator가 확정한 문단·행·표·쪽·단을 연결한다. 부분 본문을 다른 너비에서 다시 만든 조판의 옛 행 번호로 그리지 않는다.
- 새 출력 계획은 새 표준 행, 실제 선택 행의 내용·측정치, 최종 물리 좌표와 소유가 일치할 때만 만든다. 임의 JSON이나 옛 캐시 행으로 계획을 발급하지 않는다.
- 표가 예약한 흐름과 실제로 그리는 원점, 표 바깥 여백, 명시 쪽·구역의 최종 프레임을 별도로 확인한다. 실제 구역 쪽 번호 carry도 알려진 정확한 변화만 검사한다.
- 새 표의 구조 앵커 행은 본문 행과 다른 종류로 검증한다. 기존 유효한 표준 본문 행과 새 측정값의 수치8개가 모두 같으면 해당 본문을 새 투영에서 제외해 기존 writer가 그대로 쓰도록 한다. 태그 변경·마스킹·임의 원본 행 권한은 없다. 그 본문의 fresh·allocator·physical 검사도 계속 수행한다.
- 완료 행을 발급한 뒤 현재 조판을 다시 확정해 편집·되돌리기·다시 실행 때 Source와 실제 pass가 어긋나지 않게 했다.
- 새로운 경로가 전체 원본 조건을 지원하는지 계획 생성 전에 확인한다. 생성된 계획의 출력 바인딩 실패는 명시 오류다. 이를 숨기고 다른 경로로 저장하지 않는다.

전체 원본·정확한 변환형·각 문단·원시/미지 데이터의 보호, 내용 손실 보고, 기존 전체 공개 배치 비교0.2는 유지했다. 자원 지문 입력은 이전 항목을 순서대로 모두 유지하고261개가 됐다. 합치는 과정의 컴파일 오류와 기존 표3건의 회귀도 고친 뒤 재검증했으며 실패 원본을 증거에 보존했다.
