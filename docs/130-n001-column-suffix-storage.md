# N001 명시 단 경계와 후행 본문 저장 검증

[파일·저장·복구·형식 보존 작업표](features/05-files-storage-recovery.md#n001) · [이전 결과141](129-n001-current-frame-storage.md) · [검증 원본과 해시](evidence/n001-2026-10-19/general143/README.md)

**파일·저장·복구·형식 보존의 일반 복합 배치 N001만 진행 중이다.** 문서 엔진 변경은 Rust다. 이번에는 명시 단 경계의 저장과 좁은 단으로 넘어간 뒤쪽 본문의 문자 누락을 수정했다. 다른 작업45파일은 그대로 보존하고 검수 앱에서 제외했다. 한글 직접 비교는 요청대로 미뤘다.

모든 본문 검사는 첫 문단에 한정하지 않는다. 각 구역의 본문 문단에 대해 Unicode scalar 순서·누락·중복, UTF16 대응과 charX 개수를 검사하고 양형식 파일28개를 실제 디스크에 쓴 뒤 다시 연다. 이전141의 supplementary 문자2입력에서 뒤쪽 본문 누락을 재현하고 현재143에서 해결을 확인했다. 전체 문서 종류의 호환성을 뜻하지는 않는다.

## Rust 수정

- 명시 단 경계에서 실제 선택된 불변 formatter, allocator가 확정한 단별 문단·표, 현재 물리 프레임을 묶는다. 표 조회가 첫 번째 단의 원점을 잘못 사용하는 경로를 고쳤다.
- 좁은 후속 단의 본문은 실제 소비한 scalar/UTF16 위치부터 현재 전체 조판의 나머지를 그린다. 다른 너비에서 조판한 행 번호를 재사용하지 않는다.
- 후행 본문 paint 증명은 저장 원본 행 권한이나 전체 export trace 권한을 부여하지 않는다. 전체 조판 예산4096행·16MiB·256쪽은 유지한다. 실제128쪽 입력에서 전체 trace 예산을 넘기면 RenderError로 명시 거절하고 원문·이벤트가 변하지 않는 것을 확인했다. 이 음성 검사는 큰 문서 지원 완료가 아니다.
- 이전141의 원본·원시 데이터·완료 행·전체 의미와 배치 보호 검사를 유지했다. 새 계획의 검증 실패를 다른 저장 경로로 숨기지 않는다.
