# N001 일반 복합 배치 저장 구현·자동 검증

## 수정한 저장·재조판 경계

| 실제 원인 | 수정과 보호 |
| --- | --- |
| 문단 상대 표의 위치를 쪽 상단의 body-wide 예약으로 중복 취급 | 실제 배치 생산자의 좌표 도메인을 분리했다. Page/Paper 기존 경로를 유지했다. |
| 폭이 다른 단을 거친 본문·빈 호스트의 현재 조판을 저장 행으로 연결하지 못함 | 현재 원문·서식·물리 프레임과 실제 formatter·확정 배치를 증명한 새 행만 발행한다. 원본 캐시나 과거 권한을 새 권한으로 표시하지 않는다. |

출력 비교 허용 오차0.2, 원본·이벤트 불변, 내용 손실 거절, 자원 지문과 trace 예산을 유지했다. 본문 문자가 빠지면 저장을 성공으로 처리하지 않는다. 이미 화면에 존재하는 body-wide 표의 넘침을 보존하는 것은 인쇄 영역 맞춤이나 한글 조판 동등성 보장이 아니다.

## 남은 일반 배치 구현

기존 고정44입력의 저장 결함을 닫은 것과 N001 전체 완료는 구분한다. 추가로 만든 자체 원형으로 다음 조합을 병렬로 실측·수정 중이다. 이 문서와 집계는 아직23/24·부분1을 유지한다.

| 조합 | 확인된 상태 |
| --- | --- |
| 음수 위치 + 여러 단 | 실제 편집·저장에서 Native/XML 원점과 복수 프레임의 잔여 실패를 수정 중 |
| 일반 캡션 + 여러 단 | 캡션 폭·줄 정보를 HWPX에서 잃는 실제 결함 수정 중 |
| 실제 표 쪽 분할·셀 분할·이어짐 | 기존 legacy 지원부터 실측하고 일반 현재 조판 저장 계약을 보강할 대상 |
| 쪽·종이 기준 절대 원점 + 여러 단 | 자체48 WASM 사례 중 기존156은8통과·40실패; 잘못된 문단 상대 원점 분류와 표 호스트 간격을 수정 중 |

안전한 거절을 해당 조합의 양성 구현 성공으로 세지 않는다. 고정44원형·검수기와 보호 오차를 바꾸거나 위 조합을 완료 분모에서 제외하지 않는다.

## 실행·남은 검수

루트 `Start-Jueony-FileReview.cmd`가 검수 실행본159을 연다. 공식 소스는 `c95d08a807583f1e`, 패치147개다. 이 실행본의 실제 source/resource/WASM 지문은 증거에 함께 보존했다. Python/JavaScript는 빌드·검수 도구다.

이 실행본의 기존 고정 회귀 검사에서 남은 실패는0이다. 별도 일반 배치 확대 시험에는 아직 해결 중인 실패가 있어 N001 전체는 부분 상태다. 증명하지 못한 문서 구조와 trace 예산 초과는 계속 명시적으로 거절한다. 사용자 문서를 덮어쓰지 않았고 키·모델·외부 제공자를 호출하지 않았다. N001/N002 실제 한글 재저장·출력·복합 문서 비교는 후속 검수이며, 다른 제품 기능의 구현으로 넘어가지 않았다.
