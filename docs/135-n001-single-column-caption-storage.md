# N001 단일 단 캡션의 현재 줄 간격 저장

[파일·저장·복구·형식 보존](features/05-files-storage-recovery.md#n001) · [이전164](134-n001-caption-signed-storage.md) · [검증 원본·해시](evidence/n001-2026-10-21/general165/README.md)

**다른 기능으로 넘어가지 않고 N001의 저장 보존을 수정했다.** 이번 공식 Rust165 통합본은 단일 단 캡션의 현재 줄 간격과 후속 편집·저장을 추가한다. 남은 일반 복합 배치까지 완료한 상태는 아니므로 구현 집계는23/24·부분1, 종합 검증은22/24·부분2를 유지한다. 한글 직접 비교는 사용자 요청대로 보류했다.

| 이번에 수정한 저장 경계 | 실제 확인한 범위 | 결과 |
| --- | --- | --- |
| 음수 위치 표 호스트의 저장 행·원점 | 같은 폭2·3단/다른 폭2단, 실제 사용 단1개; −1/−300/−1200HU, 겹침 속성 양쪽, Native/XML·일반/암호 | 24사례·144회 디스크 재열기 |
| 캡션 자체 줄·폭·현재 문맥 | 단일 단·같은 폭2·3단, 실제 사용 단1개; 글자처럼 취급하는 표의 위/아래 캡션 | 48사례·384회 디스크 재열기 |

제공자 호출이나 대화 응답으로 결과를 대신하지 않았다. 실제 WASM의 공개 편집·저장 API와 앱의 기존 저장 보호 검사를 사용했다. 원본 고정44문서, 의미 비교, 모든 공개 배치 필드의0.2오차 기준을 그대로 유지했다. 각 본문·셀·캡션의 전체 문자 순서와 Unicode scalar/UTF16 길이, 중복·누락, 원본 직렬화 바이트와 이벤트 불변을 검사했다.

## 구현

- 음수 문단 상대 위치는 별도 현재 단 배치 계약으로 다룬다. 원문·서식·측정값의 모든 필드·완료된 배치 소유·실제 표/본문 위치가 맞아야 새 표준 저장 행을 만들 수 있다. 원본 캐시나 태그만으로 권한을 만들지 않는다.
- 단일 단 캡션의 간격은 현재 캡션 소유·원문·측정값·호스트·인접 문단이 정확히 연결된 경우만 반영한다. 단일 단·다단의 기존 간격 경로는 유지한다.
- 캡션은 본문 행과 구분한 현재 출력 경로로 연결한다. 실제 caption owner, 폰트 측정, 캡션 폭과 모든 줄·글자 배치를 확인한다. 이 계약으로 본문/표 원점/페이지 적합 권한을 발급하지 않는다.
- 저장 대상 복사본은 원문 전체와 런타임 측정·관측을 포함해 정확히 연결한다. 저장 전에 이미 존재하던 권한을 새로 인증하거나 조용히 부분 저장하지 않는다.
