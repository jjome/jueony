# N001 실제 다단·분할 표의 편집 후 저장

[파일·저장·복구·형식 보존](features/05-files-storage-recovery.md#n001) · [이전165](135-n001-single-column-caption-storage.md) · [원본 증거와 해시](evidence/n001-2026-10-21/general166/README.md)

이번 공식 Rust166은 **실제 사용 단이 여러 개인 음수 위치 표**와 **실제로 쪽을 나눈 표의 셀 편집 후 최초 저장**을 수정했다. 마지막 N001 전체의 완료는 아니며, 구현23/24·부분1과 종합 검증22/24·부분2를 유지한다. 한글 직접 비교는 요청대로 보류했다.

| 수정 | 원인과 구현 | 실제 WASM 결과 |
| --- | --- | --- |
| 여러 단에 배치된 음수 위치 표 | 실제 완료 프레임·전체 측정·현재 문단을 연결하여 표준 저장 행을 만든다. 기존 본문 적합과 종이 안의 기존 넘침은 별도 계약이다. | 8사례·48회 디스크 저장/재열기, 실패0 |
| RowBreak 표의 셀 편집 후 최초 HWPX | 행을 예약한 높이와 현재 패딩을 포함해 그린 높이의 차이를 현재 전체 행 측정으로 해결한다. 부분 셀 자르기와 저장 행 권한을 부여하지 않는다. | RowBreak/CellBreak32사례·96회 혼합 재열기·이력64회·잘못된 암호48회 거절 |
| 기존 음수 표 | 기존 1개 사용 단 경로 유지 | 24사례·144회 디스크 재열기 |
| 기존 위·아래 캡션 | 단일 단·2/3단 설정의 기존 경로 유지 | 48사례·384회 디스크 재열기·이력96쌍·잘못된 암호192회 거절 |

모두 실제 공개 편집/저장 API와 기존 앱 저장 보호 검사를 통과했다. HWP/HWPX·평문/암호 조합, 전체 본문·셀·캡션의 Unicode scalar/UTF16 순서·누락·중복, 의미 손실0, 공개 배치0.2 기준, 원본 직렬화와 이벤트 불변을 확인했다. 단순한 거절을 새 지원의 통과로 세지 않았다. 고정44원본과 기존 검수 도구의 기준은 바꾸지 않았다.

## N001의 남은 조합

| 조합 | 이번 공식166 상태 |
| --- | --- |
| 음수 위치 + 단일 단3표의 XML→HWP | 별도 후보에서 실제24회 통과했으며 원형·음성 검사 후 통합 대기 |
| 음수 위치 + 실제 여러 쪽의 문단 분할 | 2개 유효 입력에 잔여 실패, 수정 중 |
| 글자처럼 취급하지 않는 캡션 + 실제 다단 | 원점·후행 문단 간격 차이 수정 중 |
| 쪽/종이 기준 표 + 실제 여러 단 | 별도 현재 프레임·예약 영역 계약 수정 중 |
| 병합·중첩·캡션·특수 개체와 표 이어짐의 조합 | 이번 평면 표 검사로 지원을 입증하지 않음 |

너무 커서 실제 종이를 벗어나는 자체 입력1개는 의도한 음성 시험이며, 위 유효 입력의 잔여 실패와 구분한다. 기존 실패 기록을 삭제하거나 지원 범위를 바꿔 N001을 완료로 표시하지 않는다.
