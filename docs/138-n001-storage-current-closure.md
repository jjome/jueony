## 마지막 결함을 해결한 방식

문서 처리와 보존 수정은 **Rust 문서 엔진**에 구현했다. Python과 JavaScript는 빌드·시험 실행·증거 정리 도구다.

가로 병합 표는 현재 셀의 실제 조판·측정 높이와 행별 최대 높이를 함께 검증한다. 빈 Center 셀의 위치를 잘라내던 오래된 표 높이는 별도 현재 범위 증명으로 배제한다. 실제 셀 본문과 캡션 편집을 구별해 캡션 수정이 셀 본문의 재조판 권한으로 잘못 전달되지 않게 했다. 마지막 캡션 뒤 빈 줄은 실제 현재 프레임의 물리 경계로 검사하며 기존 논리 안전 여백을 바꾸지 않는다.

행 높이 예약 수정으로 고정 원형의 초기 쪽 수는 기존2열3→4쪽, 3열6→7쪽, 4열7→8쪽으로 바뀐다. 세로 병합 이어짐에서는 중복8개 run을 제거했다. 이는 초기 표시도 바꾸는 수정이며 실제 한글과 일치한다고 확정한 결과는 아니다. 세로 병합 테두리의 기존 넘침 역시 저장 전후 동일성 검사만으로 해결됐다고 세지 않는다.

짧은 다쪽 문서에서는 단을 옮기기 전에 선택한 본문 조판을 paint 단계에서도 그대로 사용한다. 재열기 때 유효한 빈 문단을 이전 프레임의 잔재로 숨기던 경로는 별도 현재 조판·표 측정·실제 공간 증명으로 구별한다. 저장된 단 경계가 첫 조각의 공간 검사를 생략하던 경로에는 전환 전후 분할 경계, 다음 프레임 상태와 수용 공간을 확인한 진입 검사를 추가했다. 열린 원문이나 그 캐시를 고쳐 우회하거나 불명확 원점을 임의 추정해 저장하지 않는다.

기존 전체 의미·0.2 배치 검사, 본문/셀/캡션의 scalar·UTF16 소유, source/events, undo/redo, 암호 오류 거절과 실제 디스크 재열기를 유지했다. 원래 실패했던 입력과 중간 결과도 최종 증거의 history 및 이전177 기록에 보존했다. 통과를 위해 실패 입력이나 보호 조건을 제거하지 않았다.

## 실행과 남은 검수

저장소 최상단의 [Start-Jueony-FileReview.cmd](../Start-Jueony-FileReview.cmd)를 실행한다. 최종 합본을 별도의 로컬 검수 묶음으로 준비했으며 사용자 문서·기존 앱 창·API 키는 변경하지 않았다. 이 묶음은 기존45개 작업 파일과 분리한 앱 소스에 최종 엔진을 연결해 검사했다.

한글 직접 비교는 아직 수행하지 않았다. 상위10개 항목의 모든 대화상자·문맥·한글 동등성을 완료로 바꾸지 않았다. Square 입력 통과만으로 실제 옆흐름을, 대표 중첩 원형 통과만으로 임의의 모든 중첩 구조를 증명하지 않는다. 현재 계약 밖의 불명확한 구조와 한도 초과 상태는 안전한 거절을 유지하며, 보존 읽기 계약이 검증하지 못하는 바이너리·전자서명·변경 추적 등의 제한도 그대로 안내한다.
