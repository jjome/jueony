# HyperCLOVA X API 연결 가이드 — 일반 NAVER Cloud 개발 계정

기준: 2026-10-11. 사용자가 선택한 일반용 개발 계정을 기준으로 한다.
Jueony의 전용 연결 코드는 준비했으며 실제 키는 제공받지 않았다. 계정 신청·키 발급·실제 모델 호출은 아직 수행하지 않았다.

## 1. 계정 준비

1. [NAVER Cloud 콘솔](https://console.ncloud.com/)에 본인 계정으로 로그인한다.
2. 콘솔의 AI Services → CLOVA Studio에서 상품 이용 신청을 진행한다. 이미 신청했다면 Studio에 접속되는지 확인한다.
3. 화면에 표시되는 약관·결제/이용 조건을 확인한다. 모델 권한과 한도는 계정별 화면을 기준으로 한다.
4. 사용량은 콘솔의 CLOVA Studio Usage에서 확인한다. 테스트 키를 쓴다고 무료라고 가정하지 않는다.

공식 절차: [CLOVA Studio 시작](https://guide.ncloud-docs.com/docs/clovastudio-start). 이 작업에서 계정 가입·약관 동의·상품 신청을 대신 수행하지 않았다.

## 2. API 키 발급

콘솔의 CLOVA Studio → API 키 → 테스트에서 테스트 API 키를 발급한다. 발급 팝업을 닫으면 원문 키를 다시 확인할 수 없으므로 별도의 안전한 개인 보관소에 저장한다. 키는 Git, 작업 문서, 채팅, 스크린샷에 넣지 않는다.

실제 서비스 운영용 키는 등록된 서비스 앱을 위한 별도 경로다. 이번 개인 개발 확인에서는 테스트 키부터 사용한다. 예전 Deprecated 탭의 두 종류 키를 이번 설정에 섞지 않는다.

공식 안내: [API 키 발급·관리](https://guide.ncloud-docs.com/docs/clovastudio-apikey).

## 3. Jueony에 등록할 값

프로젝트 루트 `C:\Users\jjome\Documents\work\jueony\Start-Jueony.cmd`로 실행하고 **AI 연결 설정**을 연다.

| 항목 | 입력값 |
| --- | --- |
| API 방식 | HyperCLOVA X · v3 구조화 출력 |
| 연결 이름 | NAVER Cloud 개발 등 구분 가능한 이름 |
| Endpoint | `https://clovastudio.stream.ntruss.com/v3/chat-completions` |
| 모델 ID | `HCX-007` |
| 최대 출력 토큰 | 처음에는 `4096` |
| API 키 | 발급한 테스트 API 키의 원문, Bearer 접두어 없이 입력 |

방식을 선택하면 일반용 endpoint와 모델 예시가 채워진다. 계정에서 HCX-007을 사용할 수 있는지는 별도 확인이 필요하다. 현 native adapter는 이 모델의 구조화 출력에 맞췄다. 모델 ID를 endpoint에 중복해서 붙이지 않는다.

실제 요청 URL은 위 주소 뒤에 `/HCX-007`을 붙인 값이며 Bearer 헤더를 사용한다. [공식 API 규격](https://api.ncloud-docs.com/docs/ai-naver-clovastudio-summary), [구조화 출력 지원](https://api.ncloud-docs.com/docs/clovastudio-chatcompletionsv3-so).

## 4. 먼저 연결만 검사

1. **연결 테스트 (API 호출)**를 누른다.
2. 앱은 짧은 합성 요청을 한 번 보낸다. 열린 문서, workspace 대화, 선택 자료는 전송하지 않는다. 이 버튼은 실제 API를 호출하므로 사용량이 발생할 수 있다.
3. “연결 테스트 성공”을 확인한다. 이 결과는 인증·연결·기본 JSON 응답 계약 확인이다. 실제 문서 작업 품질까지 통과한 것은 아니다.
4. 키 입력창은 테스트 후 비워진다. 같은 키를 다시 입력하고 **연결 등록**을 눌러 설정을 저장한다.
5. 채팅 상단에서 방금 등록한 연결과 모델을 선택한다.

연결 테스트는 입력한 키를 지속 보관하지 않는다. 연결 등록은 프로세스 메모리에만 키를 보관하며, 등록 자체로 API를 호출하지 않는다. 로컬 서버를 다시 시작하면 같은 연결의 키를 재입력한다. 창만 닫으면 서버가 계속 실행될 수 있다. **연결 키 삭제**는 실행 중인 서버의 등록 키 전체를 지운다.

## 5. 실제 편집 검수 순서

개발 계정 검수에는 합성 문서를 사용한다. 기관 자료를 개발 클라우드로 전송하는 절차로 해석하지 않는다.

1. 새 workspace와 채팅을 만들고 새 문서를 연다.
2. “가상의 주민 교육 계획서 초안을 제목, 목적, 일정, 기대 효과의 네 문단으로 작성해줘”라고 요청한다.
3. 오른쪽 문서가 실제로 작성되고 실행 상태가 완료인지 확인한다.
4. “목적 문단을 두 문장으로 바꾸고, 마지막에 문의 안내 문단을 추가해줘”라고 요청한다.
5. 변경 내용 보기에서 비교하고, 요청 되돌리기로 원래 내용을 복원한다.
6. 사용자가 직접 한 문장을 고친 뒤 후속 요청에서 미저장 내용이 반영되는지 확인한다.
7. 가상의 `참고.txt`를 명시적으로 선택해 요청하고 자료 범위/출처를 확인한다.
8. HWP와 HWPX로 각각 저장하여 실제 한글에서 열기·내용·문단 경계·서식·재저장을 확인한다.

AI 표/서식/개체/쪽 설정과 자동 저장은 미지원이다. 기존 본문 중 표 내부·필드·컨트롤·복합 서식 등은 편집 가능 판정에 따라 제한된다. 출력이 많으면 요청을 나눈다. 길이 제한에 걸린 결과는 적용하지 않으며 자동으로 재요청하지 않는다.

검수 기록에는 날짜, 모델 ID, 합성 입력, 앱의 변경 결과와 오류만 남긴다. 키나 원격 오류 원문은 남기지 않는다. [수용 검사표](mvp-acceptance-results.csv)의 실제 LLM 관문도 이 결과를 얻은 후 갱신한다.

## 6. 연결 오류 해결

| 표시/증상 | 확인할 사항 |
| --- | --- |
| 인증 또는 모델 권한 오류 | CLOVA Studio 테스트 키인지, 복사 누락·키 삭제 여부, 계정의 모델 권한 |
| 모델 설정 오류 | native 방식은 HCX-007만 지원. 다른 모델을 이름만 바꾸어 지원한다고 보지 않음 |
| HTTP 400/404 등 | endpoint 경로와 API 계열, 모델 지원을 공식 문서와 대조 |
| 호출 한도 | 콘솔 사용량·한도 확인 후 직접 재요청. 앱은 자동 반복하지 않음 |
| 연결/시간 제한 오류 | 네트워크·프록시·인증서 확인. TLS 검증을 끄지 않음 |
| 출력 토큰 한도 | 짧은 작업으로 나누거나 출력 상한을 조절. 이번 앱은 128~8192 범위 |
| JSON 계약 확인 실패 | 자유문장/미지원 schema/응답 형태 문제. 연결 성공으로 기록하지 않음 |
| 화면에 HyperCLOVA 선택지가 없음 | 최신 묶음인지 확인하고 저장 후 로컬 서버와 앱을 재시작 |
| 새 화면인데 서버가 설정을 거부함 | 예전 로컬 서버 프로세스가 계속 실행 중인지 확인 |

최신 소스를 빌드해도 이미 실행 중인 Node 서버는 메모리의 이전 코드를 유지한다. 시작 스크립트는 같은 포트의 서버를 재사용한다. 변경 문서를 저장한 뒤 작업 관리자에서 **해당 Jueony 서버**만 종료하고 Start-Jueony.cmd로 다시 연다. 모든 Node/브라우저 프로세스를 일괄 종료하지 않는다.

## 7. 다른 CLOVA 연결 방식과 기관망

CLOVA Studio는 OpenAI 호환 경로도 제공한다. 기존 호환 adapter의 endpoint는 `https://clovastudio.stream.ntruss.com/v1/openai`로 설정할 수 있다. 그 경로는 이번 native 방식과 요청/응답 규격이 다르며, 현재 호환 adapter는 schema 강제 기능을 보내지 않는다. 전용 연결 실패 시 자동 우회하지 않는다. [공식 호환 규격](https://api.ncloud-docs.com/docs/clovastudio-openaicompatibility).

일반용 개발 계정 연결이 성공해도 기관망 배포 검증이 끝난 것은 아니다. 공공용은 별도 콘솔·endpoint·키·권한을 확인해야 한다. 기관 내부 gateway/전용망 모델은 실제 계약 규격을 확인한 뒤 연결한다. 일반용 키와 호스트를 공공용에 자동 재사용하지 않는다. 참고: [공공용 API 안내](https://api-gov.ncloud-docs.com/docs/clovastudio-overview).

문서 열기·편집·저장은 로컬 기능이지만 이번 일반 클라우드 AI 호출에는 해당 서버로의 네트워크 연결이 필요하다. 현재 앱은 사용자가 설정한 endpoint로 전송하고 redirect를 거부한다. 기관 관리자의 호스트 allowlist·인증서 배포·키 영구 암호화 정책은 별도 후속 작업이다.

## 8. 구현·검증 근거와 남은 일

- 구현: native v3 adapter, 4종 편집 명령용 schema, 설정 UI, 출력 토큰 상한, 합성 연결 테스트, 정제 오류, 취소/크기/종료 상태 검사.
- 계정 없이 검증: 로컬 protocol fixture와 실제 rhwp 편집 엔진으로 생성·여러 위치 변경·undo·저장 경로.
- 아직 검증하지 않음: 실제 NAVER 인증/요금/모델 출력, 클라우드의 schema 수용, 실제 한글 재열기.
- 검증 결과와 실행 명령은 [검증 기록](evidence/llm-adapters-2026-10-11/README.md)에 기록한다.
- 네 제공자의 전체 개발 작업은 [adapter 구현 명세](13-llm-provider-adapters.md)를 따른다.

다음 사용자 작업은 **테스트 API 키 발급 → 앱의 연결 테스트 → 연결 등록 → 합성 문서 요청**이다. 키를 개발자나 이 채팅에 전달할 필요가 없다.
