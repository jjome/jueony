# 기능별 미완료 작업 진행 기록

2026-11-21. [기능별 진행 현황](jueony-progress.md)의 세 축을 기준으로 코드, 실행 검사, 실제 Agent 명령과의 연결을 확인한다. 구현 범위와 근거는 [작업표 원본](jueony-work-checklist.csv)에 기록한다.

## 자료의 근거 위치

N034에서 HWP와 HWPX의 일반 본문 및 평면 표의 문단·셀을 Unicode 추출문과 대조한다. 추출문 전체가 엔진에서 확인한 순서와 일치할 때만 정확한 주소를 표시한다. XLSX의 보이는 시트에서는 주소를 값과 함께 기록한다. 검색과 조회 도구는 제공하는 구간에 온전히 포함된 주소만 전달한다.

AI 응답의 **자료 범위와 출처**에서 한글 문단 또는 셀을 고르면 연결 자료의 업무, 첨부한 채팅, 원본 SHA-256을 다시 확인한다. 디스크에서 확인한 자료는 인용한 바이트의 확인용 사본을 열고, 미저장 자료는 같은 버전의 열린 탭에서 이동한다. Chrome에서 모의 모델이 총액과 단위를 인용한 뒤 2행 2열로 직접 이동한 것을 확인했다. HWP와 HWPX에서 동일한 수치가 여러 평면 표 셀에 있는 경우 각 셀의 위치를 검증했다.

일반 중첩 표에서는 추출문과 엔진의 정확한 검색 결과가 한 위치로 일치할 때 바깥 셀과 안쪽 셀 주소를 전한다. 같은 안쪽 표에서 문단 전체가 동일한 값이면 추출문과 실제 검색 건수를 대조하고 셀의 저장 순서대로 각각 연결한다. HWP와 HWPX에서 같은 값 두 건을 각각 다른 좌표에 연결했고, 바깥 본문과 표에 걸친 동일 값은 추출문 줄 번호를 유지했다. Chrome에서 같은 금액 두 건을 각각 선택해 중첩 표의 2행 1열과 2행 2열로 이동했고 원본 바이트도 확인했다. 필드나 다른 개체가 함께 있는 복합 자료도 출처의 추출문을 사용한다. Chrome에서 Excel 출처의 **예산 · C2**를 골라 파일과 시트의 저장값 `12500`을 확인했다. Excel 확인 화면은 원본 SHA-256이 일치하는 표시 시트의 저장값을 읽는다.

N034와 G126에서 Excel 시트 이름과 셀 주소를 함께 지정한 읽기 전용 요청을 검증했다. 합성 파일의 예산 시트와 결산 시트는 모두 C2가 있었고 저장값은 각각 `12500`, `9999`였다. 로컬 Qwen3.5가 **예산 시트 C2**의 조회를 요청했고, Jueony는 일치하는 셀 하나의 저장값과 출처를 채팅에 표시했다.

PDF는 실제 파일의 쪽 번호를, Word는 표 셀을 포함해 본문 XML 순서의 문단 번호를 추출문 위치에 연결한다. Chrome에서 로컬 Qwen3.5가 **PDF 1쪽**과 **Word 본문 3문단**을 조회했다. 각 위치에 하나의 완전한 근거가 확인된 경우 Jueony가 추출문을 그대로 채팅에 표시했다. 출처를 눌러 원본의 해시를 다시 확인하고 같은 쪽·문단을 열었다. PDF·Word·Excel 원본과 현재 편집 문서가 유지됐다. 복합 문서의 OCR·읽기 순서 품질과 운영 모델 검증은 남았다.

## 기존 표 반복 작업

N005의 임의 셀 분할을 최신 Chrome에서 55건 검증했다. HWP와 HWPX에서 기본 셀, 중첩 표, 이름이 있는 문단, 지원하는 누름틀과 캡션, 여러 쪽으로 이어지는 셀을 나눴다. 실제 채팅과 저장·재열기, 요청별 되돌리기·다시 실행을 확인했다. 무효한 격자나 대상, 보호된 셀과 소유자를 식별할 수 없는 일부 필드는 변경 전에 거절했다. 검수용 로컬 응답으로 4가지 모델 연결을 거쳤으며 독립 한글 비교는 남았다.

N038에서 완료한 AI 요청 중 기존 평면 표의 셀 내용·서식과 행·열 추가·삭제를 반복 작업으로 저장할 수 있다. 실행할 때 대상 표를 고르고 변수를 입력한다. 기록한 표와 대상의 원문·서식·격자를 대조하며, 편집 권한과 저장 보존 검사는 기존 문서 명령을 사용한다. 문서가 설정창을 연 뒤 바뀌면 재확인하도록 안내한다.

Chrome에서 AI가 만든 셀 변경을 기록하고 기존 변경을 되돌린 뒤 새 변수값으로 재실행해 HWPX에 저장·재열기했다. 중첩되어도 해당 표의 격자·본문·서식을 확인할 수 있으면 일반 셀 값과 지원되는 단독 행·열 변경을 기록할 수 있다. Chrome에서 내부 표의 행을 새 변수로 추가한 뒤 재열어 바깥 셀을 대조했다. HWP와 HWPX에서 중첩 행·열 명령, 두 단계 중첩 셀 값 변경, 다른 계층의 표 거절 및 원본 복원을 확인했다.

Chrome에서 AI로 일반 본문의 잠금이 없는 단독 도형 한 개의 단색 채우기를 바꾸고 변경 내용을 확인했다. 그 명령을 반복 작업에 저장해 되돌린 뒤 같은 속성의 도형을 선택해 재실행하고 다시 열었다. 네이티브 HWP·HWPX에서 다른 도형과 속성의 보존, 다른 대상 거절 및 한 번 되돌리기를 확인했다. 병합·보호 표의 반복 실행, 그림·복합 도형과 기타 개체 조작은 후속 범위다.

## 수동 편집 기록

N039에서 **반복 작업 → 문단 정렬 기록**을 시작하고 일반 본문의 왼쪽·가운데·오른쪽·양쪽·배분 정렬을 기록한다. Chrome에서 실제 Ctrl+Shift+C 입력과 다른 정렬 명령이 각각 한 번씩 기록되는 것을 확인했다. 기록은 현재 업무에 저장한다. 저장 기록과 내보낸 JSON에는 시작 문서의 SHA-256과 문단 위치·해시를 넣는다. 같은 바이트로 다시 연 문서에서 **현재 문서에 불러오기** 또는 **JSON 가져오기**를 사용한다. Chrome에서 화면을 닫고 다시 띄운 뒤 업무에 저장된 기록을 불러왔다. 다른 문서와 파일 저장 명령을 거절했고, 일치하는 원본에서 정렬 두 건을 재생한 뒤 한 번에 되돌렸다.

불러온 정렬 기록을 **채팅으로 요청**에서 확인하고 보낼 수 있다. 모델에는 기록된 정렬 명령과 문단 ID를 보내며 원문과 파일명, 자료 및 이전 대화는 제외한다. 모의 모델이 정렬 하나를 바꾸자 문서에 적용하지 않았고, 같은 순서의 정확한 명령을 돌려받은 경우 Chrome에서 재생하고 한 번에 되돌렸다.

2026-11-22. **반복 작업 → 수동 편집 기록**에서 일반 본문의 키 입력과 삭제, 같은 문단의 선택 글자 교체, 확정된 한글 조합을 정렬과 함께 기록한다. 한 문단에서 이어진 입력은 시작 원문과 최종 결과를 대조해 저장할 편집 한 건으로 재생한다. 내보낸 JSON에는 재생할 입력 문자열이 들어간다. AI 채팅은 문단 ID와 편집 범위, 입력값 표식만 받아 정확한 순서와 값을 돌려준다. 실제 문자열은 편집기에서 적용한다.

Chrome에서 HWP와 HWPX의 실제 입력, 선택 교체, 중간 한글 조합을 제외한 최종 글자 기록을 검증했다. HWP는 내보낸 JSON을 가져왔고 HWPX는 업무를 다시 열어 저장된 기록을 불러왔다. 모의 모델이 입력값 표식을 바꾸면 원본 바이트가 유지됐다. 일반 편집 지시와 분리한 짧은 매크로 요청으로 로컬 Qwen3.5 0.8B에서도 두 형식의 기록을 재생했다. 모델에 보낸 요청에서 원문과 입력 문자열이 빠졌는지 확인했고, 저장한 파일을 다시 읽고 한 번 되돌린 뒤 원본을 대조했다. 여러 문단을 가로지르는 삭제는 매크로 기록을 취소하며 일반 되돌리기를 지원한다. 개체·특수 영역과 문단 구조 편집 기록, 운영 모델 및 독립 한글 비교는 남았다.

## 장문 문서 조회

N030에서 **문서·자료 조회 도구**를 켜면 12만 자 또는 1,000문단을 넘는 문서를 나누어 조회한다. 처음에는 구역별 문단 수만 보내고, 한 번에 문단 ID 40개 또는 본문 4,000자를 반환한다. 문단 응답에 남은 범위를 표시하고, 사용자가 문서를 바꾸거나 편집하는 동안 도착한 조회 응답은 거절한다. 일반 문서에서도 읽은 글자 범위를 벗어난 최종 편집을 차단한다.

Chrome에서 12만 자가 넘는 36문단 HWPX의 전체 본문을 먼저 보내지 않고 마지막 문단의 확인일을 읽었다. 모의 모델 세 번 호출과 문서 바이트를 확인했다. **이 요청에서 조회한 본문 편집**을 선택하면 직접 읽어 편집 가능으로 확인된 본문 문단의 범위를 한 번 바꿀 수 있다. Chrome에서 조회하지 않은 날짜의 변경을 거절하고, 조회한 제목만 바꿔 저장·재열기한 뒤 한 번에 되돌렸다. 보호·복합 문단은 읽기용이며 편집용으로 재검사할 수 있는 본문 한도는 120만 자다.

로컬 Qwen3.5에서 Unicode 추출문 기준 122,595자인 HWPX를 열었다. 초기 요청의 본문 문단은 0개였다. 처음에는 확인되지 않은 출처를 제안하거나 문단 주소를 여러 번 잘못 요청했다. 장문 조회에 첫·마지막 문단 주소를 제공하고 문단 전체를 요청하는 읽기용 안내를 보냈다. 문단 번호를 명시하지 않은 질문에도 마지막 문단을 읽어 **2039년 02월 17일**을 답했다. 검사에서 문서 바이트가 일치했다. 여러 유형의 장문 질문과 복합 문단을 운영 모델에서 확인하는 일은 남았다.

N032에서 허용된 조회의 인자가 잘못되면 한 번 바로잡을 수 있는 응답을 돌려준다. 두 번 연속 실패하거나 등록되지 않은 도구를 요청하면 중단한다. 이미 성공한 조회를 다시 요청하면 기존 결과를 사용한 읽기 전용 답변을 요청한다. 일반 본문에서 연속해 읽은 구간은 사용자가 편집을 선택했을 때 한 수정 범위로 사용할 수 있다. 테스트에서 잘못된 문단 범위를 응답받은 모의 모델이 정확한 범위로 다시 읽었다.

읽기 전용 요청의 첫 모델 응답이 조회하지 않은 자료를 인용하면, 그 답변과 출처를 보내지 않고 확인된 근거를 조회하도록 한 번 다시 요청한다. 기존 네 번의 모델 호출 한도 안에서 진행하며, 두 번째 응답도 확인되지 않은 출처를 인용하면 차단한다. Chrome에서 첫 잘못된 출처를 건너뛰고 마지막 문단을 실제로 읽는 네 번의 호출과 원본 바이트를 검사했다.

N033의 자료 조회는 전각 숫자와 분해된 한글도 찾아 원래 글자 범위와 셀 주소를 돌려준다. 한국어 색인 모드에서 현행 기준을 묻는 경우 같은 폴더의 문서군을 명시된 시행일이나 적용 시작일로 비교한다. 이미 시행된 최신 판을 우선하고 폐기·초안이라고 명시된 자료는 순위를 낮춘다. 과거 판이나 초안을 요청하면 해당 상태를 우선한다. 시행일 누락·동률처럼 판본을 고를 근거가 부족한 경우 시행일 가중치를 적용하지 않는다.

총예산과 착수·완료일 요청에서는 해당 값이 담긴 예산서와 일정표를 우선한다. 날짜를 지정한 회의는 문서 제목에 있는 날짜를 비교한다. 질문에서 구체적으로 지목한 사업을 선택한 자료에서 찾지 못하면 검색 결과에 본문을 전달하지 않는다. 같은 합성 21파일에서 BM25의 첫 출처 적중은 12/18에서 18/18로, 무답 질문에 자료를 보낸 건수는 1/4에서 0/4로 바뀌었다. 상위 8개 출처 안에 정답이 포함된 비율은 18/18이었다. Chrome에서 현행 예산·착수일·특정 회의록이 첫 자료로 전달되고 다른 사업의 미선택 자료가 전달되지 않는 것을 확인했다. 이 평가는 합성 자료의 검색 결과 범위이며 운영 모델의 인용과 무답 검증은 남았다.

## 저장 글자 스타일과 자료 권한 해제

N012에서 AI가 현재 문서의 저장 글자 스타일 이름과 ID를 조회하고 일반 본문의 일부에 적용한다. 문단의 원문과 글자 위치, 저장 스타일 정의를 적용 직전에 재검사하며 변경 확인에 적용한 스타일과 정확한 글자 범위를 표시한다. HWP와 HWPX에서 글자 모양과 원문 보존, 재열기 및 단일 되돌리기를 검사했다. 전체 앱에서는 로컬 모의 모델이 `가😀나다라` 중 `😀나`에만 업무 강조 스타일을 적용했고, 저장한 HWPX를 다시 열어 확인했다. 보호 영역이나 특수 영역, 독립 한글의 재열기는 별도 검증 범위다.

## 스타일마당과 표·구역 서식 재검증

저장 높이·너비, 기본 탭, 바탕쪽을 AI 변경 내역에 다시 표시했다. 설치에 포함된 글꼴은 그대로 사용하고, 빌드에서 제거된 외부 글꼴 주소는 읽기 후보에서 제외했다. 로컬 모의 GPT Responses, Claude, Gemini, OpenAI 호환 서버를 사용한 Chrome 검사에서 HWPX 셀 너비 15건, 행 높이 14건, 구역 서식과 줄 번호 10건, 바탕쪽 11건이 통과했다. 네 묶음 모두 페이지 오류, 콘솔 오류, 외부 요청이 0건이었다.

G042에서 HWP의 일반 본문 표에도 AI 열 너비와 행 높이 편집을 연결했다. 전체 행에 걸친 열이나 전체 열에 걸친 행을 균등하게 맞추거나 지정한 밀리미터 값으로 바꾼다. HWP로 다시 저장할 때 문서 전체의 내용과 배치, 수정한 표의 셀과 글줄 위치를 확인한다. Chrome에서 HWP의 균등 변경과 직접 지정 각각을 검증하고, 한 번 되돌린 바이트와 다시 실행한 뒤 저장한 표를 대조했다. 보호·병합·혼합 서식 원본과 내용이 넘치는 높이 변경은 거절했다.

표가 하나이고 열 전체 또는 행 전체를 같게 해 달라는 단독 요청에는 로컬 모델로 검증된 대상과 범위만 보낸다. 로컬 Qwen3.5 0.8B로 Chrome 채팅에서 두 요청을 각각 실행하고 저장한 HWP를 다시 열었다. 모델이 다른 범위를 반환하거나 다른 편집을 더한 경우 적용을 거절한다. 여러 표·참고자료·별도 명령이 함께 있는 요청은 기존 채팅 경로를 사용한다. 독립 한글과 운영 모델 비교는 남았다.

## 비정상 종료와 복구

N044에서 앱이 자동 저장하거나 문서를 닫을 때, 마지막으로 읽거나 저장한 복구본의 식별자를 저장소에서 확인한다. 그 뒤에 기록된 복구본이 있으면 저장이나 삭제를 멈추고 열린 문서를 유지한다. 기존 복구본은 처음 열 때 내용과 무결성 정보를 보존하며 식별자를 부여한다. 창 전체를 종료할 때는 여러 복구본의 쓰기와 폐기를 한 번에 처리하고, 도중에 실패하면 기존 기록을 남긴다.

격리된 Chrome을 강제 종료한 뒤 HWP와 HWPX의 미저장 편집을 복구하고 원본 바이트를 대조했다. 종료 확인 12건과 문서 닫기 4건을 검증했다. AI 문서 작업 15건에서는 탭 닫기 중 최신 복구본이 발견되면 탭을 유지하고, 승인된 HWP·HWPX 원본 저장은 재읽기까지 확인했다. Windows 고정 WebView2에서도 실제 브라우저 프로세스를 강제 종료한 뒤 같은 HWPX 복구본의 바이트를 확인했다. Windows 설치 앱 검수본은 MSVC 링커 `link.exe`가 없어 빌드가 멈췄다. 설치 앱의 실제 창 종료와 운영체제 전체 장애는 별도 검증 범위다. [복구 검증 기록](106-recovery-integrity.md)

N018에서 같은 실행 중의 되돌리기·다시 실행 이력과 새 프로세스의 이력을 비교했다. Chrome 프로세스를 다시 시작하면 HWP·HWPX의 문서는 복구되고 새 편집기의 되돌리기와 다시 실행 기록은 비어 있다. 저장을 위해 계산된 표 높이가 직전 AI 명령에 함께 기록된 경우, 파일을 다시 읽어 일치함을 확인한 뒤에만 이전 요청의 되돌리기를 연결한다. HWP·HWPX에서 저장 취소 뒤 요청별 되돌리기를 거절하고 같은 문서의 재저장 후 한 번에 되돌리거나 다시 실행했다. 브라우저 다운로드는 사용자 확인을 쓰며, 되돌리기는 일반 편집 메뉴에서 한다. 그 외 편집 명령의 이력 수명과 독립 한글 비교는 남았다.

N014에서 HWP·HWPX의 일반 글상자 커서, 정방향·역방향 범위, 회전 글상자와 탭 전환을 실제 Chrome에서 검증했다. 한글 조합을 확정한 뒤 화면을 다시 열어 글상자 본문과 미저장 상태, Unicode 커서를 대조했다. 캡션과 보호 영역 등 일반 글상자와 다른 소유자는 이 복원 경로에서 거절한다. N016에서는 엔진이 문서에 필드가 없다고 확인하면 일반 중첩 셀의 텍스트 범위를 기존 복원 경로로 전달한다. 기존 필드 보호와 미주 복원도 함께 검사했다. 복합 필드와 독립 한글 비교는 남았다.

N015에서 본문의 수식 한 개 또는 수식과 문서에 포함된 그림을 함께 선택했을 때 업무를 다시 열면 선택 순서와 활성 개체를 복원한다. Chrome의 HWP·HWPX 네 가지 검사에서 저장한 선택, 재열기 뒤 실제 선택, 문서 바이트 보존, 채팅의 키보드 포커스를 대조했다. 본문이 바뀌면 이전 선택을 거절한다. 기존 그룹과 바깥 도형 복원은 네이티브 엔진에서도 검증했다. 보호·캡션·중첩 개체와 복합 그룹의 별도 화면 비교는 남았다.

N023은 Chrome의 배율·좁은 화면 등 6건을 다시 통과했다. 이 검사는 브라우저에서 배율과 뷰포트를 조절한다. Windows 디스플레이 설정과 복수 모니터 좌표에서의 동작 비교는 별도 범위다.

N043에서는 실제 Windows 파일에 대한 저장·교체 검증 11건을 통과했다. HWP·HWPX와 합성 HWT를 사용해 읽기 전용, 독점 잠금, 교체 차단, 외부 수정 감지와 사본 보존을 확인했다. Windows 설치 앱의 파일 선택창과 조직의 파일 권한 환경은 별도 범위다.

## 공문 본문 초안과 화면 구조

N040에서 기본 업무 양식의 빈 본문 항목에 AI 제안을 받을 수 있다. 사용자가 그 자리에서 입력한 메모와 빈 본문 항목 이름을 선택한 모델로 보낸다. Chrome에서 허용 밖 문단 서식 제안을 거절했고, 사용자가 이미 채운 본문을 보존하고 확인한 초안만 별도 HWPX 사본에 넣었다.

편집기 **기관 양식**에서 기관이 제공한 HWP·HWPX 파일을 선택한다. 일반 본문과 단순 표에서 `{{항목}}`에 값을 채운다. `{{본문:항목}}`을 사용한 빈 항목에는 확인한 문장 초안을 제안받을 수 있다. 앱은 파일명·양식 원문·이미 입력한 값을 제외하고 본문 항목 이름과 메모만 AI에 보낸다. HWP·HWPX 사본에서 용지와 스타일, 표 및 원본 파일의 바이트를 대조했다. Chrome에서 사용자 양식의 AI 제안을 확인해 새 HWPX 사본으로 열었다.

**반복 작업 → 문서 검토 묶음**에서 현재 문서, 선택한 붙임과 검토 메모를 초안 ZIP으로 다운로드한다. 문서와 붙임의 바이트 수와 SHA-256을 묶음에 기록한다. Chrome이 실제로 받은 ZIP을 다시 열어 HWPX 본문과 붙임 원본의 일치를 확인했다. 기관 결재 시스템과 장기 보존소의 통합은 남았다.

N017에서 새 편집기가 시작될 때 현재 사용자 프로필의 기본 용지와 글자 설정을 읽기 전용으로 가져온다. Chrome에서 저장한 220mm 너비가 새 탭에 적용됐다. 스타일 창과 리본을 다시 열고 환경 JSON을 가져왔으며, 쓰기 실패와 미래 버전에서도 저장된 값이 유지되는 것을 확인했다. 보기 설정 8건과 언어별 글꼴 설정 9건을 검사했다. 대표 글꼴의 일곱 언어 설정은 HWP·HWPX 저장과 재열기에서 대조했다. 실제 한글의 기본값 비교는 남았다.

## 로컬 검증과 별도 환경

복원한 Windows 실행 환경에서 같은 엔진·자료로 회귀를 반복한다. 독립 한글 2024와 실물 출력, 실제 운영 모델과 기관망, 기관 서명 설치 패키지는 각각 실제 환경에서 확인한다. 모의 모델과 같은 엔진의 저장 재열기 결과는 해당 항목의 자동 검증 근거로 기록한다.

2026-11-22에 별도 Windows 실행 묶음에서 포함된 Node 24.22.3으로 편집기를 시작했다. 새 구역 검사에서 네이티브 엔진 14건과 Chrome 15건이 통과했다. Chrome은 묶음에 포함된 실행기에서 네 가지 공급자 방식의 모의 응답을 사용했다. 같은 편집기 빌드의 전체 Chrome 검사에서 장문 조회·편집, 인용, 반복 작업과 HWPX 사본도 확인했다. 편집기 2,046건과 실행기 72건이 통과했고, 패치 없는 엔진용 검사 1건이 제외됐다. 기관용 오프라인 빌드는 고정 WebView2에서 HWPX 셀을 읽고 승인 주소가 없는 외부 모델 요청을 차단했다.

N043의 격리된 Windows 개발판에서 실제 운영체제 파일 선택창으로 합성 HWP와 HWPX를 각각 열고 다른 이름으로 저장했다. 두 원본의 SHA-256이 유지됐고 HWP 사본은 원본과 바이트가 일치했다. HWPX 사본은 바이트에 차이가 있었으며 독립 ZIP/XML 본문 확인과 엔진의 보존 항목 34개 대조를 통과했다. 설치본 배포와 기관 계정의 파일 권한 검증은 남았다.

같은 Windows 개발판에서 열어 둔 HWPX를 별도 프로세스로 바꾼 뒤 편집기에서 저장을 눌렀다. 저장이 거절되면서 편집 내용이 열린 문서에 남았고, 다른 이름으로 저장한 사본의 XML에서는 그 편집 내용을 읽을 수 있었다. 외부에서 바꾼 디스크 원본의 SHA-256은 두 저장 시도 이후에도 같았다. 이 개발판은 저장 미완료를 알렸다. [검증 기록](evidence/checklist-completion-2026-11-21/manifest.json)
