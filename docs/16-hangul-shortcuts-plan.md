# 한글 2024 단축키 구현과 검증

작성일: 2026-10-11. 사용자 승인으로 구현 착수. [전체 AI 제어 계획](15-ai-editor-control-plan.md)의 공통 명령 계층과 함께 진행한다.

1차 결과: K01/K02의 공통 매핑·연속키·포커스 경계를 구현하고 K03/K04/K06 일부를 연결했다. `Ctrl+Y`, `Alt+Shift+C`, 글자색 연속키, 글자/표 대화상자, `Ctrl+PageUp/PageDown`을 실제 Edge 입력으로 검사했다. 단위 6개와 브라우저 9개 검사가 통과했다. `Ctrl+N,T`도 브라우저 키 입력으로 동작했으며 실제 Windows 물리 키/IME 및 네이티브 호스트 K05 검수는 남아 있다. [구현 기록](17-editor-control-implementation.md)에 미지원 범위를 명시한다.

## 기준과 사용자 경험

한글 2024 Windows의 기본 한/글 매핑을 따른다. 한/워드·한/쇼 또는 Office 호환 테마의 키를 혼합하지 않는다. 사용자가 익힌 키가 같은 기능을 실행하는 것이 목표다. 메뉴·도구 상자·도움말의 표시도 같은 목록에서 만든다.

공식 기준은 [단축키 일람](https://help.hancom.com/hoffice130/ko-KR/Hwp/view/toolbar/shortcut(table).htm), [파일 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/file.htm), [편집 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/edit.htm), [표 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/table.htm), [글자 속성](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/font/fonts(font_style).htm)이다. 설명문과 화면 자산을 복제하지 않고 기능과 키 대응을 구현한다.

현재 upstream에는 다음과 같은 차이가 있어 교정한다.

- Ctrl+Y는 한 줄 지우기다. 기존 redo 연결을 제거한다.
- Alt+Shift+C는 보통 모양이다. 기존 가운데 정렬 연결을 제거한다.
- Ctrl+N 계열은 표·각주·수식 등 삽입, Ctrl+M 계열은 글자색에 사용한다.
- Alt+O/Alt+S/Alt+V/Alt+P는 열기/저장/다른 이름/인쇄에 연결한다. Ctrl+O는 문서 끼워 넣기이므로 열기로 처리하지 않는다.
- 셀 블록에서 문자키와 계산 단축키는 해당 문맥에서만 작동한다. 본문에 같은 글자를 입력하는 동작을 막지 않는다.

## 작업 목록

| 작업 | 산출물 | 완료 조건 |
| --- | --- | --- |
| K00 | 공식 키·문맥·command·지원 상태 목록 | 미구현과 브라우저 충돌 포함; 다른 기능 오연결 없음 |
| K01 | 물리 키 기반 resolver와 연속키 상태 | 한영 입력 상태 일치; Ctrl/Alt/Shift 정확 비교; Escape·blur·만료·반복키 처리 |
| K02 | 현재 편집기 dispatcher 연결 | 수동 UI와 동일한 실행/undo; 채팅·대화상자 입력은 자기 키 유지 |
| K03 | 누락 기본 편집 기능 보강 | 줄/단어 삭제·글자 속성/색·문맥별 명령 실제 변화 확인 |
| K04 | 셀·개체·탐색·선택 키 호환성 | F3/F5/Tab/이동 키·문맥별 중복 키를 실제 엔진에서 검사 |
| K05 | Windows 호스트의 예약키 전달 | Ctrl+N 등 실제 물리 키가 활성 문서로 전달되고 브라우저 창이 열리지 않음 |
| K06 | 지원 목록 UI와 회귀·IME·저장 검사 | 표시와 동작 일치; HWP/HWPX undo와 재열기; 한글 대조 결과 별도 기록 |

## 이벤트 처리 조건

키는 현재 포커스가 속한 편집기에서만 처리한다. 검색/파일 이름/AI 채팅/대화상자 입력 중에는 문서 단축키가 문서를 바꾸면 안 된다. 셀 블록·개체 선택의 문자키는 일반 본문 입력과 구분한다. 모델 작업으로 편집기가 잠긴 동안에는 단축키 쓰기도 막는다.

연속키는 첫 조합 후 두 번째 키를 처리한다. 대기 상태를 화면에 표시하고 Escape·포커스 이동·정해진 유효 시간 뒤 해제한다. modifier를 놓는 것은 취소가 아니다. 반복 keydown으로 대화상자나 문서를 여러 개 만들지 않는다. 한글 조합 중 명령은 미완성 글자를 잃지 않도록 보호하고 실제 Windows IME 검수를 별도 수행한다.

등록만 된 stub는 실행 성공으로 표시하지 않는다. 미지원 키를 눌렀을 때 다른 기능이 대신 실행되어서는 안 된다. 현재 문맥에서 불가능한 명령은 설명하고 원본 내용을 보존한다. 클립보드·파일 대화상자는 OS 권한과 사용자 활성화 조건을 유지한다.

## 호스트와 검증

브라우저/앱 창에서 모든 OS 예약키를 JavaScript로 가로챌 수 있다고 가정하지 않는다. 키 이벤트 단위 테스트, 실제 Edge/Chrome 키 입력, Windows 데스크톱 호스트를 분리한다. 네이티브 연결 전에는 해당 조합을 제한으로 표시하고 원래 한글 매핑을 유지한다. 다른 기능의 키로 재배정하여 호환된 것으로 보고하지 않는다.

검사 항목: 한영 물리 키 일치, 연속키 성공/만료/취소/잘못된 두 번째 키, 선택 영역·셀·개체 문맥, 조합 시작/종료, 채팅/검색 입력 보호, 메뉴 라벨 일치, 단일 history 기록, undo/redo, 읽기 전용 문서, 적용 중 잠금, 두 문서 탭, 실제 예약키 전달, 저장·재열기. 단순 키 dispatch 테스트를 Windows IME 또는 실제 한글 검수 통과로 표시하지 않는다.
