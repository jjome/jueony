# Agent 입력 무반응과 새 문서 작성 실패 수정

2026-10-11. 사용자의 ‘반응이 없다’는 보고에 따라 실제 앱 화면의 입력 경로와 자연어 초안 작성을 다시 검사했다. 이전 표·서식 검사만으로 새 문서 작성 경로까지 정상이라고 판단할 수 없었다. 사용자가 입력했던 정확한 문장은 확인되지 않았으므로 아래 재현이 모든 사용자 증상의 원인이라고 단정하지 않는다.

## 재현한 문제

1. 입력창에서 Enter는 전송 대신 줄바꿈만 했다. 화면에서 키 안내도 없었다.
2. ‘새 회의 안내문을 작성해줘’라는 요청을 보내기 버튼으로 전송하면 실제 HCX-005가 같은 `s0p0` 뒤에 제목·일시·장소를 각각 삽입하는 명령 3개를 반환했다. HTTP 응답은 성공했지만 앱의 중복 대상 검증이 거절해 문서는 그대로였다. [수정 전 기록](evidence/agent-interaction-2026-10-11/before.json)
3. 모델 미설정 등의 전송 전 오류는 상단 상태줄에만 표시되어 입력창 근처에서는 알아보기 어려웠다.

## 수정

- Enter로 전송하고 Shift+Enter로 줄바꿈한다. 한글 조합 상태·`isComposing`·IME의 229 키 코드에서는 전송하지 않는다. 입력창 아래에 사용 방법을 표시한다.
- 새 초안은 `create_document` 하나의 문단 배열로 제출하도록 제공자 지침을 명확하게 했다. 예시는 특정 제목·날짜에 의존하지 않는다.
- 같은 위치의 **연속 삽입 명령**은 모델이 반환한 순서대로 한 배열에 묶어 적용한다. 원문을 추측하거나 문구를 바꾸지 않는다. 모든 원래 명령의 속성·문단 유효성을 검사한 뒤 기존 대상·길이·revision 검사를 수행한다.
- 한 문단의 본문 변경 1개와 그 뒤 문단 삽입 1개는 함께 실행할 수 있다. 같은 본문을 두 번 수정하거나 중간에 다른 명령이 끼어든 동일 위치 재삽입은 계속 거절한다.
- 채팅에 ‘모델 응답 대기 / 명령 검증 / 문서 적용’ 진행 항목을 표시하고, 오류는 입력창 아래에도 표시한다. 문서 준비 중 전송도 무반응 대신 안내한다.
- 자동 모델 재시도·자율 반복 실행은 추가하지 않았다.

## 실제 검사

현재 `http://127.0.0.1:4173/` 서버에 별도 Edge 프로필로 접속했다. 저장된 HCX-005 연결을 자동으로 불러온 상태에서 합성 요청을 채팅 입력창에 입력했다. 사용자 기존 workspace·문서를 수정하지 않았다. 서버 재시작 후 암호화 연결 1개가 자동 복원되는 것도 확인했다.

최종 실제 호출 2회:

1. **Enter** → 회의 안내문 새 문서 작성: 제목·주어진 일시·장소가 실제 문서의 별도 문단으로 나타남.
2. **보내기 버튼** → 제목을 ‘업무 회의 안내’로 변경하고 16pt 굵게 적용: 일시·장소는 그대로 보존.

이어서 요청 되돌리기로 첫 번째 생성 문서의 내용·서식을 복원했다. [최종 응답과 검사](evidence/agent-interaction-2026-10-11/after.json), [실제 편집 화면](evidence/agent-interaction-2026-10-11/edited-after.png), [작업 중 표시](evidence/agent-interaction-2026-10-11/request-pending.png). 초기 실패 재현과 중간 확인을 포함해 이번 작업에서 실제 API 호출은 총 5회였다.

| 검사 | 결과 |
| --- | --- |
| 실제 WASM·Agent 관련 회귀 | 17개 통과. 실패 응답과 같은 연속 삽입, 순서 유지, HWP/HWPX 재열기·undo, 잘못된 명령 거절 포함 |
| 제공자·로컬 서버 | 23개 통과 |
| workspace·채팅·저장 브라우저 회귀 | 19개 통과. 연결 미설정 Enter에 대한 입력창 오류 표시 포함 |
| 실제 모델·입력 통합 | 6개 확인 통과. 실제 API 2회와 요청 undo 포함 |
| TypeScript·Vite | 통과 |

IME 가드는 합성 composition 이벤트와 Edge 키 입력으로 확인했다. 실제 Windows 물리 키보드의 모든 IME 상태를 검수한 것은 아니다. 실제 모델 결과도 위 요청들에 대한 성공이며 모든 자연어 요청의 정확도를 보증하지 않는다.

재현: 실행 중인 앱과 HCX-005 연결이 있을 때 `node apps/editor/scripts/verify-agent-interaction.mjs --live`. 실제 API 사용량이 발생하며 별도 브라우저 프로필을 사용한다. API 키를 테스트 파일이나 결과에 기록하지 않는다.

## 업데이트 적용

실행 묶음을 갱신했고 로컬 API 서버를 재시작했다. 기존 문서 창은 닫지 않았다. **열린 문서를 저장한 뒤 사용하던 브라우저 화면을 새로고침**해야 새 입력 처리와 새 서버 세션이 연결된다. 입력창 아래에 ‘Enter로 전송 · Shift+Enter로 줄바꿈’이 보이면 새 화면이다.
