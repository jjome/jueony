# 한글 2024 기능 동작 및 상태 저장 우선 점검 계획

2026-10-11. Jueony의 출발점은 **한글 2024의 사용 습관과 문서 작업을 그대로 이어갈 수 있는 편집기에 Agent를 결합하는 것**이다. 한글에서 하던 수동 작업·단축키·환경 설정·저장 동작이 기준이며 Agent를 사용하지 않는 동안에도 편집기가 독립적으로 완결되어야 한다.

최우선 순서는 **한글과의 기능·동작 전수 대조 → 문서 및 환경 상태의 저장·복원 대조와 보강 → 같은 편집기 안에 UI와 Agent 통합**이다. 브라우저 계정 연결·RAG·loop·AI 명령·매크로의 기존 계획은 유지하되 이 기반 점검과 수정 다음에 진행한다. 실행 중인 제품을 새로 교체하거나 코드를 구현한 결과가 아니라, 다음 작업을 위한 지시서다.

## 1 제품 기준

- 문서 편집이 주 작업이다. 메뉴·리본·상황별 도구·대화상자·단축키·마우스 조작·포커스 이동·저장 상태를 한글 2024 기준으로 맞춘다.
- 사용자에게 이미 익숙한 동작을 다시 배우게 하지 않는다. 같은 키가 다른 편집 기능을 실행하거나, 동일한 설정이 탭마다 다르게 해석되면 차이로 기록한다.
- Agent는 같은 문서 session·선택·서식·명령·undo·저장 서비스를 사용한다. 대화 패널을 접어도 수동 편집 기능과 환경값이 유지된다.
- rhwp의 Rust/WASM 엔진·Studio 명령·설정·복구를 먼저 확인하고 재사용한다. gongmuwon의 자료 관리 등은 업무 계층의 참고로 유지한다. 기존 기능을 읽지 않고 중복 구현하지 않는다.
- “한글과 완전히 같은 동작”은 최종 검증 목표다. 메뉴 표시·코드 존재·엔진 자체 재열기만으로 달성했다고 판정하지 않는다. 미구현·부분 지원·미검증은 실제 차이로 남긴다.

## 2 이번에 확인한 현재 코드

아래는 정적 코드 확인이며 실제 한글과 나란히 실행해 통과 판정한 결과가 아니다.

| 영역 | 확인 근거 | 남은 점검 |
|---|---|---|
| 업무와 복구 문서 | `apps/editor/src/mvp/store.ts`가 IndexedDB `jueony-workspaces`의 state/documents를 저장 | 앱 종료·브라우저 origin·프로필·업데이트에 따른 실제 복원과 실패 경로 |
| 복구 문서 필드 | `mvp/model.ts`의 SavedDocument는 id·workspaceId·name·bytes·dirty·updatedAt | 커서/선택/배율/원본 파일 handle은 이 레코드의 명시 필드가 아님. 엔진 파일에 포함되는 상태와 다른 저장소의 상태를 별도로 실사 |
| 복원과 원본 저장 | `shell.ts`는 복원 bytes를 handle 없이 열고 다른 이름 저장을 안내 | 한글의 다시 열기/최근 문서/복구와 비교, 권한 재확인 후 원본과 재연결하는 경로 |
| 보기와 환경 설정 | 재사용 Studio `core/user-settings.ts`에 글꼴·테마·대화상자·문단/조판 부호·도구 상자·쪽 배치·zoomFitMode·자동복구 설정과 localStorage 저장 코드가 있음 | 정의 존재와 통합 앱에서의 적용·저장·재실행 성공을 구분. 문서별/앱 공통 적용 범위를 한글과 비교 |
| 추가 화면 상태 | `chrome-2024.ts`의 스타일 창은 별도 localStorage 키, AppState에 split/agentWidth가 존재 | 여러 탭·창의 동기화, 창 크기 변경, 충돌·초기값·복원 순서 |
| 복구본 생성 | `editor-bridge.ts`가 엔진에서 파일 bytes와 dirty를 얻고 `shell.ts`가 문서 레코드 저장 | 원본 파일 저장과 복구본 저장의 표시·수명·보관 한도·종료 시 경합 |
| 실제 저장 보호 | `save-guard.ts`에 revision, 외부 파일 변경 hash, writable close, 중복 저장 제어 | 취소·쓰기 실패·외부 변경·읽기 전용·재실행 후 원본 식별과 한글 사용자 흐름 |
| AI 요청 undo | 현재 열린 문서의 revision/receipt와 undo에 연결. shell은 재시작 후 요청 undo를 제한 | 한글의 일반 undo 수명과 AI 실행 기록의 수명을 따로 정의하고 복구된 문서를 자동 재적용하지 않음 |

재사용 설정 소스는 `upstream/rhwp-source/rhwp-studio/src/core/user-settings.ts`이며 빌드 시 `apps/editor/.build/studio/src/core/user-settings.ts`로 복사된다. 생성된 `.build` 파일을 직접 고쳐 기능을 유지하는 방식은 사용하지 않는다.

## 3 한글 기준 환경 고정

H00에서 다음 항목을 기록한다. 실제 한글 설치가 없으면 코드·공식 도움말 점검은 진행하되 실동작 비교는 `BLOCKED_REFERENCE`로 남긴다. 도움말을 읽은 것을 실제 한글 실행으로 보고하지 않는다.

- 한글 2024 제품/에디션·정확한 빌드·패치·한국어 UI와 선택한 메뉴/단축키 프로필.
- Windows 빌드, 디스플레이 해상도·배율, 모니터, 한국어 IME/키보드, 글꼴 목록, 인쇄/PDF 환경.
- 처음 실행한 환경과 사용자가 환경값을 바꾼 환경을 분리한 기준 프로필. 운영 중인 사용자 설정을 초기화하지 않고 별도 검수 환경 사용.
- 비교할 HWP/HWPX·양식·이미지·수식 등 표본 hash와 해당 기능의 수동 기대 결과.
- Jueony commit·엔진/WASM/자산 버전·실행 경로·origin·브라우저 프로필을 기록.

공식 목록은 [한글 2024 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/hwpbase/action(hwp).htm), [도구 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/tools.htm), [보기 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/view.htm), [단축키 일람](https://help.hancom.com/hoffice130/ko-KR/Hwp/view/toolbar/shortcut(table).htm)을 사용한다. 설치 빌드와 도움말의 차이는 실제 빌드 기준으로 기록한다.

## 4 기능 및 동작 전수 목록

현재 [AI 제어 기능표 68행](ai-editor-capability-matrix.csv)은 초기 분류다. 이를 한글 전체 기능 목록으로 간주하지 않고, **한글 쪽 목록을 먼저 만든 다음** Jueony의 메뉴·명령·엔진을 연결한다. Jueony에 없는 기능도 분모에서 빠지지 않는다.

각 메뉴의 대화상자 탭·선택 옵션·우클릭 항목·연속 단축키·상황별 활성 조건을 하위 case로 확장한다. 같은 이름의 명령이라도 본문/표/셀 블록/개체/대화상자에서 다르게 동작하면 별도 case다.

H01 산출물 `hangul-2024-feature-audit.csv`의 필드:

`feature_id, parent_id, hancom_menu, action_or_shortcut, context, prerequisite, reference_build, reference_evidence, jueony_command, engine_path, expected_effect, expected_scope, expected_focus, cancel_behavior, undo_behavior, persistence_ids, implementation_status, comparison_status, evidence_path, defect_id, next_action`

구현 상태는 `MISSING / STUB / PARTIAL / WIRED`, 비교 결과는 `NOT_RUN / BLOCKED_REFERENCE / PASS / FAIL`로 나눈다. 코드에 연결된 기능도 비교 결과가 없으면 PASS가 아니다. 제외/외부 의존 항목은 사유를 표시하되 전체 기능 수에서 조용히 제거하지 않는다. 기존 68행 및 기본 E 작업과 ID 관계를 유지한다.

## 5 같은 기능을 비교하는 절차

1. 동일한 초기 문서와 환경에서 한글과 Jueony를 연다. 초기 내용·서식·배율·포커스·선택을 기록한다.
2. 같은 메뉴/단축키/마우스 조작을 수행한다. 기본값·단위·입력 범위·적용 범위·Enter/Escape·확인/적용/취소 결과를 각각 검사한다.
3. 내용·문단/표/개체 구조·레이아웃·쪽수·선택·커서·스크롤·도구 모음·dirty 표시와 다음 키 입력의 결과를 비교한다.
4. undo/redo와 연속 동작을 검사한다. 명령의 이름이 같아도 선택 범위나 되돌리기 묶음이 다르면 차이로 기록한다.
5. 문서 변경 기능은 두 형식으로 저장해 엔진에서 재열고 실제 한글에서도 확인한다. 인쇄/PDF의 글꼴·줄바꿈·쪽 넘김·개체 배치를 비교한다.
6. 환경값과 보기 기능은 아래 상태 생명주기 검사를 수행한다. 파일 byte가 달라야 하는 상태와 달라지지 않아야 하는 상태를 구분한다.

같은 엔진의 export/import는 내부 일관성 근거다. 실제 한글의 수동 기대본·UI·인쇄 결과를 독립 기준으로 둔다. 텍스트 추출 결과만 같거나 화면이 비슷해도 표 구조·개체 anchor·머리말·쪽 분할이 다르면 합격이 아니다. 허용 오차가 필요한 렌더링 값은 측정 환경과 허용 이유를 case에 기록하며 의미 있는 레이아웃 차이를 평균 점수로 숨기지 않는다.

## 6 상태의 소유 범위와 저장 수명

“상태 저장”은 모든 값을 무조건 영구 보관하는 뜻이 아니다. **한글이 어떤 범위에 적용하고 언제 유지/초기화하는지를 먼저 관찰해 동일하게 구현한다.** 실제 한글이 초기화하는 선택·undo·대화상자 값까지 임의로 영구 복원하지 않는다.

공식 도움말의 확인 가능한 기준 예:

- 환경 설정은 앱의 편집 환경 기본값으로 여러 문서에 적용된다. [환경 설정](https://help.hancom.com/hoffice130/ko-KR/Hwp/file/options/options.htm).
- 현재 문서의 편집 용지와 새 문서 기본값은 범위가 다르다. 새 문서 기본값은 재실행 후 유지되고 기존 문서에는 소급 적용되지 않는다. [환경 설정의 새 문서](https://help.hancom.com/hoffice130/ko-KR/Hwp/file/options/options(newpaper).htm).
- 새 문서의 용지·스타일·개요 번호는 바탕문서와 연결된다. Jueony에서도 사용자 기본 양식을 통한 같은 의미를 구현하고 기존 파일의 값을 덮어쓰지 않는다. [새 탭과 바탕문서](https://help.hancom.com/hoffice130/ko-KR/Hwp/file/new_tab.htm).

아래는 상태 계약을 작성할 점검 대상이다. 한글 기대값이 아직 관찰되지 않은 행은 `REFERENCE_PENDING`으로 시작한다.

| S08 | 도구 상자·작업 창·눈금자·테마 | 사용자 보기 환경인지 문서별 환경인지 기준 관찰. 여러 탭/창 동기화 |
| S09 | 조판/문단 부호·격자·안내선·보기 색 | 문서 속성과 보기 설정 구분. 표시 변경이 원문을 오염시키는지 검사 |
| S10 | 확대율·쪽/폭 맞춤·쪽 배열 | 숫자 확대율과 맞춤 모드 구분. 문서 크기·창 크기·재실행 시 재계산 및 소유 범위 관찰 |
| S11 | 커서·현재 쪽·스크롤·본문/표 편집 위치 | 문서별 보기 상태. 문서 탭 전환·닫기 후 재열기·프로그램 재실행의 수명 관찰 |
| S12 | 본문/셀/개체 선택·편집 모드 | 선택 종류와 대상 revision을 함께 식별. 유지되는 경우만 복원하며 잘못된 셀/개체로 이동 금지 |
| S13 | 메뉴/단축키 사용자 설정 | 사용자 프로필·기본 매핑·충돌·초기화·내보내기/가져오기 및 업데이트 유지 |
| S14 | 대화상자 마지막 탭·입력값·단위 | 명령별로 기억/초기화·확인/취소 차이를 관찰. 공통 전역값으로 임의 통합 금지 |
| S15 | 최근 문서·저장 형식·마지막 폴더 | 사용자 환경과 문서 원본 식별 분리. 파일 이동/이름 변경/삭제/권한 철회 검사 |
| S16 | 열린 창/탭·순서·활성 문서 | 한글의 종료 옵션별 복원 동작 관찰. 문서/창별 ID와 중복 열기 처리 |
| S17 | 창 크기·최대화·위치·분할 | 사용자 창 환경, DPI/모니터 변경 때 보이는 영역에 복원. 실제 한글 기준과 비교 |
| S18 | 자동 저장·복구 간격·백업 정책 | 설정 저장과 복구 데이터 보관을 구분. 파일 저장 여부와 복구 가능 여부를 따로 표시 |
| S19 | dirty·마지막 저장본·복구본·파일 연결 | 저장/취소/버리기/실패/충돌 시 정확한 값. 복구 후 원본 덮어쓰기 가능 여부와 경로 확인 |
| S20 | undo/redo·AI 요청 되돌리기 | 일반 편집 이력의 한글 수명을 관찰. AI receipt는 기록과 실행 가능성을 구분하고 재시작 후 자동 적용 금지 |
| S21 | 인쇄/PDF 옵션·장치·쪽 범위 | 문서/앱/프린터 드라이버의 소유 범위와 이전 설정 유지 여부 |
| S22 | 업무·채팅·자료·Agent 패널 | Jueony 추가 상태. 한글 대응 없음으로 표시하고 문서 고유값·기본 편집 동작에 영향 없음 검증 |

H02 산출물 `editor-state-contract.csv`에는 다음을 채운다:

`state_id, field, reference_default, scope, owner, persistence_medium, save_trigger, restore_trigger, restore_order, reset_condition, file_effect, dirty_effect, undo_effect, migration, reference_evidence, jueony_evidence, status`

S01~S22는 상태 묶음이다. 같은 행의 필드라도 한글의 범위·수명이 다르면 개별 행으로 분리한다. 문서 환경값을 모두 localStorage로 보내거나 모든 UI 설정을 HWP에 기록하는 방식으로 단순화하지 않는다.

## 7 상태 저장 구현 작업

1. 현재 엔진 파일·Studio 설정·workspace DB·localStorage·복구 저장소를 조사해 필드별 소유자를 하나로 정한다. 기존 저장소는 이관 계획 없이 지우지 않는다.
2. 문서 고유 상태는 엔진의 HWP/HWPX 직렬화를 사용한다. 앱 설정으로 문서 값을 다시 만들거나 파일을 열 때 기본값으로 덮어쓰지 않는다.
3. 사용자 기본값·보기값·문서 session을 목적별로 구분하고, 기존 설정 서비스를 연결하는 작은 adapter부터 적용한다. 설정 schema/version과 이전 값 이관·부분 누락·손상 시 복구 규칙을 둔다.
4. 복원 순서를 환경 준비→엔진/문서 로드→문서 고유값 적용 확인→해당 문서 보기 상태→선택/커서→도구 모음 동기화로 설계한다. 로드 도중 초기 UI 이벤트가 저장된 값을 덮어쓰지 않게 한다.
5. 문서별 상태는 파일 이름만으로 식별하지 않는다. 원본 파일 식별·형식·해시/버전·세션 ID를 구분하고 이름 변경·다른 이름 저장·복사본·외부 변경을 처리한다.
6. 원본 파일 handle/권한의 재연결을 검증한다. 복구본이 있다는 사실만으로 원본 파일 쓰기 권한이나 최신성을 가정하지 않는다. 브라우저 방식으로 필요한 한글 동작이 불가능하면 네이티브 파일/설정 서비스 도입 결정을 별도로 기록한다.
7. 파일 저장과 설정/복구 저장의 완료를 따로 기록한다. 저장 실패·quota·권한 거부·disk 오류에서 값이 사라지거나 dirty가 잘못 해제되지 않게 한다. 정상 종료 때 필요한 commit을 기다리고 강제 종료에 대비한 주기 checkpoint를 둔다.
8. 한 사용자 프로필의 앱 공통값이 여러 문서/창에서 충돌하지 않도록 적용 이벤트·버전 규칙을 둔다. 문서별 값이 다른 문서로 새지 않게 한다.
9. 런처의 고정 프로필/origin, 업데이트·설치 경로·포트 변경·Windows 계정 변경 시 보존 범위를 확인한다. 브라우저 저장이 된다는 이유만으로 데스크톱 설정 보존이 완성됐다고 하지 않는다.
10. 환경 초기화·기본값 복원·설정 가져오기/내보내기·업데이트 migration을 검증한다. 인증정보는 기존 보호 저장소에서 관리하며 환경 파일에 포함하지 않는다.

내부 저장 매체가 한글의 구현과 같아야 하는 것은 아니다. 관찰 가능한 적용 범위·기본값·수명·복원 결과·오류 처리가 같아야 한다. 운영 중인 한글의 레지스트리나 바탕문서를 Jueony가 임의로 수정하지 않는다.

## 8 상태 생명주기 검사

각 S 필드를 아래 전이에 대조한다. 한글에서 유지하는 값은 유지하고 초기화하는 값은 같은 조건에서 초기화한다. 모든 조합을 동일 기대값으로 처리하지 않는다.

| 검사 | 전이/반례 | 확인할 것 |
|---|---|---|
| T01 | 변경→같은 창에서 다른 문서 탭→원래 탭 | 문서별/전역 범위, 포커스, 다음 입력 위치 |
| T02 | 현재 문서 설정 변경→새 문서 만들기 | 현재 문서 값과 새 문서 기본값 분리 |
| T03 | 새 문서 기본값 변경→기존 문서→새 문서 | 기존 문서 불변, 새 문서만 지정값 적용 |
| T04 | 저장→닫기→원본 다시 열기 | 내용·구조·서식·문서 환경·dirty·원본 경로 |
| T05 | 정상 종료→앱 재실행 | 설정·탭/최근 문서·보기·입력 위치의 기준 수명 |
| T06 | 미저장 변경→닫기 취소/저장/버리기 | 대화상자·dirty·복구본 정리·원본 파일 상태 |
| T07 | 복구 checkpoint 전/후 강제 종료 | 보존 시점 표시, 문서 복구, 원본 오인·자동 덮어쓰기 없음 |
| T08 | 다른 이름/다른 형식 저장→양쪽 재열기 | 이전/새 파일 상태 분리, HWP/HWPX의 구조 및 환경값 |
| T09 | 외부 프로그램의 수정/이름 변경/삭제 | 충돌·재연결·읽기 전용과 사용자 선택 |
| T10 | 저장 중 사용자/Agent 편집·중복 저장 | 저장 revision과 dirty 정합성, 입력·undo 복귀 |
| T11 | IndexedDB/localStorage/file 쓰기 실패 | 영구 저장 실패를 성공으로 표시하지 않음, 문서 보존과 재시도 |
| T12 | 두 창에서 공통 설정 변경 | 갱신·충돌 처리와 문서별 설정 분리 |
| T13 | 창/DPI/모니터 변경 | 창 접근성, 보기 배율/맞춤 모드, 실제 용지 크기 불변 |
| T14 | 앱 업데이트·설정 schema 변경 | 기존 문서/설정 보존, 실패 migration 복구 |
| T15 | 새 사용자 프로필·초기화·설정 가져오기 | 기본값·사용자 구분·설정 파일 버전·원본 문서 보존 |
| T16 | Agent 숨김/표시·수동 편집→AI 변경→undo | 한글 기본 동작·문서 환경 보존, AI의 지정 변경만 반영 |

두 문서가 의도적으로 다른 용지·여백·서식·보기값을 가진 표본을 사용한다. 재시작은 새 페이지 reload뿐 아니라 실제 런처/브라우저 프로세스를 종료하고 다시 시작하는 경로를 포함한다. 결과 기록에는 관찰한 한글 상태와 Jueony 상태, 입력 순서, 저장 파일, 화면 증거를 함께 둔다.

## 9 작업 순서와 관문

실행 배정은 [병렬 작업 순서](26-parallel-execution-plan.md)를 따른다. H00 기준 고정 후 H01 기능 대조와 H02 상태 대조, 엔진/검사 준비는 병렬이다. 관련 비교 기준과 상태 계약을 확정한 뒤 H03의 입력/편집·상태 보존·파일/복구 수정을 나눠 진행하고 H04 통합 검수에서 합친다. 실제 한글 GUI와 공용 파일·빌드는 한 담당씩 순차 사용한다.

| 단계 | 작업 | 산출물과 통과 조건 |
|---|---|---|
| H00 | 한글 기준 환경·표본 고정 | 빌드/설정/IME/글꼴/인쇄 기준, 표본과 초기 상태, 가능한 검사/환경 대기 구분 |
| H01 | 기능과 동작 전수 대조 | 한글 목록의 각 항목이 누락 없이 Jueony 구현·차이·검사에 대응. 모든 상태를 PASS/FAIL/NOT_RUN/BLOCKED로 분류 |
| H02 | 상태 범위·저장/복원 계약 대조 | S 필드별 실제 한글 수명과 저장 매체·복원 순서, T 전이별 기대값 |
| H03 | 기반 차이 수정 | 입력·선택·단축키·명령·기본값·저장/복구의 우선 결함 수정. 한글과 다른 미구현 동작도 계속 작업표 유지 |
| H04 | 재실행과 파일 왕복 독립 검수 | 여러 문서·정상/비정상 종료·설정 migration·두 형식 저장·실제 한글 재열기 증거 |
| H05 | 동일 편집기에 UI·Agent 통합 회귀 | 수동 동작 기준 유지, 같은 명령/상태 사용, AI 숨김/표시·편집·undo·저장 검사 |

점검 완료와 완전 호환 완료는 다르다. H01/H02의 목록과 차이 보고가 만들어져도 미검증 항목은 남아 있을 수 있다. 데이터 유실·원본 오저장·입력 불가·잘못된 단축키 실행·상태의 문서 간 혼입·재실행 설정 유실 등 기반 결함은 새 Agent 기능 확대보다 먼저 수정한다.

UI 통합 중 한글 기본 조작을 맞추는 변경은 H03에 포함할 수 있다. 장식 변경이나 새로운 Agent 능력으로 기반 차이를 덮지 않는다. 고급 기능도 최종 동등성 목표에 포함되며 외부 의존 기능·미지원 항목을 임의로 제외해 전체 완성을 선언하지 않는다.

전체 동작 동등성은 고정한 한글 기능 목록의 대조·해당 상태 전이·독립 저장 검수가 모두 통과하고 미검증/미구현/차이가 남지 않았을 때만 선언한다. 특정 표본 통과를 모든 파일과 모든 한글 빌드의 호환 보증으로 확대하지 않는다.

## 10 첫 실제 점검 과제

**Agent를 사용하지 않고 한글 사용자의 하루 작업을 재현한다.**

1. 기준 한글의 새 문서·열기·입력·표·서식·쪽·보기·저장·종료 기본 동작과 환경값을 기록한다.
2. Jueony에서 같은 작업을 하고, 기존 수동 기능/설정 서비스의 재사용 가능 부분과 차이를 분리한다.
3. 새 문서 기본값과 문서별 설정이 다른 두 문서를 저장하고 탭 전환·닫기/재열기·완전 종료/재시작을 비교한다.
4. 한글에서 저장물을 확인하고 내용·서식·표·쪽·환경값 차이와 원본 파일 연결 문제를 기록한다.
5. 첫 차이 보고서와 우선 수정 목록을 만든 뒤 구현을 시작한다. 첫 검수에서 발견되지 않은 전체 기능도 H01에서 계속 전수 대조한다.

완료 보고에는 전체 목록 수·정적 연결 수·실행 비교 수·PASS/FAIL/미실행 수·남은 기반 결함·상태별 복원 결과를 구분한다. 사용자가 이미 확인한 한글 입력/특정 파일 재열기 성공은 해당 증거로 유지하며, 이 계획 작성 중 새 검사를 통과한 것으로 집계하지 않는다.
