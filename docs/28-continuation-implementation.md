업무/문서 상태는 브라우저 origin별로 분리된다. 새 검수본에 기존 업무 목록이 바로 보이지 않아도 삭제된 것이 아니다. 원본 문서의 검수용 복사본을 열어 사용한다. API 키는 실행 묶음이나 Git에 포함하지 않았으며, 기존 연결 관리와 Windows 보호 저장소를 사용한다.

`review-documents`에 합성 HWP/HWPX 저장 결과를 넣었다. 실제 한글에서 내용·표·쪽·줄바꿈을 비교할 수 있다. EXE도 검수 포트로 컴파일하지만, Windows가 기본 포트용 테스트 EXE 실행을 차단했으므로 스크립트 실행을 안내한다. 정책을 해제하거나 우회하지 않았다.

## Agent 경계와 제한

`UI → context/retrieval → runOnce 또는 runBounded → LLMPort → 기존 provider adapter` 구조다. 검색/검토 로직은 공급자 adapter와 분리했다. GPT·Claude·Gemini·HyperCLOVA X 연결 방식은 기존 API 키 adapter를 유지하며 이번에 브라우저 계정 인증을 구현한 것은 아니다.

검색은 요청마다 명시 자료의 추출 텍스트를 분할하는 **어휘 기반 RAG**다. 한국어 bigram·단어·제목으로 점수를 매긴다. 구간 최대 1,000 UTF-16자, 최대 8구간/8,000자, 파일당 최대 3구간이다. 출처 ID, 원문/구간 hash, 문자 범위, 추출 텍스트 줄 번호를 기록한다. 줄 번호는 실제 한글 쪽 번호가 아니다. 자동 폴더 분석·영구 인덱스·임베딩·벡터 DB·reranker·웹 검색은 없다. 기존 읽기 대상 HWP/HWPX/TXT/MD와 자료 수/크기 제한을 그대로 적용한다.

검토 실행은 메모리의 편집 후보를 재검토하는 제한된 흐름이다. 동일 명령에 도달하면 2회로 끝내며 최대 3회, 120초, 누적 입력 문자 예산을 적용한다. 토큰이나 원화 요금 상한을 보장하지 않는다. 중간 후보를 문서에 적용하지 않는다. 취소·문서 변경·업무/채팅 이동·잘못된 명령·사전 검사 실패 시 오래된 후보를 덮어쓰지 않는다. 임의 도구를 호출하는 자율 loop, 자동 복구/무한 재시도는 구현하지 않았다. 종료 이유와 단계는 실행 기록에 남긴다.

AI 편집은 기존 본문 삽입/교체/삭제, 글자·문단 서식, 단순 표의 셀 텍스트/서식·행열 추가삭제, 구역 용지/여백과 연결한다. 병합/중첩 표 편집, 그림·개체·필드·머리말 등 모든 한글 기능 제어는 아직 완성되지 않았다. 암호/보호 문서는 평문 사본을 만들지 않기 때문에 AI 사전 검사와 자동 편집을 제한한다.

반복 작업 v1은 새 문서·본문 변경·글자/문단 서식·새 표 명령만 기록한다. 기존 표 변경과 쪽 설정은 아직 기록하지 않는다. 대상은 저장한 원문과 일치하는 편집 가능 문단 한 곳으로 다시 찾으며 없거나 중복되면 거부한다. `{{변수}}`는 결과 문자열에만 대입하고 최종 명령을 다시 검증한다. 한글 스크립트 매크로/키 입력 녹화·호환 실행과는 범위가 다르다. 요청 undo는 현재 열린 세션의 해당 변경 이후 편집이 없을 때 가능하며, 재시작 후 undo 이력 복원은 지원하지 않는다.

## 수정 중 발견해 해결한 결함

- 숨긴 문서 iframe의 DOM 스크롤이 0으로 바뀌어 저장값을 덮어쓰던 문제: 숨기기 전 view suspend, 다시 표시한 뒤 복원 완료까지 대기.
- 통합 메뉴가 원래 도구상자의 화살표 기호만 가져오던 문제: 안정된 메뉴 ID로 한글 이름 표시.
- 최근 문서 메뉴의 항목 식별자 누락과 목록 미갱신: 파일 메뉴를 열 때 원래 저장소에서 목록을 갱신하고 항목 ID를 기존 열기 명령에 전달. 최대 20개를 표시한다.
- 서로 다른 매크로 기준 문단이 한 문단에 중복 대응되던 문제: 일대일 매핑 검사.
- 단색 표 배경의 patternType 0이 HWPX 저장 후 -1로 변하던 문제: 명령에서 무늬 없음(-1)을 명시. 다른 패턴 필드를 비교에서 제거하지 않음.
- 새 HWPX 사전 검사 사본의 기본 글자 속성 미등록 및 비활성 배경 기본값 정규화: 빈 문서 초기화 후 대상 형식으로 export/reopen하여 기준 사본 생성. 이후 적용·저장·재열기 구조 전체 비교를 유지.

## 남은 범위와 다음 작업

현재 기능표는 1차 182개 묶음 중 71 WIRED / 35 PARTIAL / 3 STUB / 73 MISSING이다. WIRED는 코드 연결 상태이며 한글 동등성 통과 수가 아니다. 실제 한글 2024 편집기가 없는 상태는 그대로이며 **G2 실제 한글 검수는 BLOCKED_REFERENCE**다. 사용자가 추가 자율 진행을 요청하여 독립 검증 가능한 옵션 기능을 구현했지만 이를 G2 통과로 처리하지 않았다.

1. 실제 한글 2024 편집기 설치 환경에서 합성/기관 대표 파일의 레이아웃·저장 재열기·단축키·IME·인쇄를 비교한다.
2. 기능표의 누락 명령을 고급 표→개체/필드→쪽/출력 순서로 보강하고, 검증한 명령만 AI에 공개한다.
3. 브라우저 계정 인증은 제공자의 공식 앱 등록/권한·허용 계약을 확인한 뒤 구현한다. CLI 구독이나 임의 토큰을 API 키로 재사용하지 않는다.
4. 익명화된 업무 평가 세트를 확보해 single/검색/검토 실행의 정확도·비용·지연을 비교하고, 검색 품질이 필요할 때 임베딩/reranker를 추가한다.
5. 영구 검색 인덱스, 일반 도구 loop, crash 후 실행 journal 복구, 한글 매크로 호환, 기관 배포 정책은 별도 후속 개발이다.

```powershell

Set-Location apps/editor
node scripts/build.mjs
node --experimental-strip-types --test tests/*.test.ts
.\node_modules\.bin\tsc.cmd --project .build/studio-continuation/tsconfig.json --pretty false
node scripts/verify-agent-workbench.mjs

powershell.exe -NoProfile -File scripts/Build-Standalone.ps1 -OutputName jueony-continuation-20261011 -FrontendProfile continuation -ReviewPort 4191
```

공용 빌드와 패키징은 순차 실행하며, frozen build에 대해 E2E만 서로 다른 포트로 병렬 실행한다. live Claude 검사 스크립트는 기존 등록된 연결을 사용해 합성 요청을 최대 3회 호출하므로 필요할 때만 별도로 실행한다.
