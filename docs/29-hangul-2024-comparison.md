# 한글 2024와 Jueony: 기능 차이 및 미구현 목록

검토일: 2026-10-11. 대상 소스 HEAD: `f5be2b81d247a5468750952cea20c7db297d188a`.

**현재 Jueony는 한글 2024와 기능·동작이 동일하지 않다.** 편집 엔진에 이미 있는 기능, 제품 UI에 빠진 기능, AI가 호출하지 못하는 기능을 분리하여 점검했다. 이번에는 기능 재고와 개발 과제를 작성했으며 제품 코드는 변경하지 않았다.

## 1. 비교 범위와 결과를 읽는 방법

| 구분 | 확인 범위 |
|---|---|
| 참조 프로그램 | 설치된 한컴오피스 2024 Edu의 한글, Hwp.exe `13.0.0.711` |
| 실제 한글 화면 | 컴퓨터 사용 도구로 빈 문서의 파일·편집·보기·입력·서식·쪽·보안·검토·도구 메뉴를 열어 접근성 트리와 화면 확인. 본문은 0글자로 유지 |
| Jueony | 최신 continuation 빌드, 빌드 패치와 배포 JS, 앱·Agent 코드, 고정 rhwp 소스 및 실행 WASM 대조 |
| 실행 엔진 | `@rhwp/core@0.8.7`, rhwp 소스 `1a76570e833917d15817415a53c09ad61ab3203f`. 설치본과 continuation WASM SHA-256 일치 |
| 정적 감사 | 편집 UI/단축키, 엔진/저장, 상태/AI의 세 영역을 병렬 조사한 뒤 통합 |
| 미실행 | 양 앱의 모든 기능을 같은 문서에서 실행하는 비교, 모든 대화상자·우클릭·표/개체 문맥, 저장 후 한글 왕복, 인쇄 결과, IME/물리 키 전수 검사, 재실행 상태 수명 시험 |

Jueony 새 실행을 컴퓨터 사용 도구로 시도했으나 앱 승인 대기 시간이 초과되어 이번 작업에서 새 GUI 비교는 완료하지 못했다. Jueony 쪽 판정은 코드·빌드·기존 증적에 근거한다. 한글 메뉴 관찰도 해당 기능의 모든 동작을 실행했다는 뜻은 아니다. 따라서 **완전한 동작 비교 완료나 호환률 100%를 선언하지 않는다.**

기존 182행에 실제 한글 메뉴에서 새로 발견한 6행을 추가하여 [188행 기능 체크리스트](hangul-2024-gap-checklist.csv)를 작성했다.

| 구현 상태 | 행 수 | 의미 |
|---|---:|---|
| MISSING | 78 | 조사한 제품 UI·명령 경로에 대응 기능 없음 |
| STUB | 3 | 메뉴/명령은 등록되었으나 실행 비활성 또는 빈 구현 |
| PARTIAL | 42 | 일부 옵션·문맥만 지원하거나 연결/보존 문제가 있음 |
| WIRED | 65 | 구현 경로 존재. 한글과 동일한 결과라는 뜻은 아님 |

총 123행에 미구현·stub·부분 구현 과제가 있다. **행 수는 한글 전체의 독립 기능 수가 아니다.** 여러 하위 기능을 묶은 행과 메모 중복 행(B092/B136)이 있고, 대화상자 세부 옵션은 계속 분해해야 한다. 신규 체크리스트의 실제 동작 비교는 모두 `NOT_RUN`이다. 기존 시험 결과와 사용자의 재열기 성공 경험을 무효화하는 뜻이 아니라, 이번 전수 비교의 PASS로 재사용하지 않는다는 뜻이다.

이 문서와 신규 CSV가 현재 차이 목록이다. 기존 `hangul-2024-feature-audit.csv`, 상태/AI 행렬 및 27·28번 구현 보고서는 당시 기록으로 보존하며, 오래된 설명의 정정은 아래 및 세부 감사에 기록했다.

## 2. 가장 먼저 해결할 차이

| 우선 | 차이 | 근거와 필요한 작업 |
|---|---|---|
| P0 | 저장 손실 보고 누락 | HWPX의 Unknown 컨트롤을 출력하지 않는 경로가 구조화된 손실 보고에 포함되지 않는다. `contentLoss.count=0`만으로 무손실을 보장할 수 없다. 누락/오류 보고를 완성하고 저장·자동 복구·AI 사전 검사와 연결 |
| P0 | 전체 문서 보존 검사 부족 | 현재 AI 사전 검사는 본문과 최상위 표 중심이다. 모든 글자 run, 그림 바이트, 개체 기하, 필드·바탕쪽·서명 등을 비교하지 않는다. 읽기 모델 및 보존 검증 확장 |
| P0 | F6 스타일 충돌 | 실제 한글 메뉴의 F6는 스타일. Jueony 빌드가 iframe에 먼저 설치한 F6 capture listener는 채팅 이동을 요청하며 이후 listener를 차단한다. 포커스 이동 키 재설계 후 본문/셀/입력창/IME에서 실측 |
| P0 | 감추기·캡션의 저장/undo 경계 | 머리말·꼬리말 감추기는 세션 상태이며 영구 문서 속성을 바꾸지 않는다. 기본 개체 캡션 추가는 일반 history 경로를 통하지 않는다. 기능별 dirty·undo·저장·재열기 검사 |
| P1 | 공문 핵심 조작의 빈 부분 | 통합 머리말/꼬리말·쪽 번호 대화상자, 구역 나누기, 기본 탭 간격, 표 선택 문맥·균등 크기·쪽 배경 옵션 보강 |
| P1 | 환경·복구 정책의 일관성 | shell 복구 예약과 Studio 자동 복구 설정을 통합하고, 한글의 실제 기억 범위를 확인하여 기본값·대화상자·커서·창 상태 계약 확정 |

위 저장 공백은 정적 코드에서 확인한 위험 경로다. 모든 문서에서 손실이 발생한다는 뜻은 아니다. 기존 공개 표본 `python-hwpx-1`의 HWP 변환은 손실 보고 0이면서 본문 비교가 불일치했던 별도 증거가 있다. 실제 한글에서 해당 표본의 끝 문단·쪽 수 영향을 먼저 판정한다. 상세 위치와 제한은 [엔진 감사](evidence/hangul-comparison-2026-10-11/engine-code-audit.md)에 기록했다.

## 3. 사람이 사용하는 편집기에 빠진 기능

아래는 기능군 요약이다. 각 항목의 행 ID·현 상태·다음 작업은 CSV 및 문서 끝의 전체 목록을 기준으로 한다. 파일에 들어 있는 정보를 파싱/보존하는 능력과 새로 생성·편집하는 기능은 구분한다.

| 영역 | 미구현 또는 stub |
|---|---|
| 문서 작성·변환 | 문서마당, 시작 도우미, PDF 가져오기 변환, 그림 OCR 변환, 일반 XML 서식 관리, 모바일·DAISY·점자 출력, 문서 정보 통합 UI, CCL/공공누리 표시 |
| 기본 편집 | 골라 붙이기, 조판 부호 종류별 삭제, 글자 변환·정렬, 이전/다음 커서 위치, 문서 끼워넣기 |
| 보기·작업 창 | 쪽 윤곽의 동일 동작, 교정 부호/그림/메모 표시 세부 옵션, 개체 안내선, 한자 발음, 문서 보기 색, 책갈피·개요·클립보드 등 작업 창, 같은 문서 화면 분할, 여러 문서 창 배열 |
| 표 작성 | 표 그리기·지우개, 문자열↔표 변환, 표 자동 채우기, 표마당 |
| 입력·개체 | 새 차트 생성, 글맵시, 멀티미디어/OLE 신규 삽입, 양식 개체 신규 생성 UI, 문단 띠, 상용구, 글자 겹치기, 덧말, 한자 입력, 로마자·외래어 표기, 상호 참조 |
| 서식 | 문단 첫 글자 장식, 스타일마당, 빠른 내어쓰기·문단 여백/첫 줄·스타일 번호 등 일부 빠른키 |
| 쪽 | 바탕쪽 편집 UI, 줄 번호, 구역 나누기 전용 연결, 원고지·라벨, 쪽 삭제·복사·붙이기 |
| 검토 | 메모 생성/모양/표시, 파일 내부 변경 추적·수락/거절, 교정 부호·자료 연결 |
| 언어·자동화 | 맞춤법, 사전, 빠른 교정, 메일 머지, 차례·색인, 참고 문헌, 한글 스크립트 매크로·키 녹화, 문서 찾기, 개인정보 변환, 프레젠테이션 |
| 보안·사용자 설정 | 배포용 문서 저장/편집 UI, 개인정보 보호·해제, 문서 보안 정책, 사용자 메뉴·도구상자·키맵 편집 |
| 외부 연계 | 한컴독스·메일·웹 전송, 번역/사전 서비스, COM 추가 기능, 한컴 애셋, 오피스 톡. 폐쇄망 제품의 필수 호환 범위와 외부 서비스 의존성을 별도 결정 |

한글의 해당 기능군은 설치 메뉴와 [파일](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/file.htm), [편집](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/edit.htm), [입력](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/insert.htm), [쪽](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/Page.htm), [검토](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/review.htm), [표](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/table.htm), [도구](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/tools.htm) 공식 도움말을 대조했다. 실행판과 도움말이 다를 경우 현재 설치판을 기준으로 기록한다. 예를 들어 실제 구역 나누기 메뉴는 `Alt+Shift+Enter`였다.

## 4. 구현은 있지만 한글과 같지 않은 부분

| 기능 | 이미 있는 부분 | 남은 차이/검증 |
|---|---|---|
| 표 편집 | 행열 추가/삭제, 병합/분할, 표 나누기/붙이기, 셀 속성, 계산식 | 병합·중첩·개체 포함 표와 여러 쪽 배치 전수 검수. 균등 크기는 단순 표의 전체 행/열 선택 등으로 제한 |
| 글자·문단·스타일 | 기본 서식/스타일 및 개별 탭 위치 | 기본 탭 간격 변경 비활성, 전체 옵션·혼합 서식·입력 대기 서식·기본값·단축키 검증 |
| 글상자·개체 | 삽입, 회전/뒤집기, 속성, 묶기/풀기 | 글상자 세로쓰기/영문 방향/한 줄 입력/양식 모드와 개체 기울임 비활성 |
| 캡션 | 기본 캡션 추가/진입 | 위치/없음 9개 메뉴 stub. undo·dirty·번호·저장 검사 |
| 차트·OLE | 기존 일부 OOXML 차트 데이터 편집, 일부 OLE 표시 | 새 차트·전체 디자인·다층 라벨 구조·임의 OLE 외부 앱 편집 미지원. 미리보기를 편집 지원으로 계산하지 않음 |

| 각주·미주 | 삽입·내용 편집·일부 모양 | 미주 번호 작은 크기 옵션 비활성. 변환·다중 구역·표/수식 포함·출력 검증 |

## 5. 상태 저장: 구현된 것과 남은 것

**이미 구현됨:** workspace·채팅·폴더 연결·실행 기록, 문서 복구 bytes/dirty/이름, 열린 탭 순서/활성 문서, 문서별 배율·맞춤·스크롤, 일부 사용자 설정 동기화, 브라우저 원본 파일 handle 및 fingerprint 재연결. 이를 다시 ‘전부 미구현’으로 적지 않는다.

| 할 일 | 현재 경계 | 완료 조건 |
|---|---|---|
| 재실행 커서·선택·셀/개체 모드 | 문서별 스크롤 복원과 별개로 저장 계약 없음 | 한글이 기억하는 범위를 먼저 실측하고 동일 수명 구현 |
| 새 문서 기본 서식 | 용지·여백·방향·기본 글꼴/크기만 저장 | 기본 스타일·문단·번호·개요·다단/양식 관리 및 적용 범위 검증 |
| 대화상자 기억 | 일부 옵션만 저장 | 마지막 탭/단위/값, 확인·취소·재열기·재실행별 계약 수립 |
| 자동 복구 | Studio 설정과 shell 고정 1.4초 예약이 따로 존재 | 복구 끄기·간격·원본 저장과 복구본의 차이를 일관되게 적용 |
| 암호 문서 복구 | 평문 복구를 의도적으로 차단 | 암호화 복구 저장/재개 경로 및 실패·취소 처리 |
| 창/모니터 | 앱 자체 위치·최대화·DPI 저장 계약 없음 | OS/브라우저 복원과 구분하여 실제 런처·다중 모니터 검사 |
| 환경 설정 전체 | 일부 view/theme/font/autosave 저장 | 한글 환경 탭과 항목별 대응, 메뉴/키/도구상자 사용자화 저장 |
| 상태 이관·백업 | IndexedDB/localStorage origin별 저장 | 검수 포트/업데이트/PC 이동 시 workspace·환경 내보내기/가져오기 |
| AI 요청 되돌리기 | 최신 요청과 revision/undo top 일치 때만 가능 | 후속 수동 편집·중단·재실행 정책과 적용 단위 명확화; 안전한 선택 복원은 별도 확장 |
| 재실행 undo 이력 | 직렬화 없음 | 한글도 보존하는지 실측 전에는 ‘한글 대비 결함’으로 단정하지 않음 |

임시 참고 첨부를 새로고침 시 해제하는 것은 현재 설계다. 영구 첨부와 기관 공통 자료는 별도 기능으로 추가한다. 현재 상태를 모두 파일에 쓰는 방식은 피하고 문서 속성·사용자 설정·일시 상태를 각각 한글의 실제 수명과 비교한다. [상태·Agent 감사](evidence/hangul-comparison-2026-10-11/state-agent-code-audit.md)에서 코드 위치와 기존 상태표 S15/S16/S19 정정을 확인할 수 있다.

## 6. AI가 아직 제어하지 못하는 기능

현재 AI 편집은 **14종 명령**이다. 새 본문 문서, 본문 삽입/교체/삭제, 글자/문단 서식, 단순 표 생성/셀 내용·서식/행열 추가·삭제, 기존 구역의 용지·여백 설정이다. 요청당 30명령, 문서 입력 120,000자 등 한도가 있다. 글자 서식은 문단 전체, 셀은 한 문단·동일 서식·컨트롤 없음으로 제한되며 병합·중첩 표를 허용하지 않는다.

| 우선 연결할 AI 기능 | 엔진/수동 기능과의 관계 |
|---|---|
| 혼합 서식 범위, 문단 나누기/합치기/이동/복제, 찾아 바꾸기 | 엔진 경로와 안전한 대상 주소 연결 필요 |
| 스타일·글머리표·문단 번호·탭/문단 테두리 | 수동 기능 존재. AI schema와 검증/undo 미연결 |
| 표 병합/분할·크기·여백/테두리·배치·반복 제목·계산·중첩 구조 | 수동 기능이 있어도 현재 AI 명령은 없음 |
| 구역·다단·쪽/단 나누기·머리말/꼬리말·쪽 번호·바탕쪽 | 일부 수동 기능 존재, 일부는 편집기부터 추가 필요 |
| 그림·도형·글상자·수식·캡션·개체 위치/자산·차트 | 기존 수동/API 재사용 범위를 유형별 검증 |
| 각주·미주·누름틀·책갈피·링크·상호참조·메모·변경 추적 | 수동 미구현 기능과 AI 미연결 기능을 분리해 개발 |
| 문서 열기/닫기/전환·저장·PDF/인쇄·문서 속성/보호 | 사용자가 실행하는 기능은 있지만 AI tool 계약에 없음 |
| 긴 문서 추가 조회, 변경 후 구조/출력 관찰 | 전체 자료를 한 번 넣는 방식에서 필요한 노드를 추가 조회하는 도구로 확장 |

Agent 확장도 아직 남아 있다. 현재 RAG는 **지정 자료의 어휘 검색**, loop는 **후보 검토 최대 3회 후 한 번 적용**이다. 둘을 미구현이라고 지우지 않되, 영구 인덱스·증분 갱신·임베딩/reranker·OCR·PDF/DOCX/XLSX 분석·쪽/셀 출처·일반 도구 실행 loop·실패 후 관찰/재계획은 추가 과제다.

반복 작업은 7종 명령의 저장·변수·재실행 수준이다. 기존 표/쪽 명령, 키/마우스 녹화, 한글 매크로 호환, 조건/반복·다중 파일 일괄 처리는 없다. 브라우저 로그인 인증과 **미저장 열린 문서를 제어하는 제품 MCP server**도 없다. MCP는 내부 공통 명령·권한·버전·undo 계약을 외부에 노출하는 별도 연결 계층이며, 편집기 기능 구현 자체를 대신하지 않는다.

## 7. 실제로 ‘같이 동작한다’고 판정할 검사

각 기능군을 다음 단위로 분해하여 두 앱에 같은 복사본·입력을 사용한다.

1. 메뉴·단축키·빠른 메뉴로 진입, 기본값/활성 조건/포커스 기록.
2. 본문·일반 표·병합/중첩 표·개체·머리말/각주·IME 조합에서 적용/취소 비교.
3. dirty와 undo/redo 묶음, 취소 시 무변경, 커서/선택 복귀 확인.
4. HWP/HWPX 각각 원본→무수정 저장→단일 수정 저장→실제 한글 재열기→Jueony 재열기.
5. 글꼴·줄/쪽 수·표 분할·개체 위치·필드·자산을 비교하고 PDF/인쇄 결과도 대조.
6. 문서 전환·닫기/재열기·앱 재실행·환경 변경·원본 외부 수정·저장 실패에서 상태 수명 검사.

최소 표본군: 기본 본문/혼합 서식, 번호·스타일, 여러 쪽 병합·중첩 표, 여러 구역·머리말·다단·바탕쪽, 그림/도형/글상자/캡션, 수식·차트·OLE, 각주·필드·메모/변경 추적, 암호·배포용 문서, 공문/계획/결과보고 양식. 각 표본은 원본을 보존하고 파생본으로 검사한다. 기존 공개 5개 표본만으로 전체 기능 통과를 선언하지 않는다.

## 8. 다음 작업 순서와 병렬 경계

1. **증거·재현 기반:** P0 표본과 물리 F6 재현, 저장 손실 보고 누락 및 상태 수명 실측. 사람이 익숙하게 편집하고 결과를 보존하는 것을 우선한다.
2. **편집 기본기:** 핵심 단축키/포커스, 표·쪽·머리말/번호, 기본값·대화상자 기억. 수동 UI와 엔진 보존을 함께 완료한다.
3. **AI 연결:** 통과한 수동 명령을 공통 계약에 추가해 범위·버전·원문·서식·undo를 검증한다.
4. **확장 기능:** 필드/검토/개체/업무 서식, RAG/실행 loop, 매크로, 인증/MCP를 순차 확장한다.

병렬 작업은 (A) 수동 UI/단축키, (B) 엔진/저장 호환, (C) 환경/상태 복원으로 나눈다. 공통 문서 모델·bridge·build 파일 변경은 한 통합 담당자가 조율한다. AI 확대는 B의 해당 명령 보존 검증 이후 진행한다. 외부 협업 서비스는 공문 작성 필수 기능과 별도로 범위를 결정한다.
