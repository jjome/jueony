# 기본 편집·상태 보존 보강 결과

2026-10-11. 모듈 리팩터링 `e08edcc`를 원격 저장소에 반영한 뒤, [한글 차이 목록](hangul-2024-gap-checklist.csv)의 편집·저장 결함부터 보강했다. **이번 결과는 아래 범위의 구현과 회귀 검증이다. 한글 2024 전체 기능·화면·조판의 동등성을 달성한 것은 아니다.**

## 실행과 확인

최신 검수본은 [`build/jueony-features-20261011/Start-Review.cmd`](../build/jueony-features-20261011/Start-Review.cmd), 포트 **4193**이다. 이미 이 검수본을 실행 중이라면 문서를 저장하고 창을 닫은 뒤 같은 폴더의 `Restart-Jueony.cmd`를 실행한다. 기존 4173/4191/4192 묶음은 그대로 둔다. 포트별 업무 저장소가 달라 기존 업무·연결이 자동으로 표시되지 않을 수 있다.

1. 문서를 열고 **F6**으로 스타일 창을 연다. 채팅과 문서 사이의 포커스 이동은 **Alt+F6**이다.
2. **쪽 → 머리말/꼬리말**, 또는 **Ctrl+N,H**에서 종류와 양쪽·홀수·짝수 적용을 선택한다. 기존 내용이 있으면 그대로 편집한다.
3. **쪽 → 감추기**, 또는 **Ctrl+N,S**에서 현재 쪽의 머리말·꼬리말·바탕쪽·테두리·배경·쪽 번호를 선택한다. 취소·되돌리기와 저장 후 복원을 지원한다.
4. 본문의 표·그림·도형을 선택해 캡션 위치와 없음을 사용한다. 각 변경은 편집기 되돌리기에 기록된다.
5. **파일 → 문서 정보**에서 저장 전 내용의 문단·개체·글자 통계를 확인한다. 한글 통계와 계산 범위가 같다는 뜻은 아니다.
6. **도구 → 환경 설정 → 파일**에서 정기 복구와 쉬는 동안 복구를 조절한다. 두 옵션을 모두 끄면 새 복구본을 만들지 않고 이전 복구본을 유지한다. 원본 파일 저장은 별도 명령이다.

실제 한글에서 열어 볼 합성 검수 파일은 [검수 문서](evidence/features-2026-10-11/documents/)와 실행 묶음의 `review-documents`에 있다. `agent-style-columns-hide.hwp/.hwpx`는 문단 스타일·2단·머리말/쪽 번호 감추기, `page-hide.hwp/.hwpx`는 감추기, `header-preserved.hwpx`는 기존 머리말 보존, `table-caption.hwpx`는 표 오른쪽 가운데 캡션이다. 실제 한글에서 외관·쪽 수·캡션 배치·재저장을 별도로 비교해야 한다.

## 구현 범위

| 영역 | 실제 변경 | 남은 제한 |
|---|---|---|
| 단축키 | F6 선점 해제, Alt+F6 채팅 이동, 셀 블록 L/C/B/F 테두리·배경 탭, Ctrl+N,F 계산식, 표 문맥 Ctrl+N,C 캡션 | 모든 한글 단축키·IME·물리 키 조합이 검증된 것은 아님 |
| 캡션 | 본문 표·그림·도형의 8개 위치와 없음, 기존 간격·너비 보존, snapshot undo | 중첩 개체·머리말·각주·다중 선택 대상은 제한 |
| 머리말·꼬리말 | 통합 선택 창, 구역별 양쪽·홀수·짝수, 없는 대상 생성, 기존 내용 보존, 생성 undo/redo | 한글의 모든 양식·대화상자 항목과 UI 동일성 미검증 |
| 감추기 | 문서 PageHide 6개 플래그를 실제로 변경, 같은 쪽 기존 부호 재사용, 저장·undo | 여러 부호가 충돌하는 쪽과 앞쪽에서 시작한 연속 문단 대상은 거부 |
| 문서 정보 | 최신 메모리 내용의 통계·사용 글꼴·원본 암호 속성 조회 | 개인 정보·문서 이력 편집과 한글 통계 동일성 미구현 |

| 저장 보존 | HWP/HWPX 수동 저장·복구·AI 사전 검증에서 직렬화 보고서와 재열기 속성 대조 | 같은 엔진 검사이며 알려지지 않은 원본 레코드의 완전 보존 증명은 아님 |

복구 주기는 기본 10분(1~120분), 쉬는 동안 복구는 기본 10초(5~600초)다. 한글의 기본값을 이번에 실측한 수치는 아니다. 문서 선택·스크롤만 바뀌면 기존 복구 바이트와 보기 상태만 저장하며 문서 직렬화를 반복하지 않는다. 작업·채팅·환경 설정의 저장은 두 문서 복구 옵션과 독립적이다.

## AI 편집 계약

기존 14종에 아래 3종을 더해 **17종의 구조화된 명령**을 사용한다. UI·Agent·LLM adapter는 기존 public 계약을 통하고, 실제 WASM 호출은 `adapters/rhwp`에 둔다. 외부 MCP 서버를 추가한 작업은 아니다.

| 명령 | 입력·검증 | 실행 |
|---|---|---|
| `apply_paragraph_style` | 현재 문서의 편집 가능한 본문 ID와 기존 문단 스타일 ID | 문단 스타일 적용 |
| `set_columns` | 구역·1~6단·0~100mm 간격, 단 너비 최소 10mm, 같은 요청의 용지·여백 변경도 검사 | 너비가 같은 일반 다단 구성 |
| `set_page_hide` | 본문 대상과 6개 boolean, 같은 쪽의 기존 대상 검사 | 지정 감추기 플래그 변경 |

AI는 최신 미저장 문서와 스타일·단·감추기 속성을 읽는다. 사본에서 요청 전체를 실행하고 저장·재열기 검사를 통과한 뒤 현재 문서 버전을 다시 확인하여 적용한다. 요청 단위 undo를 유지한다. 복잡한 제어 문단, 스타일 생성·상속 편집, 불균등 단, 개체 전체 제어는 추가 구현이 필요하다. 감추기 부호가 있는 문단의 일반 본문 편집은 기존 inline-control 제한의 영향을 받을 수 있다. 새 3종을 반복 작업 매크로에 저장하는 기능은 아직 추가하지 않았다.

## 저장 보존 검사

직렬화기의 손실 보고만으로 통과시키지 않고 새 문서를 다시 열어 본문 글자 run·문단 속성·스타일, 중첩 표 셀 run, 구역·용지·다단·감추기, 컨트롤 순서·속성, 필드·책갈피·머리말 텍스트·노출된 그림 바이트 해시를 비교한다. 실패하면 원본 파일이나 기존 복구본을 덮어쓰지 않는다. 한도는 문단 10,000개·run 40,000개·컨트롤 20,000개·그림 1,024개/128MiB이며 읽기 실패나 한도 초과도 차단한다.

실제 검사에서 HWP의 알 수 없는 컨트롤이 HWPX로 바뀌며 사라지는데 엔진 보고는 손실 0으로 나오는 사례를 재현했고, 새 검사로 차단한다. 반대로 HWPX의 구역/단 메타데이터 순서와 표 캡션 편집 후 내부 TextWrap 캐시 차이는 해석된 속성이 같으면 통과하도록 정규화했다. 실제 배치 속성 차이는 계속 거부한다.

HML, 암호/서명·변경 추적 전체, 해석되지 않은 XML·바이너리 레코드, 사용하지 않는 자산·OLE 원본 payload, 바탕쪽 전체와 머리말·각주·글상자 내부의 모든 서식은 완전 검증 범위 밖이다. **통과는 검사 가능한 값의 보존을 뜻하며 실제 한글의 조판·인쇄 동등성을 뜻하지 않는다.**

1. 실제 한글에서 위 7개 파일의 저장·재열기·외관 비교. 엔진 내부 재열기 통과와 별도 관문으로 유지한다.
2. 기본 탭 간격과 진짜 구역 분할을 Rust 엔진 패치·재빌드 단위로 구현한다. 현재 렌더러는 기본 탭 간격 4000 HU를 고정 사용한다([코드 근거](evidence/manual-controls-2026-10-11/tab-spacing-blocker.json)). `breakAtCursor('section')`만 연결하는 방식은 실제 구역 분할을 보장하지 않아 활성화하지 않았다.
3. [188행 차이 목록](hangul-2024-gap-checklist.csv)의 표/개체/메모/각주/차례·필드·변경 추적과 상태 수명을 순서대로 검수한다. UI의 기존 명령과 AI 명령 지원을 구분한다.
4. 검증된 편집 명령부터 AI·매크로에 확장한다. 브라우저 계정 인증, 외부 MCP, 일반 도구 loop, 임베딩 검색은 별도 설계·구현·평가 과제로 유지한다.

기본 편집·상태·파일 검수 담당은 병렬 작업했고, 공용 계약·shell·빌드·Git 통합은 한 담당이 순서대로 처리했다. [기존 계획](26-parallel-execution-plan.md)의 실제 한글 검수 관문과 전체 동등성 판정을 통과 처리하지 않는다.
