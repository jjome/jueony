# 구역 분할·기본 탭 간격 보강

2026-10-12. 기존 편집·저장 계층을 유지하면서 고정 rhwp 소스에 추적 가능한 Rust 패치를 적용한다. 한글 2024 전체 기능·조판의 동등성을 의미하지 않는다.

## 구현

- **쪽 → 구역 나누기 / Alt+Shift+Enter**: 본문 커서에서 실제 구역을 만든다. 문단 중간은 텍스트와 글자 run을 나누고, 문단 시작·끝은 문단 경계를 사용한다. 새 구역으로 커서를 이동하고 snapshot 하나로 되돌리기·다시 실행한다.
- 기존 구역의 쪽·구역·단 설정을 새 구역으로 이어받는다. 뒤에 있던 다른 구역은 순서와 설정을 유지한다. HWP BodyText stream과 HWPX section을 각각 저장한다.
- **서식 → 문단 모양 → 탭 설정 → 기본 탭 간격 변경**: pt 단위 입력과 현재 구역/문서 전체 범위를 지원한다. 구역의 다른 설정과 문단에 지정한 사용자 탭은 유지한다.
- 구역 설정 창의 탭 입력·표시도 같은 단위로 맞춘다. 저장 raw 값은 실효 HWPUNIT의 두 배다. 8000=40pt, 4000=20pt, 12000=60pt이며 0은 기본 40pt로 처리한다.
- 기본 탭 변경 후 본문·표·글상자·캡션·머리말/꼬리말 등의 탭 조판 경로를 구역별로 다시 계산한다. 탭이 없는 본문은 기존 저장 줄 구분을 유지한다. 탭 변경 undo는 설정뿐 아니라 원래 줄 구분을 복원한다.
- 문단 모양의 기본 탭 창은 열었을 때의 문서 버전·구역 값과 달라지면 적용을 거부한다. 지원하지 않는 중첩 위치, 선택 영역, 컨트롤·필드·범위 태그를 포함한 분할 대상은 변경 전에 거부한다.

## 구현 경계

`engine/patches/default-tabs.patch`와 `section-split.patch`가 제품 엔진 변경의 원본이다. `upstream/rhwp-source`는 기준 커밋 `1a76570e833917d15817415a53c09ad61ab3203f` 그대로 유지한다. 빌드 스크립트는 별도 소스 사본에 patch 적용·역방향 검사를 수행하고 WASM/JS·patch SHA256을 남긴다. 프런트엔드는 모든 patch와 바이너리 해시가 일치한 엔진만 연결한다.

검증 중 신규 표의 바깥 여백과 흐름 속성이 저장 전후 달라지는 기존 결함을 발견했다. 구역 분할 없는 대조에서도 HWP/HWPX 모두 재현됐다. `table-creation-consistency.patch`는 신규 표 생성 시 메모리 IR과 기존 저장용 raw 기본값을 일치시킨다. writer와 보존 검사는 유지하며 한글의 신규 표 기본값을 이번에 실측했다는 뜻은 아니다.

초기 빌드에서 사본이 제품 Git 작업 트리 아래에 있어 `git apply`가 경로를 건너뛰면서 성공 코드를 반환한 문제도 발견했다. 저장소 루트에서 `--directory`로 적용하고 역방향 검사 및 컴파일된 실제 API 확인을 추가했다. 초기 바이너리와 실패 기록을 최종 성공 검증으로 사용하지 않는다.

UI → 명령 계층 → WASM 편집 명령 → 동일한 열린 문서라는 기존 경계를 유지한다. 디스크 문서를 따로 수정하지 않는다. 이번 두 기능을 Agent의 구조화된 명령 계약에 추가한 것은 아니다. Agent 17개 명령의 범위는 기존 결과 문서를 따른다.

Windows의 응용 프로그램 제어가 Cargo 생성 실행파일 실행을 차단하여 설치된 Ubuntu WSL에서 Rust 1.93.1, `cargo --locked`, wasm-bindgen 0.2.127로 빌드한다. 검수용 release WASM이며 wasm-opt를 실행한 배포 최적화 빌드는 아니다. 보안 설정은 변경하지 않았다.

## 한글 2024 비교 근거와 남은 검증

한컴 [구역 나누기 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/break/section_break.htm)은 Alt+Shift+Enter, 새 쪽 시작, 구역 설정 상속을 설명한다. [구역 설정 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/section/section.htm)은 기본 탭 40pt와 구역별 적용을 설명한다.

설치된 한글 2024의 `Normal.hwtx`를 읽어 `tabStop=8000`, `tabStopVal=4000`, `tabStopUnit=HWPUNIT`을 확인했다. 원본 템플릿은 복사하거나 배포하지 않고 경로·해시·관련 속성만 [독립 기준 기록](evidence/sections-tabs-2026-10-12/hancom-baseline.json)에 남겼다.

**한글 2024 실제 입력·인쇄 비교는 미완료**다. Computer Use가 동일한 한글 창에서 `failed to activate captured window`를 반환했고 창을 재탐색한 뒤에도 실패했다. 사용자 답변 후 상태 확인에서도 기존 창/스타일 창이 유지돼 새 검증 입력을 수행하지 못했다. 이 기록을 저장·재열기 검사 성공과 혼동하지 않는다. 실제 한글 비교 PDF 없이 렌더링 golden을 새로 등록하지 않았다.

## 한글에서 확인할 절차

검수 묶음 `review-documents`의 합성 문서는 업무·개인 자료를 포함하지 않는다. 원본 대신 사본을 열고 아래를 비교한다.

| 검수 문서 | 비교할 항목 |
|---|---|
| `boundary-0`~`boundary-6` HWP/HWPX | 첫/중간/끝/빈 문단 경계, 2개 구역, 새 쪽 시작, 본문 순서 |
| `mixed-runs-tabs` | 한글·이모지·탭 글자, 분할 전후 굵은 글자 범위 |
| `four-sections` | 중간 구역 분할 후 4개 구역 순서와 마지막 구역 60pt 탭 설정 |
| `table-header-sections` | 새 구역으로 이동한 표 셀 내용과 머리말 보존 |
| `tabs-20pt/40pt/60pt` | 문단 모양/구역 설정 표시값, 탭 뒤 글자 실제 위치, 쪽 수 |
| `scoped-and-explicit-tabs` | 구역별 간격 차이와 명시적 사용자 탭 위치 유지 |
| `new-table-properties`, `nested-cell-header-tabs` | 새 표 기본값 저장 보존과 셀·머리말의 탭 위치 |
| `ui-section-split.hwpx`, `ui-default-tabs-20pt.hwpx` | 실제 앱 UI에서 변경·저장한 문서 재열기 |

1. 한글 2024에서 각 형식의 파일을 연다. 쪽 수·본문·표·머리말·서식과 구역/탭 설정을 기록한다.
2. 중간 문단에 직접 Alt+Shift+Enter를 입력한 한글 기준 문서를 만든다. 시작/끝/빈 문단도 같은 작업을 반복한다.
3. 한글에서 새 구역의 쪽 크기·여백·단·탭 설정과 커서 위치를 확인한다.
4. 구역별 기본 탭 20/40/60pt와 사용자 탭을 직접 설정한 기준 문서를 만든다.
5. Jueony와 한글 양쪽에서 PDF를 내보내 동일한 글꼴·용지·배율로 쪽 수와 위치를 비교한다. 합격 기준은 비교 계획의 독립 렌더링 gate를 따른다.
6. 한글로 저장한 사본을 Jueony에서 다시 열어 재저장하고 한글에서 확인한다.

## 남은 제한

- 구역 경계를 Delete/Backspace로 합치는 한글 동작은 이번 구역 분할 API 범위 밖이다. undo로 이번 삽입을 취소할 수 있다.
- 구역 설정의 ‘새 구역부터’ 범위, 중첩 위치/컨트롤을 포함한 대상의 분할, 모든 특수 부호·바탕쪽 payload 보존은 추가 개발/검증이 필요하다.
- 여러 구역의 미주가 마지막 구역에 모이는 경우의 탭 원점, 상대 글자 단위 HWPX 탭은 실제 한글 비교가 남는다.
- HWPX의 표 `restrictInPage`·`allowOverlap` true 값은 기존 getter의 공통 IR 반영이 불완전해 추가 보강이 필요하다. 이번 신규 표 false 기본값 정합성 보강으로 이 전체 문제를 해결했다고 판단하지 않는다.
- 같은 엔진의 보존 검사는 알려지지 않은 원본 레코드와 한글의 실제 조판·인쇄 동일성을 보증하지 않는다.

근거 파일은 [검증 기록 폴더](evidence/sections-tabs-2026-10-12/)에 있다. 32개 엔진 합성 파일과 실제 UI 저장 파일 9개, 총 **41개 HWP/HWPX**를 실행 묶음의 `review-documents`에 넣는다. 엔진 진단은 기존 test fixture/golden을 변경하지 않는 별도 기능 진단이다. 252개 회귀는 기존 공식 npm 엔진을 포함한 단위 검사이고, 새 패치 엔진의 실제 동작 근거는 9개 진단 그룹과 12/9개 브라우저 시나리오다.

브라우저 검사는 임시 Edge 프로필·독립 테스트 포트·메모리 연결 저장소와 합성 모델을 사용한다. 사용자 DB와 API 키를 변경하거나 유료 LLM을 호출하지 않았다. 편집·복구 통합 검사의 외부 네트워크 요청과 page error는 0건이다. 빌드 당시 HEAD는 `c3f1058`이며 검증·문서 변경이 포함된 작업 상태에서 생성했다. 실제 JS/WASM·patch·제품 소스 해시로 같은 빌드를 구분한다. 이번 실행 묶음은 개발 검수용이고 한글 2024 호환성 인증 또는 배포 완료 판정이 아니다.
