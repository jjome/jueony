# 문단 단축키와 선택·표 셀 상태 저장

2026-10-12. [기본 편집·본문 커서 보강](37-basic-editing-state-result.md)에 이어 구현했다. 문단·선택 구현은 `bcb6e3c`, 종료 저장·문맥 보호는 `fd2bd45`로 푸시했다. 실제 한글 2024와 완전히 같은 동작을 검증한 상태는 아니다.

## 사용할 수 있는 기능

| 조절 대상 | 줄이기/내어쓰기 | 늘이기/들여쓰기 |
| --- | --- | --- |
| 문단 왼쪽 여백 | Ctrl+Alt+F5 / Ctrl+Shift+E | Ctrl+Alt+F6 / Ctrl+Shift+G |
| 문단 오른쪽 여백 | Ctrl+Alt+F8 / Ctrl+Shift+F | Ctrl+Alt+F7 / Ctrl+Shift+D |
| 첫 줄 위치 | Ctrl+F5 / Ctrl+Shift+O | Ctrl+F6 / Ctrl+Shift+I |
| 문단 양쪽 여백 | Ctrl+F7 | Ctrl+F8 |

매핑은 [한글 2024 공식 단축키 표](https://help.hancom.com/hoffice130/ko-KR/Hwp/view/toolbar/shortcut(table).htm)를 따른다. 각 조절을 **1pt**씩 적용한다. 왼쪽/오른쪽 1pt는 [공식 문단 속성 설명](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/paragraph/paragraph(attributes).htm)에 명시되어 있다. 첫 줄은 공식 설명의 “한 글자”와 실제 pt 증가량을 대조할 필요가 있어, 현재 1pt 구현을 실측 완료로 표시하지 않는다. 양쪽 조절의 한글 실측도 남는다.

본문·본문 선택·일반 표 셀·선택한 셀 블록에서 동작한다. 각 문단의 기존 값에 상대 값을 더하므로 서로 다른 여백을 같은 값으로 덮지 않는다. Ctrl+클릭으로 제외한 셀은 바꾸지 않는다. 한 번의 키 입력은 한 번의 undo로 되돌린다. 키를 누르고 유지하면 반복 조절하며, 다른 대화상자 단축키는 반복 실행하지 않는다. 0에서 여백을 줄이는 무변경 작업은 undo/redo를 지우지 않는다.

지원 범위는 좌우 여백 0~999pt, 첫 줄 -999~999pt다. 이미 이 범위 밖인 값은 조절을 거부한다. 양식 모드·개체 선택·머리말/주석·글상자·중첩 셀은 이번 조절 대상에서 제외한다. IME 조합 중이나 편집 대화상자가 열렸을 때 본문에 적용하지 않는다. 브라우저가 일부 키를 먼저 처리하는 경우에는 같은 기능의 대체 키를 사용할 수 있으며, Windows 호스트/실제 한글의 키 전달 비교는 별도다.

## 저장·복원되는 위치와 선택

- 본문 커서와 정방향/역방향 텍스트 선택. 선택 시작점과 끝점 및 엔진의 F3 확장 단계를 보존한다.
- 일반 표 셀의 Unicode 문자 위치와 같은 셀 안 여러 문단의 텍스트 선택.
- 일반 표의 F5 셀 블록: 시작·끝 좌표, 단계, Ctrl+클릭 제외 셀. 병합 셀의 커서도 검수했다.
- 확대율·스크롤과 함께 재실행·탭 전환 후 복원한다. 채팅 포커스를 빼앗거나 문서 dirty/내용을 바꾸지 않는다.

본문 양 끝의 길이·앞뒤 문맥을 검증하고, 선택에 포함되는 본문 문단 전체의 텍스트 hash를 확인한다. 표는 행·열·병합 구조와 셀 문단 내용 hash를 확인한다. 중간 문단이나 다른 셀의 내용이 바뀌었으면 저장된 선택을 그대로 적용하지 않는다. 표가 없어지거나 위치가 범위를 벗어나도 복원하지 않는다.

검증 한도는 본문 선택 1,000문단/100,000문자, 표 512셀/1,024문단/100,000문자다. 한도를 넘으면 검증 데이터를 잘라서 저장하지 않고 해당 커서/선택의 저장을 건너뛴다. 중첩 표·글상자·머리말·주석·개체 선택은 남은 작업이다. 암호 문서의 원문 발췌가 커서 정보에 들어가지 않도록 기존 암호 저장 정책을 따른다. 재실행 후 undo 이력 복원은 이번 범위가 아니다.

이 정보는 **Jueony 로컬 세션 값**이다. HWP/HWPX 파일 안에 선택 범위를 넣거나 한글의 커서 저장 메타데이터와 동일하다고 주장하지 않는다.

## 종료 직전과 입력 경쟁 처리

보기 변경은 기존 IndexedDB 문서 기록으로 저장한다. 선택만 바꾸어도 `cursor-rect-updated` 이벤트가 저장을 예약하므로, 문서를 수정하거나 스크롤해야만 커서가 남는 구조를 보정했다.

1.4초의 저장 지연 전에 앱을 재실행하는 경우를 위해 `beforeunload`/`pagehide`에서 작은 보기 기록을 동기 저장한다. 이 기록에는 문서 bytes나 API 키가 없다. 업무 ID·문서 ID·복구본 시각이 모두 일치하고, 일반 보기 저장보다 최신일 때만 복원한다. 최대 64개 기록과 1MB 한도를 두며 활성 문서를 우선한다. 손상/미래 버전·저장 공간 오류는 조용히 덮지 않고 오류로 처리한다. 저장 완료 시각은 단조 증가하여 대기 중인 이전 저장이 최신 종료 기록을 이기지 않는다.

레이아웃을 기다리는 동안 사용자가 키·마우스·스크롤 입력을 하거나 문서가 바뀌면 이전 복원을 취소한다. 그 도중 종료 기록을 캡처해도 오래된 대기 값 대신 현재 사용자 위치를 기록한다. 프로세스 강제 종료·전원 차단처럼 종료 이벤트 자체가 실행되지 않는 상황까지 보장하는 것은 아니다.

## 발견한 결함과 수정

- rhwp의 표시용 문단 속성은 px 값을 소수 한 자리로 반올림한다. 이를 상대 편집에 되쓰면 13.3px→원래 정수로 변환하는 과정에서 여백이 조금씩 변했다. 엔진의 `getParaShapeSet` 원본 정수를 읽고, 2배 HWPUNIT 기준 200씩 조절하도록 수정했다. 기존 소수 pt 값도 유지한다.
- 합성 키 이벤트 대상이 Window/Document인 경우 `closest`가 없는 객체를 HTMLElement로 처리하던 오류를 수정했다. 모든 최종 검사에서 페이지·콘솔 오류가 0개다.
- 셀 선택 시험은 단일 셀 이동과 직사각형 범위 설정을 구분하여 보정했다. 실제로 선택한 모든 셀과 제외 셀 각각의 정수 여백 값을 검사한다.

실패 기록은 `focused/`, `merged-exclusions/`, `browser/`에 남기며, 최종 판정은 **`verified/result.json`**을 따른다. 허용 오차를 늘려 반올림 결함을 통과시키지 않았다.

## 모듈과 검증

문단 증감 정책은 `shortcuts/paragraph-spacing.ts`, 원본 정수 조회는 rhwp adapter, 대상 선택·atomic snapshot/undo는 InputHandler 공개 명령이 맡는다. 선택 DTO 검증은 preferences domain, 실제 엔진 조회와 복원은 rhwp adapter, 레이아웃/입력 경쟁은 preferences facade, 종료 기록은 preferences의 storage port와 shell에서 연결한다. 읽기 전용 upstream과 Rust/WASM 패치는 바꾸지 않았다.

## 실행과 한글 확인용 문서

실행: **[Start-Review.cmd](../build/jueony-selection-state-20261012/Start-Review.cmd)**, 포트 **4198**. 이전 실행 묶음과 다른 포트의 업무 저장소는 유지한다. 새 포트의 업무·대화가 이전 포트에서 자동으로 공유되지는 않는다.

`review-documents/paragraph-spacing.hwp`와 `.hwpx`에서 첫 문단의 왼쪽 11pt/오른쪽 20pt/첫 줄 5pt, 둘째 문단의 왼쪽 31pt/오른쪽 40pt/첫 줄 0pt를 한글에서 확인할 수 있다. `merged-cell-cursor.hwpx`는 병합 표본이다. 커서·선택 저장은 Jueony 세션에서 확인하고, 파일 내용·서식 보존은 한글에서 별도로 확인한다.

이어서 실제 한글의 키 1회 조절량/경계/선택 수명, 중첩·특수 영역 저장과 전체 문단 모양 기능을 비교·보강한다. 이번 결과를 전 기능 동등성이나 G2/G3 전체 통과로 표시하지 않는다.
