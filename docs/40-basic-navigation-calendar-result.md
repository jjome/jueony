# 기본 편집 보강: 커서 이동 이력과 날짜·시간

2026-10-12. 문서 모양·선택 복원 작업에 이어 이전/다음 커서 위치와 날짜·시간 문자열 입력을 구현했다. 한글 전체 기능과 동등하다는 판정은 아니다. [기능 점검표](hangul-2024-gap-checklist.csv)의 상태를 구현·브라우저 검수·실제 한글 비교로 구분한다.

## 실행

- 검수 실행: [Start-Review.cmd](../build/jueony-basic-editor-20261012/Start-Review.cmd), 로컬 포트 4199.
- 데스크톱 실행: 같은 폴더의 `JueonyEditor.exe`.
- 새 구현이 포함된 프런트엔드 프로필은 `navigation-history`다. 이전 검수 빌드는 별도로 유지했다.
- `review-documents/`의 `calendar-string.hwp`, `calendar-string.hwpx`, 문단 여백·구역 분할·병합·기본 탭 간격 문서로 확인할 수 있다.

## 구현한 동작

### 이전/다음 커서 위치

`Ctrl+=`와 `Ctrl+Shift+=`로 열린 문서의 앞선 위치와 다음 위치로 이동한다. Shift를 누르면 key 값이 `+`로 바뀌는 물리 Equal 키도 처리한다. 이동 뒤 새로운 위치에 직접 커서를 놓으면 이전의 앞으로 이동 분기는 버린다.

본문과 일반 평면 표 셀에서 Unicode 문자 위치를 보존한다. 변경된 문단이나 표 구조를 가리키는 오래된 위치는 건너뛴다. 이동 자체는 내용을 바꾸거나 dirty/undo를 만들지 않는다. 최대 64개의 위치를 메모리에 보관하며 문서를 바꾸거나 다시 열면 비운다. 이력은 파일·workspace 저장소에 기록하지 않는다. 암호 문서, 중첩 표, 셀 블록, 개체 선택, 머리말/꼬리말, 각주/글상자는 지원 범위에서 제외한다.

검수 중 문서 로드가 WASM을 교체한 직후 이전 문서의 커서 주소를 새 문서 첫 이력으로 기록하는 문제를 찾았다. 문서 세대 변경 시 비우고, 로드 중에는 기록을 미룬 뒤 커서 초기화가 끝난 상태만 받아들이도록 수정했다.

### 날짜·시간 문자열

입력 메뉴와 `Ctrl+K,D`로 날짜·시간 문자열 창을 연다. 점 구분 날짜, 한글 날짜, ISO 날짜, 시각, 날짜+시각의 5개 형식과 미리보기·시각 새로고침을 제공한다. 컴퓨터의 현지 시각을 사용한다. 한 번 넣기가 한 번의 undo/redo이며 HWP/HWPX 저장에 포함된다.

창을 여는 동안 문서 버전이나 커서가 바뀌면 적용을 거절한다. 취소·Esc는 내용을 바꾸지 않는다. 현재 본문의 선택 없는 삽입점에 한정한다. 자동 갱신 날짜 코드, 사용자 형식, 표·특수 영역 삽입은 아직 구현하지 않았다. AI 도구 목록에 이 명령을 새로 노출한 것도 아니다.

추가 상태 보강에서 마지막으로 **성공적으로 넣은 형식**을 사용자 환경값 `jueony-calendar-format` v1에 저장했다. 재실행 뒤 다음 날짜 창에 복원하며 취소는 저장하지 않는다. 문서·날짜 시각·workspace 정보는 설정에 넣지 않는다. 손상된 값이나 더 새로운 버전은 덮어쓰지 않고, 알 수 없는 추가 속성은 유지한다. 설정 저장이 실패해도 이미 성공한 문서 입력은 유지하고 알림을 표시하며 창을 닫아 중복 삽입을 방지한다. 기본 형식은 점 구분 날짜이고 저장소 오류 시 그 형식으로 입력할 수 있다. 한글의 마지막 형식 복원 정책 자체는 아직 비교하지 않았다.

### 모듈 경계

`preferences/domain/navigation-history.ts`는 위치 이력 정책, `document/domain/calendar-stamp.ts`는 순수 형식·달력 검증이다. 각 모듈의 `public/index.ts`가 계약을 내보낸다. `adapters/rhwp`가 커서 복원과 엔진 명령을 연결하고 `adapters/browser`가 시계·대화상자를 담당한다. 기존 편집기와 undo 계층을 재사용했다. 공급자 adapter나 Agent 업무 흐름에 편집기 구현을 넣지 않았다.

## 실제 한글 2024 비교

사용자가 문단 모양 창을 닫은 뒤 본문에서 각 키를 한 번 적용하고 `Ctrl+S`로 저장했다. 대화상자를 반복해서 열지 않고 저장한 ZIP/XML을 Python으로 읽었다. [원시 XML 값](evidence/navigation-history-2026-10-12/native-spacing.json)과 `native-files/`의 단계별 문서를 제공한다. 원래 시험 파일은 백업했고 한글 문서를 닫은 후 복원했다. 복원 해시는 `38f2483ff4f63695992d47a5dd67af58e30c366931ec1718acd021a50f06bff2`로 원본과 같다.

본문 한 문단, 함초롬바탕 10pt의 좁은 비교 범위다. HwpUnitChar case는 100, legacy default는 200의 저장 값이 1pt에 해당했으며 앱의 정수 표현·HWPX 저장 분기와 맞는다.

| 실제 키 입력 | 저장 값의 변화 | 판정 |
|---|---|---|
| Ctrl+F6 | 첫 줄 1pt, 문단 모양 창에서도 1.0pt | 앱의 1pt 단계와 일치; 처음 상태의 직접 baseline 관찰은 없음 |
| Ctrl+Shift+G / E | 왼쪽 0→1→0pt | 일치 |
| Ctrl+Shift+D / F | 오른쪽 0→1→0pt | 일치 |
| Ctrl+F5 | 첫 줄 1→0pt | 일치 |
| Ctrl+Shift+O / I | 첫 줄 0→-1→0pt | 일치 |
| Ctrl+F8 | 양쪽 1→0pt | 공식 도움말·현재 앱 매핑과 불일치 |
| Ctrl+F7 | 양쪽 0→1pt | 공식 도움말·현재 앱 매핑과 불일치 |

[공식 단축키 일람](https://help.hancom.com/hoffice130/ko-KR/Hwp/view/toolbar/shortcut%28table%29.htm)은 양쪽 감소를 F7, 증가를 F8로 안내한다. 이 설치의 관찰은 반대다. 현재 앱은 공식 매핑을 유지했다. 설치의 사용자 키 설정/한글 구현 차이 여부를 확인하기 전 전체 기본 매핑을 조용히 뒤집지 않는다. 양쪽 키는 **실제 한글과 같다고 판정하지 않는다**. 다른 글자 크기, Ctrl+Alt 대체 키, 연속 반복·최댓값·셀 블록·특수 영역의 실제 한글 비교도 남아 있다.

앱에서 날짜 문자열을 넣어 저장한 `verified/calendar-string.hwp`와 `.hwpx`는 실제 한글 2024에서 불러와 화면과 접근성 본문을 확인했다. HWP는 `2026.10.12 21:25:27기준 본문`, HWPX는 `2026.10.12 21:25:28기준 본문`, 각각 24글자·1쪽·1구역이었다. 날짜 시각은 독립 테스트 실행 시각이므로 두 파일의 초가 다르다. 복구 경고 없이 열렸지만 이는 복잡한 문서 전체의 시각적 호환성을 뜻하지 않는다. [재열기 기록](evidence/navigation-history-2026-10-12/native-calendar-reopen.json)을 제공한다. 두 창은 사용자가 직접 확인할 수 있게 열어 두었다.

## 대화상자 자동화의 현재 한계

스타일 창의 런처 복구는 앞선 검증 범위다. 이번 문단 모양 창은 `failed to activate captured window`가 반복됐고 런처 호출로도 닫혔다고 확인하지 못해 사용자가 직접 닫았다. 전체 모달 조작이 해결됐다는 뜻이 아니다. 텍스트 전용 관찰이 owned modal을 누락할 수 있으므로 화면 확인 없이 닫기 성공으로 판정하지 않는다.

파일 불러오기 창은 접근성 `set_value`가 `Cannot set a value for an element that is not settable`을 반환했지만, 새 화면의 파일 이름 위치를 클릭하고 포커스를 화면으로 확인한 후 입력·열기를 진행할 수 있었다. 접근성 포커스 문자열은 검색창으로 잘못 보고하는 사례가 있었다. 캡처·접근성·입력 캐시 불일치의 도구 한계이며 Jueony 편집기 코드나 한글의 보안 설정을 수정하지 않았다.

## 다음 순서

추가 상태 보강의 증거는 [calendar-format-state-2026-10-12](evidence/calendar-format-state-2026-10-12/)다. 291개 편집기 테스트, 실제 브라우저 36개 사례, 새 패키징 번들의 v1 상태·파일 저장 호환성 4개 사례, TypeScript·빌드와 9개 모듈/153개 파일 경계 검사를 통과했다. 위 표는 첫 커밋의 288/35개 결과이며 덮어쓰지 않았다. 새 브라우저 사례는 재실행 복원·취소·미지원 버전·저장 공간 오류에서도 문서 입력과 undo가 한 번만 이루어지는 것을 확인한다. 추가 상태 버전에서는 서버와 Agent 코드를 바꾸지 않았으므로 앞선 47/9개 결과를 사용한다. 실행 번들은 같은 4199 경로에 최신 프런트엔드로 다시 패키징했다. `bundle-build-host.txt`가 성공 기록이며 첫 sandbox 패키징은 설치 런타임 경로를 읽지 못해 실패한 시도다.

1. 양쪽 여백 F7/F8 차이를 설치 키 설정과 대조하고 매핑 기준을 확정한다. 먼저 다른 실제 문서와 새 문서에서 재현한다.
2. 커서 이력의 실제 한글 기록 시점·최대 개수·표/문서 전환 정책을 비교한다. 현재는 안전한 일반 영역만 지원한다.
3. 날짜·시간 코드와 사용자 형식, 문서 끼워 넣기를 별도 명령 계약으로 확장한다. 마지막 형식 저장의 실제 한글 정책을 비교한다.
4. 스타일·문단 모양 등의 owned modal 비교는 도구의 실제 입력 대상 보완이 필요하다. 저장 파일 비교로 가능한 검사는 이어간다.
5. 기존 기능 점검표의 표·개체·쪽 고급 항목을 작은 단위로 구현하고 실제 한글 재열기와 저장 계약을 함께 확인한다. 지원 확인 전 AI 명령으로 노출하지 않는다.
