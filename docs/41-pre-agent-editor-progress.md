# Agent 재구성 전 편집기 보강

후속 구현과 현재 실행본은 [편집기 통합 검수](44-editor-stages-result.md)를 따른다. 아래는 2026-10-12 시점의 지원 범위와 실패 기록이며 새로운 기능의 미구현 상태를 그대로 나타내지는 않는다.

2026-10-12. 사용자 요청 범위는 한글 비교 → 기본 편집·상태 → 표·개체·쪽 보강이며, Agent의 RAG/loop 구조 재구성은 그 뒤다. 이번 기록은 해당 범위의 중간 구현 결과다. 전체 한글 기능 동등성이나 Agent 재구성 전 완료 게이트를 통과했다는 의미는 아니다.

## 진행 순서와 게이트

후속 구현: 문서 끼워 넣기의 native 이식 함수를 파일 API로 연결한 결과는 [42번 문서](42-document-insertion-result.md)에 기록한다. 아래 상태는 이번 기록 시점의 이력이며, 문서 삽입의 최신 지원 범위·검수 결과는 후속 문서를 따른다.

| 순서 | 작업 | 현재 상태 | 다음 판정 기준 |
|---|---|---|---|
| 1 | 실제 한글 입력·대화상자 비교 | 조작 도구 재연결 뒤 본문 클릭은 가능했지만 F7 결과는 확정 못함. 사용자 Esc 중단 후 재개 호출에서도 중단 상태 반환 | 문단 모양/스타일 취소·저장, F7/F8 실제 기본 매핑을 재현하고 기록 |
| 2 | 기본 편집 | 빠른 내어쓰기 추가. 문서 끼워 넣기·날짜 코드·고급 스타일은 남음 | 서식/개체 보존 가능한 문서 삽입 경로와 문맥별 키 검사 |
| 2 | 상태 저장 | 본문/평면 셀/셀 블록에 이어 본문 표 개체 선택 복원 추가 | 그림·도형·중첩 표·특수 영역과 실제 한글의 수명/초기값 비교 |
| 3 | 표 | 선택한 표의 직접 행/열 뒤집기 추가 | 병합·부분 선택 크기·계산식·문자열 변환·고급 테두리의 저장 계약 검수 |
| 4 | 개체·쪽 | 기존 쪽 단색 배경의 HWPX 재열기 오류 수정 | 고급 글상자/차트/양식·바탕쪽/줄 번호/쪽 조작 등 점검표 항목 구현 |
| 5 | Agent 재구성 시작 여부 | 시작하지 않음 | 편집 명령과 저장 계약을 먼저 검증한 후 별도 설계/작업으로 진행 |

## 이번 구현

### 빠른 내어쓰기

- 본문 `Shift+Tab`, 일반 표 셀 `Ctrl+Shift+Tab`.
- 문단 첫 시각 줄에서 커서 앞의 실제 글자 폭을 조회한다. 현재 첫 줄 시작점은 보존하고, 다음 줄이 커서의 가로 위치에 맞도록 왼쪽 여백과 음수 첫 줄 값을 함께 바꾼다.
- 기존 정수 여백값을 유지하며 같은 커서에서 반복 실행하면 추가 undo/dirty를 만들지 않는다. 한 번 undo/redo와 HWP/HWPX 저장을 검사했다.
- 표의 `Shift+Tab`은 기존 이전 셀 이동이다. 새 본문 매핑이 그 키를 가로채지 않도록 했다.
- 본문/평면 셀 첫 줄의 선택 없는 커서만 지원한다. 여러 시각 줄, 범위 선택, 중첩 표, 머리말·각주·글상자는 거절한다. 실제 한글과의 조절 결과 비교는 미완료다.

순수 계산은 `document/domain/hanging-indent.ts` 공개 계약, 엔진 좌표·변경은 `adapters/rhwp/hanging-indent.ts`에 둔다. 기존 snapshot undo 라우터를 사용한다.

### 표 개체 선택 복원

- `DocumentViewState` v1의 optional cursor에 `table-object` 종류를 추가했다. 원본 문서 형식이나 workspace DB 버전을 바꾸지 않는다.
- 본문 표의 구역/문단/컨트롤 주소, 호스트 문단 문맥, 표 구조·셀 내용 SHA-256을 검증한다. 내용이나 구조가 바뀐 예전 표 선택은 복원하지 않는다.
- 최대 512셀/1,024셀 문단/10만 문자의 기존 제한을 적용한다. 중첩 표·그림/도형 선택·암호 문서는 새 복원 대상이 아니다.
- 개체 선택 변경 이벤트를 보기 저장과 연결했다. 재실행 뒤 선택을 복원해도 문서 dirty/undo를 만들거나 채팅 입력 포커스를 빼앗지 않는다.
- 첫 브라우저 시험은 내부 테스트 API로 열린 문서를 파일에만 저장하여 workspace의 bytes가 이전 빈 문서인 상태였다. 저장된 선택 자체는 정상인 진단을 확인하고, 실제 업무 화면의 저장 버튼으로 bytes와 view를 함께 기록한 시험에서 복원을 검증했다. 실패 기록은 삭제하지 않는다.

### 표 직접 뒤집기

- 본문 표 개체를 선택하고 `T` 또는 표 메뉴의 ‘표 뒤집기 (행/열 바꾸기)’를 실행한다.
- 기존 `transposeTableCellsInPlace` 엔진 primitive를 재사용한다. 클립보드를 거치지 않고 선택한 표 자체의 행과 열을 바꾼다.
- 셀 내용·Unicode·글자 서식, 한 번 undo/redo, HWP/HWPX 저장을 검사했다.
- 병합 없는 1,000셀 이하 표로 한정한다. 보호 셀과 중첩 표는 실행 전에 거절한다. 그림 개체 선택에서 T가 다른 객체를 변경하지 않도록 표 대상만 허용한다.

### 쪽 단색 배경 재열기 수정

기존 쪽 테두리/배경 창과 snapshot 경로를 검수했다. ‘무늬 없음’은 화면에서 0, native 단색 채우기에서는 -1로 표현되는데, HWPX 재열기 뒤 -1을 select에 그대로 넣어 선택값이 사라졌다. UI 표시와 native 값의 변환을 고쳤다. 알 수 없는 무늬값 때문에 선택값이 비면 기존 값을 보존한다.

단색 색상·종이 범위 적용, 취소·undo/redo, HWP/HWPX 저장·재열기 후 ‘무늬 없음’ 표시를 확인했다. 그러데이션·배경 그림·홀짝 구분·첫 쪽만 옵션은 이번에 구현하지 않았다. 이 검수는 실제 한글의 시각적 쪽 비교를 대신하지 않는다.

## 문서 끼워 넣기를 아직 연결하지 않은 이유

현재 엔진의 내부 클립보드는 문서 handle 안에 저장된다. 다른 열린 문서의 handle로 그대로 전달하는 계약은 없다. HTML 내보내기/붙이기만 연결하면 필드·OLE·구역·자산·스타일을 잃을 수 있어 한글 문서 삽입과 동일하게 노출하지 않았다.

다음 작업은 Rust 엔진의 문서 삽입 primitive 또는 검증 가능한 제한 범위를 정하고, 스타일/글꼴/자산 ID 재매핑·구역 정책·필드/개체 보존·부분 실패 rollback을 확인하는 것이다. 사본에서 삽입·저장·재열기를 검사한 뒤 열린 문서의 명령 계층으로 적용한다.
