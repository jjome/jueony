# 문서 끼워 넣기 구현과 검수

2026-10-12. Agent 재구성 전에 기본 편집기를 보강하는 순서에서 문서 끼워 넣기를 구현했다. 한글 전체 기능 동등성이나 Agent 재구성 전 완료 게이트를 통과한 것은 아니다.

## 사용 방법

검수 묶음은 `build/jueony-document-insert-20261012/Start-Review.cmd`, 포트 4201이다. 기존 묶음과 사용자 저장소는 유지한다. 포트가 다르면 브라우저 업무 저장소도 다르다. 루트 실행 스크립트의 기존 묶음을 이 결과로 자동 교체하지 않았다.

1. 문서를 열고 본문에 선택 없는 커서를 둔다.
2. `Ctrl+O` 또는 파일 메뉴의 **문서 끼워 넣기**를 실행한다. 불러오기는 기존 `Alt+O`다.
3. 로컬 HWP/HWPX 파일을 선택하고 사전 검사 결과를 확인한다.
4. 확인을 누르면 실제 열린 문서에 삽입된다. `Ctrl+Z` 한 번으로 전체 삽입을 되돌리고 다시 실행할 수 있다.
5. 저장 버튼으로 파일을 저장한다. 삽입 원본 파일은 수정하지 않는다.

`review-documents/`에는 자동 검사에서 저장한 결과 파일이 들어 있다. 같은 이름의 서로 다른 검사 파일은 `engine-insertion/` 하위에 별도로 둔다.

## 실제 지원 범위

| 항목 | 이번 동작 |
|---|---|
| 원본 | 단일 구역 HWP/HWPX, 본문·표·그림 |
| 위치 | 현재 문서의 일반 본문 커서. 범위 선택·표 셀·특수 영역·개체 선택·조합 중은 제외 |
| 서식 | 글꼴·글자/문단 모양·스타일·표 참조와 그림 자산 ID를 대상 문서에 재매핑 |
| 첫/끝 문단 | 커서 앞/뒤 본문과 연결. 내용 있는 대상 문단의 문단 모양은 유지. 빈 대상 문단은 가져온 첫 문단 모양과 스타일을 사용 |
| 쪽 설정 | 현재 문서의 용지·여백·구역·다단 설정 유지. 빈 문서에서도 원본의 쪽 설정을 가져오지 않음 |
| 크기 | 원본 32 MiB 이하, 전체 5,000문단/100,000문자/1,000표 셀, 중첩 깊이 8 이하. 서식 참조 한도 검사 |
| 실패/취소 | 적용 전 원본·현재 문서·삽입 결과 사본의 저장/재열기 검사. 실패하면 실제 문서 미변경. 실제 적용은 snapshot undo 경로 |
| 충돌 | 파일을 읽거나 검사하는 동안 문서 버전·커서가 바뀌면 적용 거절 |

머리말·꼬리말·각주·미주·필드·도형·차트·양식/OLE 등 다른 컨트롤이 있는 원본, 여러 구역 원본, 암호 문서는 미지원이다. 한글의 스타일 유지 선택 옵션·쪽 모양 가져오기·파일명 책갈피·다른 워드프로세서 형식도 이번 범위가 아니다. 문단 첫/끝 연결과 모든 개체 배치가 한글과 같다는 판정은 하지 않았다.

현재 보존 검사는 엔진이 공개한 텍스트·서식·구역·표·개체 속성·렌더 자산을 비교한다. 해석되지 않은 XML/바이너리, 바탕쪽 전체, 전자서명/변경 추적과 모든 캡션 run 등을 독립적으로 증명하지 못한다. 이를 보존 검사 통과나 실제 한글 재열기 성공만으로 100% 호환이라고 표시하지 않는다.

## 연결 구조

```text
단축키/통합 메뉴 → 명령 registry → DocumentInsertionDialog
                                    ↓ 로컬 파일 bytes
                            rhwp 삽입 adapter
                                    ↓ 원본/대상/결과 사본 검사
                         기존 input.executeOperation(snapshot)
                                    ↓ WasmBridge.insertDocumentBytes
                         Rust DocumentCore의 외부 문서 이식
```

- 엔진 변경은 `engine/patches/document-insertion.patch`에 추적한다. 참조 저장소는 수정하지 않는다.
- Rust의 기존 `paste_foreign_document_native` 내부 이식 함수를 재사용했다. 이전 41번 문서의 클립보드 handle 제약을 조사한 뒤, 파일 bytes를 받는 새로운 WASM API로 노출했다. HTML/텍스트 변환으로 대체하지 않았다.
- 기존 클립보드의 빈 문서 쪽 모양 가져오기 동작은 유지하고, 파일 삽입 경로에는 대상 쪽 모양 유지 정책을 전달한다.
- Studio 연결은 `scripts/integration/document-insertion-patches.mjs`에서 생성된 사본에만 적용한다. 새 bridge 메서드를 mutation registry에 등록하고 입력 명령 라우터로 실행한다.
- 브라우저 대화상자는 파일 선택과 진행 표시를 맡는다. 엔진 handle 수명·보존 검사·사본/실제 명령 실행은 rhwp adapter가 맡는다. UI나 Agent 업무 로직에 Rust 객체를 추가하지 않았다.
- 공급자/Agent/RAG/loop 코드는 이번에 변경하지 않았다. 파일 import만으로 자료 분석을 실행하지 않는다.

## 검수에서 고친 오류

HWPX에서 파싱한 embedded 그림은 `BinData.data_type`이 Embedding이지만 저장용 `attr`은 0이었다. 외부 문서 이식 후 HWP 저장이 이 값 그대로 기록하여 그림을 외부 링크로 해석했고, 재열기 시 가져온 그림 자산이 사라졌다. 이식한 바이너리 항목의 종류 비트를 모델에 맞게 재생성했다. 서로 다른 빨강/파랑 PNG를 사용한 네 가지 원본/저장 형식 조합에서 자산 SHA-256을 확인했다.

빈 대상 문단에는 첫 원본 문단의 모양만 전달하고 `style_id`는 이전 값을 유지하던 부분도 파일 삽입 정책에서 보완했다. 서로 충돌하는 스타일 ID, 새 글꼴과 굵기/크기 값의 이식·재열기를 검사했다.

검사 코드의 초기 실패도 보존한다. 굵기 API의 끝 좌표를 길이로 잘못 사용한 시험, 존재하지 않는 그림 목록 API, fontFamily를 native fontIds 대신 넘긴 시험을 수정했다. 버전 충돌 시험도 native primitive 직접 호출에서 실제 input 명령 라우터를 통한 변경으로 고쳐 사용자 편집의 버전 갱신을 검사했다. 기존 단위 검사의 페이지 배경 patch fixture 목록 누락도 보완했다. 실패를 제품 완료 결과로 계산하지 않는다.

## 검증 결과와 증거

증거는 [document-insert-2026-10-12](evidence/document-insert-2026-10-12/)에 있다.

- 편집기 단위 검사 294개 통과 (`editor-tests-verified.txt`).
- 새 Rust WASM 삽입 검사 12개 통과 (`engine-complete/result.json`). 네 가지 형식 조합, Unicode·혼합 서식·표·서로 다른 그림 자산·스타일/글꼴 ID, 대상 쪽 유지, 잘못된 원본/좌표 거절을 검사했다.
- 최종 브라우저 검사 52개 통과 (`final-verified/result.json`). 기존 편집/상태 저장 회귀와 새 파일 선택·사전 검사·취소/충돌·한 요청 undo/redo·저장·재열기·암호 대상 거절을 검사했다. 실제 유료 모델 호출은 아니다.
- TypeScript/프런트엔드 빌드 통과. 모듈 9개/파일 158개, 경계 위반 0 (`module-boundaries.json`).
- 새 묶음의 기존 v1 업무 자료 복원·저장 호환성 4개 통과 (`compatibility/result.json`).
- 엔진 manifest와 실제 WASM 해시는 `engine-complete/result.json`과 프런트엔드 build evidence에 기록한다. 기준 rhwp 0.8.7 커밋은 기존과 같다.

실제 한글 2024에서는 `Ctrl+O` 창 열기, Escape 취소, 합성 원본 삽입, `Ctrl+Z` 한 번 복원을 관찰했다. 새 엔진의 HWP/HWPX 저장 결과도 한글에서 직접 열어 본문·표·그림 표시를 확인했다. 기록은 `native-observations.json`이다. 모든 레이아웃·인쇄·스타일 옵션·재저장 차이의 동등성 검사는 아니다.

이번 파일 선택 창은 좌표 입력과 Escape가 동작했지만, 접근성 element index 입력이 `element ... is not available in cached app state for Hwp.exe`를 반환한 경우가 있었다. 갱신된 스크린샷으로 전환해 진행했다. 이전 스타일/문단 모양 대화상자 문제가 전부 해결되었다고 판단하지 않는다.
