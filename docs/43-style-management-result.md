# 스타일 관리 보강과 저장 검수

2026-10-13. 문서 끼워 넣기에 이어 F6 스타일 관리의 데이터 보존과 편집 동작을 보강했다. Agent 재구성이나 한글 전체 기능 완료를 뜻하지 않는다.

## 실행과 사용

검수 묶음: `build/jueony-styles-20261013/Start-Review.cmd`, 포트 4202. 루트의 기존 실행 묶음과 기존 포트의 업무 저장소는 유지한다.

- 문서에서 F6를 눌러 스타일 창을 연다. 목록을 선택하고 방향키/처음·끝 키로 탐색할 수 있다. Tab으로 버튼과 입력란을 이동하고 Escape로 현재 대화상자만 닫는다.
- `+`는 추가, 연필은 편집, `−`는 삭제, `⧉`는 선택한 스타일 복제다.
- 글자/문단 모양 하위 창에서 확정한 값은 상위 추가·편집 창의 임시 값이다. 상위 창을 취소하면 문서와 등록 글꼴은 바뀌지 않는다.
- 상위 추가·편집 창에서 확정하면 정의와 모양·새 글꼴 등록을 한 번에 적용한다. 그 뒤 F6 관리 창의 취소는 **이미 확정한 관리 작업을 취소하지 않는다**. 관리 작업마다 Ctrl+Z로 되돌린다.
- 복제는 본문에 적용하지 않고 새 정의를 만든다. 원본 이름 뒤에 ‘복사’를 붙이고 중복되면 번호를 더한다. 영문 이름은 비워 기존 정의와 구분한다. 원본이 자기 자신을 다음 스타일로 가리켰다면 복제본도 자기 자신을 가리킨다.

## 수정 내용

### 글자 스타일 종류와 임시 글꼴

기존 추가 화면에서 ‘글자’를 선택해도 문단 스타일 종류 0으로 저장되던 조건을 고쳤다. 글자 종류 1을 저장하며 글자 스타일에서는 문단 모양 버튼과 다음 문단 선택을 사용하지 않는다.

기존 글자 모양 하위 창은 확정 시 열린 문서에 글꼴 ID를 등록했다. 상위 스타일 창을 취소해도 DocInfo가 바뀌고 undo에 포함되지 않는 경로였다. 이제 글꼴 이름을 임시 값으로 유지하다가 최종 snapshot 명령 안에서 언어별 7개 ID로 해석한다. 취소 시 bytes/버전 불변과 최종 적용 후 한 번 undo를 검사했다.

하위 창을 다시 열면 이전 임시 모양을 표시한다. 문단 raw 거리와 화면 px의 변환을 adapter에서 처리하고 임시 배열/객체를 복사해 원본 속성을 수정하지 않는다.

### 검증·충돌·실패

스타일 이름/영문 이름은 공백을 정리하고 250 UTF-16 단위 이하로 제한한다. 제어문자·중복 이름·중복 영문 이름·잘못된 다음 스타일과 256개 초과 정의를 변경 전에 거절한다. 한글이 영문 이름 충돌을 병합하는 모든 규칙을 재현한 것은 아니다. 이번 정책은 다른 이름을 입력하도록 안내한다.

스타일 관리 창과 하위 편집 창이 문서 버전을 각각 확인한다. 외부 편집 후 예전 ID로 하위 편집을 새로 시작하거나, 삭제 확인 뒤 바뀐 문서에 적용하지 않도록 다시 검사한다. 오류는 창 안에 표시한다. 값이 그대로인 편집 확인은 문서 버전·undo·dirty를 추가하지 않는다.

### 표 내부 참조 삭제 보정

기존 Rust 스타일 삭제는 본문 문단만 보정했다. 삭제한 스타일 뒤의 번호가 당겨지면 표 셀의 예전 번호가 엉뚱한 정의나 없는 정의를 가리킬 수 있었다.

`engine/patches/style-reference-deletion.patch`에서 삭제된 ID는 바탕글 0으로, 뒤 ID는 하나 낮춘다. 본문·중첩 셀·캡션·글상자·머리말/꼬리말·각주/미주·메모·바탕쪽 등 모델의 문단 트리와 덧말 스타일 참조를 순회한다. 본문/평면 셀의 실제 편집·undo·저장을 브라우저에서 검사했고, 중첩 표는 저장 후 XML에서 ID를 독립적으로 확인했다. 특수 영역 각각의 한글 시각·적용 동등성 시험은 남았다.

삭제 후의 텍스트와 직접 적용한 모양은 유지하고 스타일 연결만 바탕글로 바꾼다. 다음 스타일의 삭제/뒤 번호 보정은 기존 엔진 동작을 재사용한다.

## 모듈과 연결

| 책임 | 위치 |
|---|---|
| 제공자/화면에 의존하지 않는 정의 검증 | `document/domain/style-definition.ts`, 공개 export |
| 임시 값 변환·글꼴 해석·복제·적용·문서 버전 검사 | `adapters/rhwp/style-management.ts` |
| Studio 추가/편집/관리 창의 연결 | `scripts/integration/style-management-patches.mjs` |
| 목록 키보드 소유와 포커스 유지 | `adapters/browser/modal-keyboard.ts` |
| 모든 모델 문단의 삭제 참조 보정 | `engine/patches/style-reference-deletion.patch` |

참조 저장소를 직접 수정하지 않는다. 패치는 생성한 Studio/엔진 사본에만 적용하며 빌드 증거에 해시를 기록한다. 실문서 변경은 기존 input snapshot 명령을 사용한다. 공급자·Agent·RAG/loop 코드는 이번에 변경하지 않았다.

## 지원 제한

- 기존 스타일의 **모양 전파**는 본문과 평면 표 셀에서만 검수했다. 중첩 표·머리말·각주·글상자 등의 story가 있으면 기존 스타일 모양 변경을 미리 거절한다. 정의 추가/복제·이름 변경·삭제 참조 보정과는 별도 제한이다.
- 스타일 순서 이동, 사용자 단축키 재할당의 문서 저장, 스타일 파일 가져오기/내보내기, 스타일마당은 아직 미구현이다.
- 글자 스타일 정의를 생성하는 기능과 선택한 글자 범위에만 글자 스타일을 적용하는 기능은 다르다. 기존 적용 경로는 문단 대상이며 한글의 모든 글자 스타일 범위 동작을 재현하지 않았다.
- 미지원 특수 영역에서의 적용, 모든 직접 서식 상속 규칙과 다음 문단 입력 시의 스타일 전환도 실제 한글과 전수 비교하지 않았다.
- 암호 문서와 편집 불가/양식 모드에서 새 관리 변경을 실행하지 않는다.

## 검증

증거: [style-management-2026-10-13](evidence/style-management-2026-10-13/).

- 단위 검사 297개 통과 (`editor-tests.txt`).
- Rust/WASM 중첩 스타일 삭제·HWP/HWPX 왕복 2개 통과 (`engine-verified/result.json`). 합성 HWPX의 문단/중첩 셀 ID를 지정하고 삭제 후 저장 XML을 독립 검사했다. 초기 Python stdout 인코딩으로 읽기 시험이 실패한 기록은 `engine/`에 남긴다.
- 이전 문서 삽입 엔진 검사 12개도 새 엔진에서 통과 (`insertion-regression/result.json`).
- 최종 브라우저 전체 62개 통과 (`final-verified/result.json`): 스타일 목록 키보드, 복제, 글자 종류, 임시 글꼴 취소, 최종 한 번 undo/redo, 기존 스타일 변경/전파, 표 셀 참조 삭제, 중복/충돌 거절과 기존 편집·저장·업무 복원 회귀. 페이지/콘솔 오류 및 외부 요청 0.
- TypeScript/빌드와 모듈 경계 검사 결과는 `typecheck.txt`, `build.txt`, `module-boundaries.json`이다. 모듈 9개/소스 160개, 위반 0.
- 실행 묶음의 기존 v1 업무·자료·문서 호환성 4개 통과 (`compatibility/result.json`).

실제 한글 2024의 F6 창은 열어 목록과 기본 단축키·정보·관리 버튼을 관찰했다. Escape 입력은 새 Window를 선택하고 한 번 재시도해도 `failed to activate captured window`를 반환했다. 같은 조작을 더 반복하지 않았다. 이번 스타일 변경 결과를 한글에서 재열기/재저장한 것으로 기록하지 않는다. 이전 문서 삽입의 성공 기록을 이번 스타일 동등성 증거로 대체하지 않는다.
