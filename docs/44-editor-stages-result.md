# Agent 재구성 전 편집기 통합 검수

2026년 10월 13일. Jueony의 기본 편집, 스타일, 상태 저장, 표와 개체, 쪽 배경, 문서 호환성, 통합 화면을 보강했다. 한글 2024의 전체 기능과 지면이 동일하다는 완료 판정은 아직 할 수 없다. 이번 검수에서는 실제 편집 명령, 취소, 되돌리기, 저장과 재실행을 검사하며, 실제 한글의 독립적인 지면 비교는 사용자의 요청에 따라 후속 비교로 남긴다.

## 실행과 검수 파일

검수 실행기는 `build/jueony-pre-agent-20261013/Start-Review.cmd`다. 포트는 4203이며 기존 실행본과 기존 포트의 저장소를 유지한다. 포트가 달라지면 업무 목록이 별도로 보인다. 기존 업무를 삭제하거나 자동 이관하지 않는다.

실행 묶음의 `review-documents/pre-agent/`에는 이번에 생성한 합성 HWP와 HWPX 문서를 기능별로 넣는다. 실제 한글에서 같은 형식으로 열고, 문서 끝의 빈 문단, 표 셀, 개체 크기, 머리말과 각주, 구역별 쪽 배경을 확인한다. 공개 문서 원본과 그 파생 파일은 묶음에 재배포하지 않는다.

## 이번 단계별 결과

| 단계 | 적용한 변경 | 남은 확인과 제한 |
| --- | --- | --- |

## 기능별 동작

### 스타일

선택한 본문 글자 또는 같은 중첩 셀의 글자에 글자 스타일을 적용한다. 선택 밖 글자 모양과 문단 스타일은 유지하며 한 번에 되돌린다. 선택이 없는 글자 스타일은 기존 입력 모양 경로를 사용한다. 문단 끝에서 Enter를 누르면 유효한 다음 문단 스타일로 이어지고, 중간에서 문단을 나눌 때는 기존 동작을 유지한다.

F6 관리 창의 위아래 이동은 정의 배열뿐 아니라 본문·중첩 셀·머리말·각주 등의 스타일 참조와 다음 스타일 번호를 함께 바꾼다. 바탕글 0은 이동하지 않는다. 스타일 정의의 글자·문단 모양 변경은 특수 영역 문단 트리에도 전파하고, 기존 정의와 다른 직접 서식은 유지한다. 선택 글자에 복사한 모양은 별도 스타일 이름 연결로 저장하지 않으므로 이후 정의 변경을 모든 글자 범위에 추적 적용하는 기능은 남아 있다.

### 상태 복원

문서 보기 상태 v1에 선택 필드를 추가했다. 기존 기록은 계속 읽으며 업무별 문서 상태를 분리한다. 주소만 저장하지 않고 문서 문맥, 셀 구조, 원문 또는 그림 자산의 해시를 검사하여 내용이 바뀐 오래된 선택을 복원하지 않는다.

중첩 셀 경로, 역방향 글자 선택, F5 셀 블록, 본문 그림 개체 선택, 머리말과 꼬리말의 커서·선택 및 본문 복귀 위치, 본문 각주의 커서·선택을 복원한다. 복원이 문서 bytes나 dirty 상태를 바꾸거나 채팅 입력에서 포커스를 빼앗지 않는지 검사한다. 그룹·다중 그림·글상자 내부 커서와 지원 범위 밖의 특수 영역은 복원했다고 표시하지 않는다.

통합 화면의 중복 메뉴를 늦게 숨기면 하단 스크롤이 68px 밀리는 결함을 수정했다. 문서와 보기 상태를 복원하기 전에 최종 화면 높이를 확정한다. 각주와 꼬리말을 포함한 실제 스크롤 위치를 검사한다.

### 표 변환과 자동 채우기

문자열과 표 변환은 일반 본문의 전체 문단과 단순 표를 대상으로 한다. 탭·쉼표·세미콜론을 구분자로 사용하며 빈 셀, 공백, Unicode와 기본 서식을 보존한다. 문서 사본에서 먼저 변환과 양 형식 재열기를 검사한 뒤 열린 문서의 명령으로 적용한다. 실패하면 snapshot을 복구하고 한 번에 되돌릴 수 있다.

필드·개체가 든 문단, 혼합 글자 서식, 병합·중첩·보호 셀, 여러 문단 셀 등 지원 범위 밖 대상은 적용 전에 거절한다. CSV 인용 규칙이나 임의의 구조를 모두 변환하는 기능은 아니다.

자동 채우기는 한 행 또는 한 열의 단순 셀 블록에서 첫 두 정수의 차이로 나머지 값을 만든다. 앞자리 0을 유지하고 덮어쓸 값을 미리 보여 준다. 12자리 이하 정수·1,000셀 이하로 제한하며 날짜, 수식, 문자열 패턴 추론은 지원하지 않는다.

### 개체 고치기와 서식 도구 모음

선택한 표·그림·도형·선·글상자·그룹·수식의 기존 속성 창을 `Ctrl+N,K`와 `P`로 연다. 표 개체 선택 시 다른 커서 셀 주소를 사용해 창이 열리지 않던 경로를 수정했다. 확인 시 문서 버전과 선택 대상이 여전히 같은지 검사한다. 커서 앞의 모든 제어를 자동 검색하는 한글 동작, 중첩 표와 OLE 등은 별도 작업이다.

중복 서식 도구 모음을 새로 만들지 않고 기존 글꼴·크기·언어·정렬·강조 도구 모음을 재사용한다. 글꼴 등록 전에 문서·입력 상태와 값을 검사하며 양식·읽기 금지·IME·진행 중 작업과 오래된 선택에서 변경을 막는다. 공개 `formattingState()` 계약으로 화면 상태를 읽고 제공자와 Agent 구현을 도구 모음에 섞지 않는다.

### 쪽 테두리와 배경

양쪽·홀수·짝수 쪽의 개별 설정과 모두·첫 쪽 제외·첫 쪽만 적용 범위를 지원한다. 두 색의 선형·방사형 그러데이션을 만들고 기존 배경 그림은 테두리만 수정할 때 보존한다. 원뿔형·사각형 그러데이션은 저장 값을 보존하지만 정확한 화면 표현이 구현되지 않아 새 생성 선택지로 노출하지 않는다.

공유 배경 자원을 복사하여 셀이나 다른 쪽의 배경이 함께 바뀌는 문제를 막았다. 같은 배경색에 서로 다른 무늬를 설정했을 때 이전 자원을 잘못 재사용하던 Rust 비교 함수도 수정했다. 무늬 없음의 HWP 값 0과 HWPX 값 -1은 저장 보호 검사에서 같은 의미로 취급하며 실제 무늬 1과 2의 차이는 검출한다.

머리말·꼬리말 포함 플래그의 저장 보존은 검사했으나 실제 테두리 배치에 포함하는 계산은 아직 구현되지 않았다. UI에서 해당 범위가 완성된 것처럼 표시하지 않는다.

## 공개 문서 호환성

기존에 내려받은 표본의 해시를 확인하고 새 엔진으로 검사했다. 다음은 내용 검사와 생산 저장 보호 검사 결과를 함께 보여 준다. `내용 유지`가 개체·지면·서식 전체 동등성을 뜻하지 않는다.

| 표본 | 내용 검사 | HWP 저장 보호 | HWPX 저장 보호 |
| --- | --- | --- | --- |
| 문화체육관광부 입찰 문서 | 내용 유지, 15쪽·11개 표 | 통과 | 문단·개체 차이로 차단 |
| python-hwpx 양식 표본 | 내용 유지 | 개체 차이로 차단 | 통과 |
| python-hwpx 수식 표본 | HWP 변환 시 끝 빈 문단 1개 증가 | 차단 | 통과 |
| python-hwpx 각주 표본 | 내용 유지 | 통과 | 통과 |
| python-hwpx 서식 표본 | 내용 유지 | 제어·개체 차이로 차단 | 통과 |

원본 형식의 저장 보호 검사는 5개 모두 통과했다. 형식 변환에서 차이가 발견된 파일은 보호 검사를 느슨하게 바꿔 저장하지 않는다. 별도 합성 문서의 편집·양 형식 저장 검사는 원본 형식이 다른 공개 문서 전체 호환성을 대신하지 않는다.

## 검증 기록과 다음 비교

동일한 최종 소스와 WASM을 사용하는 검사 결과를 취합했다. 편집기 단위 검사 351개, 실제 Edge 브라우저 사례 133개, native WASM·독립 XML 사례 58개가 통과했고 실패·skip은 0이다. 9개 모듈의 178개 소스 파일 경계 검사도 통과했다. 브라우저 사례에는 이전 v1 업무 저장소·폴더 handle·기록·문서 저장 복원 4개와 기존 Agent mock 회귀 9개가 포함된다.

| 최종 검사 | 통과 사례 |
| --- | --- |
| 기본 편집과 기존 기능 전체 회귀 | 66 |
| 상태 복원과 실제 문서 탭 키 | 9 |

엔진은 rhwp 0.8.7 기준 소스와 추적 패치 10개를 Rust release로 직접 빌드한 검수용 비최적화 WASM이다. 최종 WASM SHA-256은 `5dc02a24794defb8b5e05b0bcc22fc7bdba30f8ec73c7d05a259733399d2423e`, 앱 소스 SHA-256은 `2be8e99588d66101114b658b71d444e0a047e5dc24e78f2002485869165f433c`다. 종합 검증 스크립트는 각 최종 브라우저 보고서의 앱 소스와 빌드 계약 해시, native 보고서의 WASM 해시가 같은지 검사한다. 완료된 기능 사례를 전체 한글 기능의 완료율로 환산하지 않는다.

최종 검사 수와 실행본 해시는 [통합 검증 기록](evidence/pre-agent-2026-10-13/verification-summary.json)을 따른다. 앞선 실패 기록은 별도 폴더에 남기고 최종 통과 기록과 구분한다. 단축키와 편집 동작의 공식 근거는 [한컴 새 탭](https://help.hancom.com/hoffice130/ko-KR/Hwp/file/new_tab.htm), [선택 개체 고치기](https://help.hancom.com/hoffice130/ko-KR/Hwp/edit/modification.htm), [쪽 테두리](https://help.hancom.com/hoffice/multi/ko_kr/hwp/format/pageborder/page_border%28border%29.htm)를 참고한다.

실제 한글에서 주기적으로 비교할 순서는 합성 기본 편집과 선택 → 스타일과 단축키 → 표 변환과 개체 → 구역과 쪽 배경 → 공개 복합 문서다. 각 비교에서 Jueony 저장 전후와 한글 재저장본의 내용·개체·쪽 수·지면을 독립적으로 확인하고 기능별 동등성 결과를 [차이 목록](hangul-2024-gap-checklist.csv)에 기록한다.

Agent와 LLM 제공자, 새 RAG·loop·OAuth 구조는 이번에 변경하지 않았다. 기존 Agent의 자료 지정·명령 적용·요청 undo·취소는 격리된 mock 모델로 회귀 검사하며 실제 유료 API 호출로 표시하지 않는다. 전체 수동 기능과 저장 계약이 아직 검증되지 않았으므로 Agent 재구성 완료 관문도 통과로 바꾸지 않는다.
