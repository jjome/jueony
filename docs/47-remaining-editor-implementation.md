# 잔여 편집기 기능 자율 구현

2026-10-13. [상태 점검](46-hangul-implementation-status.md)의 잔여 기능을 순서대로 보강한다. 사용자의 요청에 따라 실제 한글 GUI 비교는 마지막 별도 단계로 모으고, 구현 중에는 실제 편집기·문서 엔진·HWP/HWPX 재열기·실패 복원 검사를 진행한다. 점검표의 WIRED는 한글의 전체 옵션과 동작 동등성을 의미하지 않는다.

## 실행 순서

1. 기본 편집과 표 채우기의 미구현 경로를 연결한다.
2. 스타일 교환·사용자 환경 저장과 이관을 보강한다.
3. 표·개체·쪽 설정의 부분 구현을 확장한다.
4. 검토·반복 업무·보안을 연결한다.
5. 복합 문서 저장 문제를 원인별로 수정한다. 저장 보호 조건을 느슨하게 만들어 통과시키지 않는다.
6. 같은 최종 소스에 전체 자동 검사를 실행하고 실행 묶음을 준비한다.
7. 실제 한글에서 기능·단축키·지면·저장 결과를 일괄 비교한다. 이 단계는 이번 구현 대기의 조건으로 사용하지 않는다.

문서 변경은 열린 편집기의 snapshot router에서 수행한다. 대화상자에서 확인하기 전에 문서 버전·원문·선택을 다시 검사하고 사본의 적용·저장 보호 검사를 먼저 실행한다. 적용 중 실패하면 문서와 history를 복원한다. 원본 디스크 파일은 별도로 다시 쓰지 않는다.

단축키는 [한컴 단축키 도움말](https://help.hancom.com/hoffice120/ko-KR/Hwp/view/toolbar/shortcut%28table%29.htm)을 근거로 Alt+Space, Ctrl+Alt+Space, Ctrl+Shift+-를 등록했다. 현재는 Unicode 문자 입력 경로이며 특수 HWP 제어 생성과 지면 동등성 완료로 표시하지 않는다.

## 검증

첫 묶음은 단위 검사 360개와 TypeScript 검사 통과. 추가 브라우저 사례 12개는 격리된 Edge에서 실제 명령·대화상자·undo/redo·저장을 사용했다. HWP/HWPX에서 각각 서식 보존·날짜·Unicode 번호·여러 줄 붙이기·특수 문자 재열기를 확인했다. 취소·동일 결과 no-op·오래된 대화상자와 실문서 적용 도중 실패 복원도 확인했다. 외부 자산 요청과 page error는 0건이다.

검사 스크립트는 `apps/editor/scripts/verify-basic-text.mjs`, 기록과 한글에서 재열 수 있는 합성 파일은 `docs/evidence/remaining-editor-2026-10-13/`이다. 실제 한글 GUI 비교나 유료 LLM 호출은 수행하지 않았다. 아직 전체 잔여 기능을 완료한 상태가 아니다.

## 두 번째 구현 묶음

서식 메뉴에 `스타일 내보내기·가져오기`를 추가했다. 기본 문단·글자 스타일과 언어별 글꼴 이름·장평·자간·크기·색·글자 효과·문단 여백·간격·줄 나눔 옵션을 Jueony JSON 파일로 교환한다. 다음 문단 스타일 그래프는 자동 포함하고, ID를 대상 문서에 새로 연결한다. 이름 충돌은 미리 보여 준 새 이름으로 추가하며 기존 정의와 본문 참조를 수정하지 않는다. 사본에서 적용·저장 보호를 먼저 검사하고 실제 적용은 하나의 snapshot/undo다.

한글 STY 파일, 글꼴 바이너리, 번호/개요·테두리·배경·사용자 탭 스타일은 아직 지원하지 않는다. 고급 속성이 들어간 원본을 기본 스타일로 조용히 축소하여 내보내지 않고 오류로 안내한다. 가져온 JSON의 미지원 모양 속성도 거절한다.

도구 메뉴에 `편집 환경 내보내기·가져오기`를 추가했다. 대표 글꼴·보기·테마·기존 대화상자 옵션·복구 설정·새 문서 기본값을 교환하고 재실행 후 복원한다. 내보낼 필드를 제한해 API 키·채팅·문서 본문을 포함하지 않는다. 가져오기는 형식/범위/버전 검사와 다른 창의 설정 변경 검사 뒤 저장하며 두 번째 저장 실패 때 첫 번째 변경도 되돌린다. 기존 로컬 확장 필드는 유지한다. 문서별 커서·업무 자료·한글 전체 환경값 이관은 별도다.

두 번째 묶음의 단위 검사는 367개, TypeScript와 모듈 경계 검사 통과. 통합 브라우저 검사는 15개 통과이며 같은 빌드에서 첫 묶음도 다시 검사했다. 추가 사례는 양 형식의 실제 스타일 가져오기·다음 스타일 순환 연결·undo/redo·저장 재열기, 환경 내보내기·가져오기·재실행·다른 창 변경 거절이다. 스타일 가져오기 검수 파일은 같은 증거 폴더의 `style-import.hwp`와 `style-import.hwpx`다.

## 기본 양식·상용구·키보드와 문서 전환

파일 메뉴에 `기본 업무 양식 (빈 문서)`를 추가했다. 공문 초안·업무 추진 계획·회의 결과·업무 보고서 4종을 직접 만든 예시로 제공한다. 미리보기·제목/항목 스타일·추진 일정과 후속 조치 표를 실제 문서에 만들고 전체를 한 번에 되돌린다. 기존 내용이 있는 문서는 덮어쓰지 않는다. 기관 공식 양식, 한글 문서마당의 원본 서식, 자동 새 탭 생성과 외부 템플릿 갤러리로 완료 처리하지 않는다.

입력 메뉴에 `공통 상용구`를 추가했다. 최대 100개, 하나당 8,000자·200줄, 총 100,000자의 일반 텍스트를 저장·수정·이름 변경·삭제한다. 같은 컴퓨터의 업무에서 목록을 공유하지만 자동으로 문서나 모델 요청에 들어가지 않는다. 문서 삽입은 본문 한 문단의 커서/선택을 대상으로 여러 줄을 넣으며 단일 undo·저장을 사용한다. 목록 저장은 문서 변경과 독립적이고, 다른 창의 수정·손상된 저장소·저장 실패에서 기존 목록을 덮어쓰지 않는다. 서식·필드·변수·스크립트 실행은 지원하지 않는다.

`Shift+F10`은 현재 커서·선택의 빠른 메뉴를 연다. 방향키·Home/End·Enter/Space·Esc를 처리하고 비활성 항목을 건너뛰며 메뉴 종료 후 편집기 포커스를 복원한다. 키보드 메뉴를 열기 위해 마우스 hit-test를 수행하거나 선택을 옮기지 않는다. 메뉴를 바로 닫았을 때 뒤늦은 외부 클릭 이벤트가 남는 결함도 수정했다.

통합 검사 중 기존 문서의 표 개체 선택이 다음 문서에 남아 빈 문서 명령을 비활성화하는 결함을 재현했다. 문서 비활성화에서 이전 문서의 텍스트/셀/표/그림 선택·머리말/각주 모드·화면 좌표·메뉴를 초기화한다. 이전 문서의 주소를 새 문서 엔진에서 조회하지 않으며, 로딩 뒤 파일의 캐럿과 업무별 저장 보기 상태를 복원하는 기존 순서는 유지한다.

## 실행 묶음과 잔여 범위

이번 기능 실행기는 `build/jueony-remaining-editor-20261013/Start-Review.cmd`, 포트 4220이다. 이전 실행본과 사용자 문서는 유지한다. 포트가 다르면 업무 저장소가 별도로 보인다. 검수 문서는 묶음의 `review-documents/remaining-editor/`에서 실제 한글로 열 수 있다.

최종 수치와 소스 해시는 같은 증거 폴더의 `verification-summary.json`을 따른다. 실제 한글 비교는 수행하지 않았다. 형식 변환 4개에서 발견한 문단·개체 차이, 복잡한 표·신규 차트/OLE·바탕쪽·변경 추적·맞춤법·메일 머지·고급 매크로·문서 보안 등의 잔여 작업은 계속 남는다. Agent 재구성이나 모든 수동 기능의 AI 도구화를 이번 편집기 보강과 합산하지 않는다.

## 문단 번호 후속 우선순위 (2026-10-14)

76번에서 기존 정의 적용 경로를 연결했다. 다음은 명시적 번호 다시 시작의 양 형식 직렬화 손실과 손실 보고서 누락을 먼저 수정하고 저장 상태를 검증한다. 이후 새 번호 모양/문자 글머리표 생성은 문서 자원 등록과 raw DocInfo 무효화·공유 정의 보존·undo/redo·현재 형식 저장 재열기를 함께 연결한다. 확인 전에는 카탈로그에 없는 정의·그림/체크 글머리표·개요 명령을 성공으로 표시하지 않는다.


77번에서 새 기본 문자 글머리표 8종의 Agent 생성·적용과 Native 정의 추가의 DocInfo 무효화, 명시적 restart의 손실 보고를 연결했다. 다음은 기존 번호 모양을 유지하는 새 번호 정의/시작 값과 적용 경로를 계획하고, 실제 한글 파일의 정규 표현을 확보해 restart 직렬화를 별도로 검증한다. 현재 손실 차단을 해제하거나 쪽 번호 컨트롤로 대체하지 않는다. 사용자 지정 글머리표·개요/목차·그림/체크 글머리표는 후속 범위다.
