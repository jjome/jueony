# 쪽 테두리 포함 범위와 구역 적용

2026-10-13. [48번 구현](48-advanced-editor-continuation.md)에 이어 쪽 테두리의 머리말·꼬리말 포함, 현재 구역/문서 전체/새 구역 적용을 구현했다. 실제 한글 GUI 비교는 사용자의 요청대로 후속 일괄 단계로 남긴다.

## 동작

쪽 → 쪽 테두리/배경에서 다음 설정을 사용한다.

- 쪽 기준: 머리말·꼬리말 포함을 선택할 수 있다. 테두리의 위/아래를 편집 용지에서 계산한 해당 영역까지 확장한다. 머리말 글자가 없어도 설정된 영역을 기준으로 한다.
- 종이 기준: 포함 옵션을 비활성화한다. 저장된 포함 값은 보존하지만 테두리 위치에는 사용하지 않는다.
- 현재 구역: 수정한 양쪽·홀수·짝수 설정을 현재 구역에 적용한다.
- 문서 전체: 현재 구역의 최종 양쪽·홀수·짝수 설정을 모든 구역에 복사한다. 구역별 용지·여백·본문은 유지한다. 다른 구역의 기존 테두리 차이는 덮어쓰는 범위임을 선택지에 표시한다.
- 새 구역으로: 선택 없는 본문 커서에서 구역을 나누고 새 구역에 설정을 적용한다. 본문 분할과 테두리 설정을 한 번에 되돌린다. 표/개체 선택·머리말/각주·글상자·문자 선택에서는 이 범위를 비활성화한다.

옵션의 활성 기준과 적용 범위는 [한글 2024 공식 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/pageborder/page_border(border).htm)을 확인했다. 구체적인 포함 좌표는 rhwp의 현재 PageAreas 계약에서 계산하며, 한글의 모든 지면·글꼴·빈 머리말 동작과 동등하다고 판정하지 않는다.

모든 작업은 열린 문서의 snapshot 명령으로 적용한다. 저장·재열기 사본을 먼저 검사하고, 버전과 새 구역의 커서 위치를 재검증한다. 여러 구역/여러 종류를 적용하다 실패하면 이미 바꾼 구역도 복원하며 undo 기록을 남기지 않는다.

## 엔진과 경계

`engine/patches/page-border-inclusion.patch`는 renderer의 테두리 위치와 getPageInfo의 테두리 좌표에 같은 포함 범위를 반영한다. `pageBorderInclusionEnabled()`로 실제 지원을 확인한다. 고정 참조 저장소를 직접 고치지 않고 전체 패치 묶음에서 WASM을 새로 빌드했다. 검수 패키지는 `build/rhwp-engine/source-7faba1e743412dab/pkg`다.

양쪽 설정을 쓰면 엔진의 홀수·짝수 슬롯도 초기화된다. 적용 계획은 이 순서를 반영하여 필요한 홀수/짝수 설정을 다시 쓰고 최종 값을 검증한다. 초기화가 필요 없는 종류는 변경된 값만 쓴다. 기존 고급 설정을 기본 값으로 축소하지 않는다.

그림 배경의 문서 전체 복사는 아직 지원하지 않아 거절한다. 현재 구역의 기존 그림 배경 속성 보존과 새 구역의 기존 자산 상속은 기존 경로를 사용한다. 바탕쪽 편집, 새 배경 그림, 테두리 영역 배경의 정밀 조판과 특수 문맥에서 새 구역 생성은 완료 범위가 아니다. 새 수동 설정을 Agent의 지원 명령에 추가한 것으로 표시하지 않는다.

## 검증과 실행

`docs/evidence/page-inclusion-2026-10-13/`에 실제 WASM·SVG 좌표·독립 저장 XML·브라우저·회귀 결과를 기록한다. 서로 다른 머리말/꼬리말 폭으로 네 가지 포함 조합을 검사하고, 종이 기준에서는 좌표가 변하지 않는지 확인한다. 양 형식에서 전체 구역과 새 구역 적용, 단일 undo/redo·저장 재열기, 두 번째 구역 실패 후 전체 복원을 검사한다.

최신 실행기는 `build/jueony-page-inclusion-20261013/Start-Review.cmd`이며 포트는 4223이다. 기존 4222 실행본과 작업 문서는 자동 종료하거나 덮어쓰지 않는다. 실제 한글 재열기용 합성 파일은 실행 묶음의 `review-documents/page-inclusion/native/`와 `browser/`에 포함한다. 최종 검사 수치와 해시는 증거 폴더의 `verification-summary.json`을 따른다.
