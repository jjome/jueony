# 쪽 배경의 실제 채울 영역

2026-10-13. [49번 쪽 설정](49-page-border-inclusion-and-scope.md) 후속 구현이다. 실제 한글 GUI 비교는 후속 일괄 단계로 남긴다.

## 변경

쪽 → 쪽 테두리/배경 → 배경의 채울 영역은 종이/쪽/테두리를 구분한다. 기존 엔진은 테두리 값을 저장했지만 화면에서는 종이 전체를 채웠다. 새 `page-border-region.patch`는 테두리 좌표를 계산하는 하나의 함수를 테두리 선과 배경이 함께 사용하게 한다.

- 종이: 편집 용지 전체.
- 쪽: 본문 영역. 머리말/꼬리말 포함 플래그 때문에 본문 배경을 넓히지 않는다.
- 테두리: 쪽 또는 종이 기준의 거리, 머리말/꼬리말 포함 설정을 반영한 실제 테두리 영역. 종이 밖으로 나간 부분은 잘라낸다.

각 영역의 의미는 [한글 2024 공식 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/pageborder/page_border(background).htm)을 확인했다. 현재 엔진의 선 좌표를 사용하는 구현이며 굵은 복합선의 안쪽 가장자리까지 한글과 동일하다는 판정은 아니다.

색/그러데이션 배경이 같은 영역 계산을 사용한다. 저장된 그림 배경도 같은 bbox 경로를 소비하지만 그림별 배치/효과의 완전한 비교는 이번 색/그러데이션 검사에 포함하지 않는다. 새 그림 배경 삽입은 여전히 미지원이다. 홀짝 설정과 첫 쪽 표시 조건, 열린 문서 snapshot·사본 검증·단일 undo·저장 경로를 유지한다.

`pageBorderFillAreaEnabled()`가 있는 엔진에서 테두리 영역을 활성화한다. 이전 엔진에서는 저장 값을 보존해서 표시하고 새 테두리 영역 선택을 비활성화한다. 지원 여부를 무시한 새 설정도 adapter가 거절한다.

## 검증

실제 WASM의 색 배경 SVG 좌표를 종이/본문/테두리 영역별로 검사한다. 두 형식과 두 위치 기준, 서로 다른 여백, 머리말/꼬리말 포함, 색/그러데이션, 종이 바깥 clipping, 홀짝/첫 쪽 감춤, 사본 저장과 재열기를 검사한다. 별도 Python XML 파서가 저장된 fillArea를 확인한다. 브라우저에서는 실제 대화상자 선택 → undo/redo → 저장까지 검사한다.

현재 결과는 `docs/evidence/page-region-2026-10-13/verification-summary.json`에 집계한다. 과거 결과를 새 엔진 결과로 재사용하지 않고 앱·패치·WASM 해시가 일치하는 회귀 검사를 새로 실행한다. 실제 한글 조판·인쇄 및 큰 공개 문서의 기존 변환 문제는 별도 검증 대상이다.
