# 새 그림 배경과 편집 용지 적용 범위

2026-10-14. [50번 배경 영역](50-page-background-region.md) 후속 구현이다. 한글 2024 직접 비교는 사용자의 요청대로 후속 일괄 검수로 남긴다.

## 새 그림 배경

쪽 → 쪽 테두리/배경 → 배경에서 PNG/JPEG를 고른다. 원본 폴더를 연결하지 않고 문서 내부 자산으로 포함한다. 본문에 그림 개체를 추가하거나 디스크의 열린 파일을 따로 수정하지 않는다.

- 늘려 채우기, 바둑판식, 가운데 배치.
- 비율 유지 맞춤은 HWPX에서만 활성화. HWP 저장 경로에서 늘려 채우기로 바뀌는 것을 실제 왕복 검사로 확인하여 지원으로 표시하지 않는다.
- 원래 색/회색조/흑백, 밝기·대비 각각 -100~100. 워터마크 버튼은 밝기 70, 대비 -50을 설정한다.
- 종이/본문/테두리 영역, 양쪽/홀수/짝수와 첫 쪽 조건.
- 현재 구역/문서 전체/새 구역 적용. 같은 열린 문서의 자산 참조를 재사용하며 다른 구역의 용지는 유지한다.
- 기존 그림 교체, 효과 수정, 배경 제거는 같은 대화상자와 snapshot 경로를 사용한다.

채우기와 효과 항목은 [한글 2024 공식 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/pageborder/page_border(background).htm)을 확인했다. 화면·인쇄의 모든 효과가 한글과 동등하다는 의미는 아니다. BMP/GIF/TIFF/SVG 신규 삽입, 외부 파일 연결 방식, 혼합 그림/색 채우기의 전체 편집과 모든 고급 그림 배치는 이번 완료 범위에 포함하지 않는다.

신규 파일은 10MiB 이하 PNG/JPEG, 한 변 8192px 이하·1600만 픽셀 이하로 제한한다. 실제 디코더에서 확장자/형식과 내용을 검사하고 실패하면 자산을 추가하지 않는다. 파일 선택만으로 문서를 바꾸지 않는다. 바이트는 대화상자의 임시 map에 두며 확인 시 사본 검사와 snapshot 안에서만 자산을 등록한다. 취소·파일 읽기 중 문서 변경·적용 실패 때 새 자산이 문서에 남지 않는지 검사한다.

## 엔진과 저장 계약

`page-border-z-image.patch`는 `registerPageBackgroundImage(bytes, extension)`, `getPageBackgroundImageBytes(section, kind)`, `pageBackgroundImageEnabled()`를 추가한다. 기존 `setPageBorderFillEntry`가 유효한 문서 내부 이미지 참조, 채우기 방식, 효과와 화면 기준 밝기/대비를 검증해 적용한다. HWP5의 내부 두 바이트 순서와 HWPX/화면 순서는 getter/setter에서 변환한다.

그림 자산 등록은 기존 엔진의 임베드 등록기를 사용하여 기존 storage ID와 충돌하지 않는다. 공용 테두리 자원을 직접 고치지 않고 복사한다. 저장 보존 검사는 표시되지 않는 첫 쪽 그림도 전용 byte reader로 해시를 검사한다. 자산 번호가 아니라 실제 내용과 속성을 비교한다. 저장 검사 실패를 무시하거나 손실 기준을 완화하지 않는다.

UI 연결은 `page-background-image.ts`, 범위 적용은 `page-border-settings.ts`, 값 계약은 document 모듈의 공개 export를 사용한다. 참조 저장소를 직접 고치지 않고 추적 패치에서 새 WASM을 빌드했다. 새 수동 기능을 Agent 지원 명령에 추가했다고 표시하지 않는다.

## 편집 용지

기존 편집 용지 창은 문서 전체/새 구역을 표시했지만 확인 경로가 현재 구역만 고쳤다. `page-setup-settings.ts`가 다음을 실제 적용한다.

- 현재 구역: 해당 구역만 변경.
- 문서 전체: 모든 구역의 용지·여백·방향·제본을 선택한 값으로 변경.
- 새 구역: 선택 없는 본문 커서에서 나누고 새 구역의 편집 용지만 변경. 특수 story/표/개체/문자 선택에서는 비활성화.

용지 변경과 새 구역 생성은 하나의 undo/redo다. 전체 적용 중 실패하면 먼저 변경한 구역도 복원한다. 문서 버전과 커서 위치를 적용 전에 재검증하고 저장 사본을 검사한다. 본문이 소멸하는 여백은 기존 엔진의 본문 한도 규칙으로 거절한다.

mm 표시를 바꾸지 않았다면 원래 HWPUNIT를 유지한다. 반올림된 210.0mm를 단순 확인하여 너비 59529를 59528로 바꾸거나, 0.0mm로 보이는 작은 제본 여백을 0으로 없애지 않는다. 사용자가 새 용지 프리셋을 고르면 그 프리셋의 정확한 원본 치수를 사용한다. 변경 없는 확인은 dirty/undo를 만들지 않는다.

## 검증과 남은 쪽 기능

`docs/evidence/page-image-2026-10-14/`에 소스·통합 코드·엔진 패치·WASM 해시가 같은 검사 결과를 저장한다. 원본 자료를 사용하지 않고 직접 생성한 RGB 띠 PNG/JPEG를 사용한다. HWP의 비율 유지 맞춤 거절은 지원 동작 검사와 별도로 구분한다.

바탕쪽 편집, 줄 번호, 쪽 복사/붙이기/삭제, 원고지/라벨, 세로쓰기 전체 UI, 복합선 안쪽 배경의 정밀 조판과 한글 직접 출력 비교는 여전히 남아 있다. 이 문서는 전체 한글 기능 완료를 주장하지 않는다.

최종 자동 검사는 단위 395개, 브라우저 184개, 실제 WASM 90개를 통과했다. 브라우저에는 이번 그림 배경/편집 용지 26개와 기존 편집·표·상태 복원·mock Agent·실행 묶음 회귀가 포함된다. 엔진 수치에는 저장 미지원·잘못된 파일의 거절 검사도 포함하며 모든 그림 옵션을 지원한다는 의미는 아니다. TypeScript와 9개 모듈/218개 소스 파일의 경계 검사도 통과했다. 유료 LLM은 다시 호출하지 않았다.
