# 기본 텍스트 바탕쪽 편집

2026-10-14. [51번 그림 배경·용지 설정](51-picture-background-and-paper-scope.md)의 후속 작업이다. 한글 2024 직접 비교는 후속 일괄 검수로 남긴다. 바탕쪽 전체 기능의 완료나 한글과의 동등성을 뜻하지 않는다.

## 실제 구현 범위

통합 쪽 메뉴 또는 편집기 쪽 도구에서 **바탕쪽 (기본 텍스트)**을 연다. 본문과 같은 열린 엔진에 텍스트 바탕쪽을 추가·수정·삭제한다. 저장하지 않은 문서에도 적용하며 디스크의 원본 파일을 별도로 다시 쓰지 않는다.

- 양쪽·홀수 쪽·짝수 쪽 텍스트, 용지 왼쪽 위 기준 가로·세로 위치, 글자 크기·색·진하게.
- 현재 구역부터, 첫 구역부터, 현재 구역에 저장. 문서 전체 적용에서도 각 구역의 용지 설정을 유지한다.
- 적용한 전체 작업을 한 번의 되돌리기·다시 실행으로 복원한다.
- 취소, 변경 없는 확인, 잘못된 좌표, 오래된 문서 버전은 변경으로 남기지 않는다.
- 저장 전 임시 문서에 먼저 적용하고 저장·재열기 검사를 수행한다. 실제 적용 중 실패하면 자원·구역 내용과 기존 undo 기록을 복원한다.
- 균일 기존 글자 서식은 기울임 등 노출하지 않은 값도 유지한다. 표·그림·필드·혼합 서식·확장 바탕쪽이 있는 구역은 읽기 전용이다.

한글 도움말의 양쪽·홀수·짝수 구분과 구역 적용 개념을 기준으로 삼았다. 한글의 별도 바탕쪽 편집 상태와 달리 이번 구현은 기본 텍스트 대화상자다. [한글 2024 바탕쪽](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/masterpages/master_pages.htm), [종류와 적용 범위](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/masterpages/master_pages(compose).htm).

## 파일 형식과 적용 제한

HWPX는 기본 양쪽·홀수·짝수 조합을 저장한다. HWP는 현재 파서의 순서 해석에서 저장 왕복이 유지되는 조합만 허용한다: 없음, 양쪽만, 홀수만, 양쪽+홀수, 양쪽+홀수+짝수. 다른 조합은 적용 전에 거절하고 HWPX 사용을 안내한다. 짝수만 생성하거나 세 종류 중 홀수만 삭제하는 작업을 성공으로 표시하지 않는다.

구역에 직접 저장된 해당 종류만 삭제한다. 앞 구역에서 이어지는 바탕쪽이 다시 보일 수 있다. ‘현재 구역에 저장’은 이후 구역의 상속을 완전히 차단한다는 의미가 아니다. 임의 쪽·마지막 쪽·덧붙이기·겹침·앞으로 보내기는 미지원이다.

기본 편집 한도는 Unicode 문자 4,000개, 문단 100개, 글자 크기 1~72pt, 실제 용지 안의 시작 위치다. 개체가 없는 왼쪽 정렬의 균일 기본 문단만 편집한다. 이는 이 기본 편집 API의 보호 조건이다. 문장이 용지 밖으로 넘치는지에 대한 완전한 조판 검사나 한컴 인쇄 일치는 아직 검증하지 않았다.

## 코드 경계

- `modules/document/domain/master-page-settings.ts`: 엔진과 독립적인 값 검증·변경 없는 확인.
- `adapters/rhwp/master-pages.ts`: 구역별 계획, 모든 대상의 원문 상태 확인, 대화상자, 엔진 실행.
- `engine/patches/master-page-editing.patch`: `getMasterPages`/`setMasterPageText`, IR 변경, 직렬화 레코드 정리, 조판 갱신, 홀수 표시 보정.
- 기존 snapshot/dirty/history, 저장 보존 검사와 통합 메뉴 dispatcher를 재사용한다. 고정 업스트림 소스는 수정하지 않았다.
- 대화상자는 Agent의 변경을 계속 막는다. 자신의 적용 검사에서만 자기 대화상자를 busy 상태의 예외로 지정하고 다른 작업·대화상자는 검사한다.

검수 엔진은 `build/rhwp-engine/source-b5764245b2c033bb/pkg`다. WASM SHA-256은 `32ceb479eaab8960a4fe505daced5e6c020b2a92c2afb136446a20a39f611acb`이며 빌드 증거와 보고서에서 대조한다. 최적화하지 않은 검수 빌드다. 엔진 MIT 및 제삼자 고지를 유지한다.

## 검증과 실행

바탕쪽 전용 엔진 17개와 실제 Edge 화면 17개 검사가 통과했다. 저장·재열기 후 종류·텍스트·서식·좌표, 실제 SVG 글자 위치와 홀짝 표시, 표 바탕쪽 변경 거절과 균일 기울임 유지를 합성 HWP/HWPX로 확인한다. 직접 한글에서 만든 golden과의 동일성 검사는 아니다.

전체 회귀는 단위 398개, 브라우저 201개, 엔진 107개가 통과했다. [검증 요약](evidence/master-page-2026-10-14/verification-summary.json)에 실제 소스·통합 패치·WASM 해시를 대조한 결과를 기록한다. 9개 모듈의 220개 소스 경계와 TypeScript 검사도 통과했다. Agent 회귀는 로컬 mock이며 유료 모델 호출은 실행하지 않는다.

최신 실행 묶음은 `build/jueony-master-page-20261014/Start-Review.cmd`, 주소는 `http://127.0.0.1:4226/`다. 이전 4225 묶음은 유지한다. `review-documents/master-page/master-native`와 `master-browser`의 저장 파일을 실제 한글에서 확인할 수 있다.

## 남은 작업

바탕쪽 전용 캔버스 편집, 표·그림·필드·복잡한 문단, 임의/마지막 쪽·겹침, 전용 Agent 명령·완전한 보존 검사, 실제 한글 비교가 남았다. 임의 단축키를 한글 단축키로 추가하지 않았다.

줄 번호는 UI 토글만으로 해결할 수 없다. 현재 SectionDef 모델과 HWPX writer에는 줄 번호 설정을 보존·조판하는 경로가 없고 writer는 표시를 끄는 값을 쓴다. parser → IR → serializer → pagination → renderer를 함께 확장해야 한다. 이번 작업에서 줄 번호를 구현했다고 표시하지 않는다. 쪽 복사·붙이기·삭제, 원고지·라벨·완전한 세로쓰기 등도 미구현 목록에 남는다.
