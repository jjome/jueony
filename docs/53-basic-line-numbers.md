# HWPX 기본 본문 줄 번호

2026-10-14. [52번 바탕쪽](52-master-page-basic-editing.md) 후속 작업이다. 한글 직접 비교는 마지막 일괄 검수로 남기고 실제 코드·엔진·화면·파일 왕복 검사를 진행한다.

## 실제 동작

통합 쪽 메뉴와 편집기 쪽 도구에 **줄 번호 (기본 본문·HWPX)**를 추가했다. 화면 위에 임시 숫자만 겹쳐 놓는 방식이 아니라 SectionDef의 설정을 실제 HWPX에 저장하고 공통 렌더 트리에 번호를 생성한다. SVG와 편집기 공통 페인트 경로에서 본문 줄의 baseline에 맞춘다. 본문 텍스트에 숫자를 삽입하지 않는다.

- 표시/숨기기, 시작 번호, 번호 표시 간격, 본문과의 거리.
- 쪽마다·구역마다 다시 시작, 이전 번호에 이어서 매기기.
- 현재 구역, 문서 전체, 현재 구역부터 적용.
- 동일 결과 확인은 undo/dirty를 만들지 않는다. 숨긴 설정도 저장한다.
- 적용 전 사본의 저장·재열기를 검사한다. 여러 구역 적용 중 실패하면 먼저 바뀐 구역과 기존 history도 복원한다.
- 한 번의 적용을 한 번의 undo/redo로 처리한다. 대화상자가 열린 후 본문이 바뀌면 오래된 설정을 거절한다.

줄 번호 시작·간격·거리와 쪽/구역/이어서 방식은 [한글 2024 줄 번호 설정](https://help.hancom.com/hoffice130/ko-KR/Hwp/view/line_number_setting.htm)을 기준으로 삼았다. restartType 1/2/3의 의미와 시작·간격의 정수 범위는 [한컴 공식 ParameterSetTable_2504, SecDef 항목](https://github.com/hancom-io/devcenter-archive/blob/main/hwp-automation/ParameterSetTable_2504.pdf)을 직접 확인했다.

## 지원 경계

이번 편집·표시는 **HWPX, 가로쓰기, 한 단의 일반 본문**에 한정한다. 빈 본문 줄과 강제 줄바꿈, 자연 줄바꿈 및 여러 쪽에 걸친 한 문단을 검사했다. 시작·간격은 1~65535, 거리는 0~50mm이며 왼쪽 여백 안에 있어야 한다. 번호는 기본 함초롬바탕 8pt로 그린다. 번호 글자 모양 설정과 여백 밖의 완전한 표시 보장은 미지원이다.

표·개체·세로쓰기·숨긴 첫 빈 줄·문단별 줄 번호 제외와 알려지지 않은 번호 방식은 현재 조판 지원 범위 밖이다. 이런 원본 설정은 읽기 전용으로 보존하고 숫자를 잘못 그리지 않는다. 표시된 줄 수나 한컴 인쇄 일치를 검증한 것으로 표시하지 않는다.

이어서 매기기는 앞의 **번호 표시 구역**에서 이어진다. 번호 표시를 끈 구역은 현재 구현에서 계산하지 않는다. 시작 번호는 새로운 번호 흐름이나 재시작에서 적용하고, 표시 간격은 번호 값의 배수(예: 5, 10, 15)에 맞춘다. 이 상세 정책은 한글 일괄 비교에서 판정할 대상이다.

HWP 바이너리의 줄 번호 필드 배치를 확인하지 못했으므로 추측한 비트·확장 데이터를 쓰지 않았다. HWP 문서에서는 먼저 HWPX로 저장하라는 안내를 표시한다. HWPX의 줄 번호 설정을 HWP로 내보내면 설정이 유실되는 것을 저장 보호 검사에서 검출하여 차단한다. **표시를 꺼도 사용자 설정값이 남아 있으면 같은 보호가 적용된다.** HWP 원본의 줄 번호를 완전히 읽고 표시·편집하는 기능은 아직 아니다.

## 모델과 저장 보강

기존 HWPX parser와 writer는 `showLineNumber`, `lineNumberShape`를 보존하지 않고 기본값으로 다시 쓰고 있었다. `zz-line-number-settings.patch`는 SectionDef의 LineNumberSettings를 추가하고, parser·writer·원본 변경 봉인·편집 명령·공통 렌더러를 연결한다. 기본값 0과 미지원 원본 값은 변경 없이 저장한다.

문단의 `suppressLineNumbers`도 ParaShape에 보존한다. 자원 동일성 비교에 포함하여 제외 옵션이 다른 스타일을 합치지 않는다. 기본 줄 번호 지원 여부와 모든 원본 제외 스타일 ID를 조회하여 파일 왕복 보존 검사에 포함한다. 이 옵션의 완전한 표시 규칙이나 편집 UI는 아직 제공하지 않는다.

앱 계약은 `modules/document/domain/line-number-settings.ts`, 실행 adapter는 `adapters/rhwp/line-numbers.ts`다. 기존 snapshot/dirty/history와 preflight를 재사용하고 다른 모듈 내부에는 의존하지 않는다. Agent에 새 줄 번호 편집 명령을 연결한 것은 아니며 전용 도구 계약은 후속 작업이다.

검수 엔진은 `build/rhwp-engine/source-c1cfb65fcfbbea50/pkg`, WASM SHA-256은 `b5572627cc916a7b7963e2c2a777cde90593fad2d3a8097ab805228931da886e`다. rhwp 고정 원본과 MIT 고지를 유지하며 최적화하지 않은 검수 빌드를 사용한다.

## 검증과 실행

줄 번호 전용 엔진 검사 15개와 실제 Edge 검사 12개가 통과했다. 독립 XML 검사로 원본 옵션·제외 스타일·미지원 방식 보존을 확인했고, 자동 줄바꿈·쪽/구역 재시작·이어 매기기·숨기기·본문 후속 편집·undo/redo·오래된 대화상자·부분 실패를 검사했다. 한컴에서 만든 지면 golden과 비교한 결과는 아니다.

전체 회귀는 단위 400개, 브라우저 213개, 엔진 122개가 통과했다. [최종 검증 요약](evidence/line-numbers-2026-10-14/verification-summary.json)에서 소스·통합 패치·WASM이 각 보고서와 일치함을 확인했다. TypeScript와 9개 모듈/222개 소스의 경계 검사도 통과했다. 기존 Agent 검사는 로컬 mock으로 수행하고 API 키나 유료 요청을 사용하지 않는다.

실행 묶음은 `build/jueony-line-numbers-20261014/Start-Review.cmd`, 주소는 `http://127.0.0.1:4227/`다. 이전 4226 창과 문서는 종료하지 않는다. 검수 파일은 `review-documents/line-numbers/line-native`와 `line-browser`에 포함한다.

## 다음 자율 작업

줄 번호의 HWP 바이너리 매핑, 문단별 제외의 실제 조판·글자 모양·다단·표/개체 및 세로쓰기 지원을 별도로 확장해야 한다. 그동안 독립 구현 가능한 쪽 복사·붙이기·삭제의 대상 범위와 보존 계약을 먼저 확인한다. 부분 구현한 기능을 한글 전체 기능 완료로 집계하지 않는다.

사용자가 취침 중에도 계속 진행하도록 이 대화에 30분 간격의 계속 작업을 등록했다. 후속 실행은 현재 Git/작업 문서와 진행 중인 변경을 확인한 뒤 이어서 구현·검증·커밋·푸시한다. 직접 한글 비교와 유료 모델 실호출은 자동 검사 통과와 구분한다.
