# 완전한 본문 문단의 쪽 지우기

2026-10-14. [53번 줄 번호](53-basic-line-numbers.md) 후속 구현이다. 한글 직접 비교는 마지막 일괄 검수로 남긴다.

## 동작과 범위

통합 쪽 메뉴와 편집기 쪽 도구에서 **쪽 본문 지우기 (완전 문단)**를 실행한다. 현재 쪽에서 지울 본문을 미리 보여 주고 확인 후 실제 열린 엔진의 문단을 지운다. 미리보기는 일반 텍스트로 표시하며 문서 안의 지시문을 실행하지 않는다.

- HWP/HWPX의 첫 쪽·중간 쪽·마지막 쪽을 대상으로 한다.
- 해당 구역이 가로쓰기·한 단의 일반 본문이고, 지울 문단 전체가 현재 쪽 안에 있어야 한다. 같은 쪽에 여러 완전한 문단이 있으면 함께 지운다.
- 표·개체·필드·다단·세로쓰기·숨긴 빈 줄, 여러 쪽에 걸친 문단과 선택 블록의 여러 쪽 삭제는 아직 지원하지 않는다. 해당 구역 다른 쪽에 표 등이 있어도 현재 기본 경로는 거절한다.
- 첫 쪽을 지우면 다음 문단에 구역·단 정의와 제어 슬롯을 다시 연결한다. 남은 문단의 글자·문단 서식과 용지 설정을 유지한다.
- 구역의 모든 본문을 지울 때는 설정을 유지한 빈 문단 하나를 남긴다. 여러 구역 문서에서는 이 빈 구역을 제거하거나 앞 구역과 합치지 않는다. 따라서 이 경우 전체 쪽 수가 줄어들지 않을 수 있다.
- 이미 빈 구역이면 적용을 비활성화하며 dirty/undo를 만들지 않는다.
- 삭제 전체를 한 번의 undo/redo로 복원한다. 적용 중 실패하면 원문과 기존 history를 복원한다.

[한글 2024 쪽 지우기](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/remove_page_current.htm)는 현재 쪽이나 블록으로 선택한 여러 쪽을 즉시 지우고 되돌릴 수 있다. 이번 구현은 위의 제한된 본문 범위와 확인 대화상자를 제공한다. 한글과 모든 동작이 같다고 판정하지 않는다.

## 경계와 원본 보호

기존 `extract_page_range`는 결함 축소용 진단 함수다. 여러 쪽에 걸친 문단이 범위에 조금이라도 닿으면 문단 전체를 남기므로 정밀 편집으로 재사용하지 않았다.

`zzz-page-body-delete.patch`의 `getPageBodyDeletionPlan`은 실제 페이지네이션 항목에서 FullParagraph만 수집한다. 다른 쪽에도 나타나는 문단을 거절하고, 연속 문단 범위·원문·구역 모델 token을 반환한다. 1,000문단·10만 문자 이내다. `deletePageBody`는 현재 범위와 token을 확인한 뒤 삭제하고 구역 정의를 재연결하여 조판을 갱신한다. 기존 구역 분할의 정의/제어 슬롯 연결 함수를 공유한다.

앱 domain은 `modules/document/domain/page-body-deletion.ts`, adapter는 `adapters/rhwp/page-body-deletion.ts`다. 일반 본문 커서에서만 실행하며 문서 버전·커서·편집 가능 상태를 다시 검사한다. 사본에서 적용·저장·재열기를 먼저 검사하고, 사본의 쪽/문단 범위와 원문이 달라지면 실문서에 적용하지 않는다. 저장 보호 검사는 완화하지 않았다.

Native token은 구역 모델의 변경 검사이며 앱의 전체 문서 revision 검사를 대신하지 않는다. 다른 모듈이나 향후 Agent도 같은 revision/범위 검사를 거쳐야 한다. 디스크의 파일을 따로 고치지 않는다.

검수 엔진은 `build/rhwp-engine/source-a9cbdd94c8aad084/pkg`다. WASM SHA-256은 `3da65bae891edefd51c0b381b2dd789e5e170cb0886931903e39f09b4a1c70a6`이다. 고정 업스트림 소스는 변경하지 않았고 엔진 MIT 및 제삼자 고지를 유지한다.

## 검증과 실행

전용 엔진 검사 13개와 실제 Edge 검사 11개가 통과했다. 양 형식의 첫/중간/마지막 쪽 삭제, 한 쪽 여러 문단, 남은 혼합 글자 서식, 구역 최소 빈 문단과 용지, 뒤 구역만 비우기, no-op, 취소, 오래된 원문, 걸친 문단·표 거절 및 실문서 적용 후 실패 복원을 확인했다.

HWPX의 비활성 채우기 기본값 차이는 기존 보존 계약과 같이 실제 표시 속성과 구분한다. 실문서 적용 전후 글자 속성은 그대로 비교하고, 저장 재열기에서는 활성 서식과 표시 값들을 검사한다. 한글 지면 golden과의 동일성 검사는 아니다.

전체 자동 회귀와 소스·통합 패치·WASM 해시 대조는 [검증 요약](evidence/page-delete-2026-10-14/verification-summary.json)에 기록한다. TypeScript, 단위 검사와 모듈 경계도 검사하며 Agent는 로컬 mock을 사용한다.

최신 묶음은 `build/jueony-page-delete-20261014/Start-Review.cmd`, 주소는 `http://127.0.0.1:4228/`다. 이전 창은 종료하지 않는다. 한글에서 나중에 열어볼 합성 저장 파일은 `review-documents/page-delete/delete-native`와 `delete-browser`에 포함한다.

## 다음 구현

[한글 쪽 복사](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/copy_page.htm)는 현재 쪽을 복사해 선택한 쪽 바로 뒤에 붙이며, 용지·쪽 스타일이 다르면 구역을 변경한다. 이 계약을 다음 단계로 삼는다. 본문 범위뿐 아니라 자원·문단/글자 서식·구역 설정을 함께 보존해야 하며 진단용 추출이나 일반 텍스트 붙여넣기로 완료 처리하지 않는다.

쪽 복사·붙이기, 걸친 문단의 부분 삭제, 개체·표와 여러 쪽 선택, 빈 구역 정리, Agent의 전용 쪽 편집 도구는 남아 있다. 자동 계속 작업은 활성 상태를 유지한다.
