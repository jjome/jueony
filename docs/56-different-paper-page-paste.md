# 다른 용지의 쪽 붙이기

2026-10-14. [55번 쪽 본문 복사·붙이기](55-page-body-copy-and-paste.md)의 같은 용지 제한을 기본 용지 범위에서 보강했다. 한글 2024 직접 비교는 마지막 일괄 검수로 남긴다. 이 문서는 당시 용지 전용 구현 기록이며 기본 테두리·단색·두 색 그러데이션의 다른 모양 이식은 후속 [57번 구현](57-basic-page-style-paste.md)에서 추가했다.

## 실제 동작

쪽 메뉴의 **쪽 본문 복사 (완전 문단)**로 사본을 만들고 대상 문서의 **쪽 뒤에 본문 붙이기**를 실행한다. 확인 창은 같은 용지인지 다른 용지인지와 추가될 구역 수를 보여 준다.

- 용지 크기·방향·여백·제본이 같으면 기존처럼 현재 구역 안의 새 쪽에 넣는다.
- 용지만 다르면 붙인 본문을 독립 구역에 넣고 원본 사본의 용지를 적용한다.
- 그 뒤에 같은 구역의 본문이 남아 있으면 원래 용지의 구역을 다시 만든다. 따라서 새 구역은 2개다. 끝 쪽이면 붙인 구역 1개만 만들며 복원용 빈 구역을 만들지 않는다.
- 원래 다음 구역은 내용·용지·서식을 유지하고 위치만 뒤로 이동한다.
- 새 구역의 명시적 쪽/그림/표/수식 시작 번호는 0으로 두어 이어간다. 앞 구역의 지정 시작 번호는 유지한다.
- 붙인 전체를 한 번의 undo/redo로 복원한다. 반복해서 붙이면 각각 독립 이력이 된다. 일반 문서 저장 보호를 통과한 뒤 저장한다.

현재 사본은 한 쪽에 완전히 들어가는 일반 본문 문단이며, 1,000문단·10만 문자·32MiB 이하다. 다른 용지 붙이기 대상 전체는 5,000문단·10만 문자 이하의 가로쓰기·한 단 일반 본문 문서다.

배경·테두리·단·기본 탭 등 용지 외 설정이 다르면 아직 붙일 수 없다. 표·개체·필드·머리말/각주, 세로쓰기·다단·숨긴 빈 줄·바탕쪽·줄 번호·그림 배경·개요 번호는 다른 구역에 있어도 다른 용지 경로에서 거절한다. 홀짝 시작과 현재 구역의 첫 쪽 전용 테두리/배경도 새 경계의 표시가 달라질 수 있어 거절한다. 여러 쪽에 걸친 문단과 OS/한글 클립보드 연동은 남는다.

[한글 2024 쪽 복사](https://help.hancom.com/hoffice130/ko-KR/Hwp/format/copy_page.htm)의 대상 쪽 뒤 붙이기와 다른 용지의 구역 변경을 기준으로 삼았다. 한글의 전체 쪽 스타일·개체 동작과 같다고 판정하지 않는다.

## 모델·명령·계약

`zzzzz-page-body-paper-paste.patch`는 기존 자원 이식·서식 ID 재연결 뒤 본문 문단을 실제 Section 모델로 나눈다. 구역·단 정의와 HWP 제어 슬롯 연결은 기존 `install_definitions`를 공유하며, 새 용지와 복원 용지를 각각 정본 SectionDef와 시작 문단에 연결한다. 문단/문자 서식을 새로 만들거나 디스크 파일을 별도로 고치지 않는다.

`getPageBodyPastePlan`은 변경 없는 검사다. 대상 token·쪽/구역 수·본문 삽입점, 새 구역 여부·수, 반환할 커서 위치와 원본/대상 용지를 반환한다. `modules/document/domain/page-body-paste-plan.ts`는 이를 기존 본문 범위 계약과 대조한다. UI는 `adapters/rhwp/page-body-clipboard.ts`를 통해 이 계약을 읽고 표시한다.

붙이기는 문서 revision·커서·구역 token을 재검사하고 저장 사본에서 먼저 수행한다. native는 적용 뒤 붙인 쪽의 본문·문단 수·쪽/구역 수와 위치를 검증하고 불일치 시 원문 모델을 복원한다. 실문서의 snapshot 소유자가 undo/redo와 실패 시 이전 history 복원을 담당한다. 원본 보호 검사나 미지원 조건을 완화하지 않았다.

## 검증

전용 엔진 검사 15개와 실제 Edge 검사 9개가 통과했다. HWP/HWPX에서 첫·중간·끝 쪽 뒤의 다른 여백·방향·크기/제본, 원래 다음 구역, 원래 시작 번호, 여러 문단의 정렬·여백·간격과 혼합 글자 서식, 반복 붙이기의 undo, 취소·오래된 대상, 다른 구역의 표/다단·첫 쪽 표시 거절, 실문서 적용 후 실패 복원과 저장 재열기를 검사했다. 한글 2024 GUI나 지면 golden과의 동일성 시험은 아니다.

최종 자동 회귀는 단위 406개, 브라우저 244개, 엔진 166개가 통과했다. TypeScript와 9개 모듈/227개 소스 경계도 통과했다. [검증 요약](evidence/page-paper-2026-10-14/verification-summary.json)은 각 보고서의 소스·통합 패치·WASM을 같은 빌드와 대조한다. Agent 검사는 로컬 mock을 사용하며 실제 유료 모델 호출로 계산하지 않는다.

엔진은 `build/rhwp-engine/source-37fb24f6ac66650e/pkg`, WASM SHA-256은 `4283be1317925c80a9f7ae399d0b77bdc97e0f2cad12bc9db775e011a384151f`이다. 앱 소스 SHA-256은 `83f09b54e74c0567f0af0f88b47fa5cc9b3d2274d356429c27859ea44163f283`이며, 빌드 기록에는 직전 `2559520`과 작업 중 소스를 남겼다. 최종 구현과는 소스 바이트 해시로 연결한다. 고정 업스트림 소스는 수정하지 않았고 MIT/제삼자 고지를 유지한다.

검수 중 첫 쪽 전용 표시 거절 사례가 실패한 것은 합성 검사에서 UI용 `applyPage` 값만 native에 보내 실제 표시 플래그가 설정되지 않았기 때문이었다. 실제 필드로 설정하고 그 값도 확인한 뒤 거절/원문 보존 검사가 통과했다. 제품의 차단 조건이나 저장 검사를 느슨하게 하지 않았다.

새 실행 묶음은 `build/jueony-page-paper-20261014/Start-Review.cmd`, Rust 실행 파일은 같은 폴더의 `JueonyEditor.exe`, 주소는 `http://127.0.0.1:4232/`다. 한글에서 열어볼 합성 결과는 `review-documents/page-paper/paper-native`와 `paper-browser`에 포함한다. 이전 실행 창과 포트는 유지하며, 브라우저의 포트별 업무 저장소는 서로 별도다.

## 남은 구현

다른 쪽 스타일의 자원 이식과 상속, 그림 배경·바탕쪽·머리말 등 특수 영역, 걸친 문단/표/개체/여러 쪽 복사, 빈 구역 정리, OS 클립보드 및 Agent 전용 쪽 도구는 남는다. 모든 문서화 범위가 완료되지 않아 자동 계속 작업을 유지한다.
