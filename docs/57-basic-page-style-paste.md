# 기본 테두리·배경이 다른 쪽 붙이기

2026-10-14. [56번 다른 용지 붙이기](56-different-paper-page-paste.md)의 후속이다. 한글 2024 직접 비교는 마지막 일괄 검수로 남긴다. 이 문서는 당시 기본 모양 구현 기록이며 PNG/JPEG 그림 배경의 이식은 후속 [58번 구현](58-embedded-page-image-paste.md)에서 추가했다. 다음 내용은 기본 쪽 모양의 제한된 이식 범위이며 한글 전체 쪽 복사의 동등성 판정이 아니다.

## 동작과 범위

쪽 메뉴의 `쪽 본문 복사 (완전 문단)` → 대상 쪽의 `쪽 뒤에 본문 붙이기`를 사용한다. 원본과 대상의 기본 테두리·배경이 다르면 붙일 본문을 새 구역으로 만들고 원본 모양을 적용한다. 같은 구역에 뒤 본문이 남으면 원래 용지·테두리·배경으로 복원하는 구역을 추가한다. 용지와 모양이 동시에 달라도 같은 경로로 처리한다. 용지와 모양이 같으면 기존 구역 안에 새 쪽을 넣는다.

양쪽·홀수·짝수 설정이 같은 일반 테두리, 배경 없음, 무늬 없는 단색, 사용자 색상 위치가 없는 두 색 그러데이션을 지원한다. 테두리 간격·기준 위치·머리말/꼬리말 포함·배경 영역도 함께 전달한다. 붙이기 창은 용지 크기와 방향, 새 구역 수, 원본 배경 종류와 뒤 본문 복원을 표시한다.

홀짝 모양 차이, 첫 쪽 전용/첫 쪽 제외 표시, 대각선·테두리 자원의 3D/그림자 효과·중심선·투명도, 혼합 채우기·그림 배경·무늬·여러 색/개별 위치 그러데이션은 새 모양 이식에서 거절한다. 단·기본 탭·기타 구역 설정 차이도 남는다. 이 검사는 기존 고급 속성을 지원한다고 표시하거나 기본 모양으로 평탄화하지 않는다.

본문은 한 쪽에 완전히 들어오는 일반 문단, 사본 1,000문단·10만 문자·32MiB 이하를 유지한다. 새 구역 경로의 대상 문서 전체는 가로쓰기·한 단 일반 본문 5,000문단·10만 문자 이하이며, 다른 구역의 표·개체·필드·특수 영역도 차단한다. 여러 쪽에 걸친 문단, OS/한글 클립보드, 여러 쪽 선택 복사는 아직 지원하지 않는다.

## 모델·명령과 계약

`zzzzzz-page-body-style-paste.patch`가 기존 구역 분할과 서식 자원 이식에 기본 쪽 모양을 연결한다. 원본의 borderFill ID를 그대로 사용하는 대신 정규화된 값으로 기존 `set_page_border_fill_entry_native`를 호출하여 대상 문서의 자원을 만든다. 적용 후 원본 모양과 동일한지, 본문·쪽·구역 수와 위치가 계획과 같은지 검사한다.

대각선/3D/투명도 등 getter가 표현하지 않는 속성은 별도의 내부 자원 서명으로 비교한다. 대각선이 꺼진 상태의 기본 선 종류는 활성 대각선과 구분한다. 실제 slash/backSlash 플래그가 있거나 이식할 수 없는 효과가 있으면 거절한다. 미지원 효과를 잃으면서 동일한 기본 모양이라고 오인하지 않는다.

`PageBodyPastePlan`은 `paperChanged`, `styleChanged`, `newSection`과 세 표시 범위의 배경 종류를 전달한다. `newSection`은 용지 또는 모양 변경 여부와 반드시 일치해야 한다. 앱은 이 계약과 실제 native receipt, revision·커서·구역 token을 대조한다. 같은 열린 문서만 편집하며 디스크의 별도 파일을 다시 쓰지 않는다.

저장 사본 preflight와 live snapshot을 유지한다. 요청 하나의 undo/redo, 오래된 결과 거절, 적용 중 실패 시 본문·모양·history 복원과 안전한 저장 경로를 공유한다. 보호 검사를 우회하지 않는다.

## 검증 기록

전용 실제 엔진 검사 19개와 Edge 검사 10개가 통과했다. 기본 모양·용지 동시 이식, 뒤 본문 복원, 저장 재열기, 원문/이력 복원과 미지원 효과 거절을 확인했다. 최종 자동 회귀는 단위 407개, 브라우저 254개, 엔진 185개이며 TypeScript와 9개 모듈·227개 소스 경계도 통과했다. 실행 묶음 호환 4개를 포함한 보고서들의 앱 소스·통합 패치·WASM 해시를 같은 최종 빌드와 대조했다. [검증 요약](evidence/page-style-2026-10-14/verification-summary.json)을 따른다. 한글 GUI/지면 동등성 검사는 아직 수행하지 않았다.

첫 검사에서는 비활성 대각선의 기본 선 종류가 활성 대각선으로 오인되어 기본 모양도 거절되었다. slash/backSlash 표시 플래그와 구분하고 활성 대각선 거절도 다시 확인했다. 추가 검사에서는 HWPX 파서가 그림자 플래그를 읽지 않는 결함을 발견했다. `shadow`를 attr bit1에 보존하도록 수정하여 사본 생성 뒤에도 고급 효과를 확실히 거절한다. 무시하거나 평탄화해서 통과시키지 않았다.

기존 줄 번호 브라우저 검사에서 Esc로 닫은 창의 제거 이벤트를 기다리지 않고 다시 열어 이전 DOM을 클릭하는 실패가 한 번 있었다. 검사 코드가 창 제거 완료를 기다리도록 동기화한 뒤 12개가 통과했다. 제품 동작이나 보호 조건은 변경하지 않았다.

전용 사례는 HWP/HWPX의 단색·그러데이션·테두리만 있는 쪽, 첫/끝 쪽 뒤의 모양 이식, 용지와 모양 동시 변경, 실제 렌더링·저장 재열기, 홀짝/첫 쪽 표시와 고급 효과 거절이다. 브라우저에서는 실제 메뉴·변경 미리보기·undo/redo·취소·오래된 문서·실패 복원·좁은 화면을 확인한다. Agent 회귀는 로컬 mock이며 실제 유료 모델 호출로 계산하지 않는다.

## 남은 작업

그림 배경·바탕쪽·머리말 등 특수 영역, 복잡한 쪽 스타일과 상속, 걸친 문단/표/개체/여러 쪽 복사, 빈 구역 정리, OS 클립보드와 Agent 전용 쪽 도구가 남는다. 전체 문서화 범위는 완료되지 않았으며 자동 계속 작업을 유지한다.
