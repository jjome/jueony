# 그림 배경이 있는 쪽의 본문 복사·붙이기

2026-10-14. [57번 기본 쪽 모양 이식](57-basic-page-style-paste.md)의 후속이다. 한글 2024 직접 비교는 마지막 일괄 검수로 남긴다.

## 실제 동작

쪽 메뉴의 `쪽 본문 복사 (완전 문단)` → 대상 쪽의 `쪽 뒤에 본문 붙이기`에서 문서에 포함된 PNG/JPEG 그림 배경을 함께 옮긴다. 크기 맞춤·바둑판식·가운데 배치, 밝기·대비·원래 색/회색조/흑백 효과, 기본 테두리와 배경 영역을 지원한다. 같은 구역에 뒤 본문이 남으면 원래 용지·테두리·그림 배경을 복원하는 구역을 만든다. 용지와 그림이 동시에 달라도 같은 경로로 처리한다.

두 문서의 같은 자산 번호가 서로 다른 그림을 가리켜도 원본 그림을 정확히 이식한다. 다른 자산 번호가 같은 그림 바이트와 설정을 가리키면 모양이 같다고 판단하여 기존 구역 안에 새 쪽을 넣는다. 내부 복사 버퍼는 메모리에만 있으며 자동 자료 분석이나 Agent 요청에 포함되지 않는다.

사본은 기존과 같이 실제 HWPX이며 본문/글자/문단 서식 자원 이식과 구역 정의 연결을 공유한다. 원래 미리보기·외부 부가 스트림을 제외하지만 전체 서식 자원 풀이 남을 수 있으므로 최소 제출 사본이나 개인정보 제거 기능으로 간주하지 않는다.

## 계약·자원·보호

`zzzzzzz-page-body-image-paste.patch`는 쪽 설정의 자산 ID를 비교하지 않는다. 내장 그림의 실제 바이트를 제한된 로더로 읽고 BLAKE3 digest와 배치/효과 값으로 모양을 비교한다. `getPageBodyClipboardSettings`의 정규화 결과에서 원본 문서의 자산 ID를 노출하지 않는다.

기존 문서 삽입 경로가 자원을 이식한 뒤에는 이식된 바이트를 가진 대상 자산을 찾아 쪽 배경을 연결한다. 찾을 수 없으면 기존 제한된 이미지 등록 API를 사용한다. 원본 자산 번호를 대상 문서에 그대로 대입하지 않으며 기존 그림을 덮어쓰지 않는다. 적용 후 원본과 이식된 모양의 정규화 값, 본문·쪽·구역 수와 위치를 확인한다.

변경 없는 계획 조회, 문서 revision·커서·구역 token 검사, 저장 사본 preflight, live snapshot과 한 번의 undo/redo를 유지한다. 적용 후 실패하면 자산·본문·쪽 모양과 기존 history를 복원한다. 안전한 저장과 저장 완료 통지를 기존 경로로 수행한다.

이미지는 10MiB 이하, 한 축 8192px 이하·1600만 픽셀 이하이며 실제 포맷·확장자가 일치하고 디코딩 가능해야 한다. 누락·손상·크기 초과·다른 포맷과 참조 개수 초과는 적용 전에 거절한다. 그림이 표현되지 않는 상태를 성공으로 표시하지 않는다. 바이트 검사와 decoder는 로컬에서 동작한다.

## 지원 제한

양쪽·홀수·짝수 쪽의 모양이 같고 모든 쪽에 표시되는 배경을 대상으로 한다. 비율 유지 맞춤(zoom), 방향별 배치·기타 효과, 홀짝 모양 차이, 첫 쪽 전용/첫 쪽 제외 표시, 복합 채우기·테두리 자원의 3D/그림자/대각선/투명도는 이번 이식 경로에서 지원하지 않는다. 쪽 배경 편집 UI의 지원 범위와 쪽 복사 범위는 별도다. 특히 HWPX의 기존 zoom 편집/저장을 쪽 복사 지원으로 계산하지 않는다.

한 쪽에 완전히 들어오는 일반 본문 문단만 복사한다. 사본은 1,000문단·10만 문자·32MiB 이하, 새 구역 경로의 대상 전체는 가로쓰기·한 단 일반 본문 5,000문단·10만 문자 이하를 유지한다. 표·본문 그림 개체·필드·특수 영역·다단·숨긴 빈 줄 등이 있는 문서, 바탕쪽·줄 번호·개요 번호와 단/기본 탭 등 다른 설정 차이는 계속 차단한다. 그림 배경 지원을 본문 그림 개체나 전체 문서 호환성 지원으로 확장 해석하지 않는다.

## 검증 기록

전용 엔진 검사 30개와 실제 Edge 검사 17개가 통과했다. HWP/HWPX·PNG/JPEG·세 배치·첫/끝 쪽 뒤의 이식, 충돌 자산 ID·동일 바이트의 다른 ID, 용지 동시 변경, 뒤 배경 복원, 실제 SVG·preflight·저장 재열기를 확인했다. zoom/기타 효과·홀짝·첫 쪽 표시 거절과 누락/손상/바이트 한도/픽셀 한도 입력도 검사했다.

브라우저에서 실제 메뉴·그림 배경 미리보기 안내·undo/redo·원본 보존·취소·오래된 문서·적용 후 실패 복원·기존 복사 버퍼 보존·좁은 화면을 확인했다. 초기 SVG 검사가 native handle을 직접 호출하여 Canvas2D supplemental metrics의 내보내기 보호에 걸렸다. 검사에서 기존 호스트 `renderPageSvg`/portable metrics 트랜잭션을 경유하도록 수정하고 재검사했다. 엔진의 내보내기 보호나 제품의 저장 검사를 끄지 않았다.

## 남은 작업

바탕쪽·머리말 등 특수 영역, 복잡한 쪽 스타일과 상속, 걸친 문단/표/개체/여러 쪽 복사, 빈 구역 정리, OS 클립보드와 Agent 전용 쪽 도구가 남는다. 전체 문서화된 범위는 완료되지 않았으며 자동 계속 작업을 유지한다.
