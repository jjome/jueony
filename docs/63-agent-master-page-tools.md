# Agent의 기본 텍스트 바탕쪽 명령

2026-10-14. [62번 쪽 배경 도구](62-agent-page-background.md)에 이어 [52번 기본 바탕쪽 엔진](52-master-page-basic-editing.md)을 내부 Agent 명령으로 연결한다. 수동 기능을 다시 만들지 않고 현재 열린 rhwp 문서·공통 Facade·사본 검사·요청 snapshot·안전 저장을 재사용한다. 실제 한글 2024 비교는 마지막 일괄 검수로 남긴다.

## 지원과 명령 계약

`set_master_page_text`는 기존 구역에 저장된 양쪽·홀수·짝수 기본 텍스트 바탕쪽을 추가하거나 교체한다. 본문 문단과 바탕쪽은 별개다. 모든 필드가 필수이며 현재 조회한 위치·크기·색·진하게는 요청하지 않은 한 유지한다. 새 항목의 기본값은 5mm·5mm, 10pt, `#808080`, 진하게 꺼짐이다.

```json
{"kind":"set_master_page_text","section":0,"pageKind":"both","text":"기관 검토용\n작성 중","xMm":5,"yMm":5,"fontSizePt":10,"color":"#808080","bold":false}
```

`delete_master_page`는 같은 구역에 저장된 지정 종류만 삭제한다. 없는 항목은 native setter를 호출하지 않는 no-op다. 양쪽 종류를 수정해도 별도로 저장된 홀수/짝수 우선 항목은 지우지 않는다. 뒤 구역에 상속될 수 있으며 현재 구역 항목 삭제 후 앞 구역 정의가 다시 나타날 수 있다. 모든 쪽의 표시를 지우거나 상속을 차단했다고 응답하지 않는다.

```json
{"kind":"delete_master_page","section":0,"pageKind":"both"}
```

HWPX는 기본 세 종류 조합을 지원한다. HWP는 기존 엔진에서 저장 왕복이 확인된 없음·양쪽·홀수·양쪽+홀수·양쪽+홀수+짝수 조합을 유지한다. 같은 요청에서도 양쪽→홀수→짝수의 순서로 만들고 필요한 경우 역순으로 삭제한다. 보존되지 않는 중간 조합도 거절하며 자동 형식 변환이나 저장을 수행하지 않는다.

## 원본과 적용 보호

균일 기본 텍스트는 Unicode 4,000자·100문단 이하, 1~72pt, 실제 방향을 적용한 용지 안의 시작 위치를 지원한다. 줄바꿈만 허용하며 탭·제어문자는 거절한다. 기존 균일 기울임과 명령에서 노출하지 않은 글자 속성은 기존 엔진에서 유지한다. 글꼴 파일을 내려받거나 바탕쪽에 그림·표·필드·회전·겹침·앞으로 보내기를 생성하는 기능은 아니다.

구역의 원본 바탕쪽에 표·그림·필드·혼합/확장·중복 종류가 있으면 이 기본 경로에서는 변경과 삭제를 모두 거절한다. 긴 원본은 `textTruncated:true`와 읽기 전용으로 표시하고 Unicode 4,000자 미리보기만 모델 문맥에 넣는다. 잘린 원문을 전체 내용으로 취급해 교체하지 않는다. 전체 바탕쪽 문맥도 120,000자 이하로 제한한다. 보호 검사와 사본 저장·재열기 실패를 우회하지 않는다.

도메인은 문서 버전과 별도로 대상·필드·값·편집 능력·HWP 종류 조합을 검사한다. 요청 내 바탕쪽 목록을 순서대로 추적하고 용지 변경 뒤 새로 편집한 시작 위치가 벗어나면 전체 요청을 거절한다. native adapter는 실제 원본을 다시 읽고 기존 `planMasterPageEdits`/`executeMasterPageEdits`의 모든 대상 비교·결과 확인을 사용한다. 실문서 변경 중 실패하면 기존 snapshot과 현재 형식 바이트·history·dirty 상태를 복원한다. 복원되지 않았을 때의 손상 차단은 유지한다.

## 모듈 경계

공통 wire schema는 본문 4종과 구조·서식 18종, 총 22종이다. `Structure.sections[].masterPages`는 현재 구역에 **저장된 정의**의 텍스트·물리 단위 좌표·크기·색·기울임 등 표시 정보와 읽기 전용 여부를 전달한다. `hiddenOnFirstPage`로 첫 쪽 감추기를 함께 조회하며 문단의 쪽 감추기와 별도로 유지한다. 감춘 항목을 저장한 것과 실제 쪽에 표시한 것을 구분한다. 최종 조판의 상속 해석 결과나 native 핸들을 DTO에 넣지 않는다. 선택 필드가 없는 예전 기록은 유지하며 해당 도구는 조회 없이 실행하지 않는다. 변경 비교 화면에도 저장된 바탕쪽과 상속 범위 주의를 표시한다.

`domain/agent-master-pages.ts`는 값·단위·HWP 조합을, `control-operations.ts`는 요청 내 상태와 대상 검사를 맡는다. `adapters/rhwp/agent-master-pages.ts`는 native 조회의 제한된 DTO 변환과 기존 엔진 계획 실행을 맡는다. UI/Agent는 public 계약만 사용한다. 제공자별 인증·SDK 응답은 이 경계에 들어오지 않는다. GPT·Claude·Gemini·CLOVA·호환 API의 안내와 schema도 함께 갱신했다. 새 Rust 엔진이나 외부 MCP 서버는 만들지 않았다.

## 검증과 남은 작업

단위 440개·provider/server 52개·전용 엔진 17개와 기존 엔진 회귀 272개·전용 Edge 채팅 11개가 통과했다. TypeScript와 9개 모듈·234개 소스 경계도 통과했다. 네 adapter의 실제 UI 모델 선택·채팅 전달·바탕쪽 생성, 미저장 내용으로 후속 수정·삭제, 변경 비교·요청 undo/redo, HWP 홀수와 짝수 단독 거절, 복잡한 원본 보존, 실제 쓰기 이후 실패 복원, 오래된 결과 거절과 안전 저장·재실행과 HWP/HWPX 첫 쪽 감추기의 실제 조판·보존을 포함한다. 제공자 응답은 로컬 합성 fixture이며 유료 모델 품질 검증으로 계산하지 않는다.

초기 native 합성 HWPX의 첫 직렬화에서 미사용 채움 기본값이 바뀌어 전체 DTO 비교가 실패했다. 실제 편집기와 동일하게 해당 형식으로 저장한 표본을 먼저 열어 기준을 잡고 최종 검사를 다시 실행했다. 생산 코드의 저장 보존 조건이나 비교 필드를 삭제하지 않았다. 초기 실패 기록은 `build/agent-masters-native-initial-20261014`에 보존했다.

최종 단위 440개·provider/server 52개·브라우저 318개(동봉 실행 호환 4개 포함)·실제 엔진 289개가 통과했다.
