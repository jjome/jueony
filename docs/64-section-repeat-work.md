# 구역·쪽 설정 반복 작업

2026-10-14. 기존 본문 반복 작업에 현재 검증된 구역 설정 명령을 추가한다. 한글 스크립트 매크로나 모든 Agent 기능 기록을 완성한 단계는 아니다. 한글 2024 직접 비교는 마지막 일괄 검수로 유지한다.

## 실제 사용자 흐름

1. AI에게 기본 탭·쪽 여백·단색 배경·기본 텍스트 바탕쪽 등의 지원 작업을 요청한다.
2. 문서에 적용된 요청의 `반복 작업으로 저장`을 누르고 이름을 정한다.
3. 같은 업무에서 `반복 작업` 목록을 열어 실행한다.
4. 기록한 각 구역이 현재 문서의 어느 구역에 적용될지 직접 선택한다. 번호가 같아도 자동 선택하지 않는다.
5. `{{기관}}` 같은 텍스트 변수를 입력하고 명령 요약을 확인한다.
6. 실행하면 추가 모델 호출 없이 현재 편집 문서에 반영된다. 요청 되돌리기와 일반 redo를 사용하며 파일 저장은 별도로 실행한다.

폴더 자료나 다른 업무의 반복 작업은 자동으로 섞이지 않는다. 기존 공문·계획·보고 초안과 본문 원문 대조 반복 작업도 유지한다. 대상 구역은 실행마다 새로 선택하며 마지막 선택을 다른 문서에 재사용하지 않는다.

## 기록 가능한 명령

| 범위 | 명령 | 조건 |
|---|---|---|
| 기존 7종 | 새 문서, 본문 삽입·수정·삭제, 글자·문단 서식, 새 표 | 기존 V1 형식·원문 대조 유지 |
| 기본 탭 | `set_section_tabs` | 현재 조회 가능한 구역 기본값 |
| 기본 줄 번호 | `set_line_numbers` | 기존 HWPX 일반 본문 지원 범위 유지 |
| 쪽 배경 | `set_page_background` | 없음·단색 원본만, 고급 채움은 읽기 전용 |
| 기본 바탕쪽 | `set_master_page_text`, `delete_master_page` | 저장된 균일 텍스트 정의만; 상속과 별개 |
| 용지·단 | `set_page_setup`, `set_columns` | 기존 여백·폭·줄 번호·단 구성 검증 유지 |

총 14종을 기록한다. 전체 편집 계약은 기존 22종이며 새 provider 명령이나 Rust 엔진 명령을 만들지 않는다. 기존 표 셀·행/열 변경, 스타일 ID, 쪽 감추기, 그림·필드·개체와 임의 코드 기록은 아직 지원하지 않는다. 미지원 명령이 섞인 요청을 부분 기록하여 완성된 반복 작업처럼 제공하지 않는다.

## 계약과 보호 경계

`UI → AutomationFacade → DocumentFacade → 기존 rhwp adapter/엔진`으로 실행한다. Automation은 템플릿 기록·변수·대상 연결만 담당하며 별도 엔진 상태나 저장 경로를 만들지 않는다. LLM provider, RAG와 실행 loop는 이 기능에 관여하지 않는다.

기존 V1은 고유한 원문 문단을 전체 문서에서 찾는 기존 계약이다. V2는 `sectionRefs`와 실행 시 명시적 `SectionTargets`를 사용한다. 구역 설정과 본문 편집이 함께 기록된 경우 본문 기준 문단의 구역도 목록에 포함한다. 원문은 연결한 대상 구역 안에서만 정확히 하나와 일치해야 한다. 다른 구역에 같은 문장이 있어도 잘못 연결하지 않는다. 서로 다른 기록 구역을 같은 대상에 합치는 것은 거절한다. 기록 원본과 현재 문서를 변경하여 대상 정보를 조작하지 않는다.

변수 치환은 한 번의 일반 텍스트 치환이다. 변수 값에 들어 있는 다른 `{{이름}}`이나 JSON처럼 보이는 문자열은 명령으로 해석하지 않는다. 치환 이후에도 제어문자·길이·색·서식·용지 위치 등 공통 명령 검증을 다시 수행한다.

설정창을 열 때 문서 버전을 고정한다. 변수·대상을 선택하는 동안 사용자가 편집하면 실행을 거절하고 다시 열도록 안내한다. 이후에도 기존 사본 preflight, 현재 형식의 저장 보존 검사와 실문서 버전 검사를 사용한다. 정상 적용은 요청 단위 snapshot, 적용 도중 실패는 기존 전체 복원/부분 실패 판정을 따른다. 원본 보호 검사를 낮추지 않는다.

HWPX에서 기록한 줄 번호는 HWP 대상에서 전체 요청을 거절한다. 복잡한 바탕쪽·고급 배경·더 작은 용지와 충돌하는 위치도 대상의 실제 상태를 기준으로 거절한다. 삭제는 현재 구역에 저장된 바탕쪽 정의만 삭제한다. 이전 구역 상속이나 첫 쪽 감추기 정책은 기존 의미를 유지한다.

## 검증 진행

전용 단위 12개와 기존 단위 회귀, 실제 WASM 전용 9개를 검사한다. 단위는 V1 호환·필수 대상·서로 다른 구역 합치기 거절·구역 안 원문·치환·입력 불변성·형식/범위 재검증을 다룬다. WASM은 HWP/HWPX 두 구역 재연결·이전 구역 보존·바탕쪽 첫 쪽 감추기·저장 재열기·snapshot 복원과 읽기 전용/불가능한 위치의 원자적 거절을 다룬다.

전용 브라우저는 실제 채팅으로 명령을 기록한 뒤 추가 모델 호출 없이 재생한다. 명시적 선택, 변수, undo/redo, 안전 저장, 재실행 복원, 업무 격리, 오래된 설정창 거절, 제어문자 거절과 실문서 setter의 변경 후 실패 복원을 검증한다. 제공자는 로컬 합성 fixture이며 유료 모델 품질을 검증한 결과가 아니다.

검사 스크립트는 `verify-section-macros-engine.mjs`, `verify-section-macros.mjs`, `section-macros.test.ts`다. 초기 WASM 표본은 다른 내용의 문단에 원문 대조가 정상 거절한 사례를 동일 원문 표본으로 바로잡았다. 초기 브라우저 검사는 숨겨진 이전 오류 문구를 현재 실패로 오인한 검증을 실제 표시 상태로 고쳤다. 실패 기록은 `build/section-macro-native-initial`, `build/section-macro-browser-initial`, `build/section-macro-browser-hidden-error`와 `build/section-macro-browser-workspace-loading`에 보존한다. 저장 보존이나 오류 복원 조건은 제거하지 않았다.

## 남은 작업

기존 표·개체·스타일 참조의 안전한 반복 기록, 요청 미리보기의 전체 서식 상세 표현, 여러 문서 일괄 작업, 기관 양식 변수 체계, 한글 매크로 호환과 전체 한글 동등성은 남는다. 구역 생성·삭제와 고급 바탕쪽의 Agent 도구화도 별도다. 현재 반복 작업 확장을 전체 구현 완료율로 환산하지 않는다. 전체 범위는 미완료이며 계속 작업 자동화를 유지한다.
