# Agent 일반 본문 구역 나누기

2026-10-14. 기존 Rust 구역 나누기 엔진을 단독 Agent 명령으로 연결한다. 새로운 파일 재작성 경로나 두 번째 열린 문서 상태를 만들지 않는다. 구역 삭제·합치기, 복잡한 문서 전체 구역 편집, 한글 2024 조판 동등성을 완료한 단계는 아니다.

## 지원 범위와 사용

`첫 번째 제목의 이모지 앞에서 구역을 나눠줘`, `두 번째 본문 항목 시작에서 구역을 나눠줘`처럼 현재 문단과 글자 위치를 지정한다. 모델이 현재 문서 ID와 글자 위치를 사용해 다음 명령을 만든다.

```json
{"kind":"split_section","target":"s0p1","offset":0}
```

`offset`은 0부터 세는 Unicode 글자 위치다. 이모지의 UTF-16 길이를 글자 수로 사용하지 않는다. 0은 대상 문단 앞, 문단 글자 수와 같은 값은 문단 뒤다. 첫 문단 앞이나 마지막 문단 뒤를 나누면 유효한 구역을 유지하기 위한 빈 문단이 생길 수 있다.

한 단이고, 해당 구역의 모든 본문 문단이 현재 AI 편집 가능해야 한다. 표·개체·필드·혼합 글자 서식·쪽 감추기·켜진 줄 번호와 중간 문단의 특수 구역/단 제어가 있는 원본은 이 기본 경로로 나누지 않는다. 최대 구역 수는 100개다. 다른 구역의 기존 표나 다른 용지는 이 요청의 대상으로 재해석하지 않는다.

나누기는 한 요청의 **유일한 명령**이다. 이후 구역 번호·문단 ID가 이동하므로 새 구역의 용지·여백·배경 등을 바꾸려면 변경된 문서를 읽는 후속 요청을 사용한다. 같은 요청에 나누기와 서식 명령을 섞으면 전부 거절한다. 반복 작업으로 기록하지 않는다. 기존 엔진의 저장 설정·원문 보호·상속 동작을 사용하며 자동 저장을 하지 않는다.

## 계약과 실행

공통 provider 중립 편집 계약은 23종이다. `Structure.sectionSplitAvailable`은 현재 엔진의 나누기 API 존재를 알리는 선택 필드다. 이 값이 없는 이전 문맥에서는 명령을 실행하지 않는다. 일반적인 문서 지원 판정은 현재 문단·구역 구조를 별도로 검사한다. 모든 문서에서 된다는 의미로 노출하지 않는다.

Document domain이 단독 실행·대상·글자 위치·구역 수·원본 구조를 검사한다. rhwp adapter는 실제 원문과 구역 수를 다시 대조한 뒤 기존 `insertSectionBreak`를 호출한다. 예상한 앞/뒤 문단 목록, 나머지 구역 내용, 새 구역 번호와 개수를 검사하여 엔진이 성공이라고만 응답한 경우도 성공 처리하지 않는다. 임의 엔진 명령이나 원본 경로를 LLM에 열어 주지 않는다.

기존 사본 preflight에서 현재 HWP/HWPX 형식으로 적용·저장 보존을 검사한 뒤 실제 편집기에 하나의 snapshot 명령을 적용한다. 변경 비교는 새 구역과 이동한 문단을 현재 구조로 보여 준다. 최신 요청 undo와 일반 redo를 사용한다. 후속 요청까지 수행했다면 최신 요청부터 역순으로 일반 undo를 사용할 수 있다. 오래된 요청의 버전 검사는 낮추지 않는다.

실패 복원 검수에서 편집기 iframe의 `Error`가 호스트의 `instanceof Error` 검사에 걸리지 않는 공통 결함을 발견했다. 문서 바이트는 복원됐지만 채팅이 `실행 오류·적용 없음`으로 기록했다. public `readDocumentFailure` 계약으로 Error/DOMException의 이름·메시지를 서로 다른 realm에서 읽고, 실제 `RolledBackError`/`PartialApplyError`/`ConflictError` 상태를 유지한다. 일반 응답 객체를 Error로 취급하지 않고, 속성 읽기 실패도 포함한다. 이 수정은 보호 검사를 우회하거나 복원을 추정하는 기능이 아니다. 엔진이 확인한 복원 결과를 UI가 정확히 표시하는 수정이다.

## 검증

새 단위 검사는 명령 wire·가용 API·Unicode 경계·단독 실행·원본 제약·100개 제한·반복 기록 거절·원문 대조·거짓 엔진 결과와 cross-realm 오류 분류를 다룬다.

실제 WASM 전용 12개는 HWP/HWPX의 문단 중간·시작·끝·처음·빈 문서, 바탕쪽/탭/첫 쪽 감추기·용지 설정, 뒤 구역의 표·다른 용지, 후속 설정·snapshot undo와 저장 재열기를 검사한다. 최초 뒤 구역 표 표본은 컨트롤 번호를 0으로 가정해 실패했고, 실제 표 생성 반환값의 좌표를 사용하도록 수정했다. 실패 증거는 `build/agent-split-native-initial`에 보존한다.

실제 Edge 전용 검사는 GPT·Claude·Gemini·OpenAI 호환 adapter의 로컬 합성 응답으로 채팅 실행을 검사한다. 제공자·모델 반영, 구조 diff, undo/redo, 양 형식 저장, 후속 요청의 새 문서 ID, 미지원 원본/명령 묶음 거절, 늦은 실문서 실패와 정확한 바이트·이력·dirty 복원, 지연 응답 충돌, 저장·재실행을 포함한다. 실제 유료 모델 품질과 한글 직접 조판 비교는 별도다.

## 남은 범위

복잡한 본문 구역 나누기, 구역 삭제·경계 합치기의 Agent 연결, 한 요청의 구조 변경 이후 ID 재연결, 안전한 반복 기록과 고급 상속 정책은 남는다. 새로 나뉜 문서의 HWPX 파일 커서 동기화는 기존 단일 구역 일반 본문 제한을 넘으므로 별도다. 로컬 보기·문서 복원은 기존 경로를 유지한다. 전체 문서화 범위는 미완료이며 자동 계속 작업을 유지한다.


초기 채팅 실패 분류와 재실행 회귀는 `build/agent-split-before-failure-classification`에 보존한다. 새 업무 로딩 검사에서는 아직 documentElement가 없는 iframe을 조회하던 검증 스크립트의 null 처리를 수정했다. 실제 연결 완료를 기다리며, 오류 수집이나 업무 격리 검사를 제거하지 않는다. 수정한 공통 오류 계약으로 Agent와 반복 작업의 실제 늦은 실패가 `실패 · 변경 복원됨`으로 표시되는지도 검증한다.
