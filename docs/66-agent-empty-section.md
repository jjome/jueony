# Agent 빈 본문 구역 삭제

2026-10-14. 기존에 검증한 Rust 빈 구역 삭제를 Agent의 단독 명령으로 연결한다. 비어 있지 않은 구역 삭제, 구역 경계 합치기, 모든 빈 쪽 정리와 한글 2024 동등성을 완료한 단계는 아니다.

## 사용자 흐름과 정확한 의미

`두 번째 빈 본문 구역을 삭제해줘`처럼 현재 문서의 특정 구역을 요청한다. 모델은 현재 조회된 삭제 가능성을 확인해 아래 명령을 만든다.

```json
{"kind":"remove_empty_section","section":1}
```

구역 번호는 0부터 센다. 해당 구역의 **본문이 없는 문단 하나와 구역 전체의 용지·테두리·배경 설정**을 삭제한다. 앞뒤 구역을 합치거나 그 설정을 덮어쓰지 않는다. 본문이 비어 있어도 그림 배경 등이 있을 수 있으므로 시각적으로 완전히 빈 쪽이라는 뜻은 아니다. 배경이 있는 경우에도 구역 삭제 요청은 그 배경 설정을 함께 제거한다.

문서의 유일한 구역, 공백이나 본문이 있는 구역, 추가 문단이 있는 구역은 삭제하지 않는다. 현재 Native 지원 범위는 전체 5,000문단·10만 Unicode 문자 이하의 가로쓰기·한 단 일반 본문 문서다. 다른 구역의 표·개체·필드·특수 영역·바탕쪽·줄 번호·홀짝 시작·해석하지 못한 구역 확장도 제외한다. HWP3 계보는 지원하지 않는다. Agent 경로는 최대 100개 구역을 지원하며 현재 빈 문단도 AI 편집 가능해야 한다.

한 요청에는 삭제 명령 하나만 허용한다. 삭제 후 구역과 문단 ID가 이동하므로 다음 요청은 변경된 문서를 다시 읽는다. 구역 나누기로 만든 빈 구역도 후속 요청에서 삭제 가능성을 새로 확인한다. 명령을 반복 작업으로 기록하거나 자동 저장하지 않는다.

## 계약과 보호

공통 편집 계약은 24종이다. `Structure.sections[].emptySectionRemoval`은 `supported`와 미지원 `reason`만 제공한다. 내부 문서 검증 토큰·커서 계획·엔진 핸들은 모델 입력과 저장된 receipt에 포함하지 않는다. API가 없는 이전 엔진에서는 가능성을 제공하지 않고 명령을 거절한다. 원본 조회 실패나 잘못된 계획도 삭제 불가로 표시한다.

Domain은 단독 명령·현재 구역·원문·삭제 가능성을 검사한다. rhwp adapter는 실제 Native 계획을 새로 읽고 전체 본문과 구역 수를 다시 대조한 뒤 기존 token 검사를 사용하는 삭제 함수를 호출한다. 남은 본문·구역 설정·개수와 Native 결과를 검사한다. 삭제 가능성은 전체 문서에서 계산한 현재 상태이며 저장된 구역 설정이 아니므로, 남은 구역의 설정 비교에서 이 파생 정보만 분리한다. 실제 Native 구현의 남은 IR·본문·서식·쪽 수 보존 검사와 저장 보호는 그대로 유지한다.

기존 사본 preflight가 현재 HWP/HWPX 형식으로 적용·저장 보존을 검사한 뒤 하나의 실제 snapshot을 적용한다. 삭제 후 커서는 뒤 구역이 있으면 그 처음, 마지막 구역을 삭제하면 앞 구역의 끝으로 이동한다. 이번 명령의 Native 커서를 편집 명령 실행기에서 편집기로 반환하여 실제 입력 커서와 파일 저장·로컬 보기 복원에 연결한다. 다른 명령의 커서 정책을 바꾸지 않는다.

최신 요청 undo와 일반 redo, 변경 비교, 적용 중 실패의 정확한 복원 판정, 저장·원본 재연결·업무 복원은 기존 공통 경로를 사용한다. 모델 생성 중 사용자가 빈 구역에 글자를 넣었다면 오래된 삭제 결과를 거절한다. 미지원 삭제를 본문 지우기나 서식 초기화로 대신 실행하지 않는다.

## 전용 검증

새 단위 10개는 24종 wire·토큰/강제 옵션/경로 금지·가능성·원문·한 구역·100개 제한·단독 실행·공백/추가 문단·Native 응답 검증·현재 문맥 설명·반복 기록 거절을 검사한다.

실제 WASM 전용 15개는 HWP/HWPX 첫·중간·마지막 빈 구역, 서로 다른 용지·서식·탭·쪽 번호, 실제 PNG/JPEG 배경 보존, Native 커서와 snapshot 복원·저장 재열기, 혼합 글자 서식의 남은 본문 보존, 미지원 전체 문서·오래된 원문·구역 수·거짓 엔진 결과, 나누기 후 후속 삭제를 검사한다.

실제 Edge 전용 12개는 GPT·Claude·Gemini·OpenAI 호환 adapter의 로컬 합성 응답으로 검사한다. 모델 선택·변경 비교·요청 undo/redo·Native 커서·HWP 파일 커서·HWP/HWPX 저장, 새 문맥의 후속 요청, 미지원 원본과 명령 묶음 거절, 실문서 변경 후 실패의 바이트·커서·이력·dirty 복원, 지연 응답 충돌, 그림 배경 보존과 재실행 보기 복원을 확인한다. 유료 모델 품질과 실제 한글 직접 비교는 별도다.

## 남은 범위

비어 있지 않은 구역 삭제와 구역 합치기의 Agent 도구, 복잡한 원본, 안전한 구조 명령 묶음/반복 기록과 고급 상속 정책은 남는다. 다중 구역 HWPX 파일 커서는 기존 단일 구역 지원 범위 밖이며 로컬 보기 상태의 커서 복원과 구분한다. 전체 문서화된 구현 범위는 미완료다. 자동 계속 작업은 유지하고 실제 한글 비교는 마지막 일괄 검수로 진행한다.
