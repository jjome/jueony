# Agent 기존 머리말·꼬리말 텍스트 수정

2026-10-14. 수동 머리말/꼬리말 편집 엔진을 유지하면서 Agent 조회와 제한된 텍스트 변경을 연결한다. 한글 직접 비교는 마지막 일괄 검수로 미룬다.

## 지원 범위와 의미

공통 계약의 26번째 명령은 `set_header_footer_text {section, story, pageKind, originalText, text}`다. story는 header/footer, pageKind는 both/odd/even이다. 현재 구역에 저장된 기존 정의 하나의 한 문단 일반 텍스트를 바꾼다. originalText는 현재 원문과 정확히 같아야 한다. 새 텍스트는 Unicode 글자 4,000자 이하이며 줄바꿈·탭·제어문자를 금지한다.

글자·문단 서식, 홀짝 종류, 첫 쪽 감추기, 본문과 다른 구역·홀짝 정의를 유지한다. 빈 텍스트는 정의를 삭제하지 않고 빈 상속 덮어쓰기를 유지한다. 정의 생성/삭제, 자동 쪽 번호나 전체 쪽 수/파일명 필드, 그림·표·필드·표식·혼합 서식·여러 문단·긴 원본은 지원하지 않는다. 앞 구역에서 상속되어 보이는 머리말과 현재 구역에 저장된 정의를 구분한다. 텍스트를 바꿔도 감춘 쪽이나 홀짝 덮어쓰기가 자동 해제되지 않는다.

`Structure.sections[].headerFooters`는 여섯 종류의 exists·text·textTruncated·paragraphCount·editable·reason·hiddenOnFirstPage를 제공한다. Native 조회 실패는 exists=null/읽기 전용으로 표시하며 존재하지 않는 정의로 단정하지 않는다. API가 없는 이전 엔진에서는 조회 정보를 제공하지 않고 새 명령을 거절한다. 전체 머리말/꼬리말 문맥은 Unicode 글자 120,000자 이하이며 초과하면 요청을 거절한다.

## 보호와 계층

Native getter는 실제 머리말/꼬리말 IR의 중복, 문단·문자 축, 제어/필드/범위·표식·탭, 혼합 글자 모양, 추가 속성, 서식 참조와 HWP3 계보를 확인한다. BLAKE3 토큰은 원본 컨트롤과 실제 글자/문단 스타일을 결합한다. 모델 문맥과 receipt에는 토큰을 넣지 않는다. setter는 최신 토큰과 텍스트 인자를 재검증하고 기존 원자 범위 치환을 사용하며, 문단 메타데이터와 원래 글자 모양이 바뀌면 원본 document를 복원한다.

표준 네 바이트 머리말 instance ID와 문단의 instance ID/0인 변경 추적 꼬리는 파서·직렬화 계약에 따라 그대로 보존한다. 알 수 없는 길이·실제 변경 추적·고급 참조/정렬 속성을 임의로 없애지 않는다. 초기 진단에서 표준 ID를 알 수 없는 확장으로 잘못 거절한 결과를 보존하고, 실제 파서와 writer 코드를 확인하여 구분했다. 기존 제품의 보호 검사를 완화하지 않았다.

Domain은 현재 구역·종류·편집 가능성·정확한 원문·길이와 단독 실행을 검사한다. adapter는 최신 Native 가능성을 다시 읽고 내부에서만 토큰을 사용한 뒤 현재 구역의 다른 다섯 정의까지 결과를 대조한다. 현재 형식 사본 preflight와 저장 보존 검사를 거친 후 공통 한 번 snapshot으로 적용한다. 변경 비교·요청 undo/redo·실패 복원·버전 충돌·안전한 저장·업무 재실행을 연결한다. 반복 작업 기록과 자동 저장은 하지 않는다. 적용 후 커서 이동은 기존 Agent 공통 본문 위치 정책을 따르며 머리말 편집 커서를 새로 여는 기능은 아니다.

## 검증 계획과 잔여 범위

단위는 계약·원문·범위·Unicode 한도·단독 실행·기록 거절·Native 응답·토큰 비공개·조회 실패와 거짓 성공을 검사한다. 실제 엔진은 HWP/HWPX 여섯 종류·다중 구역·기존 서식·첫 쪽/본문 감추기·빈 정의 유지·snapshot undo·저장 재열기·미지원 원본·토큰/스타일 변경·잘못된 Native 호출을 검사한다. 실제 Edge는 네 제공자의 로컬 합성 응답으로 비교·undo/redo·저장·실패 복원·충돌·후속 요청·업무 재실행을 확인한다.

정의 생성/삭제와 상속 정책, 여러 문단·혼합 서식·필드·개체, 동적 쪽 번호, 서식 자체 변경·여러 머리말 일괄 실행·반복 기록은 남는다. 유료 모델 품질·실제 한글 출력·전체 한글 동등성은 미검증이다. 전체 구현 범위는 미완료이며 자동 계속 작업을 유지한다.


저장 보존 검사는 새 엔진에서 머리말/꼬리말의 각 문단 모양과 첫 글자 모양도 읽는다. AI 지원 원본은 전체 글자가 균일한 모양이므로 이를 통해 지원 범위의 서식 손실을 거절한다. 복잡한 원본의 모든 혼합 run 검증은 별도 한계로 표시한다. 실제 저장 사본의 글자·문단 모양만 의도적으로 바꾸고 본문/텍스트를 유지한 대조군도 보존 오류로 거절됨을 검사한다.
