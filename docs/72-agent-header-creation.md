# Agent 새 머리말·꼬리말 저장 정의 생성

2026-10-14. 30번째 공통 명령 `create_header_footer {section,story,pageKind,text}`는 현재 구역의 저장 정의가 없는 위치 하나에 단순 한 문단을 만든다. exists=false와 조회된 creatable=true가 필요하다. 이미 존재하면 기존 텍스트 수정 명령을 쓰며 조용히 삭제하거나 덮어쓰지 않는다.

한 문단 4,000 Unicode codepoint 이하로 줄바꿈·탭·제어문자·잘못된 서로게이트는 거절한다. 빈 문자열은 의도적인 빈 저장 정의를 만든다. 앞 구역의 상속 내용이 이 위치에서 덮어써질 수 있고, 감추기나 다른 홀짝 정의는 유지된다. 파일에 보이는 상속과 현재 구역 저장 정의를 구분한다.

일반 본문과 Native 검사를 통과한 단순 머리말/꼬리말만 있는 문서에서 지원한다. 표/개체/필드/다른 root·중첩 제어와 다른 구역의 혼합/복잡한 정의도 생성 가능성을 차단한다. 문서의 현재 기본 글자/문단 모양 0번을 사용하고 최초 사용자 지정 서식은 받지 않는다. 생성 뒤 텍스트·기본 글자 서식·정렬/백분율 줄 간격·삭제를 후속 명령으로 처리한다.

Domain의 현재 구역·종류·부재·가능성·텍스트·단독 실행 검사 뒤 Adapter가 원본을 다시 조회한다. 기존 createHeaderFooter로 빈 정의를 만들고 빈 한 문단/기본 모양/Native private token을 검증한 다음 기존 guarded setter로 텍스트를 넣는다. 토큰은 모델/기록에 노출하지 않는다. 디스크를 별도로 수정하지 않는다.

생성과 삭제가 공통 구조 보존 helper를 사용한다. 본문 전체 run의 텍스트·글자/문단/스타일·감추기를 대조하며 대상 밖 정의와 구역/쪽 설정을 유지한다. 예상된 root 제어 추가와 동적 쪽 위치·편집 가능성만 구분한다. 사본 preflight/현재 형식 저장 보호·요청 snapshot undo/redo·실제 변경 후 실패 복원·버전 충돌·안전한 저장·업무 복원을 연결한다. 복잡한 문서·필드/개체/여러 문단·최초 맞춤 서식·묶음 생성/서식·반복 기록·자동 저장은 미지원이다. 기존 삭제 보호를 완화하지 않는다.

단위·실제 WASM·격리된 Edge와 네 제공자 합성 응답으로 검사한다. 한글 2024 직접 비교와 유료 모델 품질은 마지막 별도 검수다. 확정 결과는 아래와 같다. 전체 문서화된 범위는 아직 미완료이며 자동 작업은 유지한다.

표 문서 끼워 넣기 회귀는 생성 가능성이 true에서 false로 바뀌는 것을 별도로 검사한다. 해당 값은 저장된 쪽 설정이 아니라 현재 문서의 도구 지원 가능성이며, 표가 추가되면 기존 생성 보호가 작동한다. 실제 쪽/탭/줄 번호/머리말 정의 보존 검사는 그대로 유지한다. 처음에는 기존 검사에서 이 동적 값을 설정처럼 비교해 4개 사례가 실패했으며, 보호 정책을 바꾸지 않고 비교 목적을 구분했다.
