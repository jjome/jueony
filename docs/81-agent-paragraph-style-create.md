# 81. 저장 모양을 참조하는 AI 문단 스타일 생성

2026-10-14. `create_paragraph_style`을 제공자 중립 계약에 추가한다(41종). 문서에 저장된 문단 스타일 하나의 글자·문단 모양을 참조하는 새 문단 스타일을 추가한다. 문서 본문은 변경하지 않으며 후속 요청에서 기존 `apply_paragraph_style`로 적용한다.

```json
{"kind":"create_paragraph_style","sourceStyleId":0,"name":"업무 본문"}
```

## 실제 동작과 책임 경계

모델은 현재 style 목록에서 type=0인 sourceStyleId를 선택한다. 조회 Snapshot.styleCreationSources는 생성 가능 여부·이유와 저장 원본의 구조 해시를 제공한다. 이 해시는 Native 권한 토큰이 아니며 모델이 명령에 되돌려 보내지 않는다. 원본 모양의 ID와 문서 핸들도 명령 인자로 받지 않는다.

Domain은 원본 유형·목록 상한·이름을 검증한다. Adapter는 현재 카탈로그와 원본 해시를 요청 당시 상태와 대조하고 기존 createStyle API를 정확한 저장 charShapeId/paraShapeId로 호출한다. 생성 ID와 참조를 확인한 뒤, 전체 문서 보존 증거에서 새 정의 하나만 추가되었는지 독립적으로 확인한다. getStyleDetail의 본문에 따른 유효 모양 추론 대신 getStoredStyleDetail을 사용하여 자동 번호가 붙은 본문의 영향이 새 스타일에 섞이지 않게 한다. 기존 c1700 엔진은 변경하지 않는다.

이 기능은 스타일 전체 메타데이터 복제가 아니다. 새 정의는 문단 type=0, nextStyleId=자기 ID, 영어 이름 빈 문자열, 한국어 langId=1042, 잠금 해제로 생성한다. 저장된 글자·문단 모양 자원은 원본과 공유하며 독립된 새 모양이나 상속 관계를 만들지 않는다. 이후 원본과 새 스타일의 공유 모양을 변경하는 고급 도구는 별도 설계·보존 검증이 필요하다.

이름은 NFC로 정규화하여 1~80 UTF-16 단위, 앞뒤 공백·C0/C1 제어문자·줄 구분자 금지, 정규화 후 중복 금지다. 모든 문단/글자 스타일을 합해 생성 전 256개 미만일 때만 추가한다. 생성은 한 요청에 하나만 허용하고 반복 매크로·다른 명령과 묶지 않는다.

공통 사본 preflight·현재 형식의 export/reopen·문서 버전 검사와 전체 snapshot undo/redo를 사용한다. 본문·기존 스타일·글꼴/번호/공유 자원이 계획 외로 변하거나 ID/참조가 틀리면 실패로 처리한다. 실문서 적용 중 실패는 본문·정의·커서·history·dirty를 복원한다. 메타데이터만 생성한 성공 요청은 본문 커서를 유지한다. 본문 텍스트가 같아도 변경 확인에서 전후 스타일 목록을 보여준다. 저장은 사용자가 별도로 실행한다.

## 사용과 한계

예: “바탕글의 저장 모양으로 업무 본문 스타일을 만들어줘.” 이어서 “첫 본문 문단에 업무 본문 스타일을 적용해줘.” 실제 선택한 모델이 해당 명령을 반환하는지는 모델별 품질 검수 대상이다. 이름 변경·정의 수정·삭제·글자 스타일 생성·임의 새 모양·상속·STY 교환과 한글 스타일마당 전체 동등성은 아직 완료하지 않았다. 기존 JSON 스타일 교환 기능의 범위도 그대로 유지한다.

검수본은 `build/jueony-agent-style-create-20261014/Start-Review.cmd`, 주소 `http://127.0.0.1:4288/`이다. 이전 검수 서버·묶음·사용자 파일을 종료하거나 덮어쓰지 않는다. 한글 검수용 자체 합성 HWP/HWPX는 review-documents/agent-style-create에 제공한다. 실제 한글 2024 직접 비교는 마지막 일괄 검수로 미룬다. 새 기능·관련 회귀의 자동 검사와 유료 모델/전체 동등성 판정은 구분한다.
