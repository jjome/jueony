# 81. 저장 모양을 참조하는 AI 문단 스타일 생성

2026-10-14. `create_paragraph_style`을 제공자 중립 계약에 추가한다(41종). 문서에 저장된 문단 스타일 하나의 글자·문단 모양을 참조하는 새 문단 스타일을 추가한다. 문서 본문은 변경하지 않으며 후속 요청에서 기존 `apply_paragraph_style`로 적용한다.

```json
{"kind":"create_paragraph_style","sourceStyleId":0,"name":"업무 본문"}
```

## 실제 동작과 책임 경계

모델은 현재 style 목록에서 type=0인 sourceStyleId를 선택한다. 조회 Snapshot.styleCreationSources는 생성 가능 여부·이유와 저장 원본의 구조 해시를 제공한다. 이 해시는 Native 권한 토큰이 아니며 모델이 명령에 되돌려 보내지 않는다. 원본 모양의 ID와 문서 핸들도 명령 인자로 받지 않는다.

Domain은 원본 유형·목록 상한·이름을 검증한다. Adapter는 현재 카탈로그와 원본 해시를 요청 당시 상태와 대조하고 기존 createStyle API를 정확한 저장 charShapeId/paraShapeId로 호출한다. 생성 ID와 참조를 확인한 뒤, 전체 문서 보존 증거에서 새 정의 하나만 추가되었는지 독립적으로 확인한다. getStyleDetail의 본문에 따른 유효 모양 추론 대신 getStoredStyleDetail을 사용하여 자동 번호가 붙은 본문의 영향이 새 스타일에 섞이지 않게 한다. 기존 c1700 엔진은 변경하지 않는다.

이 기능은 스타일 전체 메타데이터 복제가 아니다. 새 정의는 문단 type=0, nextStyleId=자기 ID, 영어 이름 빈 문자열, 한국어 langId=1042, 잠금 해제로 생성한다. 저장된 글자·문단 모양 자원은 원본과 공유하며 독립된 새 모양이나 상속 관계를 만들지 않는다. 이후 원본과 새 스타일의 공유 모양을 변경하는 고급 도구는 별도 설계·보존 검증이 필요하다.

이름은 NFC로 정규화하여 1~80 UTF-16 단위, 앞뒤 공백·C0/C1 제어문자·줄 구분자 금지, 정규화 후 중복 금지다. 모든 문단/글자 스타일을 합해 생성 전 256개 미만일 때만 추가한다. 생성은 한 요청에 하나만 허용하고 반복 매크로·다른 명령과 묶지 않는다.

공통 사본 preflight·현재 형식의 export/reopen·문서 버전 검사와 전체 snapshot undo/redo를 사용한다. 본문·기존 스타일·글꼴/번호/공유 자원이 계획 외로 변하거나 ID/참조가 틀리면 실패로 처리한다. 실문서 적용 중 실패는 본문·정의·커서·history·dirty를 복원한다. 메타데이터만 생성한 성공 요청은 본문 커서를 유지한다. 본문 텍스트가 같아도 변경 확인에서 전후 스타일 목록을 보여준다. 저장은 사용자가 별도로 실행한다.

## 사용과 한계

예: “바탕글의 저장 모양으로 업무 본문 스타일을 만들어줘.” 이어서 “첫 본문 문단에 업무 본문 스타일을 적용해줘.” 실제 선택한 모델이 해당 명령을 반환하는지는 모델별 품질 검수 대상이다. 이름 변경·정의 수정·삭제·글자 스타일 생성·임의 새 모양·상속·STY 교환과 한글 스타일마당 전체 동등성은 아직 완료하지 않았다. 기존 JSON 스타일 교환 기능의 범위도 그대로 유지한다.

검수본은 `build/jueony-agent-style-create-20261014-v2/Start-Review.cmd`, 주소 `http://127.0.0.1:4290/`이다. 이전 검수 서버·묶음·사용자 파일을 종료하거나 덮어쓰지 않는다. 한글 검수용 자체 합성 HWP/HWPX는 review-documents/agent-style-create에 제공한다. 실제 한글 2024 직접 비교는 마지막 일괄 검수로 미룬다. 새 기능·관련 회귀의 자동 검사와 유료 모델/전체 동등성 판정은 구분한다.

최종 검증 결과와 파일 해시는 구현·패키징 후 아래에 기록한다.

추가 UI 검수에서 Native 정의가 생성되어도 문서 로드 때 채운 스타일 드롭다운이 그대로 남는 오류를 재현했다. 문서 변경·현재 스타일 이벤트에서 저장 카탈로그를 읽어 드롭다운과 스타일 작업 창을 갱신하고 선택 스타일을 다시 맞춘다. 생성·undo·redo마다 수동 목록에 정의가 나타나거나 사라지는지, 별도 적용 뒤 선택 표시가 같은 ID인지 실제 Edge에서 검사한다. 변경 비교의 스타일 이름은 줄별로 표시하여 긴 목록이 가로로 잘리지 않게 했다.

4288 첫 후보는 그대로 보존하고 수동 스타일 UI 동기화까지 포함한 최종 v2는 4290에서 별도 준비한다.

## 최종 결과

생성 구현 `adacbeb`와 수동 UI 동기화 `357a1e6` 커밋·푸시 완료. 최종 빌드에서 전체 단위 631·provider/server 52·관련 실제 WASM 167·브라우저 87(묶음 호환 4 포함)이 통과했다. 신규 WASM 13·신규 Edge 13과 기존 개요/번호/목록/글머리표·탭/문단 테두리의 관련 회귀를 합한 범위다. 이전 전체 편집기 누적 검사 수를 이번에 전부 재실행했다고 표시하지 않는다. TypeScript와 9개 모듈·266개 소스 경계 검사도 통과했다. 예상 밖 page/console 오류·외부 자산 요청은 0건이며 관련 글머리표의 의도한 손실 저장 거절 2건은 별도로 기록한다. Native Rust unit tests는 이번에 미실행이며 기존 엔진을 재사용했다. [검사별 결과](evidence/agent-style-create-2026-10-14/verification-summary.json)를 따른다.

양 형식의 한국어·따옴표/역슬래시/이모지·NFC 이름, 정확한 저장 모양 참조·기존 정의 유지·번호 본문과 저장 원본 분리·후속 적용·단일 요청 undo/redo·실문서 실패 복원·계획 밖 글꼴/본문/자원 및 잘못된 ID/참조 거절·같은 이름의 원본 모양 변경/목록 충돌·생성 도중 사용자 편집·직접 입력·파일 저장 재열기·업무 복원을 확인했다. 네 제공자는 실제 adapter와 합성 모델 서버를 통과한 검사이며 유료 모델의 응답 품질을 주장하지 않는다.

수동 스타일 UI를 포함해 생성 직후 드롭다운/작업 창에서 새 정의가 보이는지, 클릭 적용과 수동 undo가 되는지, Agent 요청 undo/redo가 목록도 복원하는지, 적용 문단으로 커서를 이동했을 때 선택 표시가 일치하는지 검사했다. 본문과 실제 커서 위치를 분리해 확인했으며 Agent가 다른 문단을 적용했다고 현재 커서의 표시를 그 문단 스타일로 강제로 바꾸지는 않는다.
