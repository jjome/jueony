# 82. AI 문단 스타일 이름 변경과 저장 메타데이터 보존

2026-10-14. `rename_paragraph_style`을 제공자 중립 계약에 추가한다(42종). 기존 문단 스타일 하나의 한글 이름만 변경한다. 해당 스타일을 사용하는 여러 본문·셀의 스타일 ID와 서식은 유지하고 표시 이름을 갱신한다. 본문에 같은 단어가 있어도 찾아 바꾸지 않는다.

```json
{"kind":"rename_paragraph_style","styleId":22,"name":"올해 업무"}
```

## 경계와 실제 지원 범위

모델은 현재 문서의 styleRenameSources[String(styleId)].editable=true인 type=0 정의를 조회해 사용한다. Domain은 이름·기존 대상·capability를 검증하고 Adapter는 요청 시점 카탈로그와 저장 모양/메타데이터 해시를 다시 대조한다. 이름 규칙은 생성 명령과 공유한다. NFC 정규화 후 1~80 UTF-16 단위, 앞뒤 공백·C0/C1/줄 구분자 금지, 다른 스타일의 정규화 이름 중복과 자기 이름 no-op 금지다.

한 요청에 명령 하나만 허용한다. 바탕글(ID 0), 글자 스타일, 양식 잠금 스타일, 이름 재구성 시 확장 바이너리를 줄일 수 있는 HWP 원본과 필드가 있는 문서는 보호한다. 필드/차례에 저장된 스타일 이름 바인딩을 자동 갱신하는 기능은 아직 없다. 스타일 256개 상한에 도달해도 이름 변경은 정의를 추가하지 않으므로 허용한다. 영어 이름·다음 스타일·종류·글자/문단 모양·언어·잠금 값은 명령에 받지 않는다. 이들의 수정·삭제·상속·임의 새 모양은 별도 작업이다.

현재 Native updateStyle에 {name}만 전달한다. 적용 전 사본 preflight와 현재 형식 export/reopen을 검사하고 실문서 적용은 snapshot undo/redo를 사용한다. Adapter는 기대 스타일 이름과 같은 ID를 참조하는 본문 스타일 표시 이름만 바뀐 전체 보존 증거와 비교한다. 다른 텍스트/서식/영어 이름/다음 연결/공유 자원의 변화, 잘못된 성공 반환이나 no-op을 실패로 처리하고 실문서 상태를 복원한다. 기다리는 동안 사용자 변경이 있으면 오래된 결과를 적용하지 않는다. 메타데이터 변경 후 본문 커서와 수동 드롭다운/스타일 작업 창을 유지·갱신한다. 저장은 별도 동작이며 매크로로 반복하지 않는다.

## 새 Native 읽기와 보존 검사

추적 패치 `zzzzzzzzzzzzzzzzzzz-agent-style-metadata.patch`로 getAgentStyleMetadata(id)를 추가한다. 언어 ID·양식 잠금과 물리 rawCanonical 여부를 읽기만 한다. 원본 HWP 스타일 레코드와 기존 serializer의 재구성 바이트가 정확히 같은지 확인해, 알 수 없는 꼬리/예약 비트가 있는 레코드는 AI 이름 변경을 거절한다. raw 없음은 새로 모델링한 정의다. 원본 바이트·문서 핸들을 모델에 보내지 않는다. 해시는 재검사용 구조 해시이며 Native 권한 토큰이 아니다.

기존 getStyleList/getStoredStyleDetail에는 언어와 잠금이 없었다. 공통 저장 보존 증거에 두 값을 추가해 HWPX 저장 사본에서 langID 또는 lockForm만 달라져도 차단한다. rawCanonical은 물리 표현이므로 저장 전후 의미 비교 값에는 넣지 않는다. 보호된 원본을 저장한다고 허용 기준을 완화하지 않으며, HWPX 양식 잠금이 HWP 변환에서 사라지는 경우도 그대로 거절한다.

새 스타일 생성은 원본 모양 자원을 공유하되 새 메타데이터가 한국어 1042·잠금 해제라는 기존 계약을 명시적으로 검사한다. 원본 언어·잠금을 그대로 복제한다고 잘못 가정하지 않는다. 외국어/잠긴 원본에서 생성한 경우도 원본과 신규 정의를 각각 확인한다.

이것은 모델화된 메타데이터와 지원 원본의 검증이다. 모든 미모델링 XML 확장·외부 참조·복잡한 문서의 완전 호환성은 별도 과제이며 한글 2024와의 동등성을 뜻하지 않는다. 실제 한글 직접 비교와 유료 모델 품질 검수는 미실행이다.
