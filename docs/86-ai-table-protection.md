# 86. AI 보호 셀 우회 차단과 인접 셀 서식 보존

2026-10-14. 표 기능 확장 전에 실제 코드에서 보호 셀 편집 가능 판정의 누락을 발견해 우선 수정한다. 새 명령을 추가하지 않으며 제공자 중립 계약은 45종을 유지한다.

## 수정 전 실제 재현

0729789 기준에서 자체 HWP/HWPX의 첫 셀을 Native cellProtect=true로 저장 상태에 두었지만 문맥의 cell.editable은 true였다. set_table_cell의 검증·사본 저장 검사·실제 Native 실행을 통과해 보호 셀의 내용이 바뀌었다. 사용자 문서나 API 키를 사용하지 않은 자체 사본이며 [수정 전 관찰](evidence/table-protection-2026-10-14/before-fix.json)에 형식·커밋·플래그·변경 전후 텍스트를 기록한다. 저장 전후 보존 검사는 의도된 편집 자체를 허가하는 권한 검사가 아니므로 이것만으로 보호 위반을 막을 수 없었다.

## 앱의 AI 보호 정책과 경계

Native API 자체의 권한/파일 ACL을 바꾼 것은 아니다. 앱의 AI 편집 경로에서 보호 셀/표를 수정하지 않는 정책을 명시하고 수동 한글의 모든 양식 모드 동등성으로 표시하지 않는다. 사용자가 수동 셀 속성 창에서 보호를 변경하는 흐름과 AI 도구는 구분한다. AI 보호 해제 명령은 추가하지 않는다.

문맥 구성에서 보호 셀과 보호/확인 불가 표를 editable=false로 표시하고 이유를 제공한다. Domain은 기존/위조된 editable=true 힌트라도 cellProtect=true 또는 표 editable=false면 텍스트·글자/문단/배경/세로 정렬 서식을 거절한다. 행/열 삽입·삭제는 표 어디든 보호 셀이 있으면 거절한다. 문맥이 일부 셀을 누락해도 적용 직전에 실제 Native 전체 셀을 다시 순회하므로 보호 셀을 생략해 우회할 수 없다. 보호 셀을 선택하지 않은 이웃 셀의 내용/서식은 계속 지원한다. 생성한 새 표 alias와 후속 행/열/셀 명령도 유지한다.

rhwp의 table-write-guard는 실행 직전 실제 Native getControls Lock과 getCellProperties cellProtect를 다시 읽는다. Snapshot의 editable은 권한 토큰으로 신뢰하지 않는다. 알려진 비보호 값만 허용하고 누락/오류/유효하지 않은 셀 범위는 실패로 처리한다. Node 식별/버전·원문·사본 저장 보호는 기존대로 유지한다. UI/Agent는 공통 DTO와 Domain을 사용하고 Native 조회/쓰기 검사는 adapter에 둔다.

## 선택하지 않은 보호 셀까지 보존

자체 반례에서 비보호 이웃 셀의 배경색 변경이 인접한 보호 셀의 오른쪽 경계선 폭을 1→0으로 바꾸는 동작도 확인했다. 기존 format_table_cells가 배경 패치만 전달하여 Native의 경계선 정규화에 원래 경계 정보가 부족했다. 배경 변경 시 현재 네 방향 경계선·대각선/가운데 선 등 기존 모양을 명시해 함께 전달한다. 배경 외 속성을 임의 기본값으로 초기화하지 않는다.

비구조 셀 편집 전후에는 같은 표의 보호 셀 원문·모든 문단/run·서식·보호 표시를 비교한다. 보호 해제·본문/서식 변경이나 새 보호 표시가 요청 밖에서 생겨도 실패다. 공유 모양의 물리 ID는 기존 보존 비교처럼 해석된 속성으로 비교하며 실제 경계선/서식 차이는 무시하지 않는다. 새 guard를 통과시키려고 보호 조건이나 저장 손실 검사를 완화하지 않는다.

사본 preflight 실패 시 실문서를 건드리지 않는다. 실문서 첫 변경 뒤 Native 오류·이웃 보호 셀 오염이 나면 snapshot router가 전체 요청의 텍스트·보호 표시·history/dirty 상태를 복원한다. 요청 중 사용자가 정상 snapshot 명령으로 보호를 설정하면 지연된 AI 응답을 거절하고 사용자의 보호 값을 유지한다.

## 검증과 사용

자체 HWP/HWPX에서 보호 셀 내용·서식·범위·행/열·혼합 요청을 거절하고 바이트/history가 유지됨을 검사한다. 오래된 허용 문맥으로 Native 실행을 직접 요청해도 실제 보호 상태가 거절하는지 별도로 확인한다. Native 읽기 실패와 잠금 반환은 fault injection 사례로 표시하며 실제 파일의 잠금 생성 성공으로 표시하지 않는다. 비보호 이웃의 내용/굵게/배경 변경은 보호 셀 내용/경계/서식을 유지하고 undo/redo·저장·재열기를 통과한다. 새 alias와 행/열 후속 명령도 검증한다.

Edge에서는 네 제공자의 실제 adapter와 합성 프로토콜을 사용한다. 모델 입력의 readonly 표시, 실제 오류 안내, 선택하지 않은 이웃 편집 성공, 원복·위조/오래된 문맥·지연 응답·실패 중간 복원·업무 재실행을 확인한다. 유료 모델 호출·한글 2024 직접 비교는 미실행이다. 기존 570603 엔진을 재사용하며 새 엔진 컴파일/Native Rust unit tests는 이번에 실행하지 않는다.

검수본은 `build/jueony-table-protection-20261014/Start-Review.cmd`, 주소 `http://127.0.0.1:4300/`다. 기존 4298/4296 등 실행본과 사용자 파일은 유지한다. ‘보호 셀은 AI로 내용을/서식을 수정하지 않습니다’ 안내를 확인하고, 수동 보호 해제 없이 다른 명령으로 우회하지 않는다. 보호 입력 파일과 비보호 이웃 편집 성공 파일은 구분해 제공한다.

## 남은 작업

여러 제목 행·표 크기/여백/테두리·병합/분할 등 예정된 표 확장을 계속한다. Nested/특수 영역의 모든 편집 도구, 수동 양식 보호와 한글 동등성·문서 암호화/서명·OS 권한은 이번 AI guard로 완료 처리하지 않는다. 이전 row 정책의 일부 셀 이어짐과 정확한 한글 지면 비교, 남은 고급 기능도 아직 미완료다. 전체 범위 완료 전까지 자동화를 유지한다.
