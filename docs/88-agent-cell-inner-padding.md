# 88. Agent 셀 안 여백과 표 기본값 복귀

2026-10-14. 기존 format_table_cells 계약을 확장하여 HWPX 원본의 셀 안 여백 네 방향을 지정하고 표 기본값 사용으로 되돌린다. 명령은 45종을 유지한다. 수동 셀 속성 창과 같은 Native 속성을 사용하며 기존 편집·저장·undo를 재작성하지 않는다.

```json
{"kind":"format_table_cells","target":"s0p1t0","startRow":0,"rowCount":1,"startColumn":0,"columnCount":2,"properties":{"paddingMode":"custom","paddingLeftMm":2,"paddingRightMm":3,"paddingTopMm":1,"paddingBottomMm":4}}
```

표 기본 여백으로 복귀할 때는 같은 대상/범위의 properties에 `{"paddingMode":"table"}`만 보낸다. 범위의 rowCount/columnCount는 끝 좌표가 아니라 개수다.

## 범위와 계약

본문의 기존 단순 표, 200셀 이하, 보호·병합·중첩·혼합 서식·필드·세로 글씨·캡션·글자 취급/겹침이 없는 HWPX 원본을 지원한다. 조회된 cellPaddingSources[target].editable=true와 실제 Native 원본을 다시 확인한다. 현재 원본만 편집하며 새 표 alias나 다른 명령/서식 속성과 혼합하지 않는다. 단독 요청/하나의 snapshot undo이며 매크로·자동 저장은 미지원이다. 기존 일반 셀 글자/배경/정렬 명령의 범위를 줄이지 않는다.

custom은 네 방향 모두 0~100mm의 유한한 숫자가 필요하다. Native i16 범위 안의 HWPUNIT로 반올림하며 좌우 합계가 각 대상 셀 너비보다 작아야 한다. 일부 방향만 주어 표에서 상속 중이던 다른 방향의 비활성 저장값을 실수로 활성화하지 않는다. table 모드는 개별 저장값을 지우지 않고 applyInnerMargin=false로 바꿔 현재 표 기본값을 따른다. 이미 같은 결과인 요청은 no-op 오류다. 빈 셀도 글자 서식을 추가하지 않고 안 여백만 바꿀 수 있다.

Context에는 표 기본 여백을 mm로 제공한다. 비교 화면에는 개별 여백의 적용 여부와 네 방향 저장값을 표시하며 비활성 저장값을 현재 유효 여백이라고 안내하지 않는다. 수동 셀 속성 창에서도 같은 개별 값과 체크 상태를 읽는다.

## 모듈과 보존

Domain cell-padding.ts는 모드·범위·단독 요청·네 방향/너비·현재 조회와 no-op를 검증한다. Adapter cell-padding.ts는 기존 단순 표 판정으로 후보를 읽고 Native 지문·내용·서식·표 기본값·보호 상태를 적용 직전에 다시 검사한다. 전체 문서 보존 증거에서 대상 셀의 paddingLeft/Right/Top/Bottom과 applyInnerMargin 외에는 바뀌지 않아야 한다. 내용·글자/문단·테두리·배경·셀의 저장된 폭/높이·다른 셀·표 기본값·다른 표·자원을 유지한다. 안 여백으로 실제 행 높이/줄바꿈이 달라지는 것은 의도한 재조판이며 저장된 셀 크기를 몰래 변경하지 않는다.

새 보호 검사로 Native 실제 셀/글줄 배치를 저장 후 재열기한 HWPX 사본과 비교한다. 대상 표의 쪽 소속·조각·셀 사각형·글줄 식별/텍스트와 좌표/폭/높이를 대조하고 0.2px 반올림 오차만 허용한다. 배치를 읽지 못하거나 저장 후 달라지면 성공으로 표시하지 않는다. 사본 preflight에서 먼저 실행하고 실문서 실패 시 snapshot router가 전체 요청·history·dirty·커서를 복원한다. 생성 중 사용자가 문서를 편집하면 오래된 요청을 거절한다.

## 확인된 HWP 제한

기존 570603 엔진에서 Native setter를 직접 사용한 자체 HWP 사례는 개별 여백 플래그·수치·문자/서식의 저장 재열기가 같아도 글줄의 세로 위치가 편집 화면과 재열기 사이에 3.8px 달랐다. 저장 줄 정보/재조판 경로의 차이를 추가 조사해야 하며 이번 작업에서 원인 수정 완료로 표시하지 않는다. 기존 수동 HWP 편집의 모든 저장 배치 문제를 해결한 것도 아니다.

따라서 이번 AI 안 여백은 HWPX 원본부터 제공한다. HWP에는 이유를 포함한 읽기 전용 상태를 주고 명령을 변경 없이 거절한다. HWP 바이트의 파일 이름을 .hwpx로 바꾼 경우에도 실제 적용/저장 사본 배치 검사에서 거절하고 원복하는지 확인한다. 확장자 검사만으로 안전하다고 판정하지 않는다. 원본을 앱에서 자동 변환하거나 덮어쓰지 않는다.

HWP 진단 파일은 별도의 diagnostic-hwp 폴더에 보관하며 성공 편집 결과로 집계하지 않는다. 실제 한글에서 이 사례를 확인하고 Native 줄 정보·재조판·writer를 수정하는 후속 작업이 남는다. 보호 검사를 느슨하게 하거나 화면 좌표를 보정해 숨기지 않는다.
