# 90. 표 기본 안 여백의 줄바꿈과 측정 캐시

2026-10-14. 89번의 HWP 행 높이 진단을 이어서 수정했다. 표 기본 안 여백을 바꿔도 상속 셀의 저장 줄 폭은 종전 값으로 남았고, 내용 상자가 바뀐 뒤에도 텍스트 편집용 초기 행 배분 하한을 계속 사용했다. 저장 재열기에는 그 세션 캐시가 없어 화면의 행 높이가 달라졌다.

## 구현

`zzzzzzzzzzzzzzzzzzzzz-table-default-padding-reflow.patch`를 추가했다. 참조 소스를 수정하지 않고 새 `source-3cb8152e4498fbbb/pkg`에 패치를 적용하여 WSL release WASM을 빌드한다.

- 표 기본 여백 변경 전후 각 셀의 유효 내용 폭을 비교하고, 달라진 셀 문단만 기존 공통 reflow 경로로 다시 계산한다. 개별 안 여백이 활성인 셀은 기존 값을 따르므로 표 기본값 변경에 재조판되지 않는다.
- 상하 여백만 바뀌면 수평 줄 기록을 다시 만들지 않는다. 비활성 개별 저장값을 표 기본값보다 우선하지 않는다.
- 표·셀의 실제 내용 상자나 선언 크기가 바뀌면 해당 표의 이전 파생 측정만 제거한다. 다른 표의 측정, 본문, 글자/문단 서식, 테두리, 개별 저장 여백, 모델의 셀 크기는 유지한다.
- `HeightMeasurer::floor_rows_to_prev` 자체를 느슨하게 하지 않는다. 텍스트 편집의 기존 초기 행 배분 하한은 유지하되, 여백/크기 변경 후에는 이전 내용 상자를 전제로 한 하한을 재사용하지 않는다.

생산자는 `set_table_properties_native`의 유효 폭 변화 판정과 `reflow_table_cell_paragraphs`다. `reflow_cell_paragraph_with_metrics`가 기존 ParagraphBox/줄 구성을 발행하며, 현재 셀 줄 폭은 기존 4 HWPUNIT 격자 규칙을 따른다. 전체 셀 너비 20977을 줄 폭 20976으로 저장하는 것은 이 규칙이며 임의 허용 오차로 바꾸지 않는다. Native 검사도 격자로 내린 폭과 비교한다.

`invalidate_table_geometry_measurement`는 해당 paragraph/control 측정 기록만 제거한다. 이후 `measure_section_incremental/selective`가 현재 줄·여백으로 같은 표를 다시 측정하고, `typeset/table`의 페이지 적합 판정과 `layout/table_layout`의 행/셀 paint가 그 결과를 소비한다. 저장기는 갱신된 줄을 직렬화한다. 화면 좌표를 보정하거나 저장 보호 조건을 완화하지 않는다. Agent 명령은 기존 45종을 유지한다.

## 지원·미지원

수동 표/셀 속성의 기존 명령·snapshot undo/redo·안전한 저장 경로를 재사용한다. 표 기본 여백을 0으로 바꾼 뒤 다른 셀의 글자 크기와 개별 안 여백을 유지하는 경우, 좁혔다 넓힐 때의 줄바꿈을 검증한다. HWPX Agent 안 여백 기능과 실패 복원도 유지한다.

89번에서 보존한 0 기본 여백+다른 글자 크기의 HWP 진단은 새 경로에서 일치한다. 과거 실패 입력으로도 일반 셀 여백 변경 후 저장 재열기를 확인한다. 여러 표의 후속 저장 앵커 위치 차이는 아직 남으므로 **정상 HWP의 AI 안 여백 제한은 유지**한다. 기존 문서를 모두 자동 정규화하거나 잘못된 저장 줄을 일괄 삭제하지 않는다. HWP 전체 호환성 완료로 표시하지 않는다.
