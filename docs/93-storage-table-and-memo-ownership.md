# 93. 저장 후 표 위치와 메모 본문 소유

2026-10-14 시작, 2026-10-15 기록. 한글 2024 직접 비교는 마지막 일괄 검수로 유지한다.

## 수정

불변 엔진 `source-2ec811ab237212ca/pkg`에 두 추적 패치를 추가했다. MIT 참조 저장소는 수정하지 않는다.

- `following-table-flow-owner`: 같은 단의 증가하는 저장 줄 좌표만으로는 앞 표가 소비한 공간까지 입증되지 않았다. 직전 문단의 **실제 방출된 통째 개체 전용 표**가 소비한 흐름 안으로, 겹침 금지 후속 표의 저장 원점이 되돌아가는 경우 그 원점의 재사용을 거절한다. 현재 조판 흐름이 위치를 결정한다. 양수 저장 간격·겹침 허용·분할 표·텍스트 host는 기존 계약을 유지한다. 저장 줄 삭제나 좌표 clamp는 하지 않는다.
- `memo-tail-owner`: HWP5의 마지막 MEMO_LIST 보관용 root를 일반 본문으로 읽고 메모 문단을 필드에 연결하지 않던 문제를 수정했다. 마지막/MSB·빈 carrier·직접 자식 태그·목록 개수·고유 인덱스와 기존 필드 소유를 모두 확인한 뒤에만 연결하고 carrier를 본문에서 제외한다. 저장기가 내린 `%unk + 0x8000 + MEMO/`는 **실제 메모 목록의 고유 소유가 확인된 경우에만** 의미상 Memo로 복원한다. 중복·고아·불명확한 목록은 소비하지 않는다. 일반 끝 빈 문단은 유지한다.

메모 수정은 기존 메모 읽기/저장 보존 보강이다. 새 메모 작성·전체 메모 속성 UI/Agent 편집이 구현됐다는 뜻이 아니다. 저장은 live IR을 변경하지 않는 기존 snapshot 직렬화 경로를 유지한다.

## 남은 제한

겹침 허용 HWP 표는 기존 후속 원점과 편집 중 흐름의 차이가 남는다. HWP Agent 안 여백/너비 편집 제한을 열지 않는다. 공개 문서 변환 보존 검사, 보호·병합·중첩/필드 검사를 느슨하게 하지 않는다. 독립 한글 비교·유료 모델 호출·Native Rust unit suite는 미실행이다. 후속 표 크기 명령과 실행 묶음은 다음 작업 문서에서 별도 기록한다.
