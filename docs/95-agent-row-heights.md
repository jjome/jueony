# 95. Agent 행 높이와 적용 실패 복구

2026-10-15. 94번의 다음 과제인 행 높이 균등 분배·직접 지정을 구현한다. 한글 2024 직접 비교는 마지막 일괄 검수로 미룬다. 전체 편집기 완성이나 한글 동등성을 뜻하지 않는다.

## 실제 지원 범위

HWPX의 한 쪽에 전부 배치된 본문 단순 표에서 모든 열에 걸친 연속 행을 지정한다. 조회한 `rowHeightSources[target].editable`이 참인 표만 실행한다. 단일 단·문단 기준 왼쪽 배치, 일치하는 저장 행/표 높이와 200셀 이하의 평면 격자가 필요하다. 보호·병합·중첩·혼합 서식·필드·복합 원본, 여러 쪽으로 분할된 표와 HWP는 제외한다.

기존 45종 wire의 `format_table_cells.properties`에 두 속성을 추가한다. 속성 하나와 명령 하나만 단독으로 요청한다. 표 ID와 행/열 수는 최신 열린 문서 조회 결과를 사용한다.

```json
{
  "kind": "format_table_cells",
  "target": "s0p1t0",
  "startRow": 0,
  "rowCount": 3,
  "startColumn": 0,
  "columnCount": 3,
  "properties": {"equalizeRows": true}
}
```

`equalizeRows:true`는 두 행 이상을 선택한다. 선택한 저장 높이의 합을 보존하며 정수 HWPUNIT 나머지는 앞 행부터 1씩 배분한다. `rowHeightMm:20`은 한 행 이상에 각각 20mm를 지정한다. 1~300mm를 정수 단위로 반올림하고, 활성 상하 안 여백 이후 양의 내용 공간이 남아야 한다. 용지·방향·본문 여백·머리말/꼬리말 여백·표 바깥 여백·세로 오프셋을 반영한 총높이 상한도 검사한다.

이 명령은 **실제 화면 높이까지 확인**한다. 저장 값만 같게 바꾸고 내용 때문에 여전히 다른 높이를 성공으로 응답하지 않는다. 각 선택 셀의 실제 높이가 목표와 맞지 않으면 원복한다. 긴 내용 때문에 2mm나 50mm로 줄일 수 없는 반례는 거절하며, 같은 표의 내용이 들어가는 65mm 지정은 실제 WASM에서 통과한다. 저장 높이가 이미 같은 요청은 내용에 따른 자동 높이를 별도로 안내하며 거절한다.

## 경계와 원자성

- UI/Agent → 중립 wire/도메인 계획 → 공개 문서 facade → rhwp adapter → 기존 `setCellProperties`를 사용한다. 새 Rust 패치는 추가하지 않는다.
- 도메인은 detached snapshot에서 정수 높이와 대상 셀을 계산한다. adapter는 실제 Native 문서·셀·보호·배치·기본 안 여백·용지를 다시 읽는다.
- 전체 보존 증거에서 선택 셀 높이와 표 공통 총높이만 변경을 허용한다. 내용·서식·너비·테두리·다른 행/표·자원 변경은 거절한다.
- 실제 셀/글줄 배치를 HWPX 저장 재열기와 비교한다. 화면 재렌더 후에도 다시 검증하고 성공한 뒤에만 요청 이력을 확정한다.
- 재렌더 오류 시 InputHandler는 snapshot을 되돌리고 같은 callback으로 복구 화면을 그린다. 새 높이 검사는 첫 적용 렌더에만 수행한다. 복구 화면에 새 높이를 요구해 복구 실패로 잘못 표시하던 경로를 수정했다. 오류 주입으로 Native 작업 반환 이후 실패·정확한 원본 복구·새 요청 성공까지 확인한다.
- 현재 표 셀 커서, 요청 단위 undo/redo, 미저장 workspace 복원과 안전한 저장은 기존 경로를 재사용한다. 사용자 변경 뒤 도착한 모델 결과는 충돌로 거절한다.

## 실행과 증거

검수 실행기: `build/jueony-row-heights-20261015/Start-Review.cmd`(4316). 이전 4314 실행본과 사용자 서버·문서는 유지한다. 채팅에서 “행 높이를 같게”, “두 번째 행 높이를 20mm로 지정”처럼 요청할 수 있다. 모델이 실제 지원 계약을 반환해야 적용되며 미지원 표는 성공으로 표시하지 않는다.

행 높이 전용 검사는 단위 9개, 실제 WASM 14개, 실제 Edge 14개다. 네 제공자는 합성 HTTP 프로토콜로 전체 채팅 흐름을 검증하며 유료 계정 호출 성공과 구분한다. 비교 화면에 저장 높이를 표시한다. 전체·일부 연속 행·단일 행·다른 표·뒤 구역·긴 내용·상한·부분 열/혼합/묶음 거절·stale 응답·부분 setter 오류·이웃 너비/내용 오염·재렌더 오류·커서/이력/dirty 원복·재실행·안전 저장과 실제 UI 재열기를 포함한다.

최종 검사 수와 소스/엔진 해시는 [검사 집계](evidence/row-heights-2026-10-15/verification-summary.json), 실행 자산은 [실행 대조](evidence/row-heights-2026-10-15/launch-check.json)를 따른다. 실제 한글 비교·유료 모델·Native Rust 단위 suite는 미실행이다. Native `setDpi(144)` 반례는 기존 저장 보존 검사에서 거절되며, DPI 지원으로 계산하지 않는다. 셀/글줄 배치 허용 오차와 저장 보존 검사를 느슨하게 하지 않았다.
