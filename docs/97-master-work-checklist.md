# 97. 전체 작업 목록과 완료 체크 규칙

2026-10-15. 앞으로 작업은 이 목록에서 선택하고, 같은 ID의 상태와 근거를 갱신한다. 완료한 행은 삭제하지 않는다. 완료 이력을 남기고 검색 화면에서 숨긴다. 사용자의 정정에 따라 세 축은 **구현 / 검증 / Agent 연결**이다. MCP 등록은 완료 기준에서 제외한다.

## 어디에서 보는가

- [전체 표](jueony-work-checklist.md): 모든 행과 세 축, 완료조건, 근거를 읽는다.
- [검색 화면](jueony-work-checklist.html): 작업명·ID·영역으로 찾고 남은 구현·검증·Agent 연결을 각각 필터링한다. 읽기 전용 화면이다.
- [관리 원본 CSV](jueony-work-checklist.csv): 실제 상태를 수정한다. Excel에서 사용할 수 있는 UTF-8 BOM 파일이다.
- [집계](evidence/master-checklist-2026-10-15/counts.json): 원본에서 생성한 현재 수치다.

최초 기준선의 417행은 한글 상위 기능 `B001~B188` 188개, 상태 수명 `S001~S033` 33개, 실행 작업 196개로 구성된다. 실행 작업은 기존 리팩터링 `R00~R15` 16개, 현재 내부 Agent 명령 `A001~A046` 46개, 제한된 범위의 기구현 작업 `G001~G089` 89개, 명시적인 후속 작업 `N001~N045` 45개다. 상위 항목과 상세 작업은 범위가 겹친다. **417로 나눈 값을 한글 전체 완성률로 사용하지 않는다.** 상위 항목은 세부 작업을 만들었다고 완료되는 것이 아니다.

기존 목록을 없애거나 과거 보고서를 최신 결과로 덮어쓰지 않았다. `source_status`에 원래 상태를 보존한다. 기존 리팩터링의 VERIFIED_BASE는 최종 완료가 아닌 기준선 검증이므로 부분으로 유지한다. 원본 상태 목록은 ID가 중복되어 있었으므로 S ID를 고유하게 부여하고 원래 ID·필드를 유지한다.

## 무엇을 체크하는가

| 축 | 완료 표시 | 부분·대기 표시 | 완료조건 |
| --- | --- | --- | --- |
| 구현 | `DONE` / ☑ | `PARTIAL`, `MISSING`, `STUB`, `AUDIT` | 이 행에 정의한 원본·문맥·저장·오류 조건을 실제 코드에 구현 |
| 검증 | `DONE` / ☑ | `PARTIAL`, `NOT_RUN` | 정의한 자동 검사와 필요한 한글/실제 모델 검증을 모두 완료 |
| Agent 연결 | `CONNECTED` / ☑ | `PARTIAL`, `NOT_CONNECTED` | 제공자 중립 계약 → Agent → facade → 열린 실제 문서 명령에 연결; 실제 적용 결과·실패·원복을 확인 |

`NA`는 해당 행의 완료조건에 그 축이 필요 없는 경우다. API 키 보관·모듈 경계처럼 사용자 설정 또는 내부 기반인 작업에 일괄 AI 편집 권한을 부여한다는 의미가 아니다. 이후 Agent 제어 요구를 추가하면 해당 행을 다시 열거나 새 하위 작업을 만든다.

검증에는 `auto_check`와 `hancom_check`를 따로 둔다. 실제 WASM·Edge·같은 엔진의 저장 재열기에서 성공해도 한글 2024의 동작·지면 비교가 남아 있으면 주 검증은 `PARTIAL`이다. 한글과 비교할 필요가 없는 격리·오류 원복·프로토콜·경계 검사 등은 정의한 자동 검사가 모두 통과하면 검증 완료로 체크할 수 있다.

`WIRED`였던 메뉴는 상위 기능에서 `PARTIAL`로 표시한다. 메뉴 항목이 존재하거나 엔진 함수가 있다는 사실만으로 모든 대화상자 옵션·단축키 문맥·파일 호환성이 구현됐다고 체크하지 않는다. 구체적인 제한 범위의 구현은 G/A 하위 작업으로 체크한다. `AUDIT`는 미구현 단정이 아니라 현재 코드와 증거를 먼저 재점검해야 한다는 뜻이다.

최초 기준선의 Agent 46종 명령은 현재 wire와 실제 실행 경계에 연결된 범위를 반영한다. 예를 들어 `merge_table_cells` 연결은 HWPX 한 쪽 평면 표의 같은 셀 속성 사각형 병합이며 기존 병합 원본·중첩 표·분할까지 완료했다는 뜻이 아니다. 단순 표의 행 높이와 열 너비도 각 조회 가능 여부와 단독 요청 제한을 유지한다. 실제 계정 호출 성공과 합성 제공자 프로토콜 검사는 구분한다.

최신 구현 기준은 `ab0ca4c`와 [96번 검수 기록](96-agent-table-merge.md)이다. 기존 검사 기록은 단위 725·서버/제공자 52·WASM 201·Edge 187이며 이번 문서 작업에서 편집기 전체 검사를 다시 실행한 것이 아니다. 이번에는 CSV 고유 ID·상태·부모/의존 관계·근거 파일과 표시/집계 일치를 검사한다. 과거 증거가 기록한 제한을 유지한다.

브라우저에 열린 4314는 앞선 검수 포트다. 이 체크리스트는 현재 저장소와 4318 병합 검수본까지를 기준으로 한다. 기존 창과 문서를 종료하거나 덮어쓰지 않는다.

## 앞으로 처리할 순서

1. **저장 결함부터:** `N001` HWP 겹침 허용 후속 표, `N002` 형식 변환 보존 차이. 한글 비교 없이 독립 검증 가능한 모델·저장 결함을 먼저 고치며 차단 검사는 유지한다.
2. **다음 표 명령:** `N003` 기본 병합 셀 분할 → `N004~N008` 병합 후 편집·임의 분할·중첩·행/열·표 나누기/붙이기. 각 작업을 따로 완료하고 연결·원복·재열기를 검사한다.
3. **기본 편집과 상태:** `N011~N023` 스타일·선택·환경·단축키·화면. B/S 상위 항목의 하위 옵션이 빠져 있으면 작업을 추가한다.
4. **Agent와 자료 품질:** `N024~N040` 인증 링크·실제 제공자·문맥·loop·RAG·반복 작업·기관 양식. 이미 구현된 문자열 검색과 bounded review를 없애거나 미구현으로 오인하지 않는다.
5. **최종 검수:** `N041~N045` 복합 코퍼스·한글/PDF·OS 파일/복구·오프라인 배포. 사용자가 미뤄 둔 한글 직접 비교를 여기서 일괄 진행한다.
6. **모든 나머지 B/S 항목:** 문서 시작 도우미·개체·필드·수식·차트·보안·검토·차례/색인·인쇄·환경 등도 남은 범위다. 상세 실행 작업 196개만 끝내고 전체 제품이 완료됐다고 선언하지 않는다. 외부 한컴 서비스/기관 정책 의존 기능은 별도 의존성과 제품 결정을 기록한다.

동시에 작업할 때는 모듈과 파일 소유를 분리한다. Document/저장 소유, Preferences/Session, Agent/References, 비교·회귀를 독립 작업으로 나누되 공통 schema·build·facade 변경은 한 담당이 합친다. 표 모델/직렬화 변경과 같은 표의 Agent topology 변경은 같은 원본에 동시에 적용하지 않는다. 계약 변경은 관련 소비자와 통합 검사를 함께 갱신한다. 실제 한글 GUI와 공통 문서 원본은 한 담당만 조작한다.

## 한 항목을 완료하는 절차

1. ID, 소유 모듈, 원본/대상 범위, 실패 반례와 완료조건을 먼저 확정한다.
2. 구현을 마치면 I만 체크한다. UI가 작동해도 Agent가 아직 안 붙었으면 A를 체크하지 않는다.
3. 문서 변경은 기존 열린 엔진의 명령 계층을 사용한다. 동일 파일을 별도로 다시 쓰지 않는다.
4. 해당 기능에 맞는 대상·버전·보호·보존·undo/redo·안전 저장·재열기 검사를 수행한다. 필요한 실제 한글/모델 검증은 따로 기록한다.
5. Agent 계약과 실제 실행을 연결하고 지원 범위·오류·부분 적용·취소·진행·원복을 검사한 뒤 A를 체크한다. 앱의 일반 `executeCommand`나 메뉴 실행만 존재하는 상태는 연결 완료로 보지 않는다.
6. CSV의 상태·근거·남은 제한을 갱신하고 아래 명령으로 표시 파일을 다시 만든다. 완료 행은 삭제하지 않는다.
7. 커밋·푸시하고 새 소스/검수 실행본의 기준을 기록한다. 상위 기능을 완료로 바꾸려면 하위 옵션과 한글 동작까지 별도로 충족해야 한다.

```powershell
C:\Python314\python.exe scripts/render_work_checklist.py
C:\Python314\python.exe scripts/render_work_checklist.py --check
```

`build/init-jueony-checklist.py`는 이번 최초 가져오기용 임시 도구다. 상태를 초기화하므로 다시 실행하지 않는다. 앞으로는 CSV만 수정하고 추적된 렌더 도구를 사용한다.

## 비교 기준 자료

한글 메뉴 범위는 기존 `hangul-2024-gap-checklist.csv`, `hangul-2024-feature-audit.csv`와 설치 한글 관찰 기록을 보존한다. 공식 [파일 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/file.htm), [표 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/table.htm), [보기 메뉴](https://help.hancom.com/hoffice130/ko-KR/Hwp/menu/view.htm)를 재확인했다. 메뉴·도움말 목록은 비교 기준이며 설치된 프로그램의 모든 기능을 직접 실행한 증거가 아니다.

MCP는 향후 외부 클라이언트용 진입점으로 검토할 수 있지만, 지금 내부 Agent 연결의 필수 구현이나 완료 체크로 넣지 않는다. 이번에는 MCP 서버나 등록 설정을 만들지 않는다.

## 현재 갱신과 병렬 작업

기본 분할 N003/A047, 표 나누기·붙이기 N008/A048/A049와 제한된 저장 작업 G090을 추가해 현재 421행·실행 작업 200행이다. 최신 수치는 집계 JSON과 검색 화면을 따른다. [99번 통합 검수](99-agent-table-structure.md), [100번 저장 수정](100-storage-conversion-and-overlap.md)이 최신 실행본 기준이다. N002의 기록된 네 보존 차이는 해결했고 N001은 남은 두 반례 때문에 부분을 유지한다. N003은 범위를 정한 구현·자동 검사·Agent 연결 완료이며 한글 직접 비교는 부분으로 남긴다. [98번 기록](98-agent-table-split.md)의 단위 733·제공자 52·WASM 210·Edge 199 검사를 사용한다.

사용자의 병렬 진행 요청에 따라 N001 HWP 후속 표 저장, N002 형식 변환 보존, N008 표 나누기/붙이기는 별도 파일 소유로 동시에 진행한다. 신규 엔진 후보는 기존 immutable 엔진을 덮어쓰지 않는다. 공통 계약과 빌드·체크리스트는 통합 담당만 갱신하고 통합 후 회귀 검사를 수행한다. 진단·후보 구현 상태만으로 완료 체크하지 않는다.

49종 통합 후에는 병합 셀 개별 문단 편집(N004), 임의 N×M 분할(N005), 글상자 커서/선택 복원(N014)을 파일 소유가 겹치지 않는 병렬 후보로 진행한다. 후보는 지문이 확정된 실행본의 production source를 즉시 바꾸지 않으며 다음 통합에서 계약/원복/재열기를 검증한다.


## 두 번째 병렬 묶음 이후

현재 425행/실행 작업 204개다. `A050~A051`과 `G091~G092`를 추가했다. `N004`, `N005`, `N014`는 좁은 하위 범위만 구현했으므로 전체는 부분으로 유지한다. 최신 실행본은 4324이며 [104번 통합 결과](104-parallel-editor-integration.md)와 현재 집계가 기준이다. 이전 기준선 수치는 과거 기록이다. Native 자체 재열기와 독립 기대값 검사를 구분하고, 다음 병합 행 높이·story 서식 지문 후보는 검수 빌드에 포함됐다고 체크하지 않는다.
