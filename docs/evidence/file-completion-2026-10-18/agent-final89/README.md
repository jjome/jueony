# 최종89 파일·복구·Agent 저장 근거

최종 고정 프런트에서 **한 번의 통합 실행13군149/149**가 통과했다. unit970/970(skip0)을 Node22와 Node24에서 각각 실행했고, 타입·모듈 경계 검사를 통과했다. engine86의 동일 WASM/JS와95패치를 사용하며 엔진을 재컴파일했다고 표시하지 않는다.

- Agent15: HWP/HWPX의 실제 엔진 payload·기존 writer·IPC 쓰기/재읽기·별도 엔진 재열기, 모델 대기 중 사용자 편집 충돌. provider4종 응답 및 Native I/O는 자체 loopback/메모리 fixture다. 실제 API 과금 호출/OS 파일 쓰기/한글 비교가 아니다.
- XML: 실제 IndexedDB·strict 원자 CAS·SHA 무결성·복원/확인 폐기·Undo/Redo·사본 내보내기/재열기. Native 종료는 실제 coordinator+합성 IPC로 검사했다.
- I/O·복구: 원본 충돌·취소·readback·복구 원자성·다운로드·비활성 탭·프로세스 종료/재시작의 기존 자동 검수를 포함한다. 전원 장애/전체 ACL/모든 파일 형식의 인증으로 확대하지 않는다.
- 최종 Windows 파일 preview 빌드 성공: source/frontend/lock 및 이전9개 exe 불변, 새 exe 실행/설치0. API backend가 없는 파일 검수용이다. 별도 full-backend 묶음은 로컬 서버·보호·정확 WASM·포장된 저장 wire 계약7검사를 통과했다.
- iframe의 실제 Error를 단순 instanceof로 놓치던 pre-write 분류를 readDocumentFailure로 고쳤다. Node VM 별도 realm 단위 검사 포함. 실제 부분 실패는 여전히 PartialApplyError다.

앞선88의 타입/fixture/XML 통합 실패 및 그 수정 후 결과는 옆 agent-save88/history와 recovery87에 보존한다. 공개 방향·폰트 fallback 연구 때문에 안전 검사를 풀거나 원형 실패를 완료로 바꾸지 않았다. 사용자 요청으로 Windows/한글 직접 비교는 보류했다. HWT/XSL/일반XSD/XML Agent, 임의 경로 open/SaveAs/exit Agent는 미지원이다.
