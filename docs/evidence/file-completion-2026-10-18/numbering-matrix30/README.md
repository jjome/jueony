# 실제 한글의 번호 확장 속성 30사례

자체 빈 문서에 15개 번호 형식과 checkable=0/1을 조합했다. 30개 번호 정의를 본문 30개 문단에 각각 연결하고 8수준 형식에 고유 표식을 넣었다. 각 문단 연결은 엔진 조회로, 실제 HWP의 31개 정의와 30개 표식은 별도 CFB 읽기로 검사했다.

2026-10-18 실제 한글 2024에서 입력 HWPX를 HWP로 저장했다. 해당 탭을 닫고 디스크 HWP를 다시 연 뒤 별도 이름 HWPX로 저장했다. 디스크 역변환은 형식 코드0~14 모두 checkable이 코드의 홀짝값으로 정규화됨을 보여준다. 입력0/1의 각 쌍은 같은 바이너리 head가 된다. 따라서 15개는 보존, 15개는 정규화 손실이다. 메모리에 남은 원문 속성을 디스크 보존으로 세지 않는다.

이 자료는 저장 형식의 관측 근거이며 엔진 후보의 성공 보고서가 아니다. 생산 수정의 전체 회귀와 공개 문서 보존 결과는 별도 기록한다. 미사용 번호 정의만 넣었던 선행 사본은 한글이 제거했으므로 이 행렬의 근거로 사용하지 않았다. 사용자 문서·서비스 키·폰트 프로그램은 포함하지 않는다.
