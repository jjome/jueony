## 우선 확인할 결함 후보 및 세부 미지원

1. **F6 스타일 단축키 충돌.** build가 main 모듈에 동기적으로 capture listener를 설치해 iframe의 모든 F6를 `stopImmediatePropagation()` 후 채팅으로 보낸다. 한글 키 listener는 initPromise 완료 뒤 설치된다. 등록 순서상 F6 스타일 명령에 도달하지 못한다. 생성 파일 `apps/editor/.build/studio-continuation/src/main.ts:2011`, `:2185`에도 확인했다. 창 분할 이동 키를 한글 키와 충돌하지 않게 재설계하고 실제 IME/모달/입력창 문맥을 검사해야 한다. 이 감사에서는 키 입력을 실행하지 않았다.
2. **캡션 세부 명령.** 메뉴의 위치 9개 stub과 기본 캡션 추가는 구별한다. `insert:caption-toggle`은 수식/그룹을 제외하고 기본 아래 캡션을 직접 setObjectProps로 추가한다(`insert.ts:448–489`). 해당 경로는 다른 편집의 executeOperation(history) 경로를 통하지 않는다고 소스가 명시한다. 저장 상태·undo 보존 위험은 실측 과제로 남긴다. 표 캡션 명령은 별도이며 동일하게 미구현이라고 판정하지 않는다.
3. **표 균등 크기.** 비병합 직사각 격자, 전체 열/행 선택, 2개 이상 열/행만 가능. 부분 셀 선택·제외 셀·병합 셀·보호 셀은 거부한다. 높이 균등은 중첩 표 거부. 표 저장 높이에 여분이 있으면 전체 표 선택을 요구한다(`equal-cells.ts:12–64`). 기본 기능이 구현됐지만 한글의 모든 선택 문맥을 충족하지 않는다.
4. **탐색 작업 창.** 본문·표 텍스트만 검색하며 개체·수식·머리말·꼬리말·주석과 고급 조건은 지원하지 않는다고 UI가 직접 표시한다(`navigation-pane.ts:86`). 모달 찾기/바꾸기와 작업 창의 범위는 분리한다.
5. **쪽 테두리/배경.** 그러데이션·그림, 홀수/짝수 별도 적용, 첫 쪽만 적용이 비활성이다. 배경 전체를 미지원이라고 말하지 않는다.
6. **글상자 속성.** 세로쓰기, 영문 눕힘/세움, 한 줄 입력, 필드 이름, 양식 모드 항목은 생성 뒤 비활성 상태로만 남는다(`ui/picture-props-dialog.ts:1315–1361`). 기본 글상자 생성, 내부 여백/세로 정렬과 구별한다.
7. **개체 변형.** 도형/그림 회전·뒤집기 명령과 속성 대화상자의 활성화 경로가 존재한다. 반면 가로/세로 기울임 입력은 다시 설정할 때도 강제로 비활성이다(`picture-props-dialog.ts:2437–2451`). `.disabled = true` 검색만으로 회전/뒤집기까지 미구현이라고 분류하지 않아야 한다.
8. **주석 모양.** 미주 내용 번호의 작은 크기 옵션은 비활성이다(`ui/endnote-shape-dialog.ts:334–342`). 각주/미주 입력과 번호/배치 기능 전체가 미구현인 것은 아니다.
9. **기본 탭 간격.** 문단 모양의 개별 탭 추가/편집이 있어도 기본 40.0pt 간격 변경은 아직 구현되지 않았다.
10. **한글 전체 단축키.** 사용자 편집 기능 없이 고정 키맵을 사용한다. 예약만 있는 키는 문서 끼워넣기 Ctrl+O, 통합 머리말/꼬리말 Ctrl+N,H, 쪽 번호 대화상자 Ctrl+N,P, 스크립트 매크로 Alt+Shift+H, 이전/다음 커서 Ctrl+=/Ctrl+Shift+=, 글자 스타일 해제 Ctrl+-이다(`keymap.ts:17`, `:56`, `:75–77`). 일부 키는 브라우저가 먼저 선점할 수 있다고 제품 자체가 안내한다(`install.ts:108` 이후).

Jueony에 있는 정부 문서 작성 preset, 지원 AI 명령 매크로, 업무 자료 검색은 한글의 문서마당/스크립트 매크로/문서 찾기와 같은 기능으로 계산하지 않는다. 반대로 '문서 정보 UI 없음'이 엔진 메타데이터 보존 없음이라는 뜻은 아니다.

## 이미 존재하므로 새로 만들기보다 검증할 기능

- HWP/HWPX 열기·저장·다른 이름 저장, dirty 확인, 최근 문서, 출력, 되돌리기/다시 실행, 클립보드, 모양 복사, 찾기/바꾸기/이동.
- 본문 직접 편집, 글자/문단 모양, 스타일, 번호/글머리표, 기본 글자 장식/장평/자간/정렬.
- 표 생성, 셀 속성/테두리, 행·열 추가/삭제, 합치기/나누기, 표 분할/붙이기, 계산식·자릿점. 제한 있는 균등 크기는 Jueony 구현을 검증한다.
- 그림·도형·글상자·수식 생성 및 속성, 회전/뒤집기/앞뒤 순서, 묶기/풀기, 기존 차트 데이터 편집.
- 문자표, 누름틀 계열 필드, 책갈피·하이퍼링크, 각주·미주, 개별 머리말·꼬리말, 편집 용지/다단/구역 설정, 기본 쪽 배경·테두리.
- 문서 비교/이력 UI가 있어도 한글 파일 내부 추적 변경/이력과 같다는 뜻은 아니다.
- HTML export와 HTML을 `.doc` 확장자로 저장하는 출력은 있다(`command/commands/file.ts:858–872`, `command/export-html.ts:1–10`). DOCX 또는 네이티브 Word 바이너리 직렬화로 안내하면 안 된다.
- PDF 경로는 SVG print profile 생성 후 브라우저 print이다(`file.ts:578–593`, `:665`). 일반 인쇄에는 자체 새 창 미리 보기와 인쇄/닫기 버튼도 존재한다(`:527–553`, `:686`). '미리 보기 자체가 전혀 없다'고 하면 틀리지만 한글 고급 인쇄 옵션·동일 조판과는 별개다.

## 다음 비교의 최소 검사 단위

각 leaf 기능은 `기능 진입 → 동일 기본값 → 본문/셀/개체 선택 문맥 → 적용/취소 → undo/redo → 저장 → 한글 재열기 → 다시 Jueony 열기`를 별도 판정한다. 기본 상태/선택 여부에 따라 비활성인 명령은 미구현과 구별한다.

우선순위는 F6 충돌, 공문 필수 표 속성/쪽 옵션/머리말·쪽번호, 기본 탭 간격, 캡션 undo, 복잡한 표와 개체의 저장 보존이다. API/메뉴 이름 존재, UI 버튼 개수, 단위 테스트 통과만으로 한글 동등성을 PASS 처리하지 않는다.

## 재현한 조사

- `git rev-parse HEAD`, `git -C upstream/rhwp-source rev-parse HEAD`.
- `rg --files -g AGENTS.md`, 빌드 스크립트와 로컬 설치 패키지 버전 확인.
- `Import-Csv docs/hangul-2024-feature-audit.csv | Group-Object implementation_status` 및 182개 행의 명령/다음 작업 대조.
- `rg -n 'stub\(|canExecute:.*false|execute\(\) \{\}'` 명령 집합 검색 후 해당 execute 함수 확인.
- UI `disabled`와 TODO 검색 후 재활성화 경로 확인. 예: 그림 회전은 다시 활성화되므로 미지원 판정에서 제외; 글상자 세로쓰기/기울임은 비활성이 유지된다.
- 키맵 → capture listener → continuation 생성 소스 → 배포 JS의 `jueony:focus-chat` 연결 확인.
- 실행 테스트와 UI 조작은 하지 않았고 Git commit/push도 하지 않았다. 정적 근거와 실제 증거를 혼합하지 않는다.
