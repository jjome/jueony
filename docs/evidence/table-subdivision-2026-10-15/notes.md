# N005: 지정 행·열 수에 따른 한 셀 분할

## 구현 경계

별도 Agent 명령 `split_table_cell_into(target,row,column,rows,columns)`를 추가했다. 기존 병합 해제 명령 `split_table_cell`의 허용 범위와 보호 검사는 유지한다. 모델에는 조회된 `tableSubdivisionSources`만 전달하며 실제 Native 문서에서 대상·보호·버전·서식·문서 전체 보존 정보를 다시 확인한다.

지원 원본은 한 쪽에 놓인 HWPX 본문 비병합 평면 표이다. 원본 행 높이와 열 너비가 일관되고 실제 배치와 저장 단위 크기가 일치해야 한다. 선택 셀은 방향마다 1~8개로 나눌 수 있으며 적어도 한 방향이 2 이상이어야 한다. 결과 격자는 200 위치 이하이며 기존 안 여백을 수용해야 한다. 정확한 원본 HU 크기를 나누고 나머지는 첫 행·첫 열에 배분한다.

첫 셀이 원문과 서식을 보존하고 추가 셀은 같은 첫 문단·글자 서식의 빈 셀이다. 이웃 셀은 원래 크기와 내용·서식을 보존하면서 새 격자 축에 맞춰 주소와 span이 바뀐다. 요청 전체는 단일 undo 단위이고 첫 셀로 커서를 이동한다. 실제 배치 후에도 외곽·이웃 셀·분할 영역이 계획과 일치하는지 검사한다. 내용을 좁히면서 최소 높이가 커져 원래 외형이 달라지는 경우 거절하고 snapshot을 복구한다. 기존 0.2px 배치 비교 범위는 확대하지 않았다.

## 영역 서식 관측과 보호

엔진 getter에 읽기 전용 `cellZoneCount`를 추가했다. count가 정확히 0일 때만 구조를 바꾼다. 누락·알 수 없는 값도 거절한다. 셀 getter에 보이는 색·테두리가 원래 셀과 같은 영역 서식도 실제 영역 좌표를 보존해야 하므로 구조 변경을 허용하지 않는다. 이 보호는 root 통합에서 merge·기본 split·표 split/attach·행/열 삽입·삭제에도 적용됐다. 원본 zone을 삭제하거나 좌표 변경을 추정하지 않는다.

## 제한

HWP 원본, 병합·보호·제목 셀, 영역 서식, 필드·책갈피·중첩 표·개체, 혼합 글자 서식, 여러 문단, 여러 쪽 또는 복합 배치는 제외한다. 여러 셀 원본을 분할하면 이웃에 span이 생기므로 추가 임의 분할은 일반적으로 readonly가 된다. 기존 1×1 표를 나누어 비병합 평면 격자를 만든 경우에는 후속 분할 가능성을 다시 조회한다. 이는 한글 전체 셀 나누기 기능 완성을 뜻하지 않는다.
